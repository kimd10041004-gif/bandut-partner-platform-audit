## 핵심 비즈니스 모델 (시안에서 확정되는 사실)

1. **입찰 마켓플레이스**: 고객이 일감(작업 + 예산 + 희망 일정 + 사진)을 올리면 → 여러 파트너가 **입찰**(제안 금액 + 메시지 + 포함/제외 항목) → 고객이 비교 후 **선택(낙찰)** → 예약금 결제 → 시공 → 정산.
2. **입찰 상태 체계**: 입찰 가능 → 입찰 중 → 고객 선택 대기 → 낙찰 / 미낙찰 / 취소, 일감에는 마감(D-day)과 긴급 태그.
3. **작업 수행 플로우**: 작업 전 사진 → 작업 시작 → (현장에서 **추가 작업 요청** 발생 시 금액 승인: 예 "곰팡이 제거 +50,000원" 수락/거절) → 작업 후 사진 → 작업 완료 → 고객 확인.
4. **정산**: 수수료 3%(시안 기준; 현 구현은 5% — 상수 확인 필요), 월별 정산 요약, 세금계산서 발행, 관리자의 정산 승인 단계 존재.
5. **3면 구조**: 파트너 앱 + 고객 웹/앱 + 관리자 앱. 현재 28 시리즈는 **파트너 앱**에 해당 (28-5-05 단일 파트너 결정과 일치).

## 현 구현(28-6)과의 격차

| 영역 | 시안 | 28-6 구현 | 격차 |
|---|---|---|---|
| 일감 → 계약 | 예산 공개, 입찰 제안 금액+메시지, 낙찰/미낙찰 | 견적 제출 → 수락 (1:1 직접 흐름) | **구조 정렬 필요** — 용어(입찰/낙찰)와 예산·미낙찰 개념 부재 |
| 추가 작업 승인 | 시공 중 금액 추가 승인 → 정산 반영 | 없음 | 신규 구현 필요 |
| 작업 사진/채팅/체크리스트 | 있음 | 없음 | 백엔드(파일 저장·실시간) 필요 — 프론트 단독 범위 밖, 단계적 |
| 수수료율 | 3% | 5% | 상수 정정 필요 |
| 대시보드 | 오늘의 작업/입찰 가능 건수/진행 중/정산 예정 | 유사 (오늘 일정/현황/미정산) | 입찰 가능 건수 추가 |
| 고객/관리자 앱 | 별도 화면 | 없음 | 별도 단계 (관리자: 정산 승인·파트너 승인·분쟁) |

## 정렬 로드맵

- **28-7 (이번 라운드)**: 파트너 앱을 입찰 모델로 정렬 — 일감 예산·마감, "입찰하기"(제안 금액+메시지), 내 입찰 현황(낙찰/미낙찰), 추가 작업 승인 → 정산 반영, 수수료 3% 정정, 대시보드에 입찰 가능 건수.
- **이후**: 고객 측 화면(일감 올리기/입찰 비교) 시뮬레이션 → 관리자 정산 승인 흐름 → 사진/채팅 등 백엔드 필요 기능은 서버 도입 시.
