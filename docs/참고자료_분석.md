# 레퍼런스 분석 (2026-09-01, 사용자 제공 3종)

초기 틀을 잡기 위해 참고한 오픈소스 3종의 분석과, 우리 플랫폼에 채택한 것들의 기록.

## 1. 당근 오픈소스 (github.com/daangn) — 특히 seed-design (★1.1k)

**핵심 구조**: 하나의 토큰 소스 → 여러 플랫폼(React/iOS/Android)으로 일관 배포.
- **rootage**(토큰 엔진)와 **qvism**(스타일 레시피 엔진)의 분리 = **팔레트(글로벌) 토큰과 시맨틱 토큰의 계층화**.
- 컴포넌트는 CLI로 프로젝트에 추가(우리의 "TABS 배열 + feature 파일" 규칙과 동일 철학).
- 그 외: stackflow(모바일 스택 내비), icona(Figma→GitHub 아이콘 자동화).

**채택 (28-13)**: 토큰 2계층화 — `tokens.css`를 ①팔레트 계층(원색 스케일: navy/teal/gray/상태색)과 ②시맨틱 계층(`--brand`, `--bg`, `--st-blue` 등이 팔레트를 참조)으로 재구성. 컴포넌트는 시맨틱만 사용. 리브랜딩=팔레트 교체, 다크 모드=시맨틱 오버라이드로 역할이 분리된다.

## 2. naver/design-to-ui — Figma→UI 변환 + 픽셀 QA 플러그인

**핵심 구조**: 7단계 파이프라인(디자인 분석→토큰 매핑→코드 생성→**픽셀 대조 QA**).
- **project-design-system 스킬**: 프로젝트마다 색·타이포·컴포넌트 토큰 매핑을 정의한 문서를 두고, 모든 UI 작업이 그것을 참조.
- **design-qa**: 빌드된 앱과 디자인을 오버레이 비교해 자동 보정.

**채택 (28-13)**:
- `DESIGN_SYSTEM.md` 신설 — 이 프로젝트의 디자인 시스템 정의(아이덴티티/팔레트→시맨틱 매핑 표/타이포 스케일/컴포넌트 인벤토리/모션 규칙/시안 상태 가이드 매핑). UI 작업의 단일 참조점.
- `scripts/visual-check.mjs` 신설 — 주요 화면 자동 스크린샷 + 배경·테마 픽셀 검증 스크립트. 라운드 검증 절차(검증결과.md)의 공식 도구로 편입 (그동안 수동으로 하던 Playwright 검증의 스크립트화).

## 3. bear2u/my-skills — UI 스킬 모음 (★918)

**핵심(Landing Page Guide V2 철학)**: "획일적 AI 템플릿 탈피" — 대형 타이포(4rem+), 의도적 폰트 선택, 마이크로 인터랙션 CTA, 깊이감. Design Prompt Generator의 7단계 프레임워크(Identity→Emotional→Component Specs→Micro-interactions).

**채택 (28-13)**:
- 대시보드 **히어로 인사말** ("{업체명} 파트너님, 좋은 하루 되세요" + 날짜 대형 타이포) — 파트너 모바일 시안의 홈 인사말과도 일치.
- DESIGN_SYSTEM.md 구조에 7단계 프레임워크 차용(Identity/Emotion/Component Specs/Micro-interactions 섹션).
- 이미 반영돼 있던 것 확인: 대형 지표 타이포, 버튼 프레스·호버 마이크로 인터랙션, Pretendard(한국 서비스 적합 — Inter 회피 원칙과 부합).

## 도입하지 않은 것 (이유)

- seed-design 패키지 자체 도입: 당근 브랜드 토큰·컴포넌트 체계라 우리 브랜드와 충돌 — **구조만 차용**하고 값은 우리 것 유지.
- stackflow: 스택 내비게이션은 현재 탭 구조에 과함 — 화면 수가 늘어나는 시점에 재검토.
- design-to-ui 플러그인 직접 실행: Figma 원본 파일이 없음(시안은 이미지) — 문서·QA 개념만 차용.
