# 28-7 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-7` 전체 + 기획 시안 5장의 **디자인 언어** 대조. 사전 확인: `tsc --noEmit` 0 오류, vitest 115/115, node --test 7/7. 28-6 감사 4건(입찰 모델·추가 작업·수수료 3%·하위 호환) 전부 수정 확인됨.

기능 구조는 시안과 정렬됐으나, **시각 품질과 사용 동선이 시안 수준에 크게 못 미친다** (사용자 요구: "많이 이쁘고 효율적으로"). 이번 감사는 UI/UX 중심.

---

## 상 (High — 시각/동선)

### 28-7-01 · 시안의 디자인 언어가 반영되지 않음
시안은 일관된 시스템을 갖고 있다: **네이비 상단 바 + 브랜드 그린 액센트, 카드 그림자, 상태별 컬러 칩**(입찰 가능=파랑 계열, 낙찰/완료=초록, 미낙찰·취소=빨강/회색, 마감 임박=주황 — 파트너 모바일 시안 하단 "상태 가이드" 참조), 대시보드 **지표 타일**. 현 구현은 무채색 기본 스타일에 단일 초록 배지뿐이다.
→ 요구: 디자인 토큰 기반 스타일 시스템 재작성 — 네이비 헤더바, 상태별 칩 색상, 카드/버튼 위계(primary/secondary), Pretendard 계열 폰트.

### 28-7-02 · 대시보드가 시안의 지표 타일 구조가 아님
시안 대시보드 첫 화면은 **[오늘의 작업 N건 / 입찰 가능 N건 / 진행 중 N건 / 정산 예정 금액]** 4개 지표 타일이다. 현 구현은 한 줄 텍스트로 뭉쳐 있어 스캔이 안 된다.
→ 요구: 4지표 타일 그리드로 재구성.

### 28-7-03 · 일감 카드 → 입찰 폼 동선 단절 (효율)
일감 카드를 보고 입찰하려면 위의 폼으로 이동해 드롭다운에서 같은 일감을 다시 찾아야 한다.
→ 요구: 카드의 **"이 일감에 입찰"** 버튼이 폼의 대상 선택과 연동되고 폼으로 스크롤되게 할 것 (선택 상태를 탭 레벨로 승격).

## 중 (Medium)

### 28-7-04 · 마감 임박(D-day) 시각 신호 부재
D-day가 회색 메타 텍스트라 시안의 '마감 임박(주황)/긴급(빨강)' 신호가 없다. D-2 이하와 마감을 색으로 구분할 것.

### 28-7-05 · 좁은 화면·표 반응형 미흡 (효율)
폼이 1열 세로 나열이라 데스크탑에서 낭비가 크고, 표는 좁은 화면에서 몸통이 넘친다. 폼 2열 그리드(넓은 화면), 표는 가로 스크롤 컨테이너로 감쌀 것. 페이지 가로 스크롤 금지.
