## 항목별 수정 내용

### 28-22-01 [상] Claim 도메인 → 신규 구현
- `Claim { id, requestId, kind('as'|'dispute'), detail, status('open'→'in_review'→'resolved'), createdDate, resolvedDate?, resolution? }`.
- `fileClaim()`: A/S=completed/settled에서만, 분쟁=accepted~settled에서만, 사유 공백 거부. `reviewClaim()`(open→in_review) / `resolveClaim()`(처리 내용 필수, 재해결 거부). `claimsFor()`/`allClaims()`(미해결 우선·최신순)/`openClaimCount()`.
- 스냅샷 `claims?`+`claimSeq?` 하위 호환 + 요소 검증(resolved인데 처리 내용 없으면 거부). 회귀 테스트 3개 → vitest 148→151.

### 28-22-02 [상] 고객 접수 UI → 신규 구현
- 거래 상세 "A/S · 문제 접수" 카드: 완료·정산 거래에 **A/S 접수**, 낙찰 이후 거래에 **문제 신고**(분쟁). 접수 내역을 유형 태그(A/S=blue·분쟁=red) + 상태 뱃지(접수됨→검토 중→해결됨) + 처리 내용·처리일과 함께 리스트 행으로 표시.

### 28-22-03 [상] 관리자 처리 콘솔 → 신규 구현 (`AdminClaims`)
- 관리자 "A/S·분쟁" 탭: 처리 대기(미해결 우선) — 유형·거래·고객·접수일 + "검토 시작"/"처리 내용 입력 → 해결 처리". 해결 이력 별도 카드.
- 현황 탭에 "미해결 A/S·분쟁" 지표 추가(시안 4의 분쟁 접수 지표).
