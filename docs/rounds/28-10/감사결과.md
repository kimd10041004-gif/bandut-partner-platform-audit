## 상 (High — 구조)

### 28-10-01 · App.tsx 단일 파일 비대화 (~900줄)
아이콘, 상태 칩, 스텝퍼, 빈 상태, 6개 탭 화면, 폼 3종, 시드, 부트스트랩이 전부 한 파일에 있다. UI 수정 한 번에 전체 파일을 뒤져야 하고, 컴포넌트 재사용·교체가 불가능한 구조.
→ 요구: 계층 분리 —
- `src/ui/` 공용 컴포넌트(icons, StatusChip, EmptyState, WorkStepper, Dday) + 상수/포맷 유틸
- `src/features/` 탭별 모듈(Dashboard/Jobs/Work/Schedule/Settlement/MyProfile — 폼은 해당 기능 파일 내부)
- `src/app/` 앱 셸·부트스트랩
- `App.tsx`는 셸(헤더·탭·라우팅)만 담당.

### 28-10-02 · platform/refresh 프롭 드릴링
모든 화면·폼이 `{ platform, onChange }`를 손으로 전달받는다. 컴포넌트를 옮기거나 중첩할 때마다 프롭 배선을 다시 해야 한다.
→ 요구: `PlatformProvider` + `usePlatform()` 컨텍스트 훅으로 단일 공급 — 화면 컴포넌트는 프롭 없이 훅으로 접근.

### 28-10-03 · 스타일 단일 파일 — 토큰과 컴포넌트 스타일 혼재
styles.css 한 파일에 디자인 토큰·베이스·컴포넌트 스타일이 섞여 있어 "색만 바꾸기", "컴포넌트 스타일만 찾기"가 어렵다.
→ 요구: `src/styles/` 분리 — `tokens.css`(디자인 토큰 전용: 색·타입 스케일·형태), `base.css`(리셋·바디·레이아웃), `components.css`(컴포넌트별 섹션 주석) — 이후 브랜드 변경은 tokens.css 한 곳에서 끝나게.

## 중 (Medium)

### 28-10-04 · UI 기초 문서 부재
컴포넌트 인벤토리·토큰 의미·사용 규칙이 코드에만 암묵적으로 존재한다.
→ 요구: `UI_가이드.md` — 토큰 표, 컴포넌트 목록·용법, 새 화면 추가 절차(파일 위치 규칙) 문서화.
