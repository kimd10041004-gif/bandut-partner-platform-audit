# 28-48 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-48` 전체 — 운영 리포트 반영 후, **견적 정확도의 입력 품질** 점검.
사전 확인: `npm run check` exit 0 (vitest 205/205), e2e 104/104 PASS, visual-check 전 항목 PASS, `npm audit` 0건, 프로덕션 배포 그린(PR #122 머지). 28-47 감사 4건 전부 수정 확인됨.

핵심 지적: 파트너는 **글 몇 줄과 질문 답변만 보고 견적을 낸다.** 집수리에서 사진 없는 견적은 방문 후 추가 비용으로 이어지고(28-16 추가 작업 흐름이 이를 흡수하지만 분쟁의 씨앗), 고객은 "사진을 못 올리니 설명을 길게 써야 하는" 부담을 진다. 시안 1·3의 요청 화면은 사진 첨부를 전제로 한다. 현재 요청 위저드 1단계에는 사진 입력이 없고, 도메인에도 사진 개념이 없다. 브라우저 저장소 한계(localStorage ~5MB)를 고려해 **클라이언트 리사이즈 + 장수·크기 상한**이 도메인 규칙으로 있어야 한다.

## 상 (High)

### 28-48-01 · 사진 도메인
→ 요구: `RepairRequest.photos?: RequestPhoto[]` — `{ id, dataUrl(image/jpeg|png data URL), width, height, bytes }`. 규칙: 요청당 **최대 3장**, 장당 **200KB 이하**(리사이즈 후), data URL 형식·MIME 검증, `addRequest` 입력·스냅샷 검증 모두. `addPhoto(requestId, photo)`/`removePhoto(requestId, photoId)`는 낙찰 전(requested/estimated)만. `withdraw`/`anonymizeCustomer` 시 사진은 유지(거래 근거)하되 탈퇴 파기(`purge`) 대상 아님 — 요청 기록과 같은 보관 정책. **도메인 테스트 필수**.

### 28-48-02 · 위저드 사진 첨부(클라이언트 리사이즈)
→ 요구: 1단계 "현장 사진 (선택, 최대 3장)" 파일 입력 — 브라우저에서 긴 변 **960px** 이하·JPEG 품질 0.8로 리사이즈(`ui/image.ts`, canvas) 후 미리보기 썸네일·삭제. 200KB 초과면 품질을 낮춰 재시도, 그래도 초과면 안내. 4단계 확인에 썸네일 표시.

### 28-48-03 · 열람 화면
→ 요구: 파트너 일감 카드·내 작업 카드, 고객 거래 상세, 관리자 요청 상세에 썸네일(클릭 시 원본 크기 인라인 확대). 썸네일은 `.photo-strip` 공용 컴포넌트.

## 중 (Medium)

### 28-48-04 · e2e + 실측
→ 요구: e2e — 위저드에서 생성 PNG 2장 첨부(`setInputFiles`) → 확인 단계 썸네일 2 → 등록 후 파트너 일감 카드 썸네일 2 → 고객 거래 상세 썸네일. 도메인 상한(4장·200KB 초과)은 vitest. 실측: 위저드 첨부 화면·파트너 카드.
