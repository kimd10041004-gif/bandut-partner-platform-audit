# 28-81 수정사항 — 지표는 서버 모드에서만

**대상 감사**: `28-80/감사결과.md` 4건. 브랜치 `round-28-81`, 라운드 문자열 `28-81`, 버전 `28.81.0`.

28-79는 "보일지 말지"를, 28-80은 "무엇을 셀지"를 고쳤다. 남은 것은 **"누구의 것을 세는가"**였다.

---

## 28-81-01 (상) 로컬 모드에서는 내걸지 않는다 + 요청 수는 실적이 아니다

### 무엇이 문제였나

배포된 모드는 로컬 모드이고(`vercel.json`·워크플로 어디에도 `VITE_AUTH_MODE`가 없다), 로컬 모드의 저장소는
`window.localStorage`다. 그래서 랜딩의 "누적 요청 N"이 세는 것은 **그 방문자가 자기 브라우저에서 만든
요청 수**다 — 플랫폼 누적이 아니다. 방문자 둘이 서로 다른 "누적 실적"을 본다.

게다가 28-80의 게이트(`totalRequests > 0`)는 요청 하나가 올라온 순간 켜지는데, 그때 나가는 값은
**"누적 1 · 완료된 수리 0 · 낙찰률 —"** 이다. 정직하긴 해도 *아무 실적도 없다고 광고하는 화면*이다.

### 무엇을 했나

내걸지 말지를 **작은 순수 함수**로 뺐다 — `src/features/landing/publicStatsGate.ts`:

```ts
export function showPublicStats(mode: 'local' | 'server', stats: PublicStats): boolean {
  if (mode !== 'server') return false
  return stats.completedOrSettled > 0
}
```

두 조건 모두를 넘어야 내건다. **서버 모드**여야 하고(그때의 숫자는 실제로 모두가 공유하는 스냅샷이다),
**끝낸 수리가 하나라도** 있어야 한다(요청 수는 실적이 아니다). 로컬 모드는 원래 시연·단독 사용이므로
내걸 실적이 없는 것이 맞다.

`Landing.tsx`는 `showPublicStats(AUTH_MODE, pub)` 한 줄만 본다.

### 회귀 (수정 전 실패 인용)

`publicStatsGate.test.ts` 4건이 **모드 × 실적** 네 조합을 본다:

```
FAIL  src/features/landing/publicStatsGate.test.ts
Error: Cannot find module './publicStatsGate'
```

e2e 여정의 단언은 **뒤집혔다** — 28-80이 "보인다"고 단언하던 자리가 이제 "로컬 모드는 내걸지 않는다"다.
지표가 **나타나는** 쪽은 서버 모드 + 완료 실적이 있어야 하는데 `e2e:server`는 완료까지 태우지 않으므로,
그 방향은 위 단위 테스트가 네 조합으로 덮는다(§2에 그대로 적었다).

## 28-81-02 (중) 삭제에 확인 · 직전 상태 파일 · 지운 번호 기록

이 저장소는 훨씬 덜 파괴적인 복원에 타이핑 확인(`복원`) + 직전 상태 자동 내려받기 + 되돌리기 버튼을
요구하는데, 28-80이 새로 만든 비가역 조작에는 **아무것도 없었다**. 규칙이 28-59에만 있고 관례가 아니었던 셈이다.

- 확인 문구 `시연 삭제`를 입력해야 버튼이 열린다(`disabled` — 복원 카드와 같은 모양).
- 누르면 **지우기 전에** `platform.exportBackup('full')`을 `banded-before-clearseed-<날짜>.json`으로
  내려준다. 되살리는 경로는 이미 있다(위의 복원 카드).
- 운영 기록에 **지운 요청 번호 목록**이 남는다 — 28-58부터 `detail` 자리가 그 용도다:

```ts
this.record('admin', '시연 데이터 삭제', String(removed), [...ids].sort().join(', '))
```

### 회귀 (수정 전 실패 인용)

```
× 28-81-02: 운영 기록에 지운 요청 번호가 남는다
  AssertionError: expected undefined to be 'REQ-0001, REQ-0002'
```

e2e에 3단계 추가: 확인 전 비활성 · 확인 후 활성 · `banded-before-clearseed-` 파일 내려받기.

## 28-81-03 (중) 낙찰률은 한 곳에서 센다 + 호출자 없는 메서드 제거

28-80은 `publicStats()` 안에 won/lost 루프를 **한 벌 더** 두었다. 판정 규칙이 바뀌면 관리자 화면과 랜딩이
조용히 다른 낙찰률을 말할 수 있었다. `bidStats`가 요청 필터를 받게 해서 계산을 하나로 합쳤다:

```ts
bidStats(partnerId?: string, options: { excludeSeeded?: boolean } = {}): BidStats
…
winRate: this.bidStats(undefined, { excludeSeeded: true }).winRate    // publicStats
```

그리고 `hasRealActivity()`를 지웠다. 28-79가 만들고 28-80이 유일한 호출자를 `publicStats()`로 바꾸면서
**프로덕션 호출자가 0**이 됐는데, 단위 테스트 4건이 그것을 초록으로 지키고 있었다 — 게이트가 지키는 것과
사용자가 쓰는 것이 어긋난 상태다. 메서드를 지우고 단언은 실제로 쓰이는 `publicStats().totalRequests`로 옮겼다.

### 회귀 (수정 전 실패 인용)

```
× 28-81-03: 공개 낙찰률과 bidStats(시드 제외)가 같은 값을 낸다
  AssertionError: expected 67 to be 50
```

(시드 낙찰 1건 + 실제 입찰 2건 중 1건 낙찰 → 시드 포함 67%, 시드 제외 50%.)

## 28-81-04 (하) `chatReads` 키를 만드는 곳을 하나로

28-80은 `key.slice(0, key.indexOf(':'))`로 키를 **해체**했다. 같은 파일 `pruneChats`가 이미 키를 그대로
만들어 지우고 있었고(`${r.id}:customer` / `:partner`), 새로 만든 쪽이 더 약했다 — 콜론이 없는 키가 들어오면
`indexOf`가 `-1`이라 `slice(0, -1)`(마지막 글자만 뗌)로 비교한다. 뷰어 목록을 상수로 빼고 두 곳이 같은 것을 쓴다:

```ts
const CHAT_VIEWERS = ['customer', 'partner'] as const
…
for (const id of ids) for (const v of CHAT_VIEWERS) this.chatReads.delete(`${id}:${v}`)
```

### 이 항목은 **수정 전에도 통과한다** — 그대로 적는다

`ChatSender`는 `customer | partner`이고 요청 id는 `REQ-NNNN`이라 **오늘의 키에는 콜론이 정확히 하나뿐**이다.
그래서 28-80의 파싱도 지금은 맞게 동작하고, 새 회귀(`28-81-04: 시연 삭제가 읽음 워터마크까지 지운다`)는
**수정 전 코드에서도 통과했다**. 실패를 만들어 내기 위해 도달할 수 없는 상황을 꾸미지 않았다 —
이 항목은 동작 수정이 아니라 **구조 수정**이고, 회귀는 "지워진다"를 붙잡아 두는 **가드**다.

## 하지 않은 것 (조용히 빼지 않는다)

- **서버 모드 개통** — 지표를 서버 모드로 미뤘지만 서버 모드를 켜지는 않았다. 켜는 절차는
  `28-68/서버_연결.md` 그대로이고, 이 라운드는 "켜면 지표가 정직해진다"까지만 준비했다.
- **로컬 모드에 대체 콘텐츠 넣기** — 지표 자리를 무엇으로 채울지는 디자인 결정이라 다음으로 넘겼다.
  지금은 그 블록이 그려지지 않을 뿐, 히어로의 나머지(문구·CTA·신뢰 배지)는 그대로다.
- **`clearSeedData`에 되돌리기 버튼** — 복원 카드의 되돌리기를 재사용하려면 복원 스택을 건드려야 한다.
  대신 삭제 직전 상태를 파일로 내려주어 **복원 경로로 되살릴 수 있게** 했다(그 안내를 결과 문구에 적었다).
