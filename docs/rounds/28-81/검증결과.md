## 2. 수정 전 실패 (항목마다 인용)

수정한 소스 4개(`platform.ts`·`Landing.tsx`·`publicStatsGate.ts`·`AdminSettings.tsx`)만 되돌리고
**새 회귀만 남긴 채** 돌린 결과다:

```

Error: Cannot find module './publicStatsGate'                        ← 28-81-01

  AssertionError: expected 67 to be 50

```

**28-81-04는 수정 전에도 통과했다** — 위 출력의 `1 passed`가 그것이다. 숨기지 않고 적는다:
`ChatSender`가 `customer | partner`이고 요청 id가 `REQ-NNNN`이라 오늘의 키에는 콜론이 정확히 하나뿐이고,
그래서 28-80의 파싱도 지금은 맞게 동작한다. 이 항목은 동작 수정이 아니라 **구조 수정**(키를 만드는 곳을
하나로)이고, 회귀는 실패를 재현하는 것이 아니라 "읽음 워터마크가 함께 지워진다"를 붙잡아 두는 **가드**다.
실패를 만들려고 도달할 수 없는 상황을 꾸미지 않았다.

28-81-01의 e2e 단언은 **뒤집혔다**. 28-80이 넣은 단계

```

PASS  히어로 지표가 시드를 빼고 센다 — 누적 1 · 완료 0 · 낙찰률 —
```

는 이번 라운드에서

```

```

으로 바뀌었다. 즉 **28-80의 회귀가 지금 코드에서 실패하는 것**이 01의 수정 전 증거이기도 하다.

## 3. 지표가 "나타나는" 쪽은 무엇이 보증하나 (한계 명시)

`showPublicStats`가 참이 되려면 **서버 모드 + 완료·정산 1건 이상**이어야 하는데, `e2e:server` 여정은
입찰 제출까지만 태우고 완료·정산까지 가지 않는다. 그래서 그 방향은 **e2e가 아니라 단위 테스트**가 덮는다 —
`publicStatsGate.test.ts`가 모드(local·server) × 실적(있음·없음) 네 조합을 전부 단언한다:

```
Test Files  1 passed (1)
     Tests  4 passed (4)
```

e2e로 덮지 못한다는 사실을 적어 두는 이유는, 다음 라운드가 "나타나는 쪽도 e2e가 본다"를 다시 요구할 수
있기 때문이다. 그러려면 `e2e:server` 여정을 완료·정산까지 늘려야 하고, 그것은 이 라운드의 범위 밖이었다.

## 6. 이 컨테이너에서 확인하지 못한 것

라이브 도메인(`bandut-partner-platform.vercel.app`)은 이 개발 환경의 이그레스 정책이 막고 있어
**직접 열 수 없다**(`connect_rejected`). 화면 동작은 로컬 프로덕션 빌드에서 확인했고, 배포 반영은
병합 뒤 `deploy-check`로 확인해 §7에 적는다.

**이번 배포의 사용자 눈에 보이는 변화는 "히어로 실적 지표 블록이 사라진다"이다** — 라이브는 로컬 모드이므로
`showPublicStats`가 항상 거짓이다. 이것은 의도한 결과다(28-80 감사 01).


**번들 해시가 일치한다.** §1의 `visual-check`가 확인한 로컬 프로덕션 빌드가 `/assets/index-BxwXFXwe.js`
였고 라이브가 서빙하는 번들이 같은 이름이다 — Vite의 에셋 해시는 내용에서 나오므로 이름이 같다는 것은
내용이 같다는 뜻이다. §1·§5에서 검증한 그 빌드가 그대로 라이브에 올라가 있다.

§6에 적은 제약은 그대로다 — 라이브 화면을 **이 컨테이너에서 직접 열어 본 것은 아니다**(이그레스 정책).
확인한 것은 "로컬에서 검증한 번들이 라이브에 올라가 있다"까지다.

그 번들이 로컬 모드로 빌드됐다는 것은 `AUTH_MODE`의 기본값에서 따라 나온다(`vercel.json`·배포 설정
어디에도 `VITE_AUTH_MODE`가 없다 — 28-81-01의 근거와 같은 사실이다). 따라서 **라이브 랜딩에서는
`showPublicStats`가 항상 거짓이고, 히어로 실적 지표 블록이 그려지지 않는다.** 이번 라운드가 의도한
사용자 눈에 보이는 변화가 그것이고, 로컬 프로덕션 빌드에서 `npm run e2e`가 같은 것을 단언했다:

```
PASS  실제 요청 1건 등록 뒤에도 로컬 모드는 히어로 지표를 내걸지 않는다 (28-81-01)
```
