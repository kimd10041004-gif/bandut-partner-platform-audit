# 29-6 — 로그인이 우리 것이 된다

29-5가 배포 설정을 다 갖추고 프리뷰까지 세웠는데, 사람이 열어 보니 **아무도 로그인할 수 없었다.**
`ChatGPT로 로그인하고 계속하기`를 누르면 `/signin-with-chatgpt` 404가 났다.

## 1. 무엇이 빠져 있었나

29-3이 v17 화면을 들여올 때 **로그인 화면만 v17 것이 그대로 따라 들어왔다.**

서버는 우리 것으로 바꿨다. `/api/auth`는 살아 있고 세션·가입 코드·인증번호·잠금·관리자 등급이
전부 우리 규칙이다(28-70~28-89). `server/identity.ts`가 그 세션을 v17 `User`로 옮기는 유일한
다리라는 것도 적혀 있다.

**화면만 안 바꿨다.** v17은 ChatGPT 헤더로 로그인하므로 브라우저가 토큰을 들 필요가 없었고,
그래서 `lib/client.ts`의 `api()`도 인증 헤더를 붙이지 않는다. 우리 서버는 `Authorization: Bearer`를
읽는다. 그 결과 새 셸의 **모든 요청이 로그인되지 않은 채** 나갔고, 로그인하러 가는 문은 404였다.

## 2. 왜 어떤 게이트도 못 잡았나

29-5는 게이트를 여러 겹 통과했다.

| 게이트 | 무엇을 봤나 | 왜 못 봤나 |
| --- | --- | --- |
| 타입 검사 | 타입이 맞는가 | `/signin-with-chatgpt`는 그냥 문자열이다 |
| 단위 테스트 | 도메인 규칙 | 화면이 어느 주소로 보내는지는 안 본다 |
| `e2e:next` | 셸·CSP·API 401 | 로그인 화면을 열어 본 적이 없다 |
| 경로 31개 검사 | 그 주소가 사는가 | **우리가 쓰는 주소만** 셌다 — 화면이 링크한 주소는 목록에 없었다 |

넷 다 "이 주소가 우리 것인가"를 묻지 않았다. 이미지도 같은 모양이었다 — 화면은 200인데 그 안의
`/brand/logo.png`가 404였다. 이름이 v17 것이고 우리 `public/`에는 다른 이름으로 있었다.

**둘 다 사람이 눈으로 봐야만 보이는 종류였다.** 그래서 `lib/auth-wiring.test.ts`가 기계에게 맡긴다:
소스 어디에도 ChatGPT 로그인 주소가 없을 것, 라우터에 `/login`·`/signup`이 있을 것, `api()`가 인증
헤더를 붙일 것, `src="/…"`로 적힌 파일이 전부 `public/`에 있을 것. 주석은 빼고 본다 — 이 가드를
설명하는 글이 스스로 위반으로 잡히면 안 된다. **일부러 깨뜨려 실패하는 것을 확인했다.**

## 3. 무엇을 만들었나

| 파일 | 무엇 |
| --- | --- |
| `lib/session.ts` | 브라우저가 든 토큰. 저장소가 막힌 환경에서도 화면이 죽지 않게 감쌌다 |
| `lib/client.ts` | 모든 API 호출에 `Authorization: Bearer` — 이 한 줄이 없어서 전부 비로그인이었다 |
| `lib/auth-client.ts` | `login`·`register`·`verifyOtp`·`logout`. **토큰 저장은 여기 한 곳** |
| `components/marketplace/auth.tsx` | 로그인 화면, 가입 화면(신청 → 인증번호 두 걸음) |
| `app/[...slug]/page.tsx` | `/login`, `/login/partner`, `/login/admin`, `/signup`, `/signup/partner` |

ChatGPT로 보내던 여섯 자리를 전부 우리 화면으로 돌렸다 — 셸 메뉴, 권한 게이트, 첫 화면 큰 버튼,
요청 접수 중 안내, 내 계정의 로그아웃, 그리고 운영 설정·개인정보 안내의 설명 문구.

**로그아웃은 링크가 아니라 호출로 바꿨다.** 우리 세션은 서버에서 폐기해야 한다. 서버가 실패해도
이 브라우저의 토큰은 지운다 — 화면만 로그인된 것처럼 남는 상태를 만들지 않는다.

## 4. 실제로 되는지 확인한 것

로컬에 Postgres를 띄우고 빌드한 새 셸에 대고 왕복을 돌렸다.

```
1) 가입 신청  → ok, 인증번호 발급 (AC-0004, verified:false)
2) 인증번호   → ok, verified:true
3) 로그인     → ok, 토큰 발급
4) 그 토큰으로 /api/me → 우리 계정이 CUSTOMER 로 돌아온다
   관리자 로그인 → ok, /api/me 가 ADMIN
   토큰 없이 /api/me → 401
```

`e2e:next`가 13 → 19로 늘었다. 배포 확인의 경로 검사에도 로그인·가입 다섯 주소를 더했다.

문자 발송사가 아직 없어 인증번호가 화면에 나온다. 서버가 그렇게 만들어져 있고(28-31의 "시연"),
가입 화면도 그 사실을 그대로 적어 보여 준다. SMS를 붙이는 라운드에서 양쪽이 함께 사라진다.

## 하지 않은 것

- **`/interior/` 공간 꾸미기** — 별도 앱 자리다. 링크는 남아 있고 그 앱은 아직 없다.
- **"검토용 서비스" 문구** — v17 원문이 여러 화면에 남아 있다. 운영 전에 한 번에 정리한다.
- **문자 발송** — 인증번호가 화면에 나오는 것은 그때까지의 임시 상태다.
- **프로덕션 전환·병합** — 사용자가 프리뷰에서 회원가입과 로그인을 직접 확인한 뒤다.
