## 2. 실제 왕복 — 이번 라운드의 핵심 근거

로컬 Postgres와 빌드된 Next 서버로 사람이 할 순서를 그대로 태웠다.

```
1) 가입 신청   → ok, OTP 발급 (AC-0004, verified:false)
2) 인증번호    → ok, verified:true
3) 로그인      → ok, 토큰 발급
4) /api/me     → CUSTOMER
   관리자 로그인 → ADMIN
   토큰 없이     → 401
```

29-6 이전에는 이 여섯 줄 중 **한 줄도 통과할 수 없었다.** 로그인하러 가는 문이 404였고,
설령 토큰이 있어도 `api()`가 `Authorization` 헤더를 붙이지 않아 모든 요청이 비로그인으로 나갔다.

## 5-1. 배포 확인이 화면 **안**까지 본다

경로 36개가 전부 200이었는데도 사람이 열자마자 막혔다. 200은 "그 주소가 있다"까지만 말한다.
로그인 화면은 200이었고, 그 안의 버튼이 남의 주소를 가리키고 있었을 뿐이다.

그래서 `deploy-check`에 단계를 하나 더했다. 여전히 GET 뿐이라 계정도 데이터도 만들어지지 않는다.

| 무엇을 보나 |
|---|
| `/login` 에 `data-login-submit` 이 있는가 |
| 세 역할(`customer`·`partner`·`admin`)을 고를 수 있는가 |
| `/signup` 에 `data-signup-code` 와 가입 단계가 있는가 |
| 세 화면 어디에도 ChatGPT 인증 주소가 없는가 |
| 화면이 부르는 `src="/…"` 가 전부 200인가 |

**사장님이 겪은 상태를 그대로 재현해 이 단계가 실제로 잡는지 확인했다.** 가짜 서버에
`/brand/logo.png`(404)와 `signin-with-chatgpt` 링크만 두고, 우리 폼은 빼고 돌렸다.

```
::error::/login 에 우리 로그인 폼이 없습니다 (data-login-submit)
::error::/login 에서 customer 역할을 고를 수 없습니다
::error::/login 에서 partner 역할을 고를 수 없습니다
::error::/login 에서 admin 역할을 고를 수 없습니다
::error::/signup 에 가입 코드 입력이 없습니다 (data-signup-code)
::error::/signup 이 가입 단계를 그리지 않습니다
::error::login.html 에 ChatGPT 인증 주소가 남아 있습니다
::error::signup.html 에 ChatGPT 인증 주소가 남아 있습니다
::error::home.html 에 ChatGPT 인증 주소가 남아 있습니다
::error::화면이 부르는 /brand/logo.png 가 HTTP 404 입니다
화면 안에서 10 건이 어긋납니다
```

같은 단계를 실제 빌드에 돌리면 통과하고, `/brand/logo-mark.png`·`/brand/hero-main.jpg`를
직접 두드려 200을 확인한다 — 29-6 전에 404였던 바로 그 둘이다. 옛 SPA(인증 모드 `local`)에서는
건너뛴다. 어떤 경로든 `index.html`을 주는 구조라 이 단언들이 성립하지 않고, 성립하지 않는 것을
실패로 세면 안 된다.

에셋 목록은 이미지를 먼저 세운다. `/_next/static/chunks/...` 가 이름 순으로 앞서서, 그냥 정렬해
자르면 정작 보고 싶은 `/brand/...` 가 상한 밖으로 밀려난다.
