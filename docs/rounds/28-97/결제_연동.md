# 결제사 연동 — 지금 어디까지 왔고 무엇이 남았나 (28-97)

|---|---|
| 주문번호(멱등 키) | 도메인이 `BD-<요청>-<종류>-<번호>`로 발급. 같은 주문의 승인은 몇 번을 보내도 결제 한 건 |

## 켜는 순서

1. 토스페이먼츠 가맹점 등록 → 테스트 키(`test_ck_…`/`test_sk_…`).
2. Vercel 환경변수: `TOSS_CLIENT_KEY`·`TOSS_SECRET_KEY`·`PAYMENTS_ENABLED=true`.
   라이브 키는 여기에 더해 `PAYMENTS_LIVE_APPROVED=true`가 있어야 켜진다(실수 방지).
3. `POST /api/payments {op:'config'}`가 `ready:true`인지 확인한다.
4. 결제창(SDK)을 붙인다 — **아직 막혀 있는 단계**, 아래 참조.
5. 정산 계좌 이체는 여전히 사람이 한다(`markPayout`은 이체 뒤의 기록이다).

## 남은 것

- **결제창 SDK와 CSP.** `https://js.tosspayments.com`은 외부 스크립트라 현재 `script-src 'self'`에서 로드되지 않는다.
  결제창을 붙이려면 `vercel.json`의 CSP에 그 출처를 열고(`script-src`·`connect-src`·`frame-src`), 결제창 복귀 주소
  (성공/실패)를 라우팅에 더한 뒤, 복귀 시 `POST /api/payments {op:'confirm'}` → 도메인 `confirmPayment(orderId, …)`로
  잇는다. 순서가 이렇게 되는 이유: 승인은 비밀 키로만 하고, 기록은 주문번호로만 한다.
- **주문 단위 인가.** 스냅샷이 마켓플레이스 한 덩어리라(`api/snapshot.ts`) 서버는 "이 주문이 이 사람 것인지"를 모른다.
  지금은 로그인한 계정이면 남의 주문 승인을 대신 호출할 수 있다 — 이미 결제창을 통과한 결제를 확정하는 것이라 남의 돈이
  나가지는 않지만, 주문 단위 인가는 **주문을 서버가 소유**해야 성립한다(결제만 별도 테이블로 서버에 두는 것이 다음 후보다).
- **환불의 결제사 호출.** `requestRefund`/`settleRefund`는 기록이고, 결제사 취소(`cancel`)는 운영자가 별도로 부른다.
  둘을 한 흐름으로 묶으려면 위의 주문 소유가 먼저다.
- 웹훅(결제 상태 역방향 통지), 부분 취소의 세금계산서·현금영수증 반영.
