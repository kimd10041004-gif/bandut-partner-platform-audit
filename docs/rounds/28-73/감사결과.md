# 28-73 감사 결과 (`fb2c5a5` 기준)

28-73은 28-72의 수정이 실제로 성립하는지를 보고 둘을 더 고쳤다(첫 접촉 대기의 구멍, IP 잠금이 연 무차별 대입).
이번 감사는 **그 라운드가 새로 넣은 것**, 특히 28-72-03의 보관함(`stash`)을 집중해서 봤다. 결론: 보관함이
데이터 손실을 막으려다 **다른 손실을 만들 수 있다** — 용량 회계 밖에 있고(01), 계약이 테스트되지 않았으며(02),
UI가 보관한 것의 3분의 1만 꺼내 준다(04). 그리고 28-72-02가 닫은 문 옆에 작은 문이 다시 열렸다(03).

네 갈래 — 보관함·용량 / 검증 / 인증·잠금 / UI·문서.

## 28-73-01 (상) 보관함이 **용량 회계 밖에** 있다 — 손실을 막으려다 저장을 막을 수 있다

`stashOverwritten`은 덮인 스냅샷을 `banded-platform-v1:overwritten`에 **최근 3개**까지 넣는다
(`bootstrap.ts:103,126`). 스냅샷 하나의 상한은 `STORAGE_SOFT_LIMIT = 4MB`(`platform.ts:465`)이므로
보관함만으로 **최대 12MB**를 쓸 수 있다.

그런데 이 키는 플랫폼의 용량 회계 어디에도 없다:

```ts
storageUsage(): StorageUsage {
  const chars = JSON.stringify(this.snapshot()).length   // ← 플랫폼 스냅샷 하나뿐
  …
  return { chars, …, limit: this.storageLimit, ratio: chars / this.storageLimit }
}
private assertCapacity(extraChars: number) {
  const usage = this.storageUsage()
  if (usage.chars + extraChars > usage.limit) throw new PlatformError('저장 공간이 부족합니다 …')
}
```

그래서 두 가지가 동시에 성립한다:

- **가드가 초록인데 브라우저는 꽉 찬다.** `assertCapacity`는 4MB 한도 안이라 통과시키지만, 보관함이 이미
  12MB를 먹었으면 `localStorage.setItem`이 실패한다(브라우저마다 다르지만 오리진당 대개 5~10MB급이다).
  28-50-01이 "저장 실패를 가시화"해 둔 덕에 화면에는 뜨지만, **원인은 어디에도 보이지 않는다.**
- **관리자 "저장 용량" 카드가 실제 사용량을 과소 보고한다.** 사진·알림·채팅·감사 기록으로 나눠 보여 주는
  그 카드에 보관함 항목이 없다. 운영자가 카드를 믿고 "여유 있다"고 판단한다.

즉 conflict 때 잃지 않으려고 넣은 장치가, 정작 **이 기기의 정상 저장을 실패시키는** 경로를 만들었다.
28-73/수정사항.md은 "저장 용량과 싸우지 않게 최근 것만"이라고 적었지만 3개는 최대 12MB이고, 그 근거가 없다.

근본 수정(제안): 보관함을 용량 회계에 넣는다 — `storageUsage()`에 `overwrittenChars` 세그먼트를 더하고
`assertCapacity`가 그 합으로 판정한다. 보관 개수를 줄이고(1개면 충분하다 — 04 참조) 넣기 전에 **남은 여유를
확인**해 넘치면 가장 오래된 것부터 버린다. 회귀: "보관함이 있으면 용량 카드에 그 크기가 잡힌다"(수정 전: 안 잡힌다),
"여유가 없으면 보관을 건너뛰고 스냅샷 저장은 성공한다".

## 28-73-02 (중) 보관함 구현에 **테스트가 없다** — 28-72-04b가 지적한 것과 같은 모양

복제기 쪽 회귀 2건(`stash`가 불린다 / 안 불린다)은 **콜백을 스텁으로** 받는다. 실제 구현
(`stashOverwritten`·`readOverwritten`: 3개 상한, 손상 JSON 내성, 배열 아닌 값, 쓰기 실패 무시)은
단위 테스트가 **하나도 없다**:

```
$ grep -rn "stashOverwritten\|readOverwritten\|OVERWRITTEN" src --include=*.test.ts*
(출력 없음)
```

28-72-04b가 "복제기가 지키는 계약을 복제기 없이 검증했다"고 지적했는데, 그 지적을 한 라운드가 이번에는
"보관함 계약을 보관함 없이 검증했다". 서버 e2e 1단계가 브라우저에서 `localStorage`를 읽어 항목 1개를 보긴
하지만, 그것은 **경로가 이어졌다**는 확인이지 상한·내성의 계약 확인이 아니다.

관리자 UI(`data-export-overwritten` 버튼)도 단위·e2e 어디에도 없다 — 이번 라운드가 새로 만든 화면 요소인데
아무도 누르지 않는다.

## 28-73-03 (중) 계정 잠금이 **관리자 운영 중단 수단**으로 되살아났다 — 비용만 6배

28-71-02는 "누구나 5회로 관리자를 15분 잠근다"를 막으려고 잠금 키에 IP를 넣었고, 28-72-02(=28-73이 구현)는
그것이 연 무차별 대입을 막으려고 **IP와 무관한 계정 카운터 30회**를 더했다. 방향은 옳지만, 그 카운터는
28-71-02가 없앤 DoS를 **되살린다**: 관리자 아이디는 고정(`admin`)이고 전화번호도 필요 없으므로, 누구나
30회 틀리면 관리자를 15분 잠근다. 15분마다 반복하면 승인·정지·환불이 계속 멈춘다.

`28-68/서버_연결.md`는 이 대가를 정직하게 적어 두었다("5회보다는 6배 비싸다"). 그러나 **적어 두는 것과 막는
것은 다르다.** 파일럿이라도 관리자 잠금은 운영 정지와 같다.

근본 수정(제안): 계정 잠금에서 **최근 성공한 IP는 면제**한다 — 잠긴 계정이라도 최근 성공 이력이 있는 IP는
통과시키고(관리자는 늘 같은 곳에서 들어온다), 처음 보는 IP만 막는다. 그러면 무차별 대입은 여전히 30회에
막히고, 운영자는 자기 자리에서 계속 들어올 수 있다. 회귀: "계정이 잠겨도 최근 성공한 IP는 로그인된다",
"처음 보는 IP는 잠긴 동안 거부된다".

## 28-73-04 (중) 3개를 보관하는데 **1개만 꺼낼 수 있다**, 그리고 렌더마다 전부 파싱한다

`AdminSettings`의 버튼은 개수를 보여 주면서(`덮인 변경 내려받기 ({overwritten.length})`) 실제로는 언제나
**첫 항목만** 내려받는다:

```tsx
const doExportOverwritten = () => {
  const latest = overwritten[0]
  if (!latest) return
  downloadText(`banded-overwritten-${latest.at.slice(0, 10)}.json`, latest.body, 'application/json')
```

나머지 둘은 **꺼낼 방법이 없으면서 용량만 차지한다**(01의 12MB가 사실은 "쓸 수 있는 4MB + 못 쓰는 8MB"다).
개수를 3으로 정한 근거가 UI에 없다 — 1개로 줄이거나, 목록으로 셋 다 꺼낼 수 있게 하거나 둘 중 하나여야 한다.

또 `const overwritten = readOverwritten()`가 **컴포넌트 본문**에 있다 — 설정 화면이 리렌더될 때마다 최대
12MB의 JSON을 파싱한다. 다른 탭에서 저장 하나만 해도 리렌더가 도는 화면이다.

## 그 밖에 기록만 (이월)

- `sync()`의 `again` 재실행이 `await this.sync(next)`로 **재귀**한다 — 편집이 계속되는 탭에서 프레임이 쌓인다
  (28-72 이전부터 있던 모양이고, 실측으로 문제를 본 적은 없다).
- 로그인이 첫 접촉을 기다리므로 느린 네트워크에서 최대 15초(HTTP 타임아웃) 걸릴 수 있다.
- 병합(엔티티 단위 인가·API), SMS OTP, 쿠키 세션·CSP, scrypt, 엣지 레이트리밋, 비밀번호 강도 규칙,
  `applyMirror(complete)` 크기, `hashPassword`가 `for update` 안, 토큰 localStorage, `workspace` 행 무한,
  `verified`≠휴대폰 소유, `@types/node` 누출, `pg.Pool`/`-pooler`, 구 스냅샷 마이그레이션,
  `markPayout` string 오버로드, `stripComments`, `api/` 훑기 범위, StrictMode 이중 초기화, 시드·e2e의 실제 시계.
