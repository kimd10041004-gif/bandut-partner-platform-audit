## 1. 고치기 전 — 옛 안전장치는 새 도메인을 몰랐다

`origin/main` 의 `scripts/bot-kit.mjs` 를 그대로 불러 물었다:

```
OLD PRODUCTION_HOSTS = ["bandut-partner-platform.vercel.app"]
OLD refuse(https://www.bandeutjipsuri.co.kr) = "프리뷰 주소가 아닙니다: www.bandeutjipsuri.co.kr"
```

거부는 됐지만 **이유가 틀렸다** — "프리뷰가 아니다" 는 `vercel.app` 으로 끝나지 않는다는 뜻일 뿐이라, 누군가 그 조건을 완화하는
순간 운영으로 봇이 들어간다. 운영은 **이름으로** 막아야 한다(29-20 의 원칙). 새 테스트의 첫 단언(표가 셋)은 옛 파일에서 실패한다.

## 4. 새 주소 검사 (GitHub Actions, 세션 밖)

`deploy-check` 수동 실행 (run 34912788686, 2026-09-15 00:20 UTC, `base_url=https://www.bandeutjipsuri.co.kr`) — **실패, 그리고 그 실패가 답이다:**

| 항목 | 결과 |
|---|---|
| `GET /` | **200** — 그러나 라운드 표식 `29-27` 없음 (12회 재시도 모두) |
| 서빙 중인 것 | `<html lang="ko" class="geist_… h-full antialiased">` · `/_next/image` — **다른 Next.js 사이트**다(Geist 글꼴, Tailwind). 우리 셸(Pretendard, `bandut-auth-mode` 표식)이 아니다 |
| 경로 생존 | 37 중 **24 개 404** — `/login` `/signup` `/mypage` `/partner/*` 전부 404. `/services` `/privacy` 200, `/admin/*` 는 307 (그 사이트의 관리자 로그인으로 넘김) |
| `POST /api/auth` | 404 — 우리 API 가 없다 |

즉 **이 도메인은 이미 Vercel 의 다른 프로젝트에 붙어 있고, 그 프로젝트가 별개의 Next.js 사이트를 서빙 중이다.** DNS 가 Vercel 을
가리키는 이유가 그것이다. 플랫폼에 붙이려면 Vercel 에서 도메인을 **그 프로젝트에서 `bandut-partner-platform` 으로 옮겨야** 하고,
옮기는 순간 지금 그 주소에 있는 사이트는 도메인을 잃는다. 어느 프로젝트인지는 이 세션의 Vercel 연결로는 보이지 않는다 — 사장님이
Vercel 대시보드의 Domains 화면에서 확인하실 수 있다.
