# 29-28 — 운영 도메인 `www.bandeutjipsuri.co.kr` 을 붙인다

## 1. 왜 이 라운드인가

사장님 지시: **"https://www.bandeutjipsuri.co.kr 이 도메인으로 연결할겨."** 운영은 지금까지 Vercel 기본 주소
(`bandut-partner-platform.vercel.app`) 하나였다. 도메인을 붙이는 일은 두 조각이다 — **Vercel 쪽 연결**(사장님 조작)과
**저장소 쪽 준비**(이 라운드). 저장소 쪽을 먼저 끝내 두면, 연결하는 순간부터 봇 안전장치·문서·배포 확인이 새 주소를 안다.

## 2. 확인한 것 — DNS 는 이미 Vercel 을 가리킨다

이 세션은 외부 주소를 열 수 없지만(프록시 정책) DNS 조회는 된다:

```
bandeutjipsuri.co.kr        → 216.198.79.1
www.bandeutjipsuri.co.kr    → 216.198.79.1
bandut-partner-platform.vercel.app → 216.198.79.195 · 64.29.17.195
```

`216.198.79.1` 은 Vercel 의 도메인용 A 레코드다. 즉 **DNS 는 이미 맞게 잡혀 있고**, 남은 것은 Vercel 프로젝트에
이 도메인을 등록하는 일뿐이다. 이 세션의 Vercel 연결(MCP)은 이 팀의 프로젝트를 보지 못해(404·빈 목록) 등록은 사장님이 하신다.

## 3. 저장소 쪽 변경

| 파일 | 변경 |
|---|---|
| `scripts/bot-kit.mjs` | `PRODUCTION_HOSTS` 에 `www.bandeutjipsuri.co.kr`·`bandeutjipsuri.co.kr` 추가 — 계정을 만드는 봇(`e2e:signup`·`roles`·`trade`·`live`)이 새 운영 주소로 향하면 **이름으로** 멈춘다. 도메인을 붙여도 `.vercel.app` 주소는 그대로 운영을 서빙하므로 셋 다 막는다 |
| `scripts/bot-kit.test.mjs` (신규) · `vitest.config.ts` | 이 표를 단언으로 고정한다. `scripts/` 는 지금까지 테스트 수집 밖이었다 — `scripts/**/*.test.mjs` 를 include 에 더했다 |
| `scripts/e2e-signup.mjs` | 주석의 "운영은 하나" 를 "셋" 으로 |
| `README.md` | 접속 주소 표에 도메인 행 추가. 배포 확인은 여전히 Vercel 기본 주소를 본다(§5) |
| `package.json` 29.28.0 · `src/App.tsx` | 라운드 표식 |

호스트에 묶인 코드는 없었다 — 세션은 쿠키가 아니라 `Authorization` 헤더(29-2)라 도메인이 바뀌어도 로그인이 끊기지 않고,
메일 본문(29-27)에는 링크가 없으며, 결제 리다이렉트는 `window.location.origin` 을 쓴다. `vercel.json` 헤더도 호스트 무관.

## 4. 사장님이 하실 것 — Vercel 에 도메인 등록 (2분)

1. https://vercel.com/kimd10041004-gifs-projects/bandut-partner-platform/settings/domains
2. **Add** → `www.bandeutjipsuri.co.kr` → Add. DNS 가 이미 Vercel 을 가리키므로 곧 **Valid Configuration** 이 된다.
3. 같은 화면에서 `bandeutjipsuri.co.kr` 도 Add 하고 **Redirect to www.bandeutjipsuri.co.kr** (308) 을 고른다 — 루트로 들어와도 www 로 간다.
4. §5 의 검사로 확인했듯 이 도메인은 **이미 다른 Vercel 프로젝트에 붙어 있다.** Vercel 이 "이미 사용 중" 이라며 옮길지 묻는다. 옮기면 그 프로젝트에서는 이 도메인이 떨어지고, 지금 그 주소에 있는 사이트는 접속이 끊긴다 — 그 사이트가 `home-repair-landing`(다른 사업)이라면 **옮기기 전에 한 번 더 확인**하시라.
5. 등록이 끝나면 여기에 "붙였어" 라고만 적어 주시면, GitHub Actions 로 새 주소를 검사해 결과를 보고한다(§5).

## 5. 검사 — 이 세션 밖에서

이 세션은 그 주소를 열 수 없지만 GitHub Actions 는 연다. `deploy-check` 워크플로를 `base_url=https://www.bandeutjipsuri.co.kr` 로
수동 실행하면 홈 200·라운드 표식·인증 모드·경로 생존·환경변수 준비까지 같은 기준으로 잰다.

`deploy-check` 수동 실행 (run 34912788686, 2026-09-15 00:20 UTC, `base_url=https://www.bandeutjipsuri.co.kr`) — **실패, 그리고 그 실패가 답이다:**

| 항목 | 결과 |
|---|---|
| `GET /` | **200** — 그러나 라운드 표식 `29-27` 없음 (12회 재시도 모두) |
| 서빙 중인 것 | `<html lang="ko" class="geist_… h-full antialiased">` · `/_next/image` — **다른 Next.js 사이트**다(Geist 글꼴, Tailwind). 우리 셸(Pretendard, `bandut-auth-mode` 표식)이 아니다 |
| 경로 생존 | 37 중 **24 개 404** — `/login` `/signup` `/mypage` `/partner/*` 전부 404. `/services` `/privacy` 200, `/admin/*` 는 307 (그 사이트의 관리자 로그인으로 넘김) |
| `POST /api/auth` | 404 — 우리 API 가 없다 |

즉 **이 도메인은 이미 Vercel 의 다른 프로젝트에 붙어 있고, 그 프로젝트가 별개의 Next.js 사이트를 서빙 중이다.** DNS 가 Vercel 을
가리키는 이유가 그것이다. 플랫폼에 붙이려면 Vercel 에서 도메인을 **그 프로젝트에서 `bandut-partner-platform` 으로 옮겨야** 하고,
옮기는 순간 지금 그 주소에 있는 사이트는 도메인을 잃는다. 어느 프로젝트인지는 이 세션의 Vercel 연결로는 보이지 않는다 — 사장님이
Vercel 대시보드의 Domains 화면에서 확인하실 수 있다.

`deploy-check` 의 **기본 주소는 Vercel 기본 주소 그대로** 둔다. 도메인은 나중에 떼거나 옮길 수 있지만 기본 주소는 프로젝트가 있는 한
살아 있고, 병합마다 도는 검사가 도메인 등록 전에 빨개지면 안 되기 때문이다. 도메인이 붙은 뒤에는 §5 의 수동 실행이 그 주소의 검사다.

## 6. 하지 않은 것

- **Vercel 기본 주소 → 도메인 리다이렉트.** Vercel 도메인 설정에서 켤 수 있지만, 켜면 `deploy-check` 기본 검사가 리다이렉트를 따라가야 한다.
  도메인이 붙어 며칠 안정된 뒤 따로 라운드로 한다.
- **HSTS·canonical·sitemap** — 검색 노출은 도메인이 붙은 뒤의 일이다.
