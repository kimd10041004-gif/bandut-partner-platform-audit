# 28-36 수정사항 (Claude) — 알림 센터 라운드

기반: `28-35` 복사본(스크래치 wf28-36)에서 작업. 28-35 감사 3건 전부 반영.

## 28-35-01 · 알림 도메인 [반영]

- `AppNotification { id, role, requestId?, text, createdAt, read }`(DOM Notification과 충돌 회피). `PlatformService.notify()` 단일 경계에서 생성 — 저장은 각 액션의 기존 `save()`가 담당.
- 이벤트 삽입 10곳: 견적 제출→고객 / 낙찰·미낙찰→파트너 / 방문 예약→고객 / 추가 작업 요청→고객, 결정→파트너 / 작업 완료→고객("최종 결제") / 예약금→파트너, 최종 결제→파트너+관리자 / 리뷰→파트너 / A·S·분쟁 접수→관리자+파트너, 처리→고객.
- `notificationsFor(role, accountId?)`(최신순) / `unreadNotificationCount(role, accountId?)` / `markAllNotificationsRead(role, accountId?)` — **고객은 계정 스코프**(내 요청의 알림만, 28-33 스코프와 정합; 파트너·관리자는 역할 스코프). `clearNotifications()` — 데모 시드가 만든 알림은 부트 직후 비운다(실제 이벤트 아님). 스냅샷 `notifications?`+`notificationSeq?` 하위 호환 + 요소 검증(역할 집합·공백 텍스트). 도메인 테스트 2건(전 이벤트 경로·읽음·왕복·손상 거부 / 계정 스코프·시드 정리) → vitest 176→**178**.
- 실측 중 발견·수정: 최초 구현은 역할 단위라 고객이 시드·타 고객 알림(미읽음 4)까지 봤음 → 계정 스코프로 정정 후 미읽음 1(내 견적 도착)로 확인.

## 28-35-02 · 헤더 알림 벨 [반영]

- `NotificationBell` — 로그인된 역할에만 표시, 미읽음 뱃지(0이면 숨김, 99+), 클릭 시 플랫 패널(최신 20건, 열면 스코프 내 전부 읽음 처리, 닫기). 벨 아이콘 `ICON.bell` 추가. 패널 폭 `min(340px, 100vw − 32px)`로 모바일 가로 스크롤 방지.

## 28-35-03 · e2e + 실측 [반영]

- e2e 2단계 추가(48→**50**): "고객 알림 벨 미읽음(견적 도착)" / "알림 패널: 견적 도착 항목 + 읽음 처리로 뱃지 소멸". 전 여정 무회귀.
- 실측: 고객 벨 미읽음 1(내 견적 도착만) → 패널 스크린샷.
