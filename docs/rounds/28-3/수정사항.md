# 28-3 수정사항 — 28-2 감사결과 6개 항목 전부 처리 + 플랫폼 흐름 통합

작업 방식: 기존 규칙 그대로 — 28-1/28-2는 일절 수정하지 않고 스크래치 복사본(`scratchpad/wf28-3`)에서 수정 후 `28-3` 스냅샷 생성 (tar --exclude node_modules/dist).

## 항목별 수정 내용

### 28-2-01 [중] 요청 탭 전이 버튼 오류 처리 없음 → 수정
- `App.tsx` Requests가 전이를 `doTransition()`으로 감싸 try/catch 후 오류 메시지를 표시. 알려진 도메인 오류 판별은 `isKnownError()` 공용 헬퍼로 통일.

### 28-2-02 [중] parseHourInput이 25~99 통과 → 수정
- `money.ts` `parseHourInput`이 파싱 단계에서 0~24 범위를 완결 (25 이상 즉시 MoneyParseError).
- 회귀 테스트: `money.test.ts` "25~99를 파싱 단계에서 거부한다".

### 28-2-03 [중] 탭 간 데이터 단절 → 수정 (이번 라운드 핵심 구현)
- **`src/domain/platform.ts` 신설 — PlatformService 통합 계층**:
  - `submitEstimate()`: 견적 검증·저장 + requested→estimated 전이 (estimated 상태 재제출은 견적 교체).
  - `transitionRequest()`: 전이 단일 진입점 — estimated 직접 전이는 차단(견적 경로 강제), completed는 `completeJob()`으로 라우팅.
  - `completeJob()`: in_progress→completed 전이와 함께 저장된 견적의 총액/수수료로 `CompletedJob` 생성 (견적 없으면 거부, 전이 실패 시 job 미생성 보장).
  - `settle()` / `settlements()`: 정산 확정과 파트너×주차 집계.
- UI 통합: 견적 탭이 실제 요청을 선택해 제출(제출 시 상태 전이·요청 카드에 견적액 표시), 정산 탭은 하드코딩 시드 대신 `platform.settlements()` 집계. 시드 데이터(이력 3건)도 전부 실제 플랫폼 흐름(제출→전이→완료→정산)으로 생성.
- 회귀 테스트: `platform.test.ts` 12개 (제출/재제출/상태 제한/미존재 요청/완료 시 금액 일치/실패 시 job 미생성/정산 집계/방어적 복사).

### 28-2-04 [하] parseWonInput 선행 0·비정상 그룹핑 허용 → 수정
- WON_RE를 `^(0|[1-9]\d*|[1-9]\d{0,2}(,\d{3})+)$`로 교체 — '0' 허용, '007'·'0,100'·'01,000' 거부.
- 회귀 테스트: `money.test.ts` "선행 0과 비정상 쉼표 그룹핑을 거부한다".

### 28-2-05 [하] slotsOn 미사용 → 수정
- 일정 탭에 "선택한 날짜만 보기" 필터 추가 — `slotsOn()`으로 해당 파트너·날짜 슬롯을 시작 시각 순 표시.

### 28-2-06 [프로세스] vercel.json 라운드 경로 고정 → 수정
