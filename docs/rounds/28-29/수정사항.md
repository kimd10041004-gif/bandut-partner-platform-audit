# 28-29 수정사항 (Claude) — 결제 라운드 (사용자 지시: "상용화 + 결제 시스템")

기반: `28-28` 복사본(스크래치 wf28-29)에서 작업. 28-28 감사 5건 전부 반영.
돈의 흐름을 도메인 불변식으로 만들었다: **예약금(낙찰 직후) → 최종 결제(완료 후) → 영수증 → 정산은 결제 후에만**.

## 28-28-01 · 결제 도메인 [반영]

- `types.ts`: `Payment { id, requestId, kind('deposit'|'final'), amount, method('card'|'transfer'), receiptNo, paidAt }`.
- `platform.ts`:
  - `payDeposit()` — accepted에서만, 낙찰가의 10%(정수 내림, 최소 10,000원), 중복 거부, 견적 없는 요청 거부.
  - `payFinal()` — completed에서만, 최종 금액(기본+승인 추가 작업) − 기결제 예약금, 중복 거부.
  - `paymentsFor()` / `paymentFor(kind)`, 영수증 번호 `RCT-####`.
  - **`settle()` 상용 불변식**: completed인데 최종 결제가 없으면 "고객 결제 완료 후 정산할 수 있습니다" 거부(불법 전이는 기존 InvalidTransitionError 유지). `transitionRequest('settled')` 경유도 동일 차단.
  - `requestTimeline()`에 결제 이벤트 삽입: "예약금 결제 (금액)"(낙찰 다음), "결제 완료 (금액)"(작업 완료 다음).
  - 스냅샷 `payments?`+`paymentSeq?` 하위 호환 + 요소 검증(종류·수단·정수 금액).
- 도메인 테스트 4건 추가 + 기존 정산 테스트 11곳을 결제 후 정산으로 갱신 → vitest 163→**167**.

## 28-28-02 · 고객 결제 UI [반영]

- 거래 상세 `PaymentCards`: 예약금 카드(accepted·미결제 시 — 금액 미리보기·카드/계좌이체 필·결제하기), 최종 결제 카드(completed·미결제 시 — 최종 금액/예약금 차감/결제할 금액 분해), **영수증 카드**(종류·수단·RCT 번호·일시·금액, 부가세 안내). 타임라인에 결제 이벤트 표시.

## 28-28-03 · 파트너·관리자 반영 [반영]

- 파트너 내 작업 카드: `pay-tag` — "예약금 결제됨"(green) / "결제 대기"(amber, completed) / "결제 완료"(green). 결제 전 "→ 정산 완료" 시도는 도메인 오류 그대로 노출.
- 관리자 정산 탭 상단 "결제 현황" 테이블: 완료·정산 거래의 예약금/최종 결제/영수증 번호.

## 28-28-04 · PG 연동 지점 문서화 [반영]

- UI_가이드.md "결제와 상용 전환" 절: 규칙은 그대로 유지되고 `payDeposit`/`payFinal` 몸통만 토스페이먼츠 결제창 + 서버 승인 콜백으로 교체됨을 명시. 상용화 잔여(PG 가맹+서버 / 회원·인증 / 공유 DB — `PlatformSnapshot`이 이관 단위) 로드맵화. 코드 주석으로 경계 표기.
