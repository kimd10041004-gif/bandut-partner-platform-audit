# 28-82 감사결과 (GPT 감사자 역할)

**대상**: `8056d16`(#224) + `9d41bd0`(#225) + `25ce880`(#226) — 28-82가 새로 넣은 것.

라운드는 "자리를 하나씩 고치는 방식은 끝나지 않는다"는 진단을 받아들여 **전수조사**를 했고, 결과를 문서로만
남기지 않고 가드 테스트로 고정했다. 그리고 세 가지를 스스로 밝혔다 — 28-82-04에 런타임 회귀가 없다는 것,
지표 렌더링을 e2e가 아니라 SSR 테스트가 덮는다는 것, 그리고 **구현 중 발견한 서버 모드 익명 방문자 문제**.
마지막 것은 자기 감사(28-81)가 놓친 것을 스스로 찾아 적은 것이라 특히 값이 있다.

그런데 그 가드가 **자기 자신을 지키는 방식**은 조사가 아니라 목록이다. 01이 그것이고, 이번 감사에서
유일한 「상」이다.

## 01 (상) 가드의 API 목록이 **손으로 적혀 있고**, 도메인의 실제 집합에서 유도되지 않는다

`customerSurfaces.test.ts`는 검사 **대상 파일**을 디렉터리에서 유도한다 — 그것은 잘했다. 그런데 무엇을
금지할지는 상수 한 줄이다:

```ts
const SEED_INCLUSIVE = ['adminOverview', 'bidStats', 'reviewStats', 'statusCounts', 'partnerSummary', 'allReviews', 'partnerCancelCount']
```

도메인에는 "시드에 민감한 집계"라는 **실제 집합**이 이미 있다 — `{ excludeSeeded?: boolean }`을 받는
메서드들이다:

```
$ grep -n 'excludeSeeded?: boolean' src/domain/platform.ts
1630:  partnerSummary(…)
1746:    options: { excludeSeeded?: boolean } = {},      ← partnerCancelCount
2206:  bidStats(…)
2665:  statusCounts(…)
2869:  allReviews(…)
2876:  reviewStats(…)
2887:  private reviewsOf(…)
```

오늘은 두 목록이 맞아떨어진다. **내일은 아니다.** 다음 라운드가 시드에 민감한 집계를 하나 더 만들고
`excludeSeeded`를 통과시킨 뒤 `SEED_INCLUSIVE`에 적는 것을 잊으면, 고객 화면이 그것을 마음껏 부를 수
있고 **가드는 초록으로 남는다.** 이 저장소가 28-78-04에서 이름 붙인 실패가 정확히 이것이다 —
"규칙이 아니라 목록이 CI를 좌우한다". 28-82는 그 함정을 **파일 목록에서는 피하고 API 목록에서 되풀이했다.**

**고치는 방향 (그대로 유도하면 안 된다는 점까지)**: `adminOverview`는 `excludeSeeded`를 받지 않는다 —
시드를 뺄 방법 자체가 없는 집계라 목록에는 있어야 하지만 유도로는 잡히지 않는다. 그러니 유도 목록으로
**대체**하지 말고 **하한**으로 쓴다:

```ts
const derived = 시그니처에서 뽑은 excludeSeeded 수용 메서드 (private 제외)
expect(derived.filter((m) => !SEED_INCLUSIVE.includes(m))).toEqual([])   // 새로 생기면 여기서 걸린다
```

그러면 손으로 적은 목록은 "유도로 못 잡는 것을 더하는 자리"로 줄고, 빠뜨림은 테스트가 잡는다.

## 02 (중) `authMode` 프롭이 테스트가 지켜야 할 **바로 그것**을 못 보게 한다

28-82-02는 렌더링을 덮으려고 `Landing`에 프롭을 냈고, "기본값이 `AUTH_MODE`라 앱 동작은 그대로"라고 적었다.
맞다. 그런데 프로덕션은 그 기본값에 의존한다:

```tsx
// App.tsx:206 — authMode를 넘기지 않는다
<Landing
  onPostJob={(category) => enterCustomerApp('crequest', category)}
  onBrowse={() => enterCustomerApp('chome')}
/>
```

그리고 SSR 테스트는 **언제나 자기 값을 넘긴다**:

```tsx
<Landing onPostJob={() => {}} onBrowse={() => {}} authMode={authMode} />
```

즉 **기본값 경로를 실행하는 테스트가 하나도 없다.** 누가 기본값을 `'server'`로 바꾸거나 `AUTH_MODE`
import를 지워도 세 테스트는 그대로 통과하고, 라이브 랜딩은 브라우저마다 다른 숫자를 다시 내걸기 시작한다 —
28-81이 존재한 이유가 바로 그 회귀다.

28-81 감사 02는 "판단은 덮지만 렌더링은 못 덮는다"였는데, 28-82는 렌더링을 덮으면서 **판단이 프로덕션에
연결되는 지점**을 새로 덮이지 않게 만들었다. 덮는 자리를 옮긴 셈이다.

**고치는 방향**: 프롭 없이도 기본값을 확인할 수 있게 한다 — 예컨대 `authMode`를 넘기지 않고 렌더한 뒤
"로컬 빌드에서는 지표가 없다"를 단언하는 테스트를 하나 더 둔다(테스트 실행 시 `AUTH_MODE`는 `local`이다).
그러면 기본값이 `'server'`로 바뀌는 순간 그 테스트가 깨진다.

## 03 (중) 가드의 도달 범위가 `src/ui`에서 멈추는 것이 **규칙이 아니라 관례**다

```ts
// ui/ 부품만 따라간다 — 도메인·앱 계층은 화면이 아니다
if (target !== undefined && target.startsWith('src/ui') && !seen.has(target)) queue.push(target)
```

주석은 이유를 한 줄 적었지만, **왜 `src/app`은 화면이 아닌가**는 자명하지 않다. `Landing.tsx`부터가
`../../app/bootstrap`에서 `AUTH_MODE`를 가져온다 — 앱 계층은 이미 화면 코드와 얽혀 있다. 앞으로 누군가
`src/app/`이나 다른 feature에 "요약 숫자를 만들어 주는 헬퍼"를 두고 고객 화면이 그것을 쓰면, 그 헬퍼 안의
`platform.bidStats(...)`는 **가드의 시야 밖**이다.

전수조사 문서도 이 경계를 적지 않았다 — "고객이 보는 파일 = landing + customer + 그들이 쓰는 `ui/` 부품"
이라고만 하고, 왜 거기서 끊는지는 없다. 조사 문서가 다음 라운드의 지도인데, 지도의 가장자리가 왜 거기인지
말하지 않으면 그 밖은 안전한 것으로 읽힌다.

**고치는 방향**: 두 가지 중 하나. (ㄱ) `src/` 안의 **상대 경로 import를 전부** 따라가고 `domain/`만 잘라낸다
(도메인은 정의하는 쪽이지 부르는 쪽이 아니다). (ㄴ) 지금 범위를 유지하되 **왜 여기서 끊는지**를 테스트
주석과 조사 문서에 적고, 벗어나는 경우를 별도 테스트로 잡는다. (ㄱ)이 더 낫다 — 목록이 아니라 규칙이다.

## 04 (하) 전수조사 문서가 `getProfile`을 **잘못 분류했다**

조사 문서의 (ㄴ) 갈래는 이렇게 적혀 있다:

> ### (ㄴ) 운영 설정 — 활동 지표가 아니다 (조치 없음)
> `getSettings` · `enabledCategories` · `activePackages` · `questionsFor` · **`getProfile`**.
> 관리자가 CMS로 정한 내용이고, 시드가 만든 "실적"이 아니다.

`getProfile`은 CMS가 정한 것이 **아니다** — 파트너가 자기 마이페이지에서 `updateProfile`로 쓴 내용이고,
없으면 `DEFAULT_PARTNER_PROFILE`(상호 "반듯 파트너", 소개 문구)로 떨어진다. 조치가 필요 없다는 **결론은
맞지만 이유가 틀렸다**. 그리고 조사 문서는 다른 곳에서 파트너 프로필을 "숫자가 아니라 신원"이라며 따로
남겨 두었는데, 같은 문서 안에서 같은 것을 두 갈래로 분류한 셈이다.

지도 노릇을 하라고 만든 문서라 분류가 맞아야 한다 — 다음 라운드가 "CMS 내용이니 건드릴 것 없다"로 읽으면
파트너가 쓴 자유 서술이 고객에게 어떻게 보이는지는 영영 검토되지 않는다.

**고치는 방향**: (ㄴ)에서 `getProfile`을 빼고, "파트너가 직접 쓴 내용 — 시드가 아니지만 CMS도 아니다"라는
갈래를 하나 두거나, 이미 있는 「남은 경계」 절로 옮긴다.

## 이번 감사에서 **문제 삼지 않은 것** (조용히 넘기지 않는다)

- **전수조사 자체와 그 결과** — 39개 호출을 셋으로 가른 분류는 (ㄴ)의 `getProfile` 한 건을 빼면 정확하고,
  "집계는 셋뿐이고 그중 둘이 샌다"는 결론이 이 라운드의 값이다. 자리를 세는 대신 훑기로 한 판단이 옳았다.
- **가드가 파일 목록을 하드코딩하지 않은 것**과 **빈 목록을 훑고 통과하는 것을 막은 두 번째 테스트** —
  28-78-04의 교훈을 실제로 적용했다. 01은 그 교훈을 **API 목록에는** 적용하지 않은 것을 문제 삼는다.
- **28-82-04에 런타임 회귀가 없다고 스스로 적은 것** — `ChatSender`는 타입이라 확인 주체가 `tsc`다.
  실패를 꾸며 내지 않은 것이 맞다.
- **서버 모드 익명 방문자 문제를 스스로 찾아 문서·PR에 적은 것** — 자기 감사가 놓친 것을 구현 중에 발견해
  "내 28-81 감사는 이것을 놓쳤다"까지 적었다. 이 루프가 요구하는 정직함의 좋은 예다.
- **Copilot 지적 3건을 전부 실제 문제로 인정하고 고친 것**(#226) — 특히 `**원본**`이 별표째 나가던 것은
  28-82-03이 "말하지 않던 것을 말하게 하려던" 바로 그 문구였다.
