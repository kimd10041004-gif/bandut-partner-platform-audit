# 28-82 수정사항 — 고객에게 보이는 모든 숫자

**대상 감사**: `28-81/감사결과.md` 4건 + **고객 화면 전수조사**.
브랜치 `round-28-82`, 라운드 문자열 `28-82`, 버전 `28.82.0`.

28-79는 "보일지 말지", 28-80은 "무엇을 셀지", 28-81은 "누구의 것을 세는지"를 고쳤다. 세 라운드가
**한 자리씩** 고치는 동안 바로 옆 화면이 같은 결함을 그대로 안고 있었다. 이번에는 자리를 세지 않고
**고객에게 보이는 것을 전부** 훑었다 — `28-82/고객화면_조사.md`.

## 28-82-01 (상) 고객 경로를 `public*` 계열로 나누고, 조사를 테스트로 고정했다

### 무엇이 문제였나

```
랜딩 공개 지표 — {"totalRequests":0,"completedOrSettled":0,"winRate":null,...}
업체 카드     — 완료: 3 건 / 낙찰률: 100 % / 리뷰: 0 건 / 평점: null
```

`PartnerCard`는 `CustomerHome`과 **`CustomerEstimates`(견적함)** 이 쓴다. 견적함은 고객이 여러 업체의
견적을 비교해 **누구에게 맡길지 정하는 자리**다. 시드가 만든 숫자가 랜딩의 장식이 아니라 **구매 결정의
근거**로 들어가고 있었다. 28-81은 `bidStats(_, { excludeSeeded })`를 그 라운드에 만들어 놓고
`partnerSummary`에는 넘기지 않았다.

### 무엇을 했나

집계 헬퍼 넷에 `excludeSeeded`를 통과시키고(`statusCounts` · `reviewStats`/`reviewsOf` · `bidStats` ·
`partnerCancelCount`), **고객 경로 전용 메서드**를 냈다:

```ts
publicPartnerSummary(partnerId, today)   // = partnerSummary(partnerId, today, { excludeSeeded: true })
publicReviews(partnerId)                 // = allReviews(partnerId, { excludeSeeded: true })
```

`PartnerCard`가 그 둘만 쓴다. **`partnerSummary`·`allReviews`는 그대로 남는다** — 운영자와 파트너 본인은
기기에 실제로 무엇이 있는지 봐야 한다(28-80이 세운 구분과 같다).

### 조사를 테스트로 고정했다

`src/ui/customerSurfaces.test.ts` — 고객이 보는 파일에서 시드 포함 집계 API를 부르면 실패한다.
목록을 하드코딩하지 않는다: 대상은 **디렉터리에서 유도**하고 화면이 `import`한 `ui/` 부품까지 따라간다.
그리고 28-78-04의 교훈대로 **빈 목록을 훑고 통과하는 것**도 두 번째 테스트가 막는다.

### 회귀 (수정 전 실패 인용)

```
× 고객 경로는 시드를 포함한 집계 API를 부르지 않는다
  AssertionError: expected [ …(2) ] to deeply equal []
  +   "src/ui/PartnerCard.tsx → allReviews()",
  +   "src/ui/PartnerCard.tsx → partnerSummary()",

× 28-82-01: 고객에게 보이는 업체 요약은 시드를 빼고 센다
  TypeError: p.publicPartnerSummary is not a function
```

## 28-82-02 (중) 히어로 지표를 **실제로 렌더해서** 본다

28-81까지 이 블록을 덮는 것은 `showPublicStats`의 단위 테스트(판단)뿐이었고, 로컬 모드에서 e2e 단언이
둘 다 "없다"라서 **JSX를 통째로 지워도 네 게이트가 통과**했다(28-81 감사 02).

`react-dom/server`의 `renderToString`으로 실제 컴포넌트를 그린다 — **새 의존성은 없다**(react-dom은
이미 있다). 그러려면 두 가지가 필요했고, 둘 다 프로덕션 동작을 바꾸지 않는다:

- `PlatformContext`를 내보낸다(테스트가 스텁 플랫폼을 꽂을 수 있게).
- `Landing`이 `authMode` 프롭을 받는다 — **기본값이 `AUTH_MODE`**라 앱은 그대로다.

세 가지를 단언한다: 서버 모드 + 끝낸 수리 → 블록이 그려지고 **숫자가 시드를 뺀 값**(`누적 1 · 완료 1 ·
낙찰률 100%`), 로컬 모드 → 같은 데이터라도 안 그린다, 서버 모드라도 실적 0 → 안 그린다.

### 회귀 (수정 전 실패 인용)

```
× 서버 모드 + 끝낸 수리가 있으면 블록이 그려지고 숫자는 시드를 뺀 값이다
× 로컬 모드에서는 같은 데이터라도 그리지 않는다 — 그 숫자는 이 브라우저의 것이다
× 서버 모드라도 끝낸 수리가 없으면 그리지 않는다
  TypeError: Cannot read properties of undefined (reading 'Provider')
```

## 28-82-03 (중) 삭제 직전 파일이 **원본**임을 드러낸다

`clearSeedData` 직전 백업은 `exportBackup('full')` — **원본**이다(가명본은 복원할 수 없으므로, 28-61).
선택 자체는 옳았지만 화면이 그 말을 하지 않았다: 버튼은 "시연 데이터 지우기"이고, 파일명에도 안내에도
모드가 없었다. 백업 카드는 기본을 가명본으로 두고 파일명에 `pseudonymous`를 남기는데 이 경로만 감췄다.

- 파일명 `banded-before-clearseed-**full**-<날짜>.json`
- 확인 입력 옆 주의문: "지우기 전에 되살릴 수 있도록 **원본** 백업(개인정보 포함)을 자동으로 내려받습니다"
- 결과 안내에도 원본임과 보관 주의를 적는다

e2e 2단계 추가(누르기 **전** 안내 · 파일명이 `-full-`로 시작).

## 28-82-04 (하) `CHAT_VIEWERS`를 `ChatSender`에 타입으로 묶었다

```ts
const CHAT_VIEWER_SET: Record<ChatSender, true> = { customer: true, partner: true }
const CHAT_VIEWERS = Object.keys(CHAT_VIEWER_SET) as ChatSender[]
```

28-81은 손으로 베낀 목록이라 `ChatSender`에 값이 늘면 조용히 어긋났다. 이제 **빠뜨린 값이 타입 오류**다.

### 이 항목의 회귀는 **타입 검사 자체다** — 그대로 적는다

`ChatSender`는 타입이라 런타임에 목록이 없다. 그래서 "빠뜨리면 실패한다"를 확인하는 것은 vitest가 아니라
`tsc`이고, 그것이 `npm run check`의 첫 단계다. 28-81-04와 같은 이유로 **런타임 회귀를 새로 만들지 않았다** —
실패를 꾸며 낼 자리가 없다.

## 하지 않은 것 (조용히 빼지 않는다)

### 이번에 발견한 것: **서버 모드에서 익명 방문자는 스냅샷을 못 받는다**

구현 중에 확인했다. 서버 모드의 복제 포트는 세션 토큰을 요구하고(`HttpSnapshotPort('/api/snapshot',
() => tokens.any(), …)`), `/api/snapshot`은 세션 없이는 401이다(28-70에서 `WORKSPACE_SECRET`을 없앤 결과).
랜딩은 **로그인 없이 열리는 공개 화면**이므로, 익명 방문자의 플랫폼은 비어 있고 따라서
`showPublicStats`도 거짓이다.

**즉 28-81이 지표를 서버 모드로 옮겼지만, 정작 지표를 보여 주려던 익명 방문자에게는 여전히 보이지
않는다.** 히어로 지표를 실제로 내걸려면 **세션 없이 읽을 수 있는 공개 집계 엔드포인트**가 있어야 하고,
그것은 "무엇을 공개할 것인가"라는 보안 판단이 따르는 새 API다 — 이번 라운드의 범위(감사 4건 + 조사)
밖이라 만들지 않았고, 대신 여기와 조사 문서에 적어 다음 라운드로 넘긴다.

내 28-81 감사는 이 항목을 "렌더링이 테스트되지 않는다"로만 잡았다. 더 깊은 사실은 **그 렌더링이 의도한
독자에게 도달할 수 없다**는 것이었고, 그것은 놓친 것이다.

### 그 밖에

- **파트너 자신·관리자 화면의 집계** — 그대로 둔다(그 사람들은 있는 그대로 봐야 한다).
- **시드 파트너의 프로필 문구**(상호·소개) — 숫자가 아니라 신원이고, 요청에 딸리지 않아 시연 삭제로도
  사라지지 않는다. 그것이 맞는지는 별개의 판단이라 건드리지 않았다.
- **`e2e:server`를 완료·정산까지 늘리는 것** — 28-81 §3이 남긴 숙제인데, 두 컨텍스트를 오가는 8단계라
  플레이크 위험이 크다. 대신 렌더링을 SSR 테스트로 덮었고(28-82-02), e2e 확장은 남겨 둔다.
