한 번도 바뀌지 않았고, 여기 적힌 라이브 관련 확인은 전부 **프리뷰 배포**에서 잰 것이다.

## 2. CI

`gates` job과 `server` job이 이 라운드의 모든 커밋에서 초록이었다. 스키마 부트스트랩이 실제로 실행되는
두 단계(빈 DB → 표 33개, 그 위에 psql 재적용)도 건너뛰지 않고 통과한 것을 로그에서 확인했다.

## 3. 프리뷰에서 잰 것 — `deploy-check` run 95 (`a165c40`)

```
서빙 인증 모드: server
서버 환경변수 준비: yes — 세 값 모두 설정됨 · DB 왕복 확인
DB 실제 연결: ok
살아 있지 않은 경로: 0개 (31개 전수)
```

읽을 것이 세 가지 있다.

- **함수가 뜬다.** 29-5 시작 시점의 라이브는 `/api/auth`·`/api/snapshot`이 둘 다
  `FUNCTION_INVOCATION_FAILED` 500이었다. 프리뷰에서는 우리 핸들러까지 요청이 들어가 의미 있는
  400을 돌려준다. 루트 `api/` 함수와 App Router 경로가 부딪히던 문제가 실제로 해소됐다는 뜻이다.
- **세 환경변수가 다 있고 DB에 닿는다.** `{"ok":false,"error":"가입 정보가 없습니다"}` 400은 세 값 검사와
  DB 연결을 **모두 지난 뒤** 인자 검증에서 끝났다는 뜻이다. 빈 `args`라 계정도 OTP도 만들어지지 않는다.
- **경로 31개가 전부 200이다.** 주소 체계가 해시에서 서버 라우팅으로 바뀌는 라운드라 홈 하나만 보고는
  판정할 수 없었다.

## 4. 확인 안 된 것 — 그대로 남긴다

| 무엇 | 왜 못 봤나 |
|---|---|
| **회원가입·로그인이 사람 손에서 되는가** | 29-5에는 우리 로그인 화면이 없었다. 사람이 프리뷰를 열어 보고 나서야 드러났고, 그것이 29-6이다 |
| **프리뷰가 어느 DB를 보는가** | Neon 연동이 `DATABASE_URL`을 소유해 Preview 값만 따로 바꿀 수 없었다. `DATABASE_URL_PREVIEW`라는 이름을 하나 더 두는 것으로 길은 냈지만, 그 값이 실제로 설정됐는지는 저장소에서 볼 수 없다 |
| **화면의 시각적 상태** | 이 샌드박스에서 프리뷰 주소로 나가는 연결이 프록시에 막힌다(`CONNECT tunnel failed, 403`). 스크린샷을 찍을 수 없어 사람 눈에 의존한다 |
| **프로덕션 전환 뒤의 동작** | 전환을 하지 않았으므로 잰 것이 없다 |

## 5. 이 라운드에서 가드가 거짓으로 초록이 된 자리 셋

구조를 옮기면 가드가 조용히 대상을 잃는다. 세 번 일어났고, 셋 다 `함수_경로_충돌.md`에 경과가 있다.

| 가드 | 어떻게 눈이 멀었나 | 어떻게 잡혔나 |
|---|---|---|
| `src/errors.test.ts` | `AuthError`가 `src/` 밖으로 나가 훑는 그물에서 빠졌다 | 테스트 수가 690 → 688로 줄어 드러났다 |
| `serverlessState.test.ts` | 핸들러가 한 단계 깊어지자 디렉터리 훑기가 못 따라갔다 | 옮기는 커밋 안에서 잡았다 |
| `deploy-check` 환경변수 판정 | GET 405를 통과로 읽었는데, App Router는 핸들러를 부르기 **전에** 405를 준다 | **거짓 초록을 사용자에게 보고한 뒤에 잡혔다.** POST 하나로 다시 물으니 `ADMIN_PASSWORD` 없음이 나왔다 |

세 번째는 내가 틀린 보고를 한 자리다. 판정을 POST로 바꾸고 여섯 갈래 중 네 갈래를 로컬 서버로 직접
확인했다. 405 갈래는 이 함정 자체를 다음에 알아보게 하려고 남겼다.
