# 28-61 수정사항 — 개인정보·행위자 식별 (28-60 감사 4건 반영)

원본 `28-60`은 건드리지 않고 스크래치 복사본에서 작업한 뒤 `28-61`로 물질화했다 (해시 기준선 v58 검증 통과).

## 28-60-01 (상) 백업 파일이 개인정보를 평문으로 담던 문제
- `BackupMode = 'full' | 'pseudonymous'` + `exportBackup(mode)`. 관리자 카드에서 모드를 고르고 **기본값은 가명본**이다(`[data-backup-mode]`).
- 가명 처리: 고객 이름 → `고객 A`류(같은 고객은 같은 가명), 지역 → 시·구까지, 요청 내용 → `[가명 처리] <분야> 요청`, 사진·질문 답변·채팅 제거, 리뷰·A/S 본문 치환.
- **알림 문구도 지운다.** `reqLabel`이 `[분야] 요청 내용`을 만들어 알림 텍스트에 요청 내용이 그대로 실린다 — 테스트를 쓰다 이 경로로 새는 것을 발견해 막았다.
- 상태·일정·금액 등 운영 지표는 그대로 남아 분석·이관에 쓸 수 있다. 되돌릴 수 없는 변환이라 복원용이 아니며, 어느 모드로 내보냈는지가 운영 기록에 남는다.

## 28-60-02 (상) 감사 기록에 "누가"가 없던 문제
- `AuditEntry.by` 추가(선택 필드, 구 스냅샷 호환) + 스냅샷 검증(빈 문자열 거부).
- `platform.actorId`를 `PlatformProvider`가 관리자 세션 `accountId`에서 채우고, 관리자 기록에만 붙인다(시스템 기록에는 없음).
- **접기 조건에 행위자를 포함**해 다른 관리자의 같은 행위는 한 줄로 접히지 않는다.
- 화면은 주체 아래 계정 ID(`[data-audit-by]`), CSV는 `주체` 다음 `행위자` 열, 검색 대상에도 포함.

## 28-60-03 (중) 고객이 자기 데이터를 받아갈 수 없던 문제
- `exportCustomerData(customerId)` — 본인 요청 id 집합으로만 걸러 요청·견적·방문·결제·환불·리뷰·A/S·대화를 담은 JSON. 파트너 식별자·수수료 같은 운영 내부 값은 담지 않는다.
- `customerDataRows(customerId)` — 거래 요약 행(상태 라벨은 표시층이 붙인다).
- 고객 마이페이지 "내 데이터 내보내기" 카드(`[data-export-mydata]`, `[data-export-mydata-csv]`, `[data-mydata-count]`). 내보내기는 `내 데이터 내보내기`로 기록된다(주체는 시스템 — 관리자 행위가 아니므로).
