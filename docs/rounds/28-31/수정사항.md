# 28-31 수정사항 (Claude) — 로그인·인증 라운드 (사용자 지시: "로그인 후 사용, 고객·파트너 인증 필수")

기반: `28-30` 복사본(스크래치 wf28-31)에서 작업. 28-30 감사 5건 전부 반영.

## 28-30-01 · 인증 도메인 [반영]

- 신규 `src/domain/auth.ts` `AuthService` — 플랫폼과 저장 키 분리(`banded-auth-v1`).
- `register()`: 이름 공백 거부, 휴대폰 010 시작 10~11자리(숫자 정규화 저장), 비밀번호 8자 이상, 같은 역할+번호 중복 가입 거부, **파트너는 사업자등록번호 10자리 필수**. 6자리 OTP 발급(시뮬레이션 반환 — 상용 시 SMS 발송으로 교체, 코드 주석·문서 명시).
- `verifyOtp()`: 미발급/불일치 거부, 성공 시 verified + 코드 소멸(1회용).
- `login()`: **미인증 로그인 거부**, 비밀번호 불일치 거부. 관리자는 시드 계정(admin/bandut1234!). **역할별 독립 세션**(고객·파트너·관리자 동시 — 한 브라우저 시연 전제). `sessionFor()`/`logout()`.
- 저장소 왕복 + 손상 데이터는 예외 없이 초기화. 신규 테스트 파일 `auth.test.ts` 4건 → vitest 167→**171**.

## 28-30-02 · 로그인 게이트 UI [반영]

- `AuthGate` — **랜딩(홈페이지)만 공개**, 세 앱의 기능 화면은 게이트 뒤. 고객·파트너: 로그인 ↔ 회원가입(파트너는 사업자번호) ↔ OTP 3단계, 인증 성공 시 자동 로그인. 관리자: 로그인 폼 + 데모 계정 안내. 오류는 도메인 메시지 그대로(`AuthError`를 isKnownError에 등록).
- 헤더 `AuthStatus`: 로그인 사용자명("○○님") + 로그아웃.
- 컨텍스트 확장: `usePlatform()`이 `auth`도 공급(initAuth — bootstrap).

## 28-30-03 · e2e 재배선 [반영]

- 4단계 추가(36→**40**): "고객 가입 + OTP 인증 + 자동 로그인" / "파트너 가입(사업자번호) + 인증 + 로그인" / "관리자 로그인(시드 계정)" / "로그아웃 → 로그인 게이트 복귀". OTP는 화면의 시연용 코드를 읽어 입력(실제 UI 흐름 그대로). **기존 36단계 전부 로그인 상태에서 무회귀.**
