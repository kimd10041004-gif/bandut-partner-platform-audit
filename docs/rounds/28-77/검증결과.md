## 4. 라이브에서 확인한 것 — 시드는 지금 터져 있다

28-77-04의 배선 테스트가 처음에 `PlatformError: 고객 결제 완료 후 정산할 수 있습니다`로 넘어졌다.
Node만의 일인지 확인하려고 **로컬 빌드를 실제 브라우저로** 띄워 봤다:

```
PAGE ERRORS: [ 'PlatformError: 고객 결제 완료 후 정산할 수 있습니다' ]

```

첫 방문(빈 저장소·로컬 모드)의 부팅이 통째로 실패하고 스냅샷이 저장되지 않는다. 한 줄 패치로 고쳐지는 것도
같은 방법으로 확인했다:

```
PAGE ERRORS: []
키: version,rev,savedAt,store,estimates,jobs,slots,slotSeq,extraWorks,extraSeq
요청 수: 6 | settled: 3
```

**이 라운드에는 넣지 않았다** — 이유와 패치는 `28-77/수정사항.md`의 "이 라운드에서 하지 않은 것"에 있다.
`e2e-journey`의 단언 10곳이 시연 데이터의 부재를 전제로 쓰여 있어, 제품이 달라지는 결정을 먼저 받아야 한다.

## 5. 기존 테스트 두 건을 손댄 이유

28-77-02로 키 형태가 바뀌자 **고정된 문자열을 쓰던 두 테스트**가 넘어졌다. 둘 다 단언을 약하게 만들지 않고
형태에 의존하지 않게 고쳤다:

- `손상된 신뢰 IP(무한대 시각)…`: 원문 IP로 문자열 치환하던 것을 **자리로 찾아 바꾸는** 방식으로.
  치환이 실제로 일어났는지 확인하는 장치(`expect(...).toBe(1_000_000)`)는 그대로 남겼다.
- `스윕은 게이트 간격으로만 돈다…`: `acct|customer:01033334444`를 기대하던 것을 "그 계정의 항목 1건"으로
  바꾸고, **`expect(staleKey).not.toContain(stale)`을 더했다** — 이 테스트가 가명화까지 지키게 됐다.
