# 28-45 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-45` 전체 — 운영 큐 반영 후, **돈의 역방향 경로(취소·환불)** 점검.
사전 확인: `npm run check` exit 0 (vitest 199/199), e2e 91/91 PASS, visual-check 전 항목 PASS, `npm audit` 0건, 프로덕션 배포 그린(PR #110 머지). 28-44 감사 4건 전부 수정 확인됨.

핵심 지적: 고객 취소 확인 문구는 "예약금이 결제됐다면 환불 처리됩니다"라고 약속하고, 이용약관 제6조는 "방문 전 취소 시 예약금 전액 환불, 방문 후 취소는 협의한 실비 차감"이라고 정하고 있는데, **코드에는 환불이 없다.** 예약금이 결제된 요청을 취소하면 상태만 `cancelled`가 되고 결제 기록은 그대로 남는다 — 관리자는 환불해야 할 건을 알 수 없고, 고객은 환불 여부를 볼 수 없으며, 정산 감독의 결제 현황도 취소 건을 구분하지 않는다. 결제(28-29)·정산·지급(28-39)까지 닫아 놓고 환불이 비어 있으면 상용에서 첫 취소 건부터 민원이 된다. 약관대로 **정책이 코드에 있어야** 한다.

## 상 (High)

### 28-45-01 · 환불 도메인
→ 요구: `Refund { id, requestId, paymentId, amount, deduction, reason, status: 'pending' | 'done', createdAt, doneAt? }`. **취소 시 자동 생성**: 예약금 결제가 있으면 환불 대기(pending) 생성 — 방문 전(슬롯 없음·방문일 이전)이면 전액, 방문일 경과 후 취소면 `deduction` 협의 대상(관리자 입력). `settleRefund(refundId, { deduction, reason })` — 관리자 처리, `deduction ≤ amount`, 완료 시 고객 알림("예약금 환불 ₩… 완료") + 파트너 알림(차감분 있으면). 최종 결제 후 취소는 불가(현행 전이 규칙 유지). `refundFor(requestId)` / `pendingRefunds()`. `opsQueue`에 **환불 대기** 추가. 스냅샷 왕복·검증 + **도메인 테스트 필수**.

### 28-45-02 · 고객: 환불 상태 표시
→ 요구: 거래 상세 결제 카드(취소 건)에 "예약금 환불 대기 / 환불 완료 ₩… (차감 ₩…, 사유)" 표시, 취소 확인 문구를 정책 문구로 교체("방문 전 취소 시 예약금 전액 환불, 방문일 이후 취소는 협의 후 실비 차감").

### 28-45-03 · 관리자: 환불 처리
→ 요구: 현황 "조치 필요"에 환불 대기 그룹(요청·고객·예약금·방문일 경과 여부) + **환불 완료** 인라인(차감액·사유 입력, 기본 0). 정산 감독 결제 현황에 취소 건 환불 열.

## 중 (Medium)

### 28-45-04 · e2e + 실측
→ 요구: e2e — 낙찰·예약금 결제 후 고객 취소 → 조치 필요 환불 대기 1건 → 관리자 환불 완료(차감 0) → 고객 거래 상세 "환불 완료" + 알림. 실측: 환불 대기 카드·고객 환불 완료 표시.
