# 28-45 수정사항 (Claude) — 운영 큐 라운드

기반: `28-44` 복사본(스크래치 wf28-45)에서 작업. 28-44 감사 4건 전부 반영.

## 28-44-01 · 운영 큐 도메인 [반영]

- `opsQueue(today)` → `OpsQueue { overdueRequests(견적 수·경과일), staleScheduled(방문일·경과일), unpaidCompleted(완료일·경과일·금액), openClaims, pendingPayouts, counts }` — 각 목록 오래된 순. `date.ts`에 `daysBetween`.
- `sweepPaymentReminders(today)`: completed & 최종 결제 없음 & 완료 후 `PAYMENT_REMINDER_DAYS = 3`일 경과 → 고객("최종 결제가 n일째 미완료")·관리자("결제 지연 n일 … 고객 확인 필요") 알림 1회, `RepairRequest.paymentReminderFor`(완료일)로 멱등(`store.setPaymentReminder`), 스냅샷 검증. `sweepDeadlines`는 견적 0건 마감 경과를 **관리자에게도** 알림.
- 도메인 테스트 2건 → vitest 197→**199**.

## 28-44-02 · 관리자 현황 탭 "조치 필요" 카드 [반영]

- `OpsQueueCard`(`.ops-card`, 그룹 `data-ops=approval|overdue|stale|unpaid|claims|payout`): 승인 대기 파트너(인증 완료·미승인·미탈퇴, **승인** 버튼) · 입찰 마감 경과 · 방문일 경과 미시작 · 결제 지연 · 미해결 A/S·분쟁 · 지급 대기(**지급 완료** 버튼, 계좌 없으면 오류 노출). 총건수 제목, 0건이면 "오늘 처리할 항목이 없습니다".

## 28-44-03 · 부트·화면 진입 정리 호출 [반영]

- 부트(`initPlatform`)·고객 홈·관리자 현황 진입 시 `sweepDeadlines()+sweepPaymentReminders()`(멱등). 실측에서 시드 이력 중 완료·미결제 건(정민호 욕실 타일 보수, 8일 경과)이 결제 지연으로 잡힘 — 시드가 만든 항목이지만 운영 큐 시연에 유효해 유지(관리자 벨에 리마인더 1건).

## 28-44-04 · e2e + 실측 [반영]

- e2e 4단계 추가(87→**91**): 현황 조치 필요 승인 대기 1건 → 카드에서 승인 → 0건(회원 탭 승인 표시 유지) / 지급 대기 1건 / 미해결 A/S 1건. 시간 의존(마감 경과·결제 지연)은 vitest. 실측 2장.
