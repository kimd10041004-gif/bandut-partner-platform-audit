# 28-6 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-6` 전체 + **사용자가 공유한 기획 시안 5장 대조** (파트너 PC/모바일, 고객 웹/모바일, 관리자 모바일 — 분석은 저장소 루트 `기획시안_분석.md`).
사전 확인: `tsc --noEmit` 0 오류, vitest 104/104, node --test 7/7, Vercel 배포 그린. 28-5 감사 5건 전부 수정 확인됨.

이번 감사의 중심은 코드 결함이 아니라 **기획(시안)과 구현의 구조적 정렬**이다.

---

## 상 (High — 기획 정합성)

### 28-6-01 · 비즈니스 모델 불일치: 시안은 입찰 마켓플레이스, 구현은 직접 배정 흐름
시안의 파트너 핵심 여정은 "일감 찾기(예산·마감 공개) → **입찰**(제안 금액+메시지) → 고객 비교 선택 → **낙찰/미낙찰**"인데, 현 구현은 견적 제출 → 수락의 1:1 흐름이다. 구체적 격차:
- 일감에 **예산(budget)**·**입찰 마감(D-day)** 개념이 없다.
- 입찰 결과 상태 중 **미낙찰(lost)** 이 상태 머신에 없다 (시안: 낙찰/미낙찰/취소를 구분).
- 용어가 시안과 다르다 (견적 제출 ↔ 입찰하기, 수락 ↔ 낙찰).
→ 요구: 상태 머신에 `lost`(estimated → lost, 종결) 추가, 일감에 budget/bidDeadline(선택, 검증 포함), UI를 "일감·입찰 / 내 작업" 구조와 시안 용어로 재정렬. 대시보드에 '입찰 가능 건수' 표시.

### 28-6-02 · 추가 작업 승인 부재 — 시공 중 금액 변경이 정산에 반영될 수 없음
시안의 작업 수행 플로우에는 현장에서 발생하는 **추가 작업 요청(예: 곰팡이 제거 +50,000원)을 고객이 승인하면 정산에 합산**되는 단계가 명시돼 있다. 현 구현은 완료 시 낙찰 견적 금액만 정산한다.
→ 요구: `approveExtraWork(requestId, {amount, memo})` — in_progress에서만, 정수 금액 검증, 영속화. 완료 시 최종 총액 = 낙찰 금액 + 추가 작업 합계로 계산하고 **수수료도 최종 총액 기준으로 재산정**.

### 28-6-03 · 수수료율 불일치: 시안 3% vs 구현 5%
시안(파트너 PC 헤더 "수수료 3%의 합리적 구조", 모바일 정산 "사업자 수수료 (3%)")과 구현 상수 `PLATFORM_FEE_RATE = 0.05`가 다르다. 돈 계산 상수 불일치는 즉시 정정 대상.
→ 요구: 3%로 정정하고 파생 기대값(테스트)을 전부 갱신.

## 중 (Medium)

### 28-6-04 · 스냅샷 하위 호환 설계 필요
28-7에서 스냅샷에 필드(추가 작업 목록 등)가 늘어난다. 기존 사용자의 v1 백업/localStorage가 새 필드 부재로 검증에 걸려 **데이터가 초기화되면 안 된다**.
→ 요구: 신규 필드는 선택적으로 검증하고 복원 시 기본값을 채울 것 (구 스냅샷 복원 회귀 테스트 포함).
