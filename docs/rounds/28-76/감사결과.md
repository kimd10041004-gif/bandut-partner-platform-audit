# 28-76 감사결과 (GPT 감사자 역할)

**대상**: `7340be3`(#211) + `e11dad1`(#212) — 28-76이 **새로 넣은 것**만 본다.
28-75 감사 4건의 수정, 리뷰 반영(공용 부품 `ui/` 승격 + 구조 규칙 테스트), 서버 e2e의 결정적 대기.

라운드는 자기 몫을 했다: 예산이 받아들일 본문까지 세고, 부팅 때 초과분을 맞추고, 스윕에 게이트를 달고,
보관함을 역할 무관 부품으로 뺐다. 배포도 라이브에서 확인됐다(§7). 아래 4건은 **그 수정들이 새로 만든
자리**다 — 특히 01은 28-75-03이 없애려던 바로 그 증폭이 예외 경로로 되살아난 것이다.

## 01 (중) 스윕 게이트를 **올려 놓고 저장하지 않는 경로가 있다** — 한 일이 버려지고 다시 돈다

> **정정**: 이 항목의 초안은 "잠긴 계정 반복 시도에서 증폭이 되살아난다"고 (상)으로 적었다. 확인해 보니
> 틀렸다 — 실패는 `recordFail`이 `save()`하고 잠금은 15분(`LOGIN_LOCK_MS`)인데 게이트는 1시간
> (`TRUSTED_IP_SWEEP_MS`)이라, **잠겨 있는 동안은 게이트가 이미 닫혀 있다.** 무차별 대입 경로에서
> 증폭은 되살아나지 않는다. 아래는 남은 진짜 문제만 적는다.

`login()`은 `pruneTrustedIps(now)`를 먼저 부른다. 그 함수는 게이트를 통과하면 **`trustedSweptAt`을
올리고 만료 항목을 지운다** — 둘 다 메모리에서만이다. 저장은 호출자의 몫인데, 던지고 끝나는 경로가 있다:

```ts
this.pruneTrustedIps(now)        // ← trustedSweptAt = now, 만료 항목 삭제 (메모리)
…
if (account.suspended) throw new AuthError('정지된 계정입니다 …')            // ← save() 없다
if (!account.verified) throw new AuthError('휴대폰 인증이 완료되지 않았습니다 …')  // ← save() 없다
```

이 두 경로는 **비밀번호가 맞아야** 닿는다(그 앞 분기가 틀린 비밀번호를 먼저 걸러 낸다). 즉 정지된 이용자나
아직 인증을 마치지 않은 이용자가 자기 계정으로 반복 로그인하는 경우다. 그때마다:

- 스윕이 실제로 돌고(1시간이 지났다면), 지운 만료 항목은 **저장되지 않아 되살아난다**
- 게이트 시각도 저장되지 않으므로 다음 요청이 또 훑는다 — 서버 모드는 요청마다 새 인스턴스다

크지 않다. 다만 28-75-03이 세운 계약("게이트 시각은 스냅샷에 남긴다 — 서버리스는 요청마다 인스턴스를
새로 만든다")이 **일부 경로에서만 지켜지고 있다**는 것이 문제다. 계약이 절반만 참이면 다음 라운드가
그 계약을 믿고 짠 코드가 틀린다.

**고치는 방향**: `pruneTrustedIps`가 **실제로 훑었을 때**(게이트를 통과했을 때) 스스로 `save()`한다 —
호출자가 어떻게 끝나든 한 일이 남는다. 회귀: 정지된 계정으로 로그인을 시도하면(=던지는 경로)
저장된 스냅샷의 `trustedSweptAt`이 갱신되어 있다.

## 02 (중) 신뢰 IP가 **전화번호 ↔ IP**를 평문으로 남긴다 — 저장소가 이미 세워 둔 잣대에 어긋난다

28-73-03이 만든 `trustedIps`의 키는 `acct|${role}:${전화번호}`이고 값은 `IP → 시각`이다.
스냅샷에 그대로 직렬화되므로 서버 모드에서는 `auth_state` 행에, 로컬 모드에서는 브라우저 저장소에
**"이 전화번호가 이 IP에서 로그인했다"**가 평문으로 남는다.

> **정정**: 초안은 "관리자 백업 JSON에도 실린다"고 적었다. 틀렸다 — 백업은 `platform.exportBackup()`
> (플랫폼 스냅샷)이고 인증 상태는 별도 키(`AUTH_STORAGE_KEY`)라 백업에 들어가지 않는다. 확인했다.

28-74-02의 주석은 이 사실을 알고 있다:

> 키에 전화번호가 들어 있으므로 (`acct|${role}:${전화번호}`) 그것은 개인정보가 남는다는 뜻이고,
> 서버 모드에서는 `auth_state` 행에 남는다.

그런데 그 라운드가 한 일은 **만료**(30일)뿐이다. 28-61·28-62가 이 저장소에 세운 규칙은 "식별자를
그대로 남기지 않는다"였고(가명본·행위자 식별), 감사 로그의 키는 `maskKey`를 거친다 — 같은 파일 안에
이미 그 도구가 있다(`AuthService.maskKey`, `emit('로그인 실패', maskKey(key), …)`).

즉 이 저장소는 **로그에는 마스킹해 남기면서 상태에는 평문으로 남긴다.** 30일은 짧지 않고, `auth_state`는 운영 중에 사람이 들여다보는 행이다.

**고치는 방향**: 키를 `sha256(role:phone)`(또는 기존 `maskKey`와 같은 규칙)으로, IP도 해시 접두로.
면제 판정은 같은 해시로 조회하면 되므로 동작은 그대로다. 마이그레이션은 옛 항목을 버리면 된다
(면제가 사라져도 잠금이 풀리는 방향이라 안전하다). 회귀: "스냅샷 문자열에 원문 전화번호·IP가 없다".

## 03 (중) `trimOverwritten`이 **조용히** 비운다 — 지운 개수를 돌려주는데 아무도 받지 않는다

28-75-02는 부팅 때 보관함을 예산에 맞추고, **하나도 안 들어가면 비운다**. 판단 자체는 문서에 근거가
적혀 있다("꺼낼 수 없는 1MB보다 쓸 수 있는 1MB가 낫다"). 문제는 **사용자에게 아무 말도 하지 않는다**는
것이다.

```ts
export function trimOverwritten(storage: StorageLike | undefined, budget: number): number { … }
// initPlatform():
trimOverwritten(storage, stashBudget(service))   // ← 반환값을 아무도 쓰지 않는다
```

함수는 "지운 항목 수"를 돌려주도록 만들어 놓고 호출부는 버린다. 그래서 어제 "덮인 내용은 보관했습니다"를
본 사람이 오늘 앱을 열면 보관함이 비어 있고, 그 사이에 무슨 일이 있었는지 화면 어디에도 없다.

이 라운드들의 주제가 **"말과 사실을 맞추는 것"**이었다는 점에서 이것은 같은 병의 다른 얼굴이다.
28-74-04는 "보관했다고 말해 놓고 못 했던 것"을 고쳤는데, 지금은 "보관했다고 말한 것을 말 없이 버린다".

**고치는 방향**: `initPlatform`이 지운 수를 결과에 실어 `PlatformProvider`가 한 번 안내하게 한다
("저장 공간을 확보하려고 보관함 N건을 정리했습니다"). 감사 로그(`emit`)에도 남길 수 있다.
회귀: 예산 밖 보관함으로 부팅하면 안내 문구가 생긴다.

## 04 (중) 부팅 정리의 **배선**에 회귀가 없다 — 그 한 줄을 지워도 전부 초록이다

이 라운드의 핵심 수정(28-75-02)은 "`initPlatform`이 부팅 때 `trimOverwritten`을 부른다"는 **배선**이다.
그런데 테스트는 함수만 직접 태운다(`bootstrap.test.ts`의 5건). 배선을 끊어 보면:

```
// initPlatform()
// trimOverwritten(storage, stashBudget(service))     ← 주석 처리

 Test Files  21 passed (21)
      Tests  448 passed | 12 skipped (460)
```

**전부 초록이다.** 즉 다음 라운드가 이 줄을 리팩터링 중에 흘려도 아무도 알려 주지 않는다. 28-72-04b가
지적하고 28-73이 고쳤던 것과 같은 모양이다("구현은 있는데 그 구현이 실제로 불리는지는 아무도 안 본다").

겸해서, 리뷰 대응으로 만든 `src/ui/structure.test.ts`는 규칙의 **한 방향만** 본다:

```ts
// features 안의 모듈을 features의 서로 다른 파일 둘 이상이 import 하면 실패
```

`UI_가이드.md`의 규칙은 두 문장이다 — "공용으로 두 번 쓰이는 조각은 `ui/`로 승격한다"와
**"화면 전용 조각은 해당 feature 파일 안에 둔다"**. 뒤 문장(=`ui/`에 있는데 한 곳에서만 쓰이는 조각)은
검사되지 않는다. 또 `app/`이나 `ui/`가 `features/`의 조각을 가져다 써도 잡히지 않는다.

**고치는 방향**: `initPlatform`을 가짜 저장소로 한 번 태우는 테스트(예산 밖 보관함 → 부팅 뒤 줄어 있다)와,
구조 테스트에 반대 방향 검사(그리고 `features/` 밖에서의 참조 포함)를 더한다.
