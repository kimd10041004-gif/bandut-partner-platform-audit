## 5-1. CI 첫 판이 잡아낸 것 — 단언 앞의 고정 sleep (내 변경과 무관한 기존 단계)

PR #211 첫 판(head `cec828d`)의 `server` 잡이 **내 변경과 무관한 기존 단계**에서 실패했다:

  ✗ A: 서버가 같은 도메인 규칙으로 거부한다 (사업자 정보 조회 실패)

**원인은 flake가 아니라 코드다.** 그 단언 앞에 `sleep(300)`이 있었고, 서버 응답이 300ms 안에 오지
않으면 아직 없는 문구를 읽는다. 두 단계의 타임스탬프 차이가 `11:32:55.907` → `11:32:56.294`
(약 390ms)로, 정확히 sleep + 읽기 시간이다.

이것은 28-74가 **바로 앞 단계**를 `waitForText`로 고치면서 이웃을 그대로 둔 자리다. 파일을 훑으니
같은 모양이 **여섯 곳** 있었다(단언 앞 고정 sleep). 하나만 고치면 다음 라운드가 또 다른 자리에서 넘어지므로
여섯 곳을 전부 결정적 대기로 바꿨다 — 텍스트는 `waitForText`, 조건은 새 `waitFor` 헬퍼:

| 줄 | 무엇을 기다리는가 |
|---|---|
| `A: 사업자 정보 조회 실패` | 문구 |
| `B: 고객 요청 등록` | 문구 |
| `C: 시연 비밀번호로는 로그인 불가` | 문구 |
| `C: 조치 필요 — 승인 대기 1건` | 행 수 |
| `C: 승인 → 서버 auth_state에 approved` | **DB 행** |
| `A: 승인 상태가 거울에 도달` | 배너 사라짐 |

남은 `sleep(1500)` 하나는 단언용이 아니라 **설정용 지연**이라 그대로 뒀다(주석이 이유를 적고 있다:
첫 접촉 accept가 끝난 뒤에 요청을 넣어야 덮이지 않는다).

재검증: `[e2e:server] 44 passed, 0 failed` **연속 3회**, 나머지 게이트도 전부 초록

## 5-2. CI 둘째 판이 잡아낸 것 — 이 단계의 **전제**를 짐작하고 있었다

`79a92ec`가 초록이 된 뒤 §6을 채운 `128d561`에서 **다른 단계**가 넘어졌다:

```

      ↳ 저장소 1건인데 화면 목록 1건
```

저장소도 1, 화면도 1 — **UI는 맞았고 두 번째 보관 자체가 일어나지 않았다.** 이 단계의 전제는
"밀어 올리지 못한 로컬 변경이 있다"인데, 28-74는 그것을 `sleep(2500)`으로 **짐작**했다. 디바운스 push가

§5-1과 같은 병이다 — 다만 이번엔 단언이 아니라 **전제**를 짐작한 자리였다. 막힌 push는 배너에
`data-replication="offline"`으로 드러나므로 그것을 기다리게 했다:

```js
const replState = () => D.page.evaluate(() => document.querySelector('[data-sync-notice]')?.getAttribute('data-replication') ?? 'none')
const pushBlocked = await waitFor(async () => (await replState()) === 'offline')
```

실패 진단에도 `push 막힘 관측`과 배너 상태를 넣어, 다음에 넘어지면 **왜**인지 로그가 말하게 했다.

재검증: `[e2e:server] 44 passed, 0 failed` **연속 4회**.

## 6-2. 같은 병의 나머지 자리 — 단언 앞 고정 sleep 여섯 곳 더

`39b401c`의 `server` 잡이 **또** 넘어졌다. 이번에는 `A: 비밀번호 5회 실패 → 서버가 잠근다`:

```
  ✗ A: 비밀번호 5회 실패 → 서버가 잠근다 (같은 도메인 규칙)
  ✓ A: 잠금 기록이 서버 auth_state에 남는다
[e2e:server] 43 passed, 1 failed
```

**바로 다음 줄이 진단이다** — 서버 `auth_state`에는 잠금이 남아 있었다. 즉 5회 실패는 제대로 세어졌고,
읽는 시점이 이른 것뿐이다. 로그의 시각을 보면 이 루프가 12초를 썼다(왕복 한 번에 약 2.4초). 그런데 각
시도 뒤 대기는 `sleep(250)` 고정이었다.

§5-1에서 여섯 곳을 고치면서 **이웃을 또 남겼다.** 남은 자리를 전부 셌고, 단언(또는 단언에 쓸 값 읽기)
앞의 고정 sleep 여섯 곳을 마저 결정적 대기로 바꿨다:

| 자리 | 전 | 후 |
|---|---|---|
| 잠금 5회 루프 | 시도마다 `sleep(250)` | 시도마다 `남은 시도 {5-n}회`(마지막은 `잠겼습니다`)를 기다린다 — **각 시도가 세어진 것까지** 확인된다 |
| 탭 복귀 accept | `sleep(300)` | `waitForText('욕실 실리콘 재시공 (서버 e2e)')` |
| 손상 리셋 뒤 | `sleep(300)` | 같은 문구 대기 (그 뒤에 rev를 읽는다) |
| 관리자 회원 목록 | `sleep(300)` | `waitForText('반듯설비')` |
| 입찰 제출 | `sleep(300)` | `waitForText('입찰 제안 완료')` |
| 탭2 동기화 | `sleep(300)` | `waitForText('입찰 1건')` |
| 로그아웃 뒤 401 | `sleep(300)` | `me`가 401이 될 때까지 `waitFor` — 화면이 로그인 카드로 돌아온 것과 서버의 폐기가 끝난 것은 다르다 |

남은 `sleep`은 전부 **설정용**(디바운스 통과·push 유발)이거나 폴링 루프 안이며, 주석이 이유를 적고 있다.
