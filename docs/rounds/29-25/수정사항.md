# 29-25 — 거래 한 바퀴를 처음 걸어 봤다

## 1. 왜 이 라운드인가

봇이 셋 있었다. `e2e:signup`(29-18)은 가입에서 승인까지, `e2e:roles`(29-22)는 주소 열다섯 장의
권한, `e2e:docs`(29-23)는 서류 게이트를 잰다.

그 사이에 **아무도 안 걸어 본 구간**이 있었다 — 접수부터 정산까지. 견적을 내고, 낙찰하고,
계약서를 주고받고, 작업을 끝내고, 돈을 정산하는 줄이다. 이 플랫폼이 하는 일의 본체인데
브라우저로 끝까지 몰아 본 적이 한 번도 없었다.

한 바퀴 걸어 보니 **운영에서만 죽어 있는 것이 셋** 나왔다. 셋 다 단위 테스트는 초록이었다.

## 2. 찾은 것 — 넷

| | 무엇이 | 사용자가 보던 것 |
|---|---|---|
| **01** | 운영 대시보드 지표가 SQLite 전용 날짜 함수를 썼다 | 관리자 대시보드에 숫자가 하나도 안 나온다 |
| **02** | 주문 상담의 첫 커서가 `integer` 범위를 넘었다 | **대화방이 통째로 안 열린다. 메시지도 못 보낸다** |
| **03** | API 라우트가 사진 바이트를 JSON 으로 읽었다 | 사진을 올리면 `요청 내용을 확인해 주세요.` |
| **04** | 사진 업로드 세 자리가 인증 헤더를 안 실었다 | (03 뒤에 가려져 있었다) `로그인이 필요합니다.` |

넷 모두 같은 모양이다. **단위 테스트는 SQLite 로 돌고, 운영은 Postgres 다.** 그리고 화면으로
그 길을 걸어 본 적이 없었다.

### 01 — 관리자 대시보드의 숫자

`lib/community.ts` 의 `metrics` 가 이렇게 묶고 있었다.

```sql
SELECT date(created_at,'+9 hours') day, COUNT(*) n FROM orders ...
```

두 번째 인자를 받는 `date()` 는 SQLite 에만 있다. Postgres 는 `syntax error at or near "day"`
로 질의 자체를 거절한다. 지표 카드가 아니라 **운영 대시보드 전체가** 오류로 떨어진다.

날짜를 한국 시간으로 묶는 일을 SQL 에서 빼고 `dailyCounts()` 로 옮겼다. 한국 날짜는 우리가
정하는 규칙이지 저장소의 기능이 아니다.

### 02 — 열리지 않던 대화방

화면이 대화방을 처음 열 때 커서를 주지 않는다. 그러면 서버가 대신 "가장 큰 수"를 넣었다.

```ts
async chat(u, id, partnerId, before = Number.MAX_SAFE_INTEGER) { … 'seq < ?' … }
```

`messages.seq` 는 Postgres 에서 **`integer`** 다 — 21억까지. 9007조를 넣으면 Postgres 는
파라미터를 int4 로 못 바꿔서 `value "9007199254740991" is out of range for type integer` 로
거절한다. 읽기만 막히는 것이 아니다. `send()` 가 `chat()` 을 먼저 부르므로 **보내는 것도 막힌다.**

상한을 표의 상한과 같게 맞췄다(`SEQ_MAX = 2_147_483_647`, `lib/chat-model.ts`). 도메인 기본값,
HTTP 경계, 읽음 표시의 검증까지 같은 수를 쓴다.

`e2e:roles`(29-22)가 잰 채팅은 `/consult` 쪽(상담방)이고 커서를 쓰지 않는다. **주문 상담은
다른 코드**라서 그 봇이 초록인 채로 이것이 살아 있었다.

### 03 — 틀린 이유는 이유가 없는 것보다 나쁘다

`app/api/[...path]/route.ts` 가 **모든 POST** 에 `req.text()` → `JSON.parse` 를 했다. 사진은
파일 바이트로 오므로(`Content-Type: image/png`) 언제나 던지고, 사용자는

> 요청 내용을 확인해 주세요.

를 받았다. 진짜 이유(사진 저장소 미연결, 503)는 그 뒤에 있어서 한 번도 화면에 닿지 못했다.
사장님이 파일을 바꿔 가며 몇 번이고 다시 시도하게 되는 자리다.

본문 타입이 JSON 일 때만 읽도록 갈랐다(`server/requestBody.ts`). 글자로 읽는 순간 바이트가
깨지기 때문에, 그 밖의 타입은 손대지 않고 넘긴다.

### 04 — 29-6 이 못 고친 세 자리

29-6 이 `api()` 에 `Authorization` 헤더를 더했다. 그런데 사진을 올리는 세 자리는 `api()` 를
쓰지 않고 `fetch` 를 직접 부르고 있었다 — 접수 위저드, 거래 증빙, 포트폴리오 사진. **셋 다
헤더가 없었다.** 03 이 400 으로 먼저 끊어서 이 401 은 보이지도 않았다.

바이트를 올리는 자리를 `upload()` 하나로 모았다(`lib/client.ts`). 다음에 헤더가 하나 더
필요해져도 한 곳만 고치면 된다.

## 3. 새 봇 — `npm run e2e:trade`

네 사람이 동시에 걷는다: 관리자, 파트너, **다른** 파트너, 고객. 둘째 파트너는 "남의 거래는
남의 것"을 재기 위해서만 있다.

걸음마다 셋을 본다.

- **그 걸음의 주인만 누를 수 있다.** 다른 파트너는 남의 주문을 열지 못한다.
- **아직 볼 자격이 없는 것은 안 보인다.** 낙찰 전 상세주소·연락처, 남의 견적 금액, 남의 상담.
- **못 나아가면 왜인지 화면이 말한다.** 방문 시각 전 작업 시작, 결제사 미연결, 결제 전 정산.

31 걸음이 통과한다. 기록은 `검증결과.md` 에 있다.

### 봇이 시계를 미는 두 자리

규칙을 끄는 것이 아니라, **시간이 지난 상태**와 **저장소가 이미 받아 둔 상태**를 만들어 준다.

| 자리 | 왜 봇이 만들 수 없나 | 무엇을 했나 |
|---|---|---|
| 방문 시각 | 계약은 방문이 **미래**여야 맺어지고(`validateSchedule`), 작업은 그 시각이 **지나야** 시작된다. 둘 다 옳은 규칙이라 한 번에 만족시킬 수 없다 | `schedule_slots` 를 어제로 민다 |
| 증빙 사진 | 사진 바이트는 Vercel Blob 으로 가는데 로컬에는 토큰이 없다(503). 완료 확인은 전·후 사진을 요구한다 | `photos` 에 두 줄을 넣는다 |

둘 다 **거절 자체는 앞 걸음에서 따로 잰다.** 방문 전 작업 시작이 거절되는지, 저장소가 없다고
화면이 말하는지를 먼저 확인하고 나서 민다.

## 3-2. 두 번째 봇 — `npm run e2e:live`

거래 봇을 세우고 나니 남은 구멍이 보였다. 봇 다섯이 모두 **성공하는 길을 데스크톱 폭에서** 걷는다.
그리고 이번에 고친 운영 대시보드를 **화면으로 본 봇이 하나도 없었다.**

다섯 갈래를 더 걷는다.

| 갈래 | 재는 것 |
|---|---|
| 휴대폰(390×844) | 접수 위저드가 좁은 화면에서 끝까지 간다 · 가로로 밀리지 않는다 |
| 새로고침·뒤로 가기 | 다시 그려도 로그인과 내 요청이 그대로다 |
| 거절 | 틀린 비밀번호 · 중복 가입 · 로그인 없이 남의 주소. **셋 다 이유를 말해야 한다** |
| 운영 대시보드 | 숫자와 날짜별 그래프가 실제로 그려진다 |
| 취소 | 사유 없이는 못 지우고, 지우면 화면이 취소라고 말한다 |

대시보드 걸음은 **옛 코드에서 실제로 넘어지는 것**을 확인했다(`검증결과.md` §2-2).
고쳤다는 말이 아니라 **고치기 전에는 못 썼다는 증거**다.

## 4. 이번에 하지 않은 것

- **사진 저장소(Vercel Blob) 연결.** `needsBucket` 이 아직 503 을 돌려준다. 이제 그 이유가
  화면에 닿으므로, 연결은 별도 라운드에서 한다.
- **`<img src>` 가 토큰을 못 싣는 문제.** 사진 보기(`/api/photos/<id>`)는 세션을 요구하는데
  브라우저의 이미지 요청에는 `Authorization` 헤더를 붙일 수 없다. 저장소를 연결하는 라운드에서
  서명된 주소나 쿠키로 풀어야 한다. **지금은 올릴 수도 없어서 드러나지 않는다.**
- **결제사(토스) 연결.** 키가 없으면 카드 결제가 열리지 않는 것이 옳다. 봇은 예약금 0원 계약으로
  작업 완료까지 가고 잔금 앞에서 멈춘 뒤 **화면이 그 이유를 말하는지**만 잰다.
- **배포된 주소 확인.** 이 세션에서 `*.vercel.app` 으로 나가는 길이 막혀 있어(프록시 403,
  Vercel 연결도 프로젝트를 못 본다) 운영·프리뷰를 직접 열어 보지 못했다. 여기의 모든 결과는
  **같은 코드를 로컬 Postgres 로 돌린 것**이다.
- **`passwordReset` 부하 의존 흔들림.** 29-24 §7-1 에 적은 그대로 이월한다. 여러 파일이 한
  `auth_state` 줄을 함께 쓰는 자리라 그 자체로 한 라운드다.
