# 28-55 수정사항 (Claude) — 데이터 위생 라운드

기반: `28-54` 복사본(스크래치 wf28-55, Copilot 리뷰 반영 커밋 포함)에서 작업. 28-54 감사 4건 전부 반영.

## 28-54-01 · 알림 보관 정책 [반영]

- `NOTIFICATION_READ_RETENTION_DAYS = 30`, `NOTIFICATION_UNREAD_RETENTION_DAYS = 90`, `NOTIFICATION_CAP = 500`. `pruneNotifications(now)`: 읽은 알림 30일·안 읽은 알림 90일 경과 제거 → 그래도 상한 초과면 오래된 것부터(읽은 것 우선) 제거. 제거 수 반환, 멱등. 앱 기동(`initPlatform`)과 관리자 현황 sweep에 추가(사진 정리도 기동 시 함께).
- vitest 1건: 31/29일 읽음·91/89일 미읽음 경계, 520건 → 500건(읽은 10건 → 오래된 미읽음 10건 순), 재실행 0, 스냅샷 왕복.

## 28-54-02 · 채팅 한도·보관 [반영]

- `sendMessage`: `CHAT_MAX_TEXT = 500`자 초과 거부(글자 수 안내), 요청당 `CHAT_MAX_PER_REQUEST = 300`건 도달 시 거부(전화·A/S 접수 안내). `pruneChats(today, CHAT_RETENTION_DAYS = 180)`: 거래 종료일(`terminalDate` — 정산 완료일/취소 환불 생성일, `prunePhotos`와 공용으로 추출) 경과 요청의 채팅·읽음 기록 제거, 제거 요청 수 반환, 멱등, 날짜 검증.
- `ChatBox` 입력 `maxLength` + 글자 수 카운터(`[data-chat-count]`).
- vitest 1건: 501자 거부·500자 허용·300건 도달 거부·179일 유지/180일 제거·읽음 0·멱등·잘못된 날짜 거부.

## 28-54-03 · 저장 용량 내역 [반영]

- `storageUsage()`에 `notificationChars/Count`, `chatChars/Count`, `otherChars`(사진+알림+채팅+기타 = 전체). 관리자 저장 용량 카드: 4구간 내역 막대(`[data-storage-breakdown]`) + 범례(장수·건수·KB) + "오래된 알림 정리"(`[data-prune-notifications]`)·"오래된 채팅 정리 (180일)"(`[data-prune-chats]`), 결과 메시지 `[data-prune-msg]`.
- vitest 1건: 합계 = 전체, 각 항목 > 0.

## 28-54-04 · e2e + 실측 [반영]

- e2e 3단계 추가(130→**133**): 채팅 입력 500자 상한(501자 입력 → 카운터 500/500) / 저장 용량 내역에 알림·채팅 건수 / 알림 전부 읽음·40일 전으로 조정 → 현황 진입 sweep → 알림 0건. (초안은 501자를 `fill`해 도메인 거부 문구를 기대했으나 Playwright `fill`이 `maxLength`를 지켜 500자만 들어감 → 카운터 검증으로 바꾸고 도메인 거부는 vitest에 둠.)
- 실측 `capture-28-55.mjs`: 카운터 9/500 → 501자 입력 시 500/500, 내역(사진 4장 318KB · 알림 13건 2KB · 채팅 1건 · 기타 7KB), 정리 버튼 안내 2종, 알림 13건 → 40일 경과 후 기동 prune 0건, 완료일 200일 전 조정 후 채팅 0건·사진 0장(90일 정책 동시 적용), 모바일 가로 스크롤 없음.
