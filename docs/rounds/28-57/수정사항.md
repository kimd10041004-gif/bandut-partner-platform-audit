# 28-57 수정사항 (Claude) — 일정 변경·휴무 라운드

기반: `28-56` 복사본(스크래치 wf28-57)에서 작업. 28-56 감사 4건 전부 반영.

## 28-56-01 · 방문 일정 변경 [반영]

- `rescheduleVisit(requestId, { date, startHour, endHour }, by: 'customer'|'partner', today)`: `scheduled`에서만, `validateSlot` 형식 검증 → 지난 날짜·같은 일정·파트너 휴무일 거부 → 자기 슬롯을 제외한 `addSlot` 충돌 검사 → 슬롯 교체(id 유지) → `store.markRescheduled`(`rescheduleCount/rescheduledAt`, 스냅샷 검증) → 상대방 알림("고객이/파트너가 방문 일정을 변경했습니다 — 이전 → 새").
- 고객 거래 상세(방문 예정): "방문일 변경"(`[data-reschedule]`) 인라인 카드(`aria-label` 변경 날짜/시작/종료, 오류 `[data-reschedule-error]`) + 헤더 "일정 변경 n회"(`[data-reschedule-count]`). 파트너 일정 탭: 방문 예정 건이 같은 폼의 선택지에 "(방문 예정 — 일정 변경)"으로 추가되고 버튼이 "일정 변경"으로 바뀜.
- vitest 1건: 상태·과거·충돌·동일·형식·휴무 거부(실패 시 횟수 미기록), 슬롯 교체·총 슬롯 수·횟수·시각, 고객→파트너 계정 범위 알림 문구, 파트너→고객 알림, 같은 날 시간 이동(자기 슬롯 비충돌), 시공 시작 후 거부, 스냅샷.

## 28-56-02 · 파트너 휴무일 [반영]

- `daysOff: Map<partnerId, string[]>`(스냅샷 `daysOff`, 구조·날짜 검증). `setDaysOff`(검증·중복 제거·정렬·빈 배열 제거)·`toggleDayOff`·`daysOffOf`·`isDayOff`. `scheduleVisit`·`rescheduleVisit`가 휴무일 슬롯 거부(상태 변화 없음).
- 파트너 일정 탭: "YYYY-MM-DD 휴무 설정/해제"(`[data-dayoff-toggle]`, 폼의 날짜 기준), 캘린더 셀 `.dayoff` + "휴무" 라벨(`[data-dayoff]`).
- vitest 1건: 설정·중복·정렬·검증·예약 거부·토글·타 파트너 독립·스냅샷 왕복·손상 거부.

## 28-56-03 · 방문 전날 리마인더 [반영]

- `sweepVisitReminders(today)`: 내일(`VISIT_REMINDER_DAYS_BEFORE = 1`) 슬롯 중 요청이 `scheduled`인 건에 고객·파트너(계정 범위) "내일 방문 예정" 알림 1회, 슬롯 `remindedFor` 멱등 키(일정 변경으로 새 슬롯이 되면 다시 알림). 앱 기동·관리자 현황 sweep에 포함.
- vitest 1건: D-2 0건·D-1 2건(고객+파트너)·재실행 0·변경 후 재알림·스냅샷 후 멱등·날짜 검증.

## 28-56-04 · e2e + 실측 [반영]

- e2e 5단계 추가(136→**141**): 파트너 휴무일 설정(D+2) / 고객이 휴무일로 변경 → 거부 안내 / D+1 10~12시로 변경 → 예약 표시 + 변경 1회 / 새로고침(기동 sweep) → 고객 "내일 방문 예정" / 파트너 알림 "고객이 방문 일정을 변경" + "내일 방문 예정".
- 실측 `capture-28-57.mjs`: 휴무 2일 캘린더 표시·토글 라벨, 파트너가 휴무일로 일정 변경 시도 거부, 고객 휴무일 거부 → D+1 변경 성공("예약 2026-09-04 10:00 · 일정 변경 1회"), 새로고침 후 고객·파트너 리마인더, 파트너 일정 표 반영, 모바일 가로 스크롤 없음. (초안 캡처는 폼 선택지 첫 항목이 낙찰 건이라 "일정 변경" 버튼을 못 찾음 → 방문 예정 옵션을 골라 선택.)
