# 28-57 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-57` 전체 — 일정 변경·휴무 반영 후, **운영자(관리자) 행위의 추적 가능성과 목록 운용성** 점검.
사전 확인: `npm run check` exit 0 (vitest 232/232), e2e 141/141 PASS, visual-check 전 항목 PASS, `npm audit` 0건, 프로덕션 배포 그린(PR #158 머지 `2db009a`). 28-56 감사 4건 전부 수정 확인됨.

핵심 지적: 관리자는 돈과 계정을 움직인다 — 환불 완료(차감액 확정), 지급 완료, A/S 해결, 파트너 승인·거절·정지, 탈퇴 기록 파기, 보증·수수료 같은 설정 변경. 그런데 **누가 언제 무엇을 했는지 남는 기록이 없다**. 환불 차감 사유는 Refund에, 거절 사유는 Account에 흩어져 있고, 정지·파기·설정 변경은 흔적조차 없다. 분쟁이 생기면 "관리자가 그렇게 처리했다"를 증명할 수 없고, 운영자가 여러 명이 되는 순간 책임 소재가 사라진다. 또 요청 관리·회원 탭은 **검색·필터 없이 전체를 나열**해 요청이 수십 건만 돼도 원하는 행을 찾을 수 없다(요청 관리는 상태 필터도 없음).

## 상 (High)

### 28-57-01 · 운영 감사 로그
→ 요구: `AuditEntry { id, at(ISO), actor('admin'|'system'), action, target, detail? }`(스냅샷 `auditLog`, 검증). 플랫폼의 관리자 행위는 도메인 안에서 기록: `settleRefund`·`markPayout`·`reviewClaim`·`resolveClaim`·`updateSettings`(바뀐 키)·`addPackage/updatePackage/removePackage`·`addQuestion/removeQuestion`·`prunePhotos/pruneNotifications/pruneChats`(제거 수 > 0, actor system)·`sweep*`(처리 수 > 0, system). 인증 서비스의 관리자 행위(승인·거절·정지·해제·파기)는 `platform.audit(action, target, detail)`로 UI 호출부에서 기록(경계 문서화). 보관: `AUDIT_RETENTION_DAYS = 180`·`AUDIT_CAP = 1000`(`pruneAuditLog`, sweep 포함). `auditLog(limit?)` 최신순. **도메인 테스트 필수**.

### 28-57-02 · 관리자 운영 기록 카드 + CSV
→ 요구: 관리자 현황 하단 "운영 기록" 카드(`[data-audit-log]`, 최근 20건: 시각·주체·행위·대상·상세) + "CSV 내보내기"(`[data-export-audit]`, `audit-YYYY-MM-DD.csv`, BOM·CRLF, 기존 `toCsv`/`downloadText`).
