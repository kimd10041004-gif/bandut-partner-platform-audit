# 29-9 수정사항 — 탭 아이콘을 하나로

## 왜 이 라운드가 생겼나

29-8이 공간 스튜디오를 통째로 들여왔다. 시안에서 크롤해 온 정적 앱이라 **자기 `<link rel="icon">`을
들고 왔다**. 그래서 같은 사이트인데 탭 두 개가 서로 다른 아이콘을 달고 있었다.

```
/            → /favicon.svg                              270 바이트, 40×40 viewBox 마크
/interior/   → /interior/assets/bandeuthouse-logo.png    903,413 바이트, 글자까지 든 로고
```

903KB짜리는 16px 탭에서 글자가 뭉개진다. 크기 문제보다 **같은 사이트로 안 보인다**는 것이 더 나쁘다.

## 1. 본체 쪽으로 맞췄다

`public/interior/index.html`의 아이콘 링크를 `/favicon.svg`로 바꿨다. 그 파일은 40×40 viewBox로
그려진 마크라 작게도 읽힌다.

## 2. 크롤러가 받을 때 고치게 했다 — 안 그러면 되살아난다

`fetch-interior-app` 워크플로가 다음 실행에서 시안 원본을 다시 받아 오면 이 자리는 **원래대로
돌아간다**. Cloudflare 주입 스크립트에서 이미 겪은 일이다 — 손으로 지웠더니 다음 크롤에 그대로
돌아왔고 병합 충돌까지 났다. 그래서 그때와 같은 자리에서 아이콘 링크도 다시 쓴다.

```python
# 시안 것이 아니라 우리 사이트 아이콘을 단다 — 여기서 안 고치면 다음 크롤에 되살아난다
html = re.sub(r'(<link rel="icon"[^>]*href=")[^"]+(")', r'\1/favicon.svg\2', html)
```

## 3. 가드 — 갈라지면 실패한다

`lib/auth-wiring.test.ts`에 셋째 가드를 더했다. `app/layout.tsx`의 `metadata.icons` 첫 항목과
스튜디오의 `<link rel="icon">`이 **같은 경로**를 가리키는지, 그 파일이 `public/`에 있는지 본다.

되돌려 놓고 돌려 실패를 확인했다.

```
AssertionError: 탭 아이콘이 갈라졌습니다 — 같은 사이트로 안 보입니다:
  expected '/interior/assets/bandeuthouse-logo.png' to be '/favicon.svg'
```

## 하지 않은 것

**로고 PNG는 지우지 않았다.** 스튜디오 헤더가 아직 그 그림을 쓴다 — 거기서는 크게 나오므로 글자가
읽힌다. 탭에서만 쓰지 않는 것이다.
