# DB 분리 확인 완료 (2026-09-11)

프리뷰와 운영이 **서로 다른 데이터**를 본다는 것이 확인됐다. 주소 비교가 아니라 데이터 자체의
차이로 확인했다.

Neon SQL 콘솔에서 두 브랜치에 각각 읽기 전용 쿼리 하나씩.

```sql
select to_regclass('public.diagnostic_probes');
```

| 브랜치 | 결과 |
|---|---|
| 한쪽 | 비어 있음 — 표가 없다 |
| 다른 쪽 | `diagnostic_probes` — 표가 있다 |

같은 프로젝트의 두 브랜치가 같은 쿼리에 다른 답을 냈다. 그것으로 판정이 끝난다. 어느 쪽이
`main` 이고 어느 쪽이 `preview` 인지는 화면에 함께 찍히지 않아 **관찰하지 않았고**, 코드로부터
추론했다(표를 만드는 코드는 29-17 이후에만 있고 프리뷰 배포만 그것을 돌린다). 자세한 것은
`분리확인_기록.md` §2.

표식 쓰기는 하지 않았다. 표 존재 여부만으로 결론이 나서 필요가 없었고, 운영 DB 에는 읽기
쿼리 하나만 나갔다.

**이제 프리뷰에 계정을 만들어도 운영 데이터에 섞이지 않는다.** 막혀 있던 실제 가입 → 승인 왕복
검증을 진행해도 된다.
