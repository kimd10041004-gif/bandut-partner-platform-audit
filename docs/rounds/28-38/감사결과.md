# 28-38 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-38` 전체 — 약관·개인정보 동의 반영 후, **돈이 파트너에게 실제로 도달하는 경로** 점검.
사전 확인: `npm run check` exit 0 (vitest 184/184), e2e 55/55 PASS, visual-check 전 항목 PASS, 프로덕션 배포 그린(PR #85 머지). 28-37 감사 4건 전부 수정 확인됨.

핵심 지적: 고객 결제(예약금·최종 결제)는 들어오는데 **파트너에게 나가는 돈의 경로가 없다.** (1) 파트너 정산 계좌(은행·계좌번호·예금주)를 받을 곳이 없다 — 계좌 없이 "정산 확정"만 찍히는 상태라 운영자가 실제 이체를 할 수 없다. (2) "정산 확정(settled)"과 "지급 완료"가 구분되지 않아 파트너는 돈이 언제 들어오는지, 관리자는 무엇을 이체했는지 알 수 없다. (3) 지급 완료는 파트너에게 알림·영수 근거(지급일·금액·계좌)가 남아야 분쟁을 막을 수 있다. 상용 운영에서 정산 지급 기록 없이 플랫폼을 열 수는 없다.

## 상 (High)

### 28-38-01 · 정산 계좌·지급 도메인 부재
→ 요구: `AuthService.setPayoutAccount(role, { bank, number, holder })` — 파트너만, 은행명 필수·계좌번호 숫자 10~14자리·예금주 필수(사업자 파트너는 업체명과 다를 수 있으므로 자유 입력), `Account.payoutAccount`에 저장·마스킹 조회. `PlatformService.markPayout(requestId, { accountLabel })` — **정산 확정(settled) 이후에만**, 정산 계좌 없으면 거부("정산 계좌가 등록되지 않은 파트너입니다"), 중복 지급 거부, `CompletedJob.payout { paidAt, amount, account }` 기록 + 파트너 알림("정산금 지급 완료 ₩…"). `unsettledPayout()`과 별도로 **지급 대기(settled & !payout)** 집계. 저장소 왕복 + 손상 거부 **도메인 테스트 필수**.

### 28-38-02 · 파트너 정산 탭: 계좌 등록 + 지급 상태
→ 요구: 정산 탭 상단 "정산 계좌" 카드(등록/수정 폼, 마스킹 표시), 계좌 미등록 시 배너("정산 계좌를 등록해야 지급됩니다"). 주차 정산 표 각 작업 행에 **지급 상태**(대기/지급 완료 · 지급일).

### 28-38-03 · 관리자 정산 감독: 지급 처리
→ 요구: "지급 대기" 목록(정산 확정 건: 파트너·금액·계좌 마스킹·확정일) + **지급 완료** 버튼(계좌 없으면 오류 노출) + 지급 완료 목록(지급일). 상단 지표에 지급 대기 금액.
