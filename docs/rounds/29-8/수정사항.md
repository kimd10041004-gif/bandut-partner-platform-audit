# 29-8 수정사항 — 인테리어 꾸미기가 열린다

## 왜 이 라운드가 생겼나

화면 다섯 자리가 `/interior/`를 부르는데 우리 쪽은 **404**였다.

```
components/marketplace/shell.tsx    헤더 메뉴 · 하단 탭 · 푸터
components/marketplace/home.tsx     홈의 "인테리어 꾸미기" 카드
components/marketplace/request.tsx  요청 화면의 "3D 공간 꾸미기"
```

29-6의 이미지 404와 같은 부류다. 링크는 있는데 그 끝이 없다.

## 1. 시안에는 있었다

`reference-compare`에 `/interior/`를 넣어 보니 시안은 **HTTP 200**이고, 문장 123줄짜리
2D·3D 공간 스튜디오였다. 빌드가 없는 정적 앱(HTML + JS + 에셋)이라 파일만 가져오면 선다.

`fetch-interior-app` 워크플로가 `index.html`에서 시작해 크롤한다. 파일 목록을 모르기 때문이다.
받은 것 19개.

```
index.html  app.js  scene.js  model.js  products.js  materials.js
wallpaper.js  consultation.js  style.css
vendor/three/{three.module,three.core,OrbitControls,GLTFExporter,OBJExporter}.js
vendor/lucide.min.js
assets/{bandeuthouse-logo.png, airbnb-setup.jpeg, oak.png, linen.png}
favicon.svg
```

## 2. 서빙 — `/interior/`가 `/interior/index.html`이 아니다

`public/`의 파일은 **정확한 경로로만** 서빙된다. `/interior/index.html`은 열리지만
`/interior/`는 앱 라우터의 catch-all로 떨어져 404가 된다. 화면이 부르는 주소는 후자다.

`next.config.ts`에 재작성 둘을 뒀다(`/interior`, `/interior/`).

## 3. CSP — 도망가지 않았다

이 앱은 정적 파일이라 미들웨어가 본문에 nonce를 심을 수 없다. 그리고 우리 정책의
`'strict-dynamic'`은 nonce 없는 `<script src>`를 **전부** 막는다. 그대로 두면 스튜디오는
한 줄도 실행되지 않는다.

이 경로만 다른 정책을 준다. `'unsafe-inline'`은 쓰지 않았다.

| | 어떻게 |
|---|---|
| 바깥 스크립트 | `'self'` — `app.js`·`three`·`lucide` 전부 우리 도메인이다 |
| 인라인 | 임포트맵 하나뿐. 그 내용의 **sha256만** 허용 |

해시를 상수로 적어 두면 파일이 바뀌었을 때 화면이 **조용히** 죽는다. 브라우저가 임포트맵을
막고 서버는 200을 준다. 그래서 `server/csp.test.ts`가 실제 파일에서 다시 계산해 맞춰 본다.

## 4. 시안 호스트가 주입한 것을 걷어냈다

받아 온 HTML에 Cloudflare 봇 관리 스크립트가 섞여 있었다(`__CF$cv$params`,
`/cdn-cgi/challenge-platform/...`). 앱의 일부가 아니고 그 경로는 우리 배포에 없다.

처음엔 손으로 지웠더니 **크롤러가 다시 받으면서 되살아나** 커밋 충돌을 냈다. 크롤러가 받을 때
걷어내게 고쳤다. 다음 실행에서 변경 없음이 확인됐다.

## 5. 200은 여전히 "주소가 있다"까지만 말한다

정적 크롤이 텍스처 두 장을 놓쳤다. `materials.js`가 이름을 코드 안에서 조립한다.

```js
['oak','linen'].map(name => new URL(`./assets/${name}.png`, import.meta.url))
```

따옴표 속 경로를 찾는 방식으로는 안 보인다. `/interior/`는 200이었고 HTML도 멀쩡했다.
**브라우저로 열어 네트워크를 보고서야** 404 두 건이 드러났다.

정적 스캔을 완벽하게 만들려 하지 않았다 — 다음엔 또 다른 모양으로 샌다. 대신 상설 게이트를
만들었다.

`scripts/e2e-interior.mjs`가 실제로 브라우저로 연다.

| 무엇을 보나 |
|---|
| `/interior/`가 스튜디오를 여는가 (제목) |
| 3D 캔버스가 그려졌는가 |
| 단계 안내가 보이는가 |
| 플랫폼으로 돌아가는 링크가 있는가 |
| **화면이 부르는 것이 하나도 4xx·5xx가 아닌가** |
| **CSP가 스튜디오를 막지 않는가** |

`gates`의 server job에 넣었고, 배포 확인 경로 목록에도 `/interior`를 더했다(36 → 37).

## 6. 내가 CI를 빨갛게 만든 자리

새 단계를 `e2e:next` 옆에 뒀는데, 그 자리는 Playwright 설치보다 **앞**이다. 브라우저가 없어
1초 만에 실패하고 뒤 단계가 전부 건너뛰어졌다. 로컬에는 브라우저가 이미 있어 안 드러났다.

설치 뒤로 옮기고, YAML을 파싱해 두 단계의 순서를 확인했다.

## 7. 하지 않은 것

- **스튜디오 코드를 손보지 않았다.** 시안 것을 그대로 서빙한다. 저장·불러오기는 브라우저 안에
  머문다(자동 저장 없음은 그 앱이 스스로 안내한다).
- **`/interior/`를 우리 로그인과 잇지 않았다.** 시안대로 로그인 없이 열린다.
- "검토용 서비스" 문구는 그대로다. 프로덕션 전환 직전에 걷는다.
- 병합·프로덕션 전환은 사장님 승인 전에는 하지 않는다.
