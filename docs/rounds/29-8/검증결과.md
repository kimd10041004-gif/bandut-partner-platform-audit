## 2. 브라우저로 실제로 열었다 — 이 라운드의 핵심 근거

```
✓ /interior/ 가 스튜디오를 연다
✓ 3D 캔버스가 그려졌다
✓ 단계 안내가 보인다 (방 크기)
✓ 플랫폼으로 돌아가는 링크가 있다
✓ 화면이 부르는 것이 하나도 4xx·5xx 가 아니다
✓ CSP 가 스튜디오를 막지 않는다
```

**다섯째 줄이 이 라운드가 배운 것이다.** 고치기 전 같은 검사를 돌렸을 때 이렇게 나왔다.

```
HTTP 404: http://127.0.0.1:3211/interior/assets/oak.png
HTTP 404: http://127.0.0.1:3211/interior/assets/linen.png
```

그때도 `/interior/`는 **200**이었고 HTML도 멀쩡했다. 경로 검사도, 화면 안 검사도 통과했다.
`<img src>`만 세기 때문이다 — 이 두 장은 자바스크립트가 만들어 부른다.

```
content-security-policy: default-src 'self';
  script-src 'self' 'sha256-XueHYN4etha2FC3MTdxDLKyvr/69mYQU3Cch5vfvlXk=';
  style-src 'self' 'unsafe-inline'; font-src 'self' data:;
  img-src 'self' data: blob:; connect-src 'self' blob:;
  frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'
```

`'unsafe-inline'`은 스크립트 쪽에 없다. `'strict-dynamic'`도 없다 — 그것이 이 앱의
`<script src>`를 전부 막기 때문이다.
