# 28-5 수정사항 — 28-4 감사결과 5개 항목 전부 처리

작업 방식: 기존 규칙 그대로 — 28-1~28-4는 일절 수정하지 않고 스크래치 복사본(`scratchpad/wf28-5`)에서 수정 후 `28-5` 스냅샷 생성.

## 항목별 수정 내용

### 28-4-01 [상] 취소된 요청의 슬롯 미해제 → 수정
- `transitionRequest(id, 'cancelled')`가 전이 성공 시 해당 요청의 방문 슬롯을 전부 해제한다. 전이 실패(예: in_progress에서 취소 시도) 시에는 아무것도 제거되지 않으며, 완료된 작업의 슬롯은 이력으로 유지된다.
- 회귀 테스트: 취소 후 같은 시간대 재예약 성공 / 전이 실패 시 슬롯 유지 / 완료 슬롯 이력 유지 — 3개. (감사 시 재현 테스트로 버그 동작을 먼저 확인함.)

### 28-4-02 [중] 대시보드 부재 → 수정
- 대시보드 탭 신설(기본 탭): 오늘 방문 일정, 다가오는 일정 5건, 상태별 진행 현황 배지, 미정산 지급 예정 합계.
- 집계 로직은 PlatformService 헬퍼(`statusCounts()`, `upcomingSlots(fromDate, limit)`)로 두고 테스트 — 2개.

### 28-4-03 [중] 백업/이전 수단 부재 → 수정
- `exportData()`(pretty JSON) / `importSnapshot(raw)` 신설. 가져오기는 JSON 파싱·version·형태 검증을 전부 통과해야 적용되고, 실패 시 `PlatformError`와 함께 **기존 데이터 보존**. 성공 시 상태 교체 + 저장소 반영.
- `load()`의 파싱 로직을 `parseSnapshot()`으로 통합(가져오기와 동일 검증 경로).
- UI: 대시보드의 "데이터 백업" 카드 — JSON 파일 내려받기 / 파일 업로드 복원.
- 회귀 테스트: round-trip 복제(ID 연속성 포함), 손상/버전 불일치/null 거부 + 데이터 보존, 저장소 반영 — 3개.

### 28-4-04 [하] 신규 요청 폼 과거 희망일 허용 → 수정
- UI에서 오늘(UTC) 이전 희망일 거부 (도메인은 시드 이력을 위해 과거 허용 유지 — 의도 명시).

### 28-4-05 [하] 일정 표 정보 부족 → 수정
- 일정 표와 대시보드 일정 목록에 고객명 · [카테고리] 공사 내용 표시 (store 조회, 삭제된 요청은 '-').
