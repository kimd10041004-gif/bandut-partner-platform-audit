## 상 (High)

### 28-30-01 · 인증 도메인 부재
→ 요구: 별도 모듈 `auth.ts`의 `AuthService` (localStorage 키 분리 `banded-auth-v1`).
- `Account { id, role('customer'|'partner'), name, phone, password, bizNo?, verified, createdAt }`.
- `register()`: 이름 공백 거부, 휴대폰 010-포함 숫자 형식, 비밀번호 8자 이상, 같은 역할+휴대폰 중복 가입 거부, **파트너는 사업자등록번호 10자리 필수**. 가입 시 6자리 OTP 발급(시뮬레이션 — 반환값으로 노출, 상용 전환 시 SMS 발송으로 교체).
- `verifyOtp(role, phone, code)`: 불일치 거부, 성공 시 verified.
- `login(role, phone, password)`: **미인증(verified=false) 로그인 거부**, 비밀번호 불일치 거부. **관리자는 시드 계정**(admin / 초기 비밀번호) — 가입 없음.
- **역할별 독립 세션**(고객·파트너·관리자 동시 로그인 가능 — 한 브라우저 시연 전제), `logout(role)`.
- 스냅샷 검증 + 손상 시 초기화, **도메인 테스트 필수**.

### 28-30-02 · 로그인 게이트 UI
→ 요구: `AuthGate` — 세 앱 모두 세션 없으면 로그인 화면. 고객·파트너: 로그인 ↔ 회원가입(이름/휴대폰/비밀번호, 파트너는 사업자번호) ↔ OTP 입력 3단계, 오류는 도메인 메시지 그대로. 관리자: 로그인 폼 + 데모 계정 안내. **랜딩(홈페이지)은 공개 유지** — 고객 앱 기능(수리 요청·견적함·거래 상세) 진입 시에만 게이트. 헤더에 로그인 사용자명 + 로그아웃.

### 28-30-03 · e2e 재배선
→ 요구: 기존 36단계 여정에 가입·OTP·로그인 단계를 끼워 넣어 **로그인 상태에서 전 여정 무회귀**: 고객 가입+인증+로그인 → (기존 여정) → 파트너 가입+인증+로그인 → 관리자 로그인. 로그아웃 후 게이트 복귀 확인 1건.
