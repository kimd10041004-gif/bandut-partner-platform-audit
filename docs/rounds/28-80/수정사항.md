# 28-80 수정사항 — 공개 지표에서 시드를 뺀다

**대상 감사**: `28-79/감사결과.md` 4건. 브랜치 `round-28-80`, 라운드 문자열 `28-80`, 버전 `28.80.0`.

28-79는 "실적이 없으면 지표를 내걸지 않는다"까지 갔다. 그런데 **켜지는 쪽을 보지 않았다** — 게이트만
만들고 숫자는 시드를 포함한 집계를 그대로 썼다. 이번 라운드는 게이트가 아니라 **숫자**를 고친다.

---

## 28-80-01 (상) 공개 지표가 시드를 빼고 센다 + 시연 데이터를 지울 수 있다

### 무엇이 문제였나

`hasRealActivity()`는 참/거짓만 정했고, 화면에 나가는 네 숫자는 `adminOverview()`·`bidStats()`·
`reviewStats()`(전부 시드 포함)였다. 부팅 경로를 그대로 태워 확인한 값 — 실제 요청이 **1건** 생긴 직후:

```
hasRealActivity = true
누적 요청 = 7 (실제는 1건)
완료된 수리 = 3 (실제는 0건)
파트너 낙찰률 = 100 (실제 입찰 0건)
```

첫 고객이 요청 하나를 올린 그 순간 랜딩이 "누적 요청 7 · 완료된 수리 3 · 낙찰률 100%"를 내걸었다.
완료 3건과 낙찰률 100%는 **단 하나도 실제가 아니다**. 28-78 감사 01이 지적한 문장이 "실적이 생겼으니
켠다"는 명분까지 달고 되살아난 셈이다. 게다가 시드를 지우는 통로가 없어 되돌릴 수도 없었다.

### 무엇을 했나

**`PlatformService.publicStats(): PublicStats`** — `seeded` 요청과 그에 딸린 입찰·리뷰를 **빼고** 센다.
`adminOverview()`·`bidStats()`·`reviewStats()`는 **건드리지 않았다**: 운영자는 기기에 실제로 무엇이
있는지 그대로 봐야 한다. 공개 화면과 운영 화면이 서로 다른 것을 보는 것이 맞다.

```ts
publicStats(): PublicStats {
  const real = this.store.list().filter((r) => r.seeded !== true)
  const realIds = new Set(real.map((r) => r.id))
  // 낙찰률은 실제 요청에 붙은 입찰만, 만족도는 실제 요청의 리뷰만
  …
}
```

`Landing.tsx`는 이제 `publicStats()` 하나만 쓰고, 게이트도 그 값에서 파생된다(`pub.totalRequests > 0`).
28-79의 `hasRealActivity()`는 회귀와 함께 그대로 두었다(같은 판단의 다른 표현이라 서로 어긋나지 않는다).

**`clearSeedData(): number`** — 관리자 설정 > **시연 데이터** 카드(`[data-clear-seed]`). `seeded` 요청과
**그 요청을 참조하는 모든 위성 레코드**를 함께 지운다: 입찰(`bids`)·체크리스트·읽음 워터마크와,
`requestId`를 가진 11개 컬렉션(정산·슬롯·추가 작업·리뷰·A/S·채팅·결제·환불·낙찰 철회·입찰 철회·알림).
요청만 지우면 **어느 화면에서도 지울 수 없는 고아**가 남는다 — 그것을 막는 것이 이 메서드의 전부다.
운영 기록에는 `시연 데이터 삭제 · N`으로 남고, 지울 것이 없으면 아무것도 하지 않는다(기록도 저장도).

`RequestStore.removeMany(ids)`를 새로 뒀다(유일한 호출자가 `clearSeedData`다).

### 회귀 (수정 전 실패 인용)

```
× 실제 요청 1건 + 시연 이력이 있어도 공개 지표는 1 · 0 · null · null 이다
  TypeError: p.publicStats is not a function
× 시연 데이터를 지우면 그 요청을 참조하는 레코드가 스냅샷 어디에도 남지 않는다
  TypeError: p.seedDataCount is not a function
× 지울 시연 데이터가 없으면 아무것도 하지 않는다
  TypeError: p.clearSeedData is not a function
```

고아 스윕 테스트가 이 항목의 안전망이다: 운영 기록(복원에도 보존되는 별도 장부)만 제외하고
**스냅샷 전체를 문자열로 훑어** 지워진 요청 id가 하나도 남지 않았는지 본다. 컬렉션을 빠뜨리면 걸린다.

## 28-80-02 (중) 런타임 보관함 정리가 실제 지운 건수를 기록한다

28-79-02는 "부팅에만 기록하는 것은 절반이다"라며 런타임 경로에 기록을 넣었는데, 넣은 숫자가 상수 `1`이었다.
`trimOverwritten`은 **지운 건수**를 돌려주는데(`return current.length - next.length`) 그 값을 버렸다.
보관함 상한이 3건이므로 3건이 한꺼번에 지워져도 운영 기록·CSV에는 "보관함 정리 · 1"로 남았다.

```ts
const removed = trimOverwritten(storage, Math.min(stashBudget(svc), Math.max(0, before - need)))
if (removed > 0) svc.recordStashTrim(removed)
```

**없는 기록보다 틀린 기록이 나쁘다** — 없으면 모른다는 것을 알지만, 틀리면 안다고 착각한다.

### 회귀 (수정 전 실패 인용)

```
× 28-80-02: 런타임 정리는 **실제로 지운 건수**를 기록한다
  AssertionError: expected '1' to be '3' // Object.is equality
```

## 28-80-03 (중) 새 규칙과 새 영속 필드를 문서에 적었다

28-77·28-78·28-79 세 라운드가 연속으로 문서를 건너뛰었고(`README`는 28-76, `UI_가이드`는 28-64에서 멈춰
있었다), 그중 28-79는 **저장 스키마를 늘린 라운드**였다. 규칙이 코드 주석에만 있으면 그 파일을 열지 않는
사람에게는 없는 규칙이다.

- `UI_가이드.md` — **「시연 데이터와 공개 지표 (28-79 · 28-80)」** 절 신설: `seeded`가 저장되는 필드라는 것과
  붙이는 곳이 시드 한 곳뿐이라는 것, 공개 화면은 `publicStats()`만 쓰고 값이 0이면 그리지 않는다는 규칙,
  지우는 통로와 고아 스윕 회귀.
- `README.md` — 라운드 기록에 28-77·28-78·28-79·28-80 네 줄.

검증은 grep이다: 수정 전 `grep -rn '28-79|hasRealActivity|seeded' --include=*.md .`(라운드 폴더 제외)는
**무출력**이었다.

## 28-80-04 (하) 지표가 나타나는 쪽도 본다 + 도달 불가 분기 제거

28-79는 `[data-hero-stats]`가 **없다**는 단언 하나만 두어, `showStats = false`로 굳혀도 네 게이트가 전부
통과했다. 조건부 렌더링을 만들고 조건의 한쪽만 고정한 셈이다. e2e 여정에 두 단계를 더했다:

```
PASS  실제 요청 1건 등록 뒤: 히어로 지표가 보인다 (28-80-04)
PASS  히어로 지표가 시드를 빼고 센다 — 누적 1 · 완료 0 · 낙찰률 — (28-80-01):
      1 누적 요청 0 완료된 수리 — 파트너 낙찰률 — 평균 만족도
```

두 번째가 01의 e2e 증명이기도 하다 — 28-79의 코드는 여기서 `7 · 3 · 100%`를 내걸었다.

그리고 `trimExternal`의 `svc === undefined` 분기를 지웠다. `assertRoom`은 사진 경로 3곳
(`platform.ts:873,910,936`)에서만 불리고 그 경로는 `load()`가 끝난 뒤에만 열리므로 **도달할 수 없는
분기**였는데, 그 안에 28-79-02가 "틀렸다"고 선언한 옛 정책이 그대로 남아 있었다. 정책을 한 곳에 두겠다고
적어 놓고 두 곳에 두었던 것을 실제로 하나로 만들었다.

## 하지 않은 것 (조용히 빼지 않는다)

- **시드를 서버 모드로 올리지 않는 것**은 그대로다(28-70). 서버 모드에서는 애초에 시드가 없다.
- **백업/복원으로 들어온 시드를 자동으로 거르는 것** — 하지 않았다. 복원은 "그 파일 그대로"를 뜻하고,
  들어온 뒤에는 관리자가 같은 카드로 지울 수 있다. 자동으로 지우면 복원의 의미가 흔들린다.
- `adminOverview`·`bidStats`·`reviewStats`의 의미 변경 — 하지 않았다(운영 화면은 있는 그대로 봐야 한다).
