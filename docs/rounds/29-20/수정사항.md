# 29-20 — 봇을 배포된 프리뷰에 붙인다

## 1. 막혀 있던 것이 열렸다

사장님이 Vercel 의 Preview 환경에 `AUTH_DEV_OTP=on` 을 넣으셨다. 저장 직후에는 그대로였다 —
Vercel 환경변수는 **배포 시점에 주입되므로** 새 배포가 서야 들어간다(29-19-3). 재배포 뒤 같은
확인을 돌리니 바뀌었다.

```
ENV_READY: yes
ENV_DETAIL: 세 값 모두 설정됨 · DB 왕복 확인 — 서버 전환 가능
ENV_DB: ok
```

`ENV_DB: ok` 는 서버가 **실제로 DB 까지 다녀왔다**는 뜻이다. 환경변수가 있다는 것과 연결이
산다는 것은 다른 말인데, 그 둘이 같은 응답에서 함께 확인됐다.

이제 프리뷰에서 가입을 받는다.

## 2. 봇이 배포된 주소도 잰다

`scripts/e2e-signup.mjs` 에 `BASE_URL` 을 더했다. 있으면 서버를 띄우지 않고 그 주소를 그대로
연다. 없으면 지금까지처럼 로컬에 띄운다. 재는 열여섯 줄은 똑같다.

## 3. 운영 주소는 이름으로 막는다

이 검사는 **계정을 실제로 만든다.** 프리뷰 DB 가 운영과 갈라져 있다는 것이 29-17 에서 확인됐기
때문에 프리뷰에서는 돌려도 된다. 운영에서는 절대 안 된다 — 진짜 손님 데이터 옆에 봇 계정이 생긴다.

그래서 주소를 먼저 본다.

```js
const PRODUCTION_HOSTS = ['bandut-partner-platform.vercel.app']
```

운영 호스트면 아무것도 하지 않고 멈춘다. `vercel.app` 으로 끝나지 않는 주소도 거부한다.
실제로 운영 주소를 주고 돌려 확인했다.

```
[e2e:signup] 돌리지 않습니다 — 운영 주소입니다: bandut-partner-platform.vercel.app — 이 검사는 계정을 만듭니다
```

로컬 규칙은 그대로다 — 이름에 `test` 가 든 DB 에서만 돈다.

## 4. 비밀값은 저장소 비밀값으로 받는다

봇은 관리자 비밀번호와 가입 코드가 있어야 승인 단계까지 간다. 그 값들은 Vercel 환경변수에만
있고 이 저장소에도 이 대화에도 없다. **값을 채팅으로 받지 않는다.**

GitHub 저장소 비밀값으로 받는다. 사장님이 GitHub 설정 화면에 직접 넣으시면, 워크플로가 읽어
쓰고 로그에는 가려진 채로 남는다. 우리 눈에는 보이지 않는다.

| 비밀값 이름 | 무엇 |
|---|---|
| `PREVIEW_ADMIN_PASSWORD` | 프리뷰의 `ADMIN_PASSWORD` 와 같은 값 |
| `PREVIEW_SIGNUP_CODE` | 프리뷰의 `SIGNUP_CODE` 와 같은 값 |

둘 중 하나라도 없으면 이 단계는 **건너뛴다.** 없는 것을 있는 척하지 않는다.

## 5. 왜 또 deploy-check 안인가

`workflow_dispatch` 는 워크플로 파일이 기본 브랜치에 있어야 부를 수 있다(29-19-1 에서 겪었다).
`deploy-check.yml` 은 이미 `main` 에 있어 부를 수 있고, 부를 때 `ref` 로 이 브랜치를 주면
브랜치 버전이 돈다. `signup` 입력이 참이고 `base_url` 이 있을 때만 도는 단계로 넣었다.
