# 28-87 수정사항 — 가드의 남은 구멍 · 공개 경로가 로그인을 굶기지 않게 · 서버 모드 전환 준비

28-86 감사 4건을 전부 고치고, **프로덕션 서버 모드 전환을 결정할 수 있는 상태**로 만들었다.
전환 자체는 하지 않는다 — 실제 사용자 데이터가 걸린 판단이라 사장님 몫이다.

## 01 (상) 심볼 이름이 아니라 **선언 소유**를 본다

**원인.** 28-86의 `isPlatform`은 **수신자 타입의 심볼 이름**이 `PlatformService`인지 봤다.
그러면 같은 클래스의 같은 메서드인데 타입이 한 번 가공되면 놓친다.

**수정 전 실패 인용.** `PartnerCard.tsx`(고객이 업체를 고르는 자리)에 하나씩 심어 확인했다:

```
=== optional ===   const maybe: PlatformService | undefined = platform; maybe?.partnerSummary(id)
+   "src/ui/PartnerCard.tsx → partnerSummary (속성)"          ← 잡힘 (대조군)
      Tests  1 failed | 7 passed (8)

=== pick ===       const narrow: Pick<PlatformService, 'partnerSummary'> = platform
      Tests  8 passed (8)                                      ← 조용히 통과

=== rest ===       const { ...rest } = platform; rest.partnerSummary(id)
      Tests  8 passed (8)                                      ← 조용히 통과
```

**수정.** 수신자가 아니라 **속성 자체**를 본다 — 이 속성의 선언이 `PlatformService` 클래스 본문
안에 있는가:

```ts
function ownedByPlatform(sym: ts.Symbol | undefined): boolean {
  if (sym === undefined) return false
  return (sym.getDeclarations() ?? []).some((d) => d.parent === platformClass())
}
```

타입이 어떻게 가공되든 속성 심볼의 선언은 원본을 가리키므로 **`Pick<>`을 따라간다.**
스프레드는 원본이 남지 않으므로 **복사하는 자리에서** 잡는다:

```ts
if (el.dotDotDotToken !== undefined) {
  const carried = SEED_INCLUSIVE.filter((name) => ownedByPlatform(t.getProperty(name)))
  if (carried.length > 0) found.push(`${file} → ${carried.join('·')} (스프레드)`)
}
```

**덤으로 거짓 경보가 줄었다.** 이름만 같은 남의 객체(`{ partnerSummary: () => 1 }`)는 선언이
다른 곳에 있어 잡히지 않는다 — 28-86은 수신자 타입으로 걸렀지만 이제 판정이 더 정확하다.

**그리고 문서의 한계를 다시 적었다.** 28-86은 "못 잡는 것은 이름을 런타임에 만들어 부르는 것뿐"
이라고 적었는데 **틀렸다**(28-86 감사 01). 한계를 좁게 적은 문서는 없는 문서보다 나쁘다.

## 02 (상) 픽스처로 **다섯 형태를 실제로 태운다**

**원인.** 28-86의 「세 가지 접근 방법을 모두 같은 것으로 본다」는 `AdminOverview.tsx`를 봤는데,
그 파일에는 **속성 접근밖에 없다**:

```
AdminOverview 위반 라벨 분포: ["adminOverview (속성)","statusCounts (속성)","bidStats (속성)"]
대괄호 포함? false / 구조 분해 포함? false
```

`every(속성 || 대괄호 || 구조 분해)`는 전부 속성이어도 참이다 — 나머지 두 경로를 통째로 지워도
초록이었다. **이름이 말하는 것을 확인하지 않는 테스트**이고, Copilot이 #229·#232·#235에서 지적한
그 패턴이 **네 번째로** 나타난 자리다.

**수정.** `src/testFixtures/guardForms.tsx`에 잡아야 하는 다섯 형태와 잡히면 안 되는 세 형태를
심어 두고, 회귀 테스트가 **정확 비교**한다(`toEqual`, 개수까지 고정). 손으로 심어 본 것은 다음
사람에게 남지 않는다 — 커밋에 남아야 회귀 테스트다.

**수정 전 실패 인용.** 28-86 구현(`c3e585a`)에 새 테스트만 붙여 돌렸다:

```
× 다섯 가지 접근 방법을 전부 잡는다 — 픽스처로 확인한다 (28-87-02)
AssertionError: 검사기가 픽스처의 형태를 놓쳤습니다: expected [ …(3) ] to deeply equal [ …(5) ]
× 거짓 경보를 내지 않는다 — 이름만 같은 남의 메서드·문자열 (28-87-01)
× 검사 대상 파일이 전부 타입 프로그램 안에 있다 (28-87-04)
      Tests  3 failed | 8 passed (11)
```

픽스처는 `src/ui/`가 아니라 `src/testFixtures/`에 둔다 — **화면 조각이 아니라 검사기의 입력**이고,
`structure.test.ts`의 "ui/의 조각은 두 곳 이상에서 쓰인다"는 화면 조각에 대한 규칙이다.
(처음에 `src/ui/`에 두었더니 그 규칙이 걸렸다. 규칙을 고치지 않고 파일을 옮겼다.)

## 03 (중) 공개 경로가 **로그인의 커넥션을 굶기지 않게**

**원인.** 28-86은 rev 캐시로 본문 파싱을 없앴지만 `select rev`는 **매 요청 그대로 나갔다.**
그런데 먼저 마르는 자원은 CPU가 아니라 **커넥션**이다:

```ts
// server/db.ts
if (pool === null) pool = new Pool({ connectionString: databaseUrl, max: 3 })
```

**커넥션 3개짜리 풀 하나를 `/api/public-stats`(세션 없음)·`/api/snapshot`·`/api/auth`가 나눠 쓴다.**
레이트리밋이 없으므로 익명 요청 몇 개로 로그인과 저장이 대기한다. 28-86은 위험의 이름을 한 번
고쳤지만(28-85의 "유출 가치" → "자원 소모") **한 칸 덜 갔다**(28-86 감사 03).

**수정 두 가지.**

```ts
const PUBLIC_TTL_MS = 5000
// 1. TTL 안이면 DB를 아예 건드리지 않는다
const fresh = memo.get(workspaceId)
if (fresh !== undefined && Date.now() - fresh.at < PUBLIC_TTL_MS) return { ..., body: { stats: fresh.stats } }
// 2. 같은 워크스페이스를 동시에 두 번 계산하지 않는다
const pending = inflight.get(workspaceId)
if (pending !== undefined) return { ..., body: { stats: (await pending).stats } }
```

익명 요청이 아무리 몰려도 이 경로가 잡는 커넥션은 **워크스페이스당 5초에 최대 하나**다.

**수정 전 실패 인용.** 28-86 구현(`c3e585a`)에 새 테스트를 돌렸다:

```
× TTL 안의 두 번째 요청은 DB를 아예 치지 않는다 (28-87-03)
AssertionError: TTL 안인데 DB를 쳤습니다 — 풀 max:3을 로그인과 나눠 씁니다: expected [ 'rev' ] to deeply equal []
× 동시 요청이 몰려도 한 번만 계산한다 (28-87-03)
AssertionError: 동시 요청이 각자 DB를 쳤습니다: expected [ 'rev', 'rev', 'rev', 'rev', …(16) ] to deeply equal [ 'rev', 'body' ]
      Tests  2 failed | 11 passed (13)
```

동시 요청 10개가 DB를 **20번** 쳤다. 풀이 셋이라 그것만으로 로그인이 밀린다.

TTL 갱신이 rev 확인을 영원히 미루지 않는다는 것도 따로 고정했다 — 갱신이 확인을 없애면 낡은
값이 굳는다.

## 04 (중) 프로그램에 없는 파일은 **실패**다

**원인.** 28-86의 `violationsIn`은 `getSourceFile`이 `undefined`면 `[]`를 돌려줬다 —
**검사하지 않은 것**과 **위반 없음**이 구별되지 않았다. 이 저장소가 28-78-04에서 이름 붙이고
그 뒤로 세 번 겪은 침묵이 새 가드 안에 하나 더 들어와 있었다.

**수정.** 던진다. 그리고 도달 파일이 전부 프로그램 안에 있는지 테스트가 따로 고정한다:

```ts
const missing = [...customerReachableFiles(), FIXTURE].filter((f) => p.getSourceFile(f) === undefined)
expect(missing, 'tsconfig include 밖의 파일이 고객 경로에 들어왔습니다 — 검사되지 않습니다').toEqual([])
expect(() => violationsIn('src/없는파일.tsx')).toThrow(/타입 프로그램에 없습니다/)
```

정직하게: **오늘 새고 있던 것은 아니다.** `tsconfig`의 `include`가 `src`이고 도달 파일이 전부
`src` 아래라 모두 해석됐다. 잠재를 막은 것이다.

## 05 서버 모드 전환 **준비** — 켜지는 않는다

프로덕션은 28-68 이후 **스무 라운드 동안 로컬 모드**로 배포돼 왔고, 그 사실을 말해 주는 기계가
하나도 없었다. 세 가지를 갖췄다.

### 5-1. 배포 확인이 **모드를 보고한다**

모드를 빌드 시점 리터럴로 박아 서빙 번들에서 읽을 수 있게 했다. 결정은 **한 곳**(`build/authMode.ts`)에서
하고 `vite.config.ts`·`vitest.config.ts`가 같이 쓴다 — 두 곳에 적으면 조용히 어긋난다(28-81-03).

```ts
export const AUTH_MODE_MARK = AUTH_MODE === 'server' ? 'bandut-auth-mode:server' : 'bandut-auth-mode:local'
```

**실측 — 모드마다 정확히 하나만 남는다:**

```
--- local 번들 표식:  bandut-auth-mode:local
--- server 번들 표식: bandut-auth-mode:server
```

`deploy-check`가 이 표식을 읽어 요약에 적고, **로컬이면 경고**를 달고, **표식이 아예 없으면
실패**한다(계측이 조용히 끊기는 것을 막는다).

### 5-2. `npm run preflight:server`

켜기 전에 기계가 확인할 수 있는 것을 먼저 확인한다 — 환경변수 셋, 비밀번호 길이, DB 연결,
세 테이블, 워크스페이스가 `main` 하나인가.

```
✗ ADMIN_PASSWORD 길이 12자 이상       5자
✗ 테이블 snapshots                  psql "$DATABASE_URL" -f db/schema.sql 을 적용하세요
5건이 준비되지 않았습니다 — 켜기 전에 해결하세요.        exit=1
```
```
✓ snapshots 행                    main rev=7 6KB
✓ 워크스페이스가 main 하나                main만 있음
모두 통과. 남은 것은 사람이 할 일입니다                  exit=0
```

### 5-3. `28-87/서버_모드_전환.md`

무엇이 달라지는가 · 갖춰야 하는 것 · **켜는 절차 7단계**(백업 먼저) · 되돌리는 법 ·
**켜기 전에 알아야 하는 위험 6가지**(2FA 없음, 레이트리밋 없음, 풀 max:3, SHA-256 해시,
토큰이 localStorage, 이월 항목이 서버 모드에서 더 자주 드러남).

마지막 절은 결론을 흐리지 않는다: **첫 고객이 생기기 전에는 켜야 한다.** 실제 거래 기록을
브라우저 하나에 두는 것은 그 시점부터 사업 위험이다. 다만 지금 미루는 것도 합리적이다.
