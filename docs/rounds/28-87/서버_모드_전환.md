# 프로덕션을 서버 모드로 켤 것인가 — 결정 문서 (28-87)

**이 문서는 켜지 않는다.** 켜는 데 필요한 것을 갖추고, 무엇이 달라지는지·되돌리는 법·무엇이
위험한지를 적는다. **스위치는 사장님 손에 있다.**

---

## 1. 지금 상태 — 왜 이 문서가 필요한가

`https://bandut-partner-platform.vercel.app` 는 지금 **로컬 모드**로 서빙되고 있다.
`VITE_AUTH_MODE`가 어디에도 설정돼 있지 않아 빌드가 로컬 모드로 나간다.

그래서 **28-68 이후 스무 라운드의 서버 작업이 라이브에서 하나도 실행되지 않는다:**

| 라운드 | 만든 것 | 라이브에서 |
|---|---|---|
| 28-68~69 | 서버 저장 계층 (`snapshots`, rev 낙관적 동시성) | 실행 안 됨 |
| 28-70~71 | 서버 계정·세션 (`auth_state`, `sessions`, 토큰 해시) | 실행 안 됨 |
| 28-72~77 | 두 번째 기기, 덮임 보관함, 신뢰 IP | 실행 안 됨 |
| 28-85~87 | 공개 지표 API, rev 캐시, TTL·단일 비행 | 실행 안 됨 |

로컬 모드에서 데이터는 **브라우저 안에만** 있다. 기기를 바꾸면 없고, 캐시를 지우면 없고,
두 사람이 같은 데이터를 볼 수 없다. 실제 영업에 쓰려면 언젠가는 켜야 한다.

**28-87부터는 이 사실이 매 배포마다 보고된다.** `deploy-check`가 서빙 번들의
`bandut-auth-mode:` 표식을 읽어 모드를 요약에 적고, 로컬이면 경고를 단다. 스무 라운드 동안
아무 기계도 말해 주지 않았던 것이 이제 말해진다.

---

## 2. 켜면 무엇이 달라지는가

| | 로컬 모드 (지금) | 서버 모드 |
|---|---|---|
| 데이터 위치 | 그 브라우저의 localStorage | Postgres `snapshots` 한 행 |
| 계정 | 브라우저 안 `AuthService` | `auth_state` + `sessions` (토큰은 sha256만 저장) |
| 다른 기기 | 아무것도 안 보임 | 로그인하면 같은 데이터 |
| 관리자 비밀번호 | 브라우저에 저장된 것 | `ADMIN_PASSWORD` 환경변수 |
| 가입 | 자유 | `SIGNUP_CODE` 필요 |
| 비로그인 방문자 | 시연 시드 없는 화면 | `/api/public-stats`의 집계 5개 |
| 용량 한계 | 브라우저 할당량(~5MB) | Postgres |

**되돌릴 수 없는 것은 없다** — 아래 5의 절차로 로컬 모드로 되돌아갈 수 있다. 다만
**서버 모드에서 만들어진 데이터는 되돌린 뒤 브라우저에 자동으로 오지 않는다**(백업으로 옮겨야 한다).

---

## 3. 켜기 전에 갖춰야 하는 것

### 3-1. 기계가 확인하는 것 — `npm run preflight:server`

```
DATABASE_URL=... ADMIN_PASSWORD=... SIGNUP_CODE=... npm run preflight:server
```

확인하는 것: 세 환경변수 존재 · `ADMIN_PASSWORD` 12자 이상 · `SIGNUP_CODE` 8자 이상 ·
DB 연결 · `snapshots`/`auth_state`/`sessions` 세 테이블 · 워크스페이스가 `main` 하나인가.
하나라도 어긋나면 **exit 1**이고, 무엇을 해야 하는지 줄마다 적혀 나온다.

### 3-2. 사람이 준비해야 하는 것

1. **Postgres 인스턴스.** Vercel Postgres·Neon·Supabase 무엇이든 된다.
   **`-pooler` 엔드포인트를 쓸 것** — 서버리스 함수가 연결을 자주 열고 닫는다.
2. **스키마 적용**: `psql "$DATABASE_URL" -f db/schema.sql` (멱등하다).
3. **Vercel 환경변수 4개** (Production):
   - `DATABASE_URL` — pooler 연결 문자열
   - `ADMIN_PASSWORD` — 관리자 로그인. **이 값이 곧 전체 데이터의 열쇠다.** 20자 이상 권장
   - `SIGNUP_CODE` — 가입 코드. 아는 사람만 가입한다
   - `VITE_AUTH_MODE=server` — **이것이 스위치다.** 빌드 시점에 읽히므로 설정 후 재배포해야 한다

---

## 4. 켜는 절차 (권장 순서)

기존 데이터를 잃지 않는 것이 목적이다. **순서를 지키면 잃지 않는다.**

1. **지금 브라우저의 데이터를 내려받는다.** 관리자 설정 → 백업 내려받기(전체).
   이것이 유일한 사본이다 — 로컬 모드 데이터는 그 브라우저 밖에 없다.
2. 3-1의 프리플라이트를 통과시킨다.
3. Vercel에 환경변수 4개를 넣고 **재배포**한다.
4. `deploy-check`(또는 Actions에서 수동 실행)가 **`서빙 인증 모드: server`**를 보고하는지 본다.
   로컬로 나오면 `VITE_AUTH_MODE`가 빌드에 안 들어간 것이다 — 3으로 돌아간다.
5. 관리자로 로그인한다(`ADMIN_PASSWORD`). 여기서 실패하면 6으로 가기 전에 멈춘다.
6. **1의 백업을 복원한다.** 이때부터 서버에 데이터가 있다.
7. 다른 기기(휴대폰)에서 로그인해 **같은 데이터가 보이는지** 확인한다. 이것이 켠 이유다.

---

## 5. 되돌리는 법

`VITE_AUTH_MODE`를 지우고 재배포하면 로컬 모드로 돌아간다. 데이터는 DB에 그대로 남는다
(지워지지 않는다). 서버 모드에서 쌓인 데이터를 로컬로 가져오려면 되돌리기 **전에** 4-1과
같은 방법으로 백업을 내려받아 두었다가, 로컬 모드에서 복원한다.

---

## 6. 켜기 전에 알고 있어야 하는 위험 — 숨기지 않는다

- **`ADMIN_PASSWORD` 하나가 전체 데이터다.** 서버 모드에서 관리자 로그인은 모든 고객·파트너
  정보에 닿는다. 계정 잠금(30회)과 신뢰 IP 면제(28-74)는 있지만 **2단계 인증은 없다.**
  SMS OTP는 계속 이월 항목이다.
  28-89부터 이 값은 **소유자 `admin`의 비밀번호**이고, 소유자가 관리자 계정을 더 만들어 등급
  (소유자·매니저·열람)을 나눌 수 있다 — 운영을 맡기면서 파기·복원 권한은 주지 않는 길이다.
  다만 **매니저는 스냅샷을 통째로 쓸 수 있으므로**(서버가 `PUT`에서 의도를 구별하지 못한다)
  "매니저에게는 파기 권한이 없다"는 화면의 약속이지 서버의 보장이 아니다. 신뢰하는 사람에게만 준다.
- **엣지 레이트리밋이 없다.** 28-87이 공개 경로의 DB 부하를 TTL·단일 비행으로 막았지만,
  **요청 수 자체를 막는 장치는 없다.** Vercel의 기본 보호에 기대고 있다.
- **커넥션 풀이 `max: 3`이다.** 트래픽이 늘면 이 값부터 조정해야 한다(`server/db.ts`).
- **비밀번호 해시가 SHA-256이다.** scrypt/argon2가 아니다 — 계속 이월 항목이고,
  DB가 통째로 유출되는 상황에서는 약하다.
- **세션 쿠키가 아니라 토큰이다.** localStorage에 저장되므로 XSS에 취약하다. CSP는 이월 항목이다.
- **`sync()` 재귀 · 백업 복원 중 충돌** 등 이월된 항목들이 서버 모드에서 더 자주 드러난다
  (여러 사람이 동시에 쓰기 때문이다).

**이 목록은 "켜지 마세요"가 아니다.** 실제 영업 규모에서 이 정도 위험을 감수하는 서비스는 많다.
다만 **켠 뒤에 알게 되는 것과 켜기 전에 아는 것은 다르다.** 판단은 사장님이 한다.

---

## 7. 결정을 미루는 것도 결정이다

미루면: 데이터가 계속 그 브라우저 하나에 있다. 그 브라우저를 잃으면 전부 잃는다
(백업을 정기적으로 내려받는 것이 유일한 방어다).

지금 미루기 좋은 이유가 있다면 — 실제 고객이 아직 없다면 — 미뤄도 된다.
**다만 첫 고객이 생기기 전에는 켜야 한다.** 실제 거래 기록을 브라우저 하나에 두는 것은
그 시점부터 사업 위험이다.
