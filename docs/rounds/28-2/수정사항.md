# 28-2 수정사항 — 28-1 감사결과 8개 항목 전부 수정

작업 방식: 기존 원바이원 규칙 그대로 — 28-1은 일절 수정하지 않고, 스크래치 디렉터리(`scratchpad/wf28-2`)에 복사본을 떠서 수정한 뒤 새 라운드 폴더 `28-2`를 생성함 (환경에 rsync가 없어 동일 의미의 `tar --exclude node_modules --exclude dist` 복사 사용).

## 항목별 수정 내용

### 28-1-01 [상] 달력에 없는 날짜가 일정에 저장됨 → 수정
- 원인: `schedule.ts`의 날짜 검증이 정규식뿐이라 2026-02-31, 2026-13-99가 통과.
- 수정: 공용 유틸 `src/domain/date.ts` 신설 (`isValidDateStr` — 형식 + UTC 왕복 비교로 실제 달력 검증). `validateSlot`이 이를 사용.
- 회귀 테스트: `schedule.test.ts` "달력에 없는 날짜를 거부한다", "윤년 2월 29일은 허용, 평년은 거부한다" + `date.test.ts` 6개 (윤년 100/400년 규칙 포함).

### 28-1-02 [상] isoWeekLabel이 잘못된 입력에 'NaN-WNaN' 반환 → 수정
- 수정: `settlement.ts`의 `isoWeekLabel`이 진입 시 `assertValidDateStr`로 검증, 실패 시 `DateFormatError`를 던짐 (조용한 NaN 버킷 제거).
- 회귀 테스트: `settlement.test.ts` "잘못된 입력은 NaN 라벨 대신 DateFormatError".

### 28-1-03 [상] weeklySettlements가 파트너를 구분하지 않고 합산 → 수정
- 수정: 그룹 키를 `partnerId × ISO주차`로 변경, `WeeklySettlement`에 `partnerId` 필드 추가, 정렬은 파트너 → 주차 순. UI 정산 테이블에 파트너 열 추가.
- 회귀 테스트: `settlement.test.ts` "파트너가 다르면 같은 주차라도 분리 집계한다", "파트너 → 주차 순으로 정렬한다".

### 28-1-04 [중] formatDateKo가 존재하지 않는 날짜에 롤오버 요일 표기 → 수정
- 수정: `scripts/format.mjs`가 UTC 왕복 비교로 롤오버를 감지하면 TypeError. 윤년 2024-02-29는 정상 허용.
- 회귀 테스트: `tests/node/format.test.mjs` "달력에 없는 날짜는 롤오버하지 않고 거부".

### 28-1-05 [중] 견적 입력 빈 값이 조용히 0원 처리 → 수정
- 수정: `src/domain/money.ts` 신설 — `parseWonInput`(빈 값/지수/소수/음수 거부, 천 단위 쉼표 허용, 안전 정수 범위 검사)과 `parseHourInput`. EstimateForm이 `Number()` 캐스팅 대신 이를 사용, 오류 메시지 표시. 같은 문제가 있던 일정 탭의 시각 입력에도 `parseHourInput` 적용.
- 회귀 테스트: `money.test.ts` 7개.

### 28-1-06 [중] RequestStore.add가 desiredDate 미검증 → 수정
- 수정: `store.add()`가 `assertValidDateStr(desiredDate)` 수행, 실패 시 `DateFormatError` (저장소 오염 차단).
- 회귀 테스트: `store.test.ts` "달력에 없는 desiredDate를 거부한다".

### 28-1-07 [하] 미존재 요청 오류가 generic Error → 수정
- 수정: `RequestNotFoundError` 클래스 신설, `updateStatus`가 이를 던짐 — `InvalidTransitionError`와 타입으로 구분 가능.
- 회귀 테스트: `store.test.ts` "없는 요청의 상태 변경은 RequestNotFoundError".

### 28-1-08 [하] Schedule UI requestId 하드코딩 + 취약한 id 생성 → 수정
- 수정: 요청 번호 입력 필드 추가(공백 거부), 슬롯 id를 `useRef` 단조 증가 카운터로 생성 (삭제 기능 도입 시에도 중복 없음).
- 회귀 테스트: UI 컴포넌트 자체는 jsdom 환경이 없어 단위 테스트 미작성 — 로직은 도메인 함수(`addSlot`, `parseHourInput`)에 위임되어 있고 그 함수들은 테스트됨. (한계 명시: 컴포넌트 레벨 테스트는 다음 라운드에서 jsdom/testing-library 도입 여부 결정 필요.)
