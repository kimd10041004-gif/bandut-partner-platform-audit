# 28-43 수정사항 (Claude) — 다중 입찰 라운드

기반: `28-42` 복사본(스크래치 wf28-43)에서 작업. 28-42 감사 4건 전부 반영.

## 28-42-01 · 다중 입찰 도메인 [반영]

- 견적 저장을 `bids: Map<requestId, Map<partnerId, StoredEstimate>>`로 교체(`this.estimates` 참조 0건). `submitEstimate`는 requested/estimated에서 파트너별 1건(재제출 교체), 고객 알림에 "입찰 n건". `bidsFor`(합계 오름차순, 동률은 파트너 id순) / `bidOf` / `bidCount`.
- `acceptBid(requestId, partnerId)`: estimated에서만, 견적 없는 파트너 거부, `RepairRequest.acceptedPartnerId` 기록(`store.setAcceptedPartner`), 낙찰 파트너 알림 + 나머지 입찰자 **각자** 미낙찰 알림. 알림에 `accountId` 범위 추가(있으면 그 계정에만). `transitionRequest('accepted')`는 입찰 1건일 때만(여러 건이면 "acceptBid로 지정" 오류), `lost`·`cancelled`는 입찰자 전원에게 알림.
- `primaryBid`(낙찰 견적, 낙찰 전엔 단일 견적 폴백) → `getEstimate`/일정/완료/예약금/타임라인 기준. `statusFor(requestId, partnerId)` — 타 파트너 낙찰 = lost; `bidStats/statusCounts(partnerId)`가 이를 사용(전체 집계는 입찰 단위). 스냅샷 `estimates` 다중 항목 저장·복원(구 1건 호환), `acceptedPartnerId` 검증.
- 도메인 테스트 3건 → vitest 191→**194**.

## 28-42-02 · 고객 견적함 비교·선택 [반영]

- 요청별 받은 견적 전부를 `.bid-card`(업체명·최저가 태그·최저가 대비 차액·공급가/부가세·합계·메시지)로, 카드마다 "이 견적 수락"(`acceptBid`)·"업체 정보 보기"(`PartnerCard partnerId`), 요청 단위 "전체 거절". 홈 목록은 낙찰 전 "견적 n건 도착 — 견적함에서 비교", 낙찰 후 "낙찰 견적 금액".

## 28-42-03 · 파트너 일감·내 작업 [반영]

- 일감 탭: 낙찰 전 요청 전부(타 파트너 견적 건 포함) + "입찰 n건 · 내 입찰 완료 / 아직 입찰 가능", 내 견적 없으면 "이 일감에 입찰", 있으면 "제안 수정". 내 작업 탭: 내 입찰 건 중 결정된 건, `statusFor`로 타 파트너 낙찰 건은 **미낙찰**(종결 필터).
- 추가 발견·반영: 고객이 요청을 취소할 UI가 없었다(도메인은 허용) → 거래 상세에 **요청 취소**(2단계 확인, 시공 시작 전만) 추가 — 다중 입찰 e2e에서 낙찰 후 탈퇴 차단(28-40)을 해제하는 실제 경로.

## 28-42-04 · e2e + 실측 [반영]

- e2e 9단계 추가(76→**85**): 28-42의 "타 파트너 입찰 건 제외" → "노출 + 입찰 1건"으로 교체 / 고객 새 요청 → 파트너1 입찰 → 파트너2 "아직 입찰 가능" → 할인 입찰 → 입찰 2건 → 고객 견적함 2건(최저가 = 파트너2, `data-bid`) → 저가 수락 → 파트너2 낙찰 / 파트너1 미낙찰 알림 + 종결 필터 미낙찰 / 탈퇴 차단 → 요청 취소 → 탈퇴. 첫 실행 선택자 충돌(입찰 폼 카드가 설명 텍스트 포함) → h3 기준으로 정정.
- 실측 3장: 견적함 비교, 일감 입찰 수, 미낙찰 파트너 내 작업.
