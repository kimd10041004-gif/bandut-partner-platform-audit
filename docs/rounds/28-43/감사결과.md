# 28-43 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-43` 전체 — 다중 입찰 반영 후, **입찰의 시간 규칙** 점검.
사전 확인: `npm run check` exit 0 (vitest 194/194), e2e 85/85 PASS, visual-check 전 항목 PASS, `npm audit` 0건, 프로덕션 배포 그린(PR #102 머지). 28-42 감사 4건 전부 수정 확인됨.

핵심 지적: 요청에 `bidDeadline`(입찰 마감일)이 있고 파트너 일감 카드에 D-day까지 표시되지만, **마감은 아무것도 강제하지 않는다.** 마감이 지나도 파트너는 계속 견적을 낼 수 있고(`submitEstimate`는 날짜를 보지 않음), 고객은 마감이 지났다는 사실을 알 수 없으며, 견적이 하나도 안 들어온 요청은 영원히 "입찰 가능"으로 남는다. 또한 마감일은 위저드에서 선택 입력이라 대부분의 요청에 마감이 없다 — "비교 입찰"은 마감이 있어야 성립한다(파트너는 언제까지 내야 하는지, 고객은 언제 비교하면 되는지). 시간 규칙 없는 입찰은 상용에서 운영자가 손으로 정리해야 하는 미결 건을 계속 만든다.

## 상 (High)

### 28-43-01 · 입찰 마감 도메인
→ 요구: **모든 요청에 마감일** — 위저드 미입력 시 기본값 `min(희망일 − 1일, 오늘 + 3일)`(단 오늘 이상), `addRequest`는 마감일이 오늘 이전이거나 희망일 이후면 거부. `submitEstimate`는 마감일 이후 거부("입찰이 마감되었습니다"). `bidClosed(requestId, today)` / `isBidOpen`. `sweepDeadlines(today)` — 부트·요청 등록·화면 진입 시 호출되는 **멱등** 정리: 마감 지난 requested(견적 0건) → 고객 알림 "입찰 마감 — 견적 없음, 마감 연장 또는 취소", 마감 지난 estimated(견적 n건) → 고객 알림 "입찰 마감 — n건 비교 후 선택"; 요청에 `deadlineNotifiedAt` 기록으로 중복 방지. `extendDeadline(requestId, newDate)` — requested/estimated에서만, 오늘 이후, 희망일 이하, 연장 시 알림 플래그 초기화. 스냅샷 검증·왕복 + **도메인 테스트 필수**(시간은 인자로 주입, `todayUTC` 의존 금지).

### 28-43-02 · 파트너 일감: 마감 표시·차단
→ 요구: 마감 지난 요청은 일감 탭에서 "마감" 태그 + 입찰 버튼 비활성(제안 수정도 불가), 기본 정렬은 마감 임박순 옵션 추가. 입찰 폼 후보에서 마감 건 제외.

### 28-43-03 · 고객: 마감 안내·연장
→ 요구: 홈 목록·거래 상세에 "입찰 마감 D-n / 마감됨" 표시. 마감 지난 요청: 견적 0건이면 거래 상세에 **마감 연장**(날짜 입력) + 요청 취소 안내, 견적 있으면 견적함으로 유도 배너. 위저드 2단계에 마감일 기본값 자동 채움 + 안내.

## 중 (Medium)

### 28-43-04 · e2e + 실측
→ 요구: e2e — 도메인 시간 주입으로 마감 지난 요청 시나리오는 vitest에서, UI는 위저드 기본 마감일 표시·일감 D-day·마감 연장 화면을 확인. 실측: 일감 "마감" 카드(시드 중 마감 지난 건: 2026-09-02 마감 박준서 요청은 오늘 기준 D-Day → 다음날 마감), 고객 마감 안내.
