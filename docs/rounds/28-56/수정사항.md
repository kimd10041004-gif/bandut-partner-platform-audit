# 28-56 수정사항 (Claude) — 다중 탭 동기화 라운드

기반: `28-55` 복사본(스크래치 wf28-56)에서 작업. 28-55 감사 4건 전부 반영.

## 28-55-01 · 스냅샷 리비전 + 저장소 동기화 [반영]

- `PlatformSnapshot.rev`(저장마다 +1)·`savedAt`. `save()`는 스냅샷과 함께 `<key>:rev` 키에 리비전을 기록. `applySnapshot`이 `rev`를 복원, `parseSnapshot`이 음수·비정수 거부. `revision` getter, `lastSyncAt`.
- `syncFromStorage()`: 리비전 키만 먼저 읽어(큰 JSON 파싱 회피) 메모리와 다르면 스냅샷을 다시 적용하고 true. 저장소 없음·키 없음·손상이면 false.
- `PlatformProvider`: `storage` 이벤트(`banded-*` 키)·`focus`·`visibilitychange`에서 플랫폼·인증을 동기화하고 화면 갱신, 1회성 `SyncNoticeBanner`("다른 탭의 변경을 반영했습니다", 4초, `[data-sync-notice]`).
- vitest 1건: 한 저장소를 공유하는 두 서비스 — A 저장 → B 동기화 true·데이터 반영·재호출 false, 리비전 단조 증가·별도 키, 손상 rev 거부.

## 28-55-02 · 덮어쓰기 충돌 감지 [반영]

- `save()`가 쓰기 전 저장소 리비전을 읽어 메모리 리비전과 다르면 `conflictCount += 1`·`onConflict` 통지 후 `max(저장소, 메모리) + 1`로 저장(마지막 쓰기 우선 — 사용자의 방금 행동 보존). 저장 실패 시 리비전 원복.
- 앱 셸 배너 "다른 탭의 변경과 겹쳤습니다 — 그 탭이 최신 상태로 갱신됩니다", 관리자 저장 용량 카드에 "리비전 n · 탭 충돌 n회"(`[data-conflicts]`).
- vitest 1건: 같은 리비전에서 A 저장 → B 저장 시 충돌 1·통지 1·리비전 3, A 동기화 true(마지막 쓰기 우선으로 A의 중간 변경 유실 — 화면은 이벤트로 먼저 동기화하므로 실제로는 드묾), 이후 정상 저장은 충돌 0.

## 28-55-03 · 인증 동기화 [반영]

- `AuthSnapshot.rev`, `save()`가 `<key>:rev` 기록, `load()`가 복원. `AuthService.syncFromStorage()`·`revision`. 앱 셸이 플랫폼과 함께 호출 → 다른 탭의 로그인·로그아웃·잠금·세션 만료가 게이트에 반영("다른 탭의 로그인 상태를 반영했습니다").
- auth vitest 1건: A 로그인 → B 동기화 후 세션 있음, A 로그아웃 → B 세션 없음, 재호출 false, rev 키 일치.

## 28-55-04 · e2e + 실측 [반영]

- e2e 3단계 추가(133→**136**): 같은 컨텍스트의 두 번째 탭 — 관리자 탭에서 공지 저장 → 랜딩 탭 공지 배너 즉시 반영 + 안내 배너 / 두 번째 탭 관리자 세션 공유 / 첫 탭 로그아웃 → 두 번째 탭 게이트. (메인 페이지를 `browser.newPage()`에서 명시적 `browser.newContext()`로 바꿔 `page.context().newPage()`가 저장소를 공유하도록 함. 초안은 로그아웃 뒤 이어지는 "세션 만료" 단계의 전제가 깨져 1건 FAIL → 관리자 재로그인으로 복원.)
- 실측 `capture-28-56.mjs`: 탭1 저장 → 탭2 랜딩 공지 즉시 반영 + 안내, 탭2 리비전 키 조작 후 저장 → 충돌 배너·리비전 11→17·카드 "탭 충돌 1회", 탭1에 탭2 저장 반영, 탭1 로그아웃 → 탭2 게이트 + 안내, 모바일 가로 스크롤 없음.
