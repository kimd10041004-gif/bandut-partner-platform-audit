# 28-56 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-56` 전체 — 다중 탭 동기화 반영 후, **방문 일정의 생애주기(변경·휴무·리마인더)** 점검.
사전 확인: `npm run check` exit 0 (vitest 229/229), e2e 136/136 PASS, visual-check 전 항목 PASS, `npm audit` 0건, 프로덕션 배포 그린(PR #154 머지 `31a4914`). 28-55 감사 4건 전부 수정 확인됨.

핵심 지적: 방문 일정은 **한 번 잡으면 바꿀 수 없다**. `scheduleVisit`은 `accepted`에서만 호출되고 `scheduled`에서는 취소(→환불) 아니면 시공 시작뿐이라, 비가 오거나 고객이 출장을 가면 채팅으로 조율한 뒤 **실제 일정은 틀린 채로 남는다**(캘린더·리마인더·정산 보고 모두 오염). 파트너는 **휴무일을 선언할 수 없어** 충돌 검사가 "다른 예약"만 막고 "쉬는 날"은 못 막는다. 그리고 예약 확정 알림 뒤 **방문 전날 아무도 상기시키지 않는다** — 집수리 노쇼의 가장 흔한 원인.

## 상 (High)

### 28-56-01 · 방문 일정 변경
→ 요구: `rescheduleVisit(requestId, { date, startHour, endHour }, by: 'customer'|'partner', today)` — `scheduled`에서만, 지난 날짜·같은 일정·파트너 휴무일 거부, 자기 슬롯을 제외한 충돌 검사(`addSlot` 재사용), 슬롯 교체(id 유지), `RepairRequest.rescheduleCount/rescheduledAt` 기록, **상대방에게** 이전→새 일정 알림(고객이 바꾸면 파트너 계정 범위, 파트너가 바꾸면 고객). 고객 거래 상세(방문 예정) "방문일 변경" 인라인 폼(`[data-reschedule]`, `aria-label` 변경 날짜/시작/종료) + "일정 변경 n회"(`[data-reschedule-count]`), 파트너 일정 탭에서 방문 예정 건 선택 시 "일정 변경". **도메인 테스트 필수**.

### 28-56-02 · 파트너 휴무일
→ 요구: `daysOff: Map<partnerId, YYYY-MM-DD[]>`(스냅샷 `daysOff`, 날짜 검증·중복 제거·정렬). `setDaysOff`·`toggleDayOff`·`daysOffOf`·`isDayOff`. `scheduleVisit`·`rescheduleVisit`가 휴무일 슬롯을 거부. 파트너 일정 탭: 선택 날짜 "휴무 설정/해제"(`[data-dayoff-toggle]`), 캘린더 셀 휴무 표시(`[data-dayoff]`). 테스트.
