## 상 (High)

### 28-14-01 · 셸이 단일 역할 고정 — 역할 아키텍처 부재
App.tsx의 TABS는 파트너 탭 6개뿐이다. 고객·관리자를 담으려면 셸이 역할을 1급 개념으로 다뤄야 한다.
→ 요구: `ROLES` 배열(역할 = 라벨 + 전용 TABS 배열) + 헤더 역할 스위처. "새 역할 추가 = ROLES에 항목 1개 + features 하위 폴더"가 되도록. 역할 선택은 localStorage(`banded-role`) 영속, 역할 전환 시 첫 탭으로 이동, ErrorBoundary 리셋 키는 `역할:탭`.

### 28-14-02 · 고객 앱 부재 — 고객 행위가 파트너 화면 안의 "시뮬레이션"으로 존재
일감 등록 폼에 "(고객 요청 시뮬레이션)", 낙찰/미낙찰 버튼에 "고객 결정 시뮬레이션"이라 적혀 있다 — 실제 고객 동선이 없다는 자백이다.
→ 요구: `features/customer/` — ①홈(내 요청 목록 + 진행 상태), ②수리 요청 등록(파트너 탭의 시뮬레이션 폼 이관), ③견적함(받은 견적 내역 검토 + 수락/거절 결정 이관). **파트너 일감 탭에서 두 시뮬레이션 UI를 제거**하고 "고객 결정 대기" 표시로 대체 — 한 행위는 한 역할의 화면에만 존재해야 한다.

### 28-14-03 · 관리자 앱 부재 — 플랫폼 수익·전체 현황을 보는 눈이 없음
수수료(3%)는 플랫폼의 수익인데 이를 집계·감독하는 화면이 없다.
→ 요구: `features/admin/` — ①플랫폼 현황(전체 요청·진행·완료 지표, 상태 분포, 수수료 수익 확정/예정), ②요청 전체 목록(표), ③정산 감독(월별 수수료 수익 + 주간 정산 전체). 도메인 헬퍼 `adminOverview()`(요청 집계 + 수수료 확정/예정 합계) 신설 — **도메인 레벨 테스트 필수**.
