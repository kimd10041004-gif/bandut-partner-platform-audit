# 28-62 감사결과 (GPT 역할) — 가명본 안전장치·열람권 대칭 라운드

28-62는 단방향 산출물이 원본을 덮지 못하게 막았고(실측: 거부 후 고객 이름 6건 불변),
가명 처리를 "지울 것 열거"에서 "내보낼 것 선택"으로 뒤집었으며, 그 자체 검사가 지급 계좌 예금주라는
다섯 번째 유출을 실제로 잡아냈다. 방향과 실행 모두 옳다.

그런데 **그 원칙을 28-62 스스로 절반만 지켰다.** 4건을 지적한다.

---

## 28-62-01 (상) 허용 목록을 절반만 적용했고, 안전망은 아는 이름만 본다

`exportPseudonymous`가 허용 목록을 거치는 것은 `store.requests`·`reviews`·`claims`·`notifications`·
`auditLog`·`jobs` 여섯뿐이다. 나머지는 **통째로 통과**한다:

```
out.estimates = snap.estimates      out.slots = snap.slots        out.payments = snap.payments
out.refunds = snap.refunds          out.packages = snap.packages  out.questions = snap.questions
out.settings = snap.settings        out.partnerCancels = snap.partnerCancels   out.daysOff = snap.daysOff
```

그 안에 **자유 서술이 셋** 있다 — 타입에서 확인했다.

- `Estimate.memo` — 파트너가 쓴 견적 메모
- `Refund.reason` — 관리자가 쓴 차감 사유
- `PartnerCancel.reason` — 파트너가 쓴 낙찰 철회 사유

사람이 쓰는 칸이면 무엇이든 들어간다. "김○○ 고객님 요청대로", "010-…로 연락", "○○아파트 3동" 같은 것들이다.

더 문제인 것은 안전망이다. `assertNoRealNames`는 **스냅샷에 이름으로 등록된 문자열만** 찾는다.
자유 서술에 든 전화번호·주소·제3자 이름은 목록에 없으니 그대로 통과한다.
28-62가 내건 "이번엔 안 샌다가 아니라 새면 못 나간다"는 실제로는
**"아는 이름이 새면 못 나간다"**였다.

**요구**: 허용 목록을 전 컬렉션에 적용하고 자유 서술 3종을 뺀다. 그리고 안전망을 값 대조에서
**구조 대조**로 올린다 — 결과에 허용 목록 밖 키가 하나라도 있으면 내보내기를 실패시킨다.
그래야 "컬렉션을 통째로 넘기는 실수" 자체가 성립하지 않는다.

## 28-62-02 (상) 낙찰 전 입찰 철회가 아무 흔적도 남기지 않는다

`withdrawBid`는 `bids` 맵에서 입찰을 **삭제만** 한다. 남는 것은 고객 알림 한 줄뿐이다.
낙찰 **후** 철회는 28-51이 `PartnerCancel`로 남겨 신뢰 지표·운영 큐까지 잇는데, 낙찰 **전** 철회는
- 파트너별 집계에 없고, 관리자 화면에 없고,
- 28-62가 방금 만든 파트너 열람권에도 "내가 냈다가 거둔 견적"이 빠진다.

입찰만 넣고 계속 거두는 파트너가 있어도 운영은 알 수 없다.

**요구**: 철회 이력을 남기고(요청·파트너·시각·마감 전 여부), 파트너별로 집계해 관리자 회원 화면에 보이며,
파트너 열람권에도 포함한다. 낙찰 후 철회와 같은 대접이면 된다.

## 28-62-03 (중) 토글 그룹이 선택 상태를 보조기기에 알리지 않는다

`className="filter-group"` 토글이 **8곳**(고객 홈·요청 위저드 2곳·관리자 회원/운영 기록/백업 모드·
파트너 내 작업·정산)인데 선택을 `class='active'`로만 표시한다.
앱 전체에서 `aria-pressed`는 `App.tsx:181`(다크 모드) 하나뿐이다.
스크린리더 사용자는 지금 어떤 필터가 걸려 있는지 알 수 없다. 28-14가 세운 부품화·접근성 기준에서 뒤로 간 자리다.

**요구**: 공용 토글 그룹 부품을 만들어 8곳을 교체한다 — `role="group"`·이름·`aria-pressed`.
모양은 그대로 두고 의미만 채운다.

## 28-62-04 (중) 위 3건의 테스트·e2e·실측이 없다

특히 28-62-01은 **구조로 막혔는지**를 시험해야 한다 — 허용 목록 밖 키를 일부러 섞어 실패하는지.
자유 서술은 실제로 입력한 뒤 원문 대조로 확인한다.

**한 줄 요약**: 28-63은 "허용 목록 완성·입찰 이력·토글 접근성" 라운드다 — 절반만 지킨 원칙을 끝까지 적용하고, 남지 않던 흔적을 남기고, 눈에만 보이던 상태를 귀에도 들리게 한다.
