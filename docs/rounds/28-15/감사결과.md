## 상 (High)

### 28-15-01 · 추가 작업이 고객 승인 없이 확정됨 (시안 4·5의 핵심 흐름 위반)
시안 5의 중심 흐름은 "파트너가 추가 작업 승인 **요청**(내용·사유·금액) → 고객이 **승인/거절**"이다. 현재 `approveExtraWork()`는 파트너 화면에서 즉시 확정한다 — 돈이 걸린 결정이 결정권자 없이 일어난다.
→ 요구: 도메인에 승인 흐름 도입 — `requestExtraWork()`(파트너, in_progress에서 pending 생성) + `decideExtraWork()`(고객, pending → approved/rejected). `completeJob()`은 **pending이 남아 있으면 거부**, 합계는 approved만 포함. 스냅샷 하위 호환(status 없는 기존 데이터 = approved) + 도메인 테스트 필수. 파트너 내 작업 탭은 요청 UI + 상태 표시로 전환.

### 28-15-02 · 고객 거래 상세 부재 (시안 5)
고객 홈은 목록뿐 — 시안 5의 상세(서비스·주소·예약 일시·금액 구성·진행 단계·추가 작업 승인·최종 결제 예정 금액)로 들어갈 수 없다.
→ 요구: 고객 홈 카드 → 거래 상세 화면(뒤로 가기 포함): 견적 분해(공급가/부가세/합계), 방문 일정, 진행 타임라인, **추가 작업 승인 요청 카드(승인하기/거절하기)**, 최종 결제 예정 금액(견적+승인된 추가 작업), 방문 전 안내.

### 28-15-03 · 거래 진행 타임라인 부재 (시안 4·5 공통)
시안 4(관리자 관제)와 5(고객 상세) 모두 거래를 타임라인으로 보여준다. 현재는 상태 칩·스텝퍼뿐이고, 등록일·방문일·완료일이 흩어져 있다.
→ 요구: 도메인 `requestTimeline(requestId)` — 등록→견적 도착→낙찰→방문 예약→시공→추가 작업→작업 완료→정산 완료를 현재 데이터(createdAt·견적·슬롯·잡)에서 파생, 이탈(미낙찰/취소)은 종결 이벤트로. 도메인 테스트 필수. 고객 상세·관리자 거래 상세가 공용 사용.

### 28-15-04 · 관리자 거래 상세 부재 (시안 4)
요청 관리 표는 목록뿐 — 시안 4의 거래 상세(고객·파트너·금액·진행 타임라인·정산 상태)로 못 들어간다.
→ 요구: 요청 관리 행 선택 → 거래 상세(고객/파트너/금액 정보 + 타임라인 + 추가 작업 내역 + 정산 상태), 뒤로 가기.

## 중 (Medium)

### 28-15-05 · 파트너 작업 현황 칩 필터 부재 (시안 2)
시안 2의 작업 현황은 "입찰 중/낙찰/작업 예정/진행 중/완료" 칩 필터로 훑는다. 현재 내 작업 탭은 전체 나열뿐이라 작업이 쌓이면 스캔 불가.
→ 요구: 내 작업 탭 상단 칩 필터(전체/낙찰/작업 예정/진행 중/완료/종결) — 기존 `.filter-group` 부품 재사용.
