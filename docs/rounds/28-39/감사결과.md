사전 확인: `npm run check` exit 0 (vitest 186/186), e2e 62/62 PASS, visual-check 전 항목 PASS, 프로덕션 배포 그린(PR #88 머지). 28-38 감사 4건 전부 수정 확인됨.

핵심 지적: 개인정보처리방침(28-38)에 "회원 탈퇴 시 지체 없이 파기한다"고 써 놓았는데 **탈퇴할 방법이 없다.** 개인정보보호법상 정보주체는 언제든 처리 정지·삭제를 요구할 수 있고(§36·§37), 서비스는 이를 이행할 수단을 갖춰야 한다. 동시에 전자상거래법상 계약·결제 기록은 5년 보관해야 하므로 "삭제"는 **계정 식별 정보의 파기 + 거래 기록의 비식별 보관**으로 설계돼야 한다. 또한 진행 중 거래(방문 예정·시공 중·미결제)나 미지급 정산이 있는 계정이 탈퇴하면 상대방이 피해를 입으므로 도메인이 막아야 한다.

## 상 (High)

### 28-39-01 · 탈퇴·파기 도메인 부재
→ 요구: `AuthService.withdraw(role, password)` — 로그인·비밀번호 확인 필수. 탈퇴 시 **식별 정보 즉시 파기**(이름→"탈퇴 회원", 휴대폰·비밀번호·사업자번호·정산 계좌 제거), `withdrawnAt` 기록, 세션 종료, 같은 휴대폰으로 **재가입 허용**. 탈퇴 계정은 로그인 불가. `purgeAccount(accountId)` — 관리자가 보유 기간 경과 후 기록 자체를 파기(탈퇴 계정만). `PlatformService.openTransactionCount(customerId)`(수락~완료·미결제) / `partnerHasOpenWork()`(진행 중 작업 + 지급 대기) — 있으면 탈퇴 거부("진행 중인 거래가 있어 탈퇴할 수 없습니다"). `anonymizeCustomer(customerId)` — 요청·리뷰의 고객 표시명을 "탈퇴 회원"으로 치환(거래 기록 자체는 보존). 저장소 왕복 + **도메인 테스트 필수**.

### 28-39-02 · 마이페이지 회원 탈퇴
→ 요구: 고객·파트너 마이페이지 하단 "회원 탈퇴" 카드 — 안내(즉시 파기 항목 / 법정 보관 항목·기간), 비밀번호 입력, 확인 체크박스, 탈퇴 버튼. 진행 중 거래·지급 대기가 있으면 도메인 오류 노출. 탈퇴 후 로그인 게이트로 복귀하며 "탈퇴가 완료되었습니다" 안내 1회 표시.

### 28-39-03 · 관리자 회원 탭: 탈퇴 상태·파기
→ 요구: 상태 컬럼에 **탈퇴** 태그 + 탈퇴일, 필터 "탈퇴", 탈퇴 계정 행에 **파기** 버튼(보유 기간 안내) → 기록 삭제. 상단 지표에 탈퇴 수.

## 중 (Medium)

→ 요구: e2e — 고객 탈퇴(비밀번호 오류 → 거부 / 정상 → 게이트 안내) → 관리자 회원 탭 탈퇴 표시 → 파기 → 목록에서 제거 → 같은 번호로 재가입 성공. 마이페이지 탈퇴 카드·관리자 탈퇴 행 스크린샷.
