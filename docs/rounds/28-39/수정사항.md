# 28-39 수정사항 (Claude) — 정산 계좌·지급 라운드

기반: `28-38` 복사본(스크래치 wf28-39)에서 작업. 28-38 감사 4건 전부 반영.

## 28-38-01 · 정산 계좌·지급 도메인 [반영]

- `AuthService.setPayoutAccount({ bank, number, holder })` — 파트너 세션 필수, 은행·예금주 필수, 계좌번호는 숫자만 추출해 10~14자리 검증, `Account.payoutAccount { bank, number, holder, updatedAt }` 저장. `maskAccountNumber()`(앞 3·뒤 3자리만) / `payoutAccountLabel()` 공용 표기. 스냅샷 로드 시 계좌 형식 불량 계정은 초기화.
- `PlatformService.markPayout(requestId, accountLabel)` — 정산 확정(settled) 전 거부("정산 확정 후 지급할 수 있습니다"), 계좌 없음 거부("정산 계좌가 등록되지 않은 파트너입니다"), 중복 지급 거부("이미 지급된 작업입니다 (날짜)"), `CompletedJob.payout { paidAt, amount(총액−수수료), account }` 기록 + 파트너 알림("정산금 지급 완료 — … · 금액 (계좌)"). `pendingPayouts()`(확정&미지급, 완료일순) / `paidPayouts()`(최근 지급순) / `pendingPayoutAmount()` / `jobFor()`. 스냅샷 검증: payout 형식 + **정산 확정 전 지급 기록 거부**.
- 도메인 테스트 2건(auth 계좌 형식·마스킹·왕복·손상 / platform 지급 규칙·알림·집계·왕복·손상) → vitest 184→**186**.

## 28-38-02 · 파트너 정산 탭: 계좌 등록 + 지급 상태 [반영]

- 상단 **정산 계좌** 카드: 미등록 시 배너(`[data-payout-banner]`) + 등록 폼(은행 select 12종·계좌번호·예금주), 등록 후 마스킹 표기(`[data-payout-account]`)·최종 수정일·"계좌 수정".
- **작업별 지급 상태** 표(완료일 내림차순): 정산(확정/미정산) · 지급(지급 완료·지급일 / 지급 대기 / —).

## 28-38-03 · 관리자 정산 감독: 지급 처리 [반영]

- 상단 지표(지급 대기 금액·지급 완료 건수), **지급 대기** 표(요청·파트너명·완료일·지급액·계좌 마스킹 또는 "계좌 미등록" 태그·"지급 완료" 버튼) — 오류는 카드 안에 노출. **지급 완료** 표(지급일·금액·계좌). 파트너 계좌는 파트너 계정(auth)에서 조회해 도메인에 표기 문자열로 전달(단일 파트너 시연 구조, 다중 파트너 전환 시 job.partnerId↔계정 매핑으로 확장).

## 28-38-04 · e2e + 실측 [반영]

- e2e 7단계 추가(55→**62**): 관리자 지급 대기 1건(계좌 미등록 표시) / 계좌 미등록 지급 거부 / 파트너 정산 탭 배너+지급 대기 / 계좌 저장+마스킹 / 관리자 지급 완료→완료 목록 / 파트너 작업별 지급 완료 / 파트너 알림. 전 여정 무회귀.
- 실측 4장: 관리자 지급 거부(계좌 미등록), 파트너 계좌 배너·폼, 관리자 지급 완료, 파트너 지급 완료 행.
