# 29-32 — 공개한 커버가 손님에게 실제로 내려온다

## 1. 왜 이 라운드인가

29-31 을 병합한 직후, 감사 자료를 만들려고 제 코드를 다시 읽다가 **제가 낸 버그**를 찾았습니다.
업체가 공개한 커버·로고가 **손님에게 403** 으로 막혀 있었습니다.

```
AssertionError: 비로그인 손님이 커버를 못 본다: {"error":"이 사진을 볼 수 없습니다."}
expected 403 to be 200
```

## 2. 원인 — 공개 경로가 둘인데 하나만 봤다

`lib/media.ts` 의 `openPortfolioPhoto()` 는 사진을 공개로 칠 조건을 **하나만** 알고 있었습니다.

> 게시된 작업사례(`portfolio_cases.asset_id`)에 붙어 있는가

그런데 커버와 로고는 **작업사례가 아닙니다.** 공개본 설정
(`company_pages.published_config` 의 `coverAssetId`·`logoAssetId`)에 걸립니다.
29-31 이 그 두 번째 경로를 만들어 놓고 공개 판정에는 넣지 않았습니다.

결과: 커버·로고는 **그 업체 본인과 관리자에게만** 200. 손님은 로그인해도 403.
손님 화면 맨 위 배너가 깨진 이미지가 됩니다. 대표 시공 사례 사진은 게시된 사례에 붙어 있어 정상이었고,
강조 색·영역 순서·상담·Q&A 도 정상이었습니다.

**보안 등급은 낮습니다 — 과다 차단입니다.** 남의 사진이 새는 방향이 아니라 내 사진이 안 나오는 방향입니다.

## 3. 왜 게이트가 못 잡았나 (이쪽이 더 중요하다)

`e2e:roles` 의 단언이 약했습니다.

```js
await C.locator('[data-company-cover]').waitFor({ state: 'visible' })
```

Playwright 의 `visible` 은 **DOM 에 있고 박스 크기가 0 이 아니면** 통과합니다.
CSS 가 `.company-cover { height: clamp(150px,26vw,300px) }` 로 높이를 주기 때문에,
이미지 요청이 403 으로 깨져도 요소는 "보이는" 상태입니다. **그림이 떴는지는 잰 적이 없습니다.**

HTTP 테스트도 공개본 **JSON** 만 확인하고 사진 **바이트**는 받아 보지 않았습니다.

29-31 문서에 "저장되는 것과 보이는 것은 다르다" 고 써 놓고 한 층 아래에서 같은 실수를 했습니다.

## 4. 고친 것

| 파일 | 변경 |
|---|---|
| `lib/media.ts` | `shownOnPage()` 순수 함수 신설 + `openPortfolioPhoto()` 가 **두 번째 공개 경로**를 본다. 사례 조회가 비면, 로그인을 요구하기 **전에** 그 사진 주인의 공개본 설정을 읽어 커버·로고로 걸려 있는지 확인한다. 조건은 사례와 같다 — 승인된(`APPROVED`), 정지되지 않은 업체의 **공개된** 설정 |
| `lib/media.test.ts` (신규) | `shownOnPage` 6건. **여는 조건과 닫는 조건 양쪽**을 잰다 |
| `tests/companyPage.http.test.ts` | 공개본에 걸린 커버를 **비로그인**과 **로그인한 손님** 둘 다 200 으로 받는지 |
| `scripts/e2e-roles.mjs` | `visible` 뒤에 `naturalWidth > 0` 을 더한다. 브라우저가 그림을 실제로 받았는지는 그것만이 말한다 |

### 왜 JSON SQL 함수를 안 썼나

`published_config` 는 `text` 컬럼입니다. 포트가 Postgres 와 SQLite 양쪽이라
한쪽에만 있는 JSON 함수를 쓰면 다른 쪽에서 죽습니다. 그래서 설정은 **코드에서 파싱**합니다.
파싱에 실패하면 `false` — 못 읽는 설정 때문에 남의 사진이 열리는 일은 없습니다.

## 5. 하지 않은 것

- **다른 봇의 약한 단언 전수조사.** 같은 모양(`visible` 로 이미지 로드를 갈음, JSON 만 보고 바이트 안 받음)이
  다른 자리에도 있을 수 있습니다. 이번 라운드는 찾은 한 곳만 고쳤습니다. 전수조사는 GPT 감사에 맡깁니다.
- 커버 자르기·크기 맞추기, v17 탭 안의 순서 — 29-31 §5 그대로 이월.
