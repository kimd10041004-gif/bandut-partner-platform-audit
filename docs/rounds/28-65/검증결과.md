## 기존 테스트가 잡아낸 내 과잉 교정 (그대로 기록)

처음엔 `detail`을 무조건 병합 키에 넣었다. 그러자 **기존 e2e가 제품 동작으로 반박했다**:
```
FAIL  로그인 실패 4회가 한 줄 ×4로 접힘
FAIL  접힌 기록에 첫 시각~마지막 시각 표기
E2E-JOURNEY FAIL: 3건
```
`로그인 실패`의 `남은 시도 N회`는 내용이 아니라 **진행 표시**라 접히는 게 맞다.
규칙을 `PROGRESS_DETAIL_AUDIT_ACTIONS`로 좁혀(기본은 "접지 않음", 명시된 행위만 접기) 둘 다 만족시켰다.

또 축출 순서를 `[system 비보안] → [관리자] → [보안]`으로 뒤집었더니 **반대 사고**가 생겼다 —
대상을 매번 바꾸는 분산 무차별 로그인이 관리자 기록을 밀어낸다. 그래서 순수 우선순위를 버리고
**등급별 예약분**(`AUDIT_RESERVE = 200`)으로 바꿨고, 양방향을 각각 테스트로 고정했다:
```
PASS  분산 무차별 로그인(보안 폭주)이 관리자 기록을 밀어내지 못한다
PASS  평범한 관리자 작업 폭주가 로그인 잠금 이력을 지우지 못하다
```
(기존 테스트 2건도 새 규약에 맞춰 갱신했다 — `assertNoRealNames` 메시지가 '실제 식별자'로 넓어진 것,
그리고 `settings` 같은 객체를 "건너뛴다"고 **옛 결함을 박제하고 있던** 단언.)

## CI 실전 기록 — 새 게이트가 실제로 러너에서 돈 결과 (PR #191)

`gates.yml`은 만들자마자 네 번 실패했다. 전부 워크플로 자신의 결함이었고, 그 하나하나가
"이 저장소의 게이트가 지금까지 한 번도 남의 기계에서 돌아본 적이 없다"는 증거다. 순서대로 남긴다.

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | `[e2e] playwright-core를 찾을 수 없습니다` | `playwright-core`가 devDependencies에 없다 — 28-64 감사 P1-7이 지적한 그대로 | `npm i --no-save playwright@1.49.1` 단계 추가 |
| 2 | Playwright 설치가 18분 넘게 정지, job 예산 소진 | `playwright install --with-deps`의 apt 단계 | `--with-deps` 제거(ubuntu-latest에 이미 있음) + 단계별 `timeout-minutes` |
| 3 | `npm ci`가 4분 49초 걸림(로컬 13초) | npm 기본 `fetch-timeout`이 **300000ms(5분)** — 응답 없는 소켓 하나가 5분을 통째로 잡는다 | `--fetch-timeout=60000 --fetch-retries=4 --prefer-offline --no-audit --no-fund` + 1회 재시도 |
| 4 | `[e2e] Error: 프리뷰 서버 기동 실패` (15초 데드라인) | `vite preview`의 기본 host는 `localhost` — IPv6가 켜진 러너에서 `::1`로 먼저 풀리면 스크립트의 `127.0.0.1` fetch와 어긋난다 | `--host 127.0.0.1` 명시 + 데드라인 30초 + **vite 출력 캡처** |

3번은 앞선 커밋 메시지에 "npm 레지스트리 503 장애"라고 적었는데 **그건 틀렸다.** 확인한 사실은:
레지스트리는 3회 조회 모두 HTTP 200이었고, 동일 락파일로 로컬 `npm ci`는 5초에 끝났다.
러너 쪽 연결이 멈춘 것이고, npm의 5분 기본 타임아웃이 그 멈춤을 그대로 5분으로 옮겨 적은 것이다.

4번의 원인 판정은 **추정이 섞여 있다.** IPv6 해석 순서를 러너에서 직접 확인하지는 못했다.
그래서 원인 하나를 찍어 고치는 대신 (a) 바인딩 주소를 명시해 변수를 없애고,
(b) `stdio: 'ignore'`를 캡처로 바꿔 **다음에 또 실패하면 vite가 뭐라고 했는지 로그에 남게** 했다.
지금까지는 "기동 실패" 한 줄뿐이라 원인을 볼 방법 자체가 없었다.
