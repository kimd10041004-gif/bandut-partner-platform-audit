# 28-28 수정사항 (Claude) — 거래 채팅 라운드 (사용자 지시: "당근처럼 간단 채팅")

기반: `28-27` 복사본(스크래치 wf28-28)에서 작업. 28-27 감사 5건 전부 반영.
당근의 핵심 UX(거래마다 대화가 붙는다)를 이식: 고객↔파트너가 거래 안에서 직접 조율한다.

## 28-27-01 · 채팅 도메인 [반영]

- `types.ts`: `ChatSender('customer'|'partner')`, `ChatMessage { id, requestId, sender, text, sentAt(ISO) }`.
- `platform.ts`:
  - `sendMessage(requestId, sender, text)` — 공백 거부(트리밍 저장), 없는 요청 `RequestNotFoundError`, **requested 거부**("견적이 도착한 뒤 채팅할 수 있습니다"), lost/cancelled 거부("종료된 거래"). ID `MSG-####`.
  - `chatFor(requestId)` — 보낸 순서 유지.
  - `unreadCount(requestId, viewer)` / `markRead(requestId, viewer)` — **읽음 워터마크**("requestId:viewer" → 읽은 시점 메시지 수) 방식: 워터마크 이후 도착한 상대 메시지만 카운트, 자기 메시지는 제외.
  - 스냅샷 `chats?`+`chatSeq?`+`chatReads?` 하위 호환(없으면 빈 대화) + 요소 검증(발신자·공백 텍스트·워터마크 음수 거부).
- 도메인 테스트 3건 추가 → vitest 160→**163**.

## 28-27-02 · 고객 채팅 UI [반영]

- 공용 컴포넌트 `src/ui/ChatBox.tsx` — 당근 문법 말풍선: 내 메시지 우측 `--brand` 배경, 상대 좌측 플랫(배경+헤어라인 보더), 꼬리쪽 라운드 축소(14px→4px), 시각(HH:MM), 스크롤 영역(max 260px)·자동 하단 스크롤, 입력창+전송(Enter 지원), **열람 시 markRead**.
- 고객 거래 상세에 "파트너와 채팅" 카드 — requested 상태면 "견적이 도착하면 채팅이 열립니다" 안내, lost/cancelled면 미표시.
- 채팅 입력은 기존 `.form input` 스타일 셀렉터에 `.chat-input input` 추가로 동일 톤.

## 28-27-03 · 파트너 채팅 UI [반영]

- 내 작업 카드에 "채팅 열기/접기" 버튼 + **안 읽은 수 뱃지**(`.chat-unread`, 브랜드 필) — 목록에서 바로 보임. 펼치면 동일 ChatBox(viewer='partner'), 한 번에 한 카드만.

## 28-27-04 · e2e [반영]

- 4단계 추가(27→**31**): 고객 채팅 전송(말풍선) → 파트너 안 읽은 채팅 뱃지 → 파트너가 고객 메시지 수신(+답장) → 고객이 파트너 답장 확인. 기존 27단계 무회귀.
