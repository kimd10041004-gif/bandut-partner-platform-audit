## 2. 그 실행이 배포 확인의 결함을 드러냈다

보고된 판정과 실제 응답이 어긋났다.

```
서버 환경변수 준비: no — DATABASE_URL 없음 (HTTP 503)
{"ok":false,"error":"문자 발송이 아직 연결되지 않아 가입과 비밀번호 찾기를 받을 수 없습니다."}
```

분류가 `'아직 연결되지'` 를 찾는데 그 조각이 두 문구에 다 있다. 고유한 부분으로 가르도록 고쳤고,
인증번호 전달 불가를 따로 된 한 줄로 뒀다.

**핸들러의 가드 순서가 증거다.** 4번에서 걸렸다는 것은 1·2·3 을 전부 지났다는 뜻이다 —
`DATABASE_URL`·`ADMIN_PASSWORD`·`SIGNUP_CODE` 가 프리뷰에 제대로 설정돼 있다. 이것은 추론이
아니라 코드가 강제하는 순서다(`server/handlers/auth.ts` 159-178줄).

판번호만 올리고 라운드 문서를 안 썼다. 빈 디렉터리는 git 이 추적하지 않는다. 게이트가 제 일을
했다 — 28-64 가 넣은 줄이 정확히 이것을 막는다. 이 문서가 그 수정이다(29-19-2).

## 6. 브라우저 검사를 프리뷰에서 실제로 돌렸다

실행 34584354292, 러너에서. **23 통과 / 1 실패.**

```
✓ / · /companies · /consult · /password/reset · /services · /notices · /request 가 열린다
✓ 일곱 장 모두 아이콘이 글줄을 밀어내지 않는다 (1280px)
✓ / · /companies · /request (390px) 도 같다
✓ 공개 로그인 화면에 관리자 선택지가 없다
✓ 관리자 로그인 화면은 따로 열린다
✓ 가입 화면에 가입 코드 칸이 있다
✓ 틀린 가입 코드는 거절한다
✓ 진단 화면은 로그인 없이 내용을 내주지 않는다
✓ 화면 오류가 없다
✗ 깨진 자산이 없다 — 401 /api/me | 401 /api/consultations | 503 /api/auth
```

**그 하나는 앱이 아니라 내 검사가 틀린 것이다.** 셋 다 옳은 응답이다 — 로그인하지 않았으니 401,
인증번호를 전달할 방법이 없으니 503(§2 에서 확인한 그것이다). 앱이 제대로 거절하는 것을
"깨졌다"고 부르면 고칠 것이 없는데 빨간불이 선다. `/api/` 경로를 세지 않도록 고쳤다(29-19-2).

그리고 고친 분류가 제대로 답했다.

```
ENV_DETAIL: 세 값(DATABASE_URL·ADMIN_PASSWORD·SIGNUP_CODE)은 설정됨
            — 인증번호를 전달할 방법이 없어 가입만 막혀 있다
```

## 7. 환경변수는 저장만으로 들어가지 않는다 (29-19-3)

사장님이 Preview 환경에 `AUTH_DEV_OTP=on` 을 넣으신 **직후** 같은 확인을 돌렸다. 그대로였다.

```
서버 환경변수 준비: no — 세 값은 설정됨 — 인증번호를 전달할 방법이 없어 가입만 막혀 있다
{"ok":false,"error":"문자 발송이 아직 연결되지 않아 …"}
```

Vercel 환경변수는 **배포 시점에 주입된다.** 지금 서 있는 배포는 그 값이 없던 때 만들어진 것이라
저장만으로는 바뀌지 않는다. 새 배포가 서야 들어간다.

저장했는데 안 되는 것과 저장이 안 된 것은 다르다. 여기서 "잘못 넣으셨다"고 단정하지 않는다 —
재배포 뒤에 같은 확인을 한 번 더 돌려서, 그때도 같으면 그때 값을 다시 본다.
