# 28-4 수정사항 — 28-3 감사결과 6개 항목 전부 처리

작업 방식: 기존 규칙 그대로 — 28-1~28-3은 일절 수정하지 않고 스크래치 복사본(`scratchpad/wf28-4`)에서 수정 후 `28-4` 스냅샷 생성.

## 항목별 수정 내용

### 28-3-01 [상] 영속화 부재 → 수정 (핵심 구현 1)
- `PlatformService`에 저장 계층 도입: `StorageLike` 인터페이스 주입식 설계 (localStorage 호환).
  - 모든 변경 메서드(addRequest/submitEstimate/scheduleVisit/transitionRequest/completeJob/settle)가 성공 시 자동 저장 (`snapshot()` 직렬화, version 필드 포함).
  - `PlatformService.load()`: 저장 데이터 복원. 손상 JSON·알 수 없는 버전은 폐기 후 새로 시작(손상 키 제거), 저장소 접근 불가 환경은 조용히 건너뜀.
  - `RequestStore`에 `snapshot()`/`restore()` 추가 — ID 순번(seq)까지 복원되어 신규 ID 충돌 없음.
- UI: `browserStorage()` probe(try/catch)로 실동작 확인 후 연결. 최초 실행(복원 없음)에만 시드 주입.
- 회귀 테스트: round-trip 복원(상태/견적/작업/슬롯/정산 구분), ID 연속성, 복원 후 충돌 검사 유지, 손상 데이터 폐기, 버전 불일치, 저장소 없음 — 7개.

### 28-3-02 [상] 일정 탭 플랫폼 단절 → 수정 (핵심 구현 2)
- `scheduleVisit(requestId, {date,startHour,endHour})` 신설: accepted 상태의 실제 요청만 예약 가능, 슬롯 검증·충돌 검사(실패 시 아무 상태도 변하지 않음) 후 scheduled 전이까지 원자적 수행. 슬롯 id는 서비스 내부 단조 카운터.
- `transitionRequest`가 scheduled 직접 전이를 차단 (estimated와 동일 패턴). 요청 탭은 '일정 탭에서 예약' 안내.
- 일정 탭 UI: 자유 입력 대신 accepted 요청 드롭다운, 슬롯 목록은 `platform.scheduleSlots`(영속화 대상), 날짜 필터 유지.
- 회귀 테스트: 예약 성공/상태 제한/충돌 시 무변경/잘못된 날짜·시간/미존재 요청 — 5개.

### 28-3-03 [중] 정산 확정 미구분 → 수정
- `CompletedJob.settled` 필드 추가. `settle()`이 요청 전이와 함께 job에 정산 표시.
- `settlements(filter)` — 'all' | 'settled' | 'unsettled' 필터, `unsettledPayout()` 합계 제공.
- 정산 탭: 미정산 지급 예정 합계 + 전체/미정산/정산 완료 필터 버튼.
- 회귀 테스트: 정산 표시, 필터 분리 집계, 미정산 합계 — 3개.

### 28-3-04 [중] EstimateForm 선택값 고정 → 수정
- 선택값을 렌더마다 후보 목록과 대조해 목록에 없으면 첫 후보로 되돌리는 파생값 방식으로 변경. 일정 탭 요청 선택도 동일 패턴 적용.

### 28-3-05 [중] 신규 요청 등록 UI 부재 → 수정
- 요청 목록 탭 상단에 접이식 등록 폼(고객명/지역/카테고리/설명/희망일) 추가 — `platform.addRequest` 경유(검증 + 자동 저장). 필수 입력 미기재/잘못된 날짜는 오류 표시.

### 28-3-06 [하] 취소 요청의 견적 표시 → 수정 (결정 명시)
- 결정: 견적 데이터는 이력으로 **보존**하되, 취소된 요청 카드에는 견적액을 표시하지 않는다.
