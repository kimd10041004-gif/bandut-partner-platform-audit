## 상 (High)

### 28-4-01 · 취소된 요청의 일정 슬롯이 해제되지 않아 시간대가 영구 차단됨
`transitionRequest(id, 'cancelled')`가 요청 상태만 바꾸고 해당 요청의 슬롯을 남겨둔다. 취소된 방문의 시간대는 어떤 요청도 다시 예약할 수 없고, 영속화 때문에 새로고침해도 차단이 유지된다.

재현 (스크래치 복사본에서 vitest로 확인):
```
scheduled 상태 요청 취소 → scheduleSlots 1개 잔존
다른 accepted 요청이 같은 시간대 예약 시도 → ScheduleError (충돌)
Tests  1 passed (1)   ← 버그 동작을 단언하는 재현 테스트 통과
```
→ 요구: cancelled 전이 성공 시 그 요청의 슬롯을 해제(제거)할 것. 전이 실패 시에는 아무것도 제거되지 않아야 한다.

## 중 (Medium — 제품 완성도)

### 28-4-02 · 대시보드 부재 — 앱을 열어도 "오늘 할 일"이 보이지 않음
첫 화면이 전체 요청 목록이라 파트너가 매일 가장 먼저 확인할 정보(오늘 방문 일정, 상태별 진행 현황, 미정산 지급 예정액)가 흩어져 있다.
→ 요구: 대시보드 탭 신설(기본 탭) — 오늘/다가오는 일정, 상태별 요청 수, 미정산 합계. 집계 로직은 UI가 아니라 PlatformService 헬퍼로 두고 테스트할 것.

### 28-4-03 · 데이터가 한 브라우저에 갇혀 있음 — 백업/이전 수단 없음
localStorage 영속화(28-3-01)로 새로고침은 견디지만, 브라우저 데이터 삭제·기기 변경이면 전부 유실된다. 내보내기/가져오기가 없어 사용자가 스스로를 지킬 방법이 없다.
→ 요구: 스냅샷 JSON 내보내기(파일 다운로드)와 가져오기(파일 업로드 → 검증 → 교체) 제공. 가져오기는 손상/버전 불일치 데이터를 명확한 오류로 거부하고 기존 데이터를 보존할 것.

## 하 (Low)

### 28-4-04 · 신규 요청 폼이 과거 희망일을 허용
도메인은 시드 이력(과거 완료) 때문에 과거 날짜를 허용해야 하지만, 신규 등록 UI에서 과거 희망일은 입력 실수다. UI 레벨에서 거부할 것.

### 28-4-05 · 일정 표가 요청 번호만 보여줌
슬롯 행에 REQ-#### 만 있어 누구의 어떤 공사인지 표에서 알 수 없다. 고객명·카테고리를 함께 표시할 것.
