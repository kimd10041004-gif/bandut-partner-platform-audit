# 28-49 수정사항 (Claude) — 요청 사진 라운드

기반: `28-48` 복사본(스크래치 wf28-49)에서 작업. 28-48 감사 4건 전부 반영.

## 28-48-01 · 사진 도메인 [반영]

- `types.ts`: `RequestPhoto { id, dataUrl, width, height, bytes }`, `RepairRequest.photos?: RequestPhoto[]`.
- `platform.ts`: `MAX_PHOTOS = 3`, `MAX_PHOTO_BYTES = 200KB`, `validatePhotos()` — 장수 상한·id 중복·`data:image/(jpeg|png);base64,…` 형식·바이트 상한·정수 크기 검증. `addRequest` 입력과 `load` 스냅샷 모두 검증(손상 스냅샷 거부). `addPhoto`/`removePhoto`는 `requested`/`estimated`(낙찰 전)만 허용. `store.ts` `setPhotos`(빈 배열이면 키 제거). 탈퇴·익명화 시 사진은 요청 기록과 함께 유지(파기 대상 아님 — 기존 정책과 동일).
- vitest 1건 추가(205→**206**): 4장 거부·200KB 초과 거부·MIME/형식 거부·낙찰 전 추가·삭제·낙찰 후 거부·스냅샷 왕복·손상 거부. (초안은 `import type` 목록 정규식 삽입 오류(`Refund,,`)로 tsc 실패 → 정정.)

## 28-48-02 · 위저드 사진 첨부(클라이언트 리사이즈) [반영]

- `ui/image.ts` `resizeImageFile(file, maxEdge=960)`: canvas 리사이즈 후 JPEG 품질 0.8 → 0.65 → 0.5 → 0.35 순으로 200KB 이하가 될 때까지 재시도, 초과면 오류(안내 문구).
- 위저드 1단계 "현장 사진 (선택, 최대 3장 — 자동으로 줄여 저장됩니다)" 파일 입력(`aria-label="현장 사진"`, 다중) → 썸네일 미리보기·삭제, 3장 초과분은 "사진은 최대 3장까지 첨부됩니다" 안내. 4단계 확인 화면에 썸네일. `addRequest`에는 사진이 있을 때만 `photos` 전달.

## 28-48-03 · 열람 화면 [반영]

- `ui/PhotoStrip.tsx` 공용 컴포넌트(`.photo-strip`/`.photo-thumb`, 클릭 시 인라인 확대 `.photo-big`, 선택적 삭제 `.photo-remove`). 파트너 일감 카드(Jobs)·내 작업 카드(Work)·고객 거래 상세(CustomerHome RequestDetail)·관리자 요청 상세(AdminRequests)에 적용. 스타일 `components.css` 추가.

## 28-48-04 · e2e + 실측 [반영]

- e2e 3단계 추가(104→**107**): 위저드에 생성 PNG 2장 `setInputFiles` → 썸네일 2 / 파트너 일감 카드 썸네일 2 / 고객 거래 상세 썸네일 2. (초안은 PNG 생성 헬퍼의 `import`가 함수 본문 중간에 삽입돼 SyntaxError → 파일 상단으로 이동.)
