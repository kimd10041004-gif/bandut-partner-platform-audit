# 29-16 수정사항 — 거래 전 상담방

명세 7절(1:1 메신저)을 구현한다. 사장님이 정하신 네 항목(찾기 → 편집기 → Q&A → 상담방) 중 마지막이다.

## 1. 기존 거래 메시지는 그대로 둔다

`messages`는 주문에 매여 있다(`order_id`가 NOT NULL). 여기는 **주문이 없는 대화**다 — 아직
요청하지 않은 손님이 업체에 먼저 물어보는 자리다. 표를 따로 둔다.

```
consultations           고객 × 업체 한 쌍당 한 행 (유일 색인)
consultation_messages   방의 메시지. id 에 유일 색인 — 중복 방지의 근거
consultation_reads      누가 어디까지 읽었는지
```

기존 거래 채팅 코드는 한 줄도 바꾸지 않았다.

## 2. 방은 한 쌍에 하나뿐이다

같은 고객·같은 업체로 다시 열어도 새 방을 만들지 않는다. 유일 색인이 데이터 쪽에서 그것을 보장하고,
`openConsultation`이 이미 있는 방을 돌려준다.

다른 사례를 보다가 문의하면 **그 사례를 이 방에 매어 둔다.** 방을 새로 만들지 않는다 — 명세 7절의
"다른 사례에서 문의하면 기존 방에 사례 링크를 추가한다".

## 3. 다시 눌러도 한 번만 남는다

보내기가 실패한 것처럼 보여 다시 누르는 일은 흔하다. 그때 같은 글이 두 번 남으면 대화가 더러워진다.

화면이 메시지 ID를 만들어 함께 보내고, 서버가 같은 ID를 두 번째로 받으면 **조용히 넘긴다**
(`duplicate: true`). 실패했을 때 화면은 그 ID를 **비우지 않는다** — 다시 눌러도 같은 ID로 가야
중복이 안 생긴다.

## 4. 참여자만 들어온다

방을 읽는 것도 쓰는 것도 고객 본인이거나 그 업체여야 한다. 남의 고객은 403이다.

**관리자도 기본으로 열람하지 않는다.** 명세 8절의 "관리자라는 이유만으로 모든 비공개 대화를 기본
열람하도록 만들지 않는다"다. 신고 조사에 필요한 접근은 목적과 범위를 정해 따로 만든다.

승인이 풀린 업체는 더 말할 수 없다. 읽는 것은 되지만 보내기에서 막힌다.

## 5. 안 읽은 수

`consultation_reads`에 마지막으로 읽은 자리를 남기고, 목록에서 그 뒤에 온 **남의 글**만 센다.
자기가 쓴 글은 세지 않는다.

## 6. 이 대화는 계약이 아니다

방 아래에 그대로 쓴다.

> 여기서 나눈 이야기는 정식 견적이나 계약이 아닙니다. 금액 확정은 작업 요청 뒤 견적에서 합니다.

명세 7절의 "상담 내용을 정식 견적·계약·추가 작업 승인으로 자동 처리하지 않는다"다.

## 하지 않은 것

- **사진 첨부** — 사진 저장소가 아직 연결되지 않았다(`/api/photos`가 503). 표에 자리를 만들지도
  않았다. 저장소가 붙는 라운드에서 함께 본다.
- **전송 중·실패 상태 표시** — 지금은 실패하면 오류 문구를 띄운다. 말풍선마다 상태를 다는 것은
  실제로 써 보고 필요한지 정한다.
- **알림** — Q&A와 같은 이유다. `notifications.order_id`가 NOT NULL이라 주문 없는 알림이 들어가지
  않는다.
- **차단·신고** — 명세 7절에 있다. 관리자 조사 접근 정책과 함께 잡아야 해서 따로 둔다.
