# 29-16-1 — 아이콘이 글줄을 밀어냈다

29-16 을 밀고 나서 사장님이 프리뷰를 직접 열어 보셨다. `/companies` 아래쪽에서 **돋보기 아이콘이
혼자 한 줄을 차지하고** 문장을 아래로 밀어내고 있었다.

## 1. 왜 검사가 못 잡았나

`e2e:next` 는 서버가 내려 준 **HTML 문자열**을 본다. 문자열은 처음부터 맞았다. 200 이었고,
아이콘도 문장도 전부 그 안에 있었다. 틀린 것은 **그려진 자리**뿐이었다.

원인은 Tailwind preflight 다.

```css
img, svg, video, canvas, audio, iframe, embed, object { display: block }
```

그래서 문단 안에 그냥 놓인 아이콘은 인라인이 아니라 블록이 된다. 단추(`.btn`)와 링크
(`.inline-link`)는 `inline-flex` 라 멀쩡했고 — 그 자리 아이콘이 대부분이라 — 이 부류만 조용히
어긋나 있었다.

두 자리였다.

| 파일 | 자리 |
|---|---|
| `components/marketplace/companies.tsx` | 목록 아래 "원하는 업체를 찾지 못하셨다면…" 안내 |
| `components/marketplace/questions.tsx` | 질문 카드의 "누가 · 언제" 줄 |

## 2. 고친 방법

`app/globals.css` 에 한 줄짜리 규칙을 두고 두 자리에 붙였다.

```css
.icon-line{display:flex;align-items:flex-start;gap:7px}
.icon-line>svg{flex:none;margin-top:3px}
```

글자는 `<span>` 하나로 묶는다. 안 묶으면 문단 안의 링크가 **별개의 플렉스 항목**이 되어 또 떨어진다.
`align-items:flex-start` 는 좁은 화면에서 문장이 두 줄이 될 때 아이콘이 가운데로 뜨지 않게 한다.

## 3. 새 게이트 — `npm run e2e:layout`

이 부류를 다시는 사람 눈에 맡기지 않는다. `scripts/e2e-layout.mjs` 가 브라우저로 열어 **잰다.**

규칙은 하나다. 문단 안에 아이콘과 글자가 같이 있으면 **둘은 세로로 겹쳐야 한다.** 겹치지 않으면
아이콘이 자기 줄을 차지한 것이다. 글자 쪽 위치는 `Range` 로 잰다 — 문단 전체 사각형을 쓰면 두 줄짜리
문단에서 어긋난 것을 놓친다.

데스크톱(1280px)과 휴대폰 폭(390px) 두 번 본다. 우리가 만든 화면만 잰다 — v17 원본 화면은 고치지
않기로 한 자리라 여기서 재지 않는다(29-1 규칙).

**고치기 전 2건 실패 → 고친 뒤 6건 전부 통과.**

```
✗ /companies — 아이콘이 글줄을 밀어내지 않는다 — 원하는 업체를 찾지 못하셨다면 …
✗ /companies (390px) — 아이콘이 글줄을 밀어내지 않는다 — 원하는 업체를 찾지 못하셨다면 …
[e2e:layout] 4 passed, 2 failed
```

CI 의 `gates` 작업에도 같은 자리(`e2e:interior` 바로 뒤, Playwright 설치 다음)에 넣었다.

## 4. 겪은 것 하나 — 증분 빌드가 낡은 CSS 를 남긴다

고친 뒤에도 검사가 계속 실패했다. `app/globals.css` 에는 새 규칙이 있는데 빌드 결과물에는 없었다.
증분 빌드가 **이전 CSS 청크를 그대로 재사용**했다. `rm -rf .next` 뒤 다시 빌드하니 들어왔다.

CI 는 매번 새 작업 공간에서 빌드하므로 이 함정에 걸리지 않는다. **로컬에서 CSS 를 고쳤을 때는
`.next` 를 지우고 다시 빌드한다.**

## 5. 판번호

`29.16.0` → `29.16.1`. 라운드 표기는 version 의 major·minor 에서 나오므로 `29-16` 그대로다 —
화면의 표식과 상태 파일은 건드리지 않았다.
