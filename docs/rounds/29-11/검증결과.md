# 29-11 검증 결과

## 1. 고치기 전에 실패를 봤다 — 이 라운드의 근거

새 단언 셋을 먼저 넣고 `server/handlers/auth.ts`를 고치기 전 상태로 되돌려 돌렸다.

```
× 운영에 문자 설정이 없으면 가입 자체를 받지 않는다
× 플래그를 켜도 운영은 열리지 않는다
× 플래그를 켜지 않은 프리뷰도 운영과 같이 막힌다
  Tests  3 failed | 4 passed (7)
```

첫 판에서는 셋 중 하나만 실패했다. 나머지 둘이 상태 코드 503만 봤기 때문이다 — 고치기 전 상태도
DB 오류로 503을 주므로 **우연히 통과했다**. 이유 문구까지 보게 고친 뒤에 셋 다 실패했다. 상태
코드만 보는 단언은 이런 식으로 조용히 무의미해진다.

첫 `e2e:server` 시도가 가입 코드 단계에서 멈췄다. 내가 **서버 모드 빌드를 빼먹어서** 화면이
로컬 모드로 서 있었고, 그 모드에는 가입 코드 칸이 없다. CI는 `VITE_AUTH_MODE=server npx vite build`를
먼저 돌린다. 같은 순서로 다시 돌려 통과했다 — 코드 회귀가 아니다.

## 4. 확인 안 된 것 — 그대로 남긴다

| 무엇 | 왜 |
|---|---|
| **프리뷰가 어느 DB를 보는가** | 이 라운드가 확인할 **방법**을 만들었다. 값을 읽으려면 프리뷰에서 관리자로 로그인해 `/admin/diagnostics`를 열어야 한다. 비밀번호는 사장님이 직접 넣으신다 |
| **운영 화면에서 인증번호가 안 나오는가** | 운영은 아직 옛 SPA를 서빙한다. 단위 단언으로 `VERCEL_ENV=production`에서 막히는 것까지 고정했고, 배포된 자리에서의 확인은 전환 뒤에 한다 |
| **문자 발송** | 연동 자체가 없다. 이 라운드는 "없으면 막는다"까지다 |
| **비밀번호 복구** | 다음 라운드 |
| **가입→승인→상담 전체 흐름** | 프리뷰 DB 분리가 확인된 뒤에 한다. 지금 통과한 것은 로컬 DB에서의 `e2e:server` 56단계다 |

## 5. 사람이 해야 하는 일 — 프리뷰 DB 분리

제가 Vercel 프로젝트를 조회할 수 없습니다(404). 환경변수 이름 목록도 읽지 못합니다. 다음은
사장님이 직접 하셔야 합니다.

1. Neon에서 운영 DB의 **브랜치**를 하나 만든다(예: `preview`).
2. Vercel → 이 프로젝트 → Settings → Environment Variables에서 **`DATABASE_URL_PREVIEW`** 를
   추가하고, **Preview 환경에만** 체크한다. 값은 1번 브랜치의 연결 문자열이다.
   - `DATABASE_URL`은 Neon 연동이 소유하므로 건드리지 않는다(29-5에서 확인).
3. 프리뷰가 다시 배포된 뒤 `/login/admin`으로 로그인하고 `/admin/diagnostics`를 연다.
4. "운영과 분리"가 **분리됨**으로 나오면 그때부터 프리뷰에서 계정 생성·승인 검증을 한다.

값은 채팅으로 알려 주지 않으셔도 됩니다. 이 화면은 값을 받지 않고 결과만 보여 줍니다.
