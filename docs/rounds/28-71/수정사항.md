# 28-71 수정 사항 — 「서버 모드를 켤 수 있게」 (28-70 감사 4건 + 운영 최소장치)

**사용자 결정: 감사 4건 + 운영 최소장치.**

28-70 감사(`28-70/감사결과.md`)의 기준은 "서버_연결.md대로 서버 모드를 켜면 무슨 일이 나는가"였고 결론은 "아직 켜면 안 된다"였다 —
가입이 곧 마켓플레이스 전체의 읽기·쓰기 권한이고(01), 손상 리셋된 브라우저가 낡은 커서로 서버를 비운다(02). 이 라운드는 그 넷을
고치고, 켜기 전 전제를 문서에 박는다. 배포된 앱은 여전히 로컬 모드라 동작이 바뀌지 않는다.

## 28-70-01 (상) 가입 코드 — 가입이 곧 권한이므로

- `api/auth.ts`: `register`는 `SIGNUP_CODE`(8자 이상)가 없으면 **503**(DB보다 먼저 검사 — 조용히 열리지 않는다), 코드가 없거나 틀리면
  **400**(sha256 뒤 상수 시간 비교, 도메인 잠금과 무관하게 IP 실패로만 센다). `SIGNUP_CODE_MIN = 8`.
- `AuthGate`: 서버 모드에서만 가입 폼에 "가입 코드" 입력(`input[aria-label="가입 코드"]`). `RegisterInput.signupCode`.
- `gates.yml` server job `SIGNUP_CODE: ci-signup-code-1`, 계약 테스트·서버 e2e가 코드를 채운다.
- 문서: "가입 코드를 아는 사람 = 마켓플레이스 전체 권한. SMS 전까지 `verified`는 휴대폰 소유가 아니다" — `서버_연결.md` 전제 절, README.
- 회귀: 계약 "가입 코드가 없거나 틀리면 400, 맞으면 200"(수정 전 서버에서 `ok:true`), 단위 `api/auth.test.ts` "SIGNUP_CODE 없음·짧음 → 503".

## 28-70-02 (상) 낡은 커서 무효화 — 리셋된 브라우저는 새 기기다

- `bootstrap.ts`: `initPlatform()`이 `{ platform, fresh }`를 돌려주고, `initReplicator(…, fresh)`가 `clearStaleCursor()`로 커서
  (`banded-platform-v1:remote`)를 지운다. `PlatformService.load()`가 손상으로 리셋했을 때 `<key>:rev`와 커서가 남는 것이 원인이었다.
- `replicator.ts` `loadCursor()`: 커서의 `localRev`가 `source.revision()`보다 크면 버린다(커서가 로컬보다 앞설 수 없다) — 첫 save 전의 방어.
- 회귀: `replicator.test.ts` 02-d(수정 전 원격 본문이 `'{}'`로 덮였다), `bootstrap.test.ts` 3건, 서버 e2e "손상 리셋 뒤 서버 스냅샷이
  빈 본문으로 덮이지 않았다 / 리셋된 브라우저는 새 기기처럼 원격을 받아들였다".

## 28-70-03 (중) 운영 안전장치

- **(a)** `scripts/e2e-server.mjs`: DB 이름에 `test`가 없으면 `E2E_ALLOW_TRUNCATE=1` 없이는 종료 2 — `bandut_prod`로 돌려 확인.
- **(b)** `server/session.ts` `pruneSessions()`: 로그인 성공 때 만료·폐기 30일 지난 세션 삭제. 서버 e2e가 40일 전 행 둘을 심고 로그인 → 0.
- **(c)** `server/rateLimit.ts`: IP(`x-forwarded-for`) 기준 60초 20회 실패 → `login`·`register`·`verifyOtp` 429. 인스턴스 로컬 인메모리 —
  완화일 뿐임을 문서에. 단위 테스트 1건(429).
- **(d)** `api/auth.ts`·`api/snapshot.ts`: 503 본문은 일반 문구, 원문은 `console.error`.

## 28-70-04 (중) 검증·문서

- **(a)** 서버 e2e의 "서버에는 해시만" 단언을 `sha256(토큰)` 행 **정확히 1개**로 — 이전 단언은 항상 참이었다.
- **(b)** `/api/auth`의 `?workspace` 제거 — 계정 상태는 `main` 하나. 계약 "other 워크스페이스로 me → 200"(수정 전 401).
- **(c)** `PlatformContext` 주석: 서버 모드 비관리자 거울의 `extraNames` 한계. `서버_연결.md`에도.
- **(d)** `서버_연결.md`에 "켜기 전 전제" 절(가입 코드·정지=세션 폐기·IP 제한의 한계·e2e 가드·세션 정리·리셋 규칙), 절차에 `SIGNUP_CODE`.

## 곁들여 고친 것 (서버 e2e가 잡았다)

- **`TokenStore`가 매 접근 때 저장소를 다시 읽는다.** 탭1이 로그아웃해 토큰을 지웠는데 탭2가 메모리의 낡은 토큰으로 `me`를 부르면
  세션이 되살아나 탭1까지 다시 로그인됐다(28-70 e2e는 타이밍으로 통과했었다). `session.test.ts` "탭1이 지운 토큰을 탭2가 더는 모른다".
- 서버 e2e의 라운드 표기 단언이 `28-70`을 박아 두어 라운드마다 깨졌다 — `package.json`에서 읽는다.
- `vitest.config.ts` include에 `api/**`·`server/**` 테스트.

## 이번 라운드에서 하지 않은 것 (조용히 빼지 않는다)

- 실제 SMS OTP, 엔티티 단위 API(인가), 쿠키(HttpOnly) 세션·CSP, scrypt, 관리자 화면에서 가입 코드 관리 — 기록만 이월.
- 전화번호 기준 잠금(5회 → 15분)은 그대로다 — IP 제한은 완화일 뿐, 번호를 아는 사람이 남을 잠글 수 있다(SMS 2단계 전까지).
- 기록만 이월: `hashPassword`가 `for update` 안에서 돈다, `workspace` 행 무한 생성, `applyMirror(complete)` 크기, `@types/node` 누출,
  `pg.Pool`/`-pooler`, 구 스냅샷 마이그레이션, `markPayout` string 오버로드, `stripComments`, `api/` 훑기 범위, 타임아웃 커버리지,
  StrictMode 이중 초기화, 시드·e2e의 실제 시계, 같은 기기 두 탭 수십 ms 창의 거짓 "덮였습니다".
