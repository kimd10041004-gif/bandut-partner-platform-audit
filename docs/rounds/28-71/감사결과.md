### 28-71-01 (상) 첫 접촉이 로그인 직후의 로컬 변경을 삼킨다 — 두 번째 파트너부터 프로필이 사라진다

`authActions.login()`은 성공 뒤 `onSession?.()`를 **기다리지 않고** 돌아온다(`authActions.ts:74`). `PlatformContext`가 넘긴 `onSession`은
`replication.sync({ checkRemote: true })` — 첫 접촉이면 `read → 원격 있음 → pushedLocalRev undefined → acceptRemote → importSnapshot`이
**비동기로** 진행 중이다. 그 사이 `AuthGate.doVerify`(`:120-123`)가 `login` 직후 `platform.updateProfile(…)`로 파트너 프로필을 시드한다(28-32-03).
accept가 도착하면 `importSnapshot`이 상태를 **통째로 교체**하고, `again` 재실행은 `pushedLocalRev === revision()`이라 아무것도 밀어 올리지 않는다.
결과: 원격이 비어 있지 않은 모든 기기 — 즉 **두 번째 파트너부터** — 프로필 시드가 사라진다. 고객 업체 카드에 이름이 안 뜨고, 파트너는
"맞춤 일감"이 없다. 서버 e2e는 파트너 A를 **빈 원격**에 가입시켜서 이 경로를 한 번도 타지 않았다.

같은 모양이 첫 접촉 뒤 **모든** "로그인 직후 저장"에 있다(예: 고객이 로그인 직후 3초 안에 요청을 등록하면 그 요청은 accept에 덮인다 —
e2e는 1.5초를 기다려서 안 났다). 규칙 2("한 번도 밀어 올린 적 없으면 받아들인다")는 옳지만, **받아들이기 전에 저장을 허용**한 것이 틀렸다.

근본 수정: `onSession`을 `Promise`로 만들고 `login()`·`restore()`가 **기다린다** — 첫 접촉의 accept가 끝난 뒤에야 로그인이 "끝난다".
`doVerify`의 프로필 시드는 그 뒤에 돈다(정상 로컬 변경 → push). 회귀: 단위(`onSession`이 끝나기 전에 `login`이 resolve되지 않는다),
서버 e2e "두 번째 파트너(기기 D)의 프로필이 서버 스냅샷에 있다".

### 28-71-02 (상) 관리자 잠금이 인터넷에 열려 있다 — 5회 실패면 운영이 15분 멈춘다, 무한히

`login('admin', …)`의 잠금 키는 `'admin:admin'` 하나다(`auth.ts` `failKey`). 서버 모드에서 `/api/auth login`은 공개이므로 **누구나** 틀린
비밀번호 5번으로 관리자를 15분 잠그고, 15분마다 반복할 수 있다 — 파트너 승인·정지·환불이 전부 멈춘다. 28-70-03c가 "전화번호를 아는
사람이 남을 잠글 수 있다"로 적었고 28-71은 IP 제한(60초 20회)을 완화책으로 넣었지만, 그 제한은 **서버리스 인스턴스 로컬**(`rateLimit.ts`
헤더 주석대로)이라 5회는 어느 인스턴스에서도 통과한다. 관리자는 전화번호가 필요 없는 **고정 아이디**라 가장 쉬운 표적이다.

가입 코드도 같은 이유로 무차별 대입에 약하다: 틀린 코드는 IP 실패 1회로 세고, 최소 길이 8자(`12345678` 허용)뿐이다.

근본 수정: 잠금 키에 **요청 IP**를 넣는다(서버 모드) — `login(…, { lockScope: ip })`. 공격자는 자기 IP만 잠근다. 비밀번호 무차별 대입은
(계정, IP)당 5회/15분 + 8자 최소로 막힌다. 가입 코드: 틀리면 IP 실패 5회분으로 세고(분당 4회), 최소 12자.

### 28-71-03 (중) 가드가 보기보다 약하다 — `latest`도 test DB이고, 대기 중 가입은 남이 지울 수 있다

- **(a)** `e2e-server.mjs:36` `/test/i.test(dbName)` — `bandut_latest`·`contest_db`가 테스트 DB로 통과한다. 단어 경계가 없다.
- **(b)** `verifyOtp`는 공개이고 가입 코드를 묻지 않는다. 대기 중 가입의 전화번호를 아는 사람이 틀린 코드 5번으로 OTP를 지운다
  (`OTP_MAX_ATTEMPTS`) — 가입자는 "다시 가입해 주세요"를 본다. 가입 코드가 있는 사람만 verifyOtp도 할 수 있어야 한다.
- **(c)** `SIGNUP_CODE_MIN = 8`은 길이만 본다. 문서는 "8자 이상"이라고만 한다 — 무작위여야 한다는 말이 없다.

### 28-71-04 (중) 검증·문서 어긋남

- **(a)** 서버 e2e는 첫 파트너를 빈 원격에, 고객을 두 번째 기기에 넣었다 — "원격이 있을 때 파트너 가입" 경로가 없어 01을 못 봤다.
  기기 하나만 더 있으면 됐다.
- **(b)** IP 제한은 `x-forwarded-for`를 믿는다. Vercel은 이 헤더를 덮어쓰지만 `scripts/api-server.mjs`(CI·로컬)는 클라이언트가 보낸 값을
  그대로 쓴다 — 어디에도 적혀 있지 않다. `rateLimit.ts`의 "인스턴스 로컬" 한계는 코드 주석에만 있고 `서버_연결.md`에는 "완화일 뿐"으로만.
- **(c)** `28-71/검증결과.md` §2는 02-d를 "복제기 수준" 재현이라 했지만 그 테스트는 `src.rev = 41`이 아니라 `0`으로 바꿔 통과시킨 것이다 —
  `:rev` 키가 살아 있어 첫 save가 41이 되는 **실제** 경로는 복제기 가드가 못 잡고 `clearStaleCursor`만 잡는다. 문서가 그 구분을 흐렸다.
- **(d)** `pruneSessions`의 반환값(지운 행 수)을 아무도 안 쓴다. 로그도 없다.
