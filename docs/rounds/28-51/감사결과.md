핵심 지적: `auth.ts` 머리말이 "비밀번호는 데모 저장(평문)"이라고 스스로 밝히고 있다. 28-38 약관, 28-39 정산 계좌, 28-40 탈퇴·파기까지 개인정보 처리 규칙을 도메인에 넣어 놓고 **비밀번호만 평문으로 localStorage에 남기는 것**은 그 규칙들과 모순이다(브라우저 저장소는 확장 프로그램·같은 기기 사용자에게 열려 있다). 또 로그인은 **무제한 시도**가 가능하고(파트너 휴대폰 번호는 일감 카드·채팅에서 노출되므로 대입 공격 표적), OTP는 **만료·시도 제한이 없으며**, 세션은 **영구**다(공용 PC에서 로그아웃을 잊으면 영원히 로그인). 상용 전환 시 서버 인증으로 바뀌더라도 규칙(해시·잠금·만료)은 도메인에 먼저 있어야 UI·e2e가 그 규칙을 검증한다.

## 상 (High)

### 28-51-01 · 비밀번호 해시
→ 요구: `domain/hash.ts` — 의존성 없는 동기 SHA-256 + 솔트·반복(`hashPassword(password, salt, iterations)`, `randomSalt()`, `verifyPassword(password, stored)`; 저장 형식 `s256$<iterations>$<salt>$<hex>`). `Account.password` → `passwordHash`, 관리자 `adminPassword` → `adminPasswordHash`. **구 스냅샷(평문) 마이그레이션**: 로드 시 평문이면 해시로 바꾸고 저장. `AccountView`·`listAccounts`·`accountFor`는 해시도 제외. 탈퇴 시 해시 파기. 테스트: 같은 솔트 결정적·다른 솔트 상이·검증·스냅샷에 평문 없음·구 스냅샷 마이그레이션·`sha256('abc')` 알려진 벡터.

### 28-51-02 · 로그인 잠금 + OTP 만료·시도 제한
→ 요구: `LOGIN_MAX_FAILS = 5`, `LOGIN_LOCK_MS = 15분`. 역할+식별자 키로 실패 횟수 기록(스냅샷 `loginFails`), 5회 실패 시 잠금 — 잠금 중에는 **맞는 비밀번호도 거부**("N분 후 다시 시도"), 성공 시 초기화. 실패 메시지에 남은 시도 횟수. 관리자 계정도 동일. OTP는 `{ code, issuedAt, attempts }`로 저장, `OTP_TTL_MS = 5분` 경과 시 "만료 — 다시 가입", 오답 `OTP_MAX_ATTEMPTS = 5`회면 폐기. 시각은 `now` 인자로 주입(테스트 결정성). 구 스냅샷의 문자열 OTP는 발급 시각 = 로드 시각으로 마이그레이션.

## 중 (Medium)

### 28-51-03 · 세션 만료
→ 요구: `AuthSession`에 `issuedAt`·`expiresAt`(고객·파트너 24시간, 관리자 8시간 — `SESSION_TTL_MS`). `sessionFor(role, now)`가 만료 세션을 제거하고 게이트 안내("세션이 만료되어 다시 로그인해 주세요")를 남긴다. 구 세션(만료 없음)은 로드 시 TTL 부여. 마이페이지에 만료 시각 표시.

### 28-51-04 · e2e + 실측
→ 요구: e2e — 고객 로그인 5회 오답 → 잠금 메시지 → 맞는 비밀번호도 거부 → (저장소의 잠금 해제 시각을 과거로 조정 후 새로고침) 정상 로그인 / 저장소 JSON에 평문 비밀번호 없음 + `passwordHash` 존재 / 관리자 세션 `expiresAt`을 과거로 조정 후 새로고침 → 게이트 + 만료 안내. OTP 만료·시도 제한은 vitest. 실측: 잠금 메시지·저장소 발췌·만료 안내.
