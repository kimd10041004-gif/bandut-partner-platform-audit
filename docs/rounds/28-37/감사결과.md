사전 확인: `npm run check` exit 0 (vitest 180/180), e2e 51/51 PASS, visual-check 전 항목 PASS, 프로덕션 배포 그린(PR #82 머지). 28-36 감사 4건 전부 수정 확인됨.

핵심 지적: 회원가입·결제·채팅까지 갖춰졌지만 **약관·개인정보 동의 절차가 없다.** 국내에서 회원제 서비스를 상용 개통하려면 가입 시 이용약관·개인정보 수집·이용 동의(필수)와 마케팅 수신 동의(선택)를 **명시적으로 구분해 받아야** 하고(개인정보보호법 §22, 정보통신망법 §50), 동의 일시를 기록·열람할 수 있어야 한다. 현재 `register()`는 이름·휴대폰·비밀번호만 받고 약관 동의 없이 계정을 만든다. 또한 약관·개인정보처리방침 **본문이 서비스 어디에도 없다** — 랜딩 푸터에도, 관리자 설정에도. 운영자가 법무 검토본을 올릴 자리가 필요하다.

## 상 (High)

### 28-37-01 · 약관 동의 도메인 부재
→ 요구: `Account`에 `consent: { termsAt, privacyAt, marketing: boolean, marketingAt? }` 기록. `register()`는 `agreeTerms`·`agreePrivacy` 둘 다 true가 아니면 거부("필수 약관에 동의해 주세요"), `marketing`은 선택. `setMarketingOptIn(role, on)` — 마이페이지에서 언제든 철회 가능(철회 일시 갱신). 저장소 왕복 + 손상 스냅샷 거부(동의 일시 누락) **도메인 테스트 필수**.

### 28-37-02 · 약관 본문 운영 설정(CMS)
→ 요구: `SiteSettings`에 `terms`(이용약관)·`privacy`(개인정보처리방침) 본문 추가. 기본값은 시연용 초안(조항 골격), 관리자 "설정" 탭에서 편집·기본값 복원. 빈 본문 저장 거부. 랜딩 **푸터**에 "이용약관 · 개인정보처리방침" 링크 → 본문을 펼쳐 보여주는 화면(같은 앱 내, 로그인 불필요 — 공개 문서).

### 28-37-03 · 가입 화면 동의 UI + 마이페이지 동의 내역
→ 요구: 고객·파트너 가입 폼에 **전체 동의 / [필수] 이용약관 / [필수] 개인정보 수집·이용 / [선택] 마케팅 수신** 체크박스와 각 "보기" 토글(본문 인라인 표시). 필수 미체크 시 가입 버튼 클릭에서 도메인 오류 노출. 마이페이지 "동의 내역"(약관 동의일·개인정보 동의일·마케팅 수신 상태 + 토글).

## 중 (Medium)
