# 28-37 수정사항 (Claude) — 파트너 유형·사업자 조회 라운드

기반: `28-36` 복사본(스크래치 wf28-37)에서 작업. 28-36 감사 4건 전부 반영. 사용자 요구: "파트너를 사업자, 개인으로 나누고 가입 간 사업자 정보 조회 통과 필요".

## 28-36-01 · 파트너 유형 + 사업자 조회 도메인 [반영]

- `PartnerType = 'business' | 'individual'`, `PARTNER_TYPE_LABEL`(사업자/개인). `Account`에 `partnerType?`·`bizVerified?` 추가.
- `register()`: 파트너는 유형 필수("파트너 유형(사업자/개인)을 선택하세요"). **사업자**는 10자리 사업자등록번호 + `verifyBusiness()` 통과 필수 — 실패 시 "사업자 정보 조회에 실패했습니다 — 사업자등록번호를 다시 확인해 주세요". **개인**은 번호 없이 가입, `bizNo` 미저장.
- `isValidBusinessNumber()`: 국세청 검증번호 규칙(가중치 1·3·7·1·3·7·1·3·5, 9번째 자리×5의 십의 자리 가산, 마지막 자리 = (10 − 합 mod 10) mod 10). 같은 숫자 10회 반복 거부. `verifyBusiness(bizNo)`는 **상용 전환 시 국세청 진위확인 API로 교체하는 단일 경계**.
- 저장소 로드 검증: 알 수 없는 `partnerType` 거부. 도메인 테스트 `describe('파트너 유형·사업자 조회')` 추가(체크섬 유효/무효 6케이스, 사업자·개인 가입 왕복) → vitest 178→**180**. 기존 테스트의 `1234567890`은 실제 검증번호 불일치라 `1234567891`로 교체.

## 28-36-02 · 가입 UI [반영]

- 파트너 회원가입 폼: **파트너 유형 필(사업자 / 개인)** — 사업자 선택 시에만 사업자등록번호 입력란 노출, 유형별 안내 문구("가입 시 사업자 정보 조회를 통과해야 합니다" / "개인 파트너는 사업자등록번호 없이 가입"). 조회 실패는 폼 하단 오류로 표시(폼 유지, 번호만 재입력).

## 28-36-03 · 관리자·마이페이지 표기 [반영]

- 관리자 "회원" 탭: **유형** 컬럼(사업자/개인 태그) + **사업자 조회** 컬럼(통과 / 미조회 / 개인은 "해당 없음"), 사업자번호 `000-00-00000` 포맷. 태그 줄바꿈 방지.
- 마이페이지 내 정보: "파트너 유형", "사업자 정보 조회(통과)" 행 추가.

## 28-36-04 · e2e + 실측 [반영]

- e2e 1단계 추가(50→**51**): 파트너 가입에서 "사업자" 선택 → 잘못된 번호(`123-45-67890`) 입력 → "사업자 정보 조회에 실패" 거부 확인 → 올바른 번호(`123-45-67891`)로 통과 → OTP 인증 → 로그인. 이후 승인 게이트·입찰 여정 무회귀.
- 실측: 조회 실패 화면 / 파트너 마이페이지(유형·조회 통과) / 관리자 회원 목록(유형·조회 컬럼) 스크린샷 3장.
