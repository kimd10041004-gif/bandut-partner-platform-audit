첫 줄: `main`에는 분야 묶음이 그대로 저장되고(옮기지도 중복을 빼지도 않는다) 안전 답·검토 결과라는 것이 없다. 가명본 반출

e2e가 실제로 잡은 것 셋:

- 위저드가 첫 분야를 **기본 선택**한 채 다중 선택이 되니, 두 번째 요청에서 카드 하나를 누르면 `[급배수·누수·설비 + 전기·조명]`
  두 개가 실렸다(맞춤 토글 단언이 깨져 드러났다) → 처음엔 비어 있고 "하나 이상 고르세요"로 막는다.
- 관리자 설정의 **가명본 내보내기**가 `safety` 중첩 객체에서 `가명 처리에 실패했습니다 — store.requests.safety가 객체인데 중첩
  허용 목록이 선언되지 않았습니다`를 던져 화면이 교체됐고 뒤 단계가 전부 타임아웃 → `PSEUDONYMOUS_REQUEST_SPEC`(중첩 선언) +
  단위 회귀 "가명본 반출: 분야 묶음·안전 답변·검토 결과는 실리고, 검토 메모는 빠진다".
- 서버 e2e의 "탭 복귀에서 남의 요청을 받아들인다"가 파트너 일감 화면의 문구로 판정하고 있었는데, 검토 전 요청은 이제 그 화면에
  없다 → 이 기기의 거울(localStorage 스냅샷)로 판정하고, "검토 전이라 일감 목록에는 없다"를 단언으로 더했다. 서버 스냅샷
  본문은 들여쓰기된 JSON이라 `"review":{`가 아니라 `"review":\s*\{`로 본다.

## 4. e2e 여정에 더한 단언

- 위저드: 분야 두 개(주방·욕실 + 급배수) → 선택 목록 문구 · 긴급 질문 노출 · 미답 → "안전 질문에 답해 주세요" · "예"+미확인 →
  "안전 안내 확인이 필요합니다"와 안내문 · "아니요"로 바꾸면 확인 칸 사라짐 · 등록 확인의 `[data-review-notice]` · 등록 문구 ·
  고객 홈 `[data-review-hold]`.
- 파트너: 검토 전 일감 목록에 없음 → 검토 뒤 `[주방·욕실 공사 + 급배수·누수·설비] 욕실 실리콘 재시공` 카드 + 사진 2장.
- 관리자: 접수 검토 필요 1건(플래그 `WORK_SCOPE_REVIEW` + "긴급 아니요") · 확인 없이 완료 → "검토 사유를 5자 이상" · 완료 →
  검토 0건, 승인 대기는 그대로 1건. 뒤의 요청 4건(누수·전기·세면대·주방 수전)은 `adminReview()` 헬퍼로 검토한다.
- 알림: 검토 전 파트너1 벨 변화 없음 → 검토 완료 → +1.
