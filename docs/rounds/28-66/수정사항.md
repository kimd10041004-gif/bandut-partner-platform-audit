## 28-65-01 (상) 가명본 구조 검사를 재귀로 — 한 겹 아래도 본다

감사에서 탐침으로 확인한 것: `assertPseudonymousShape`가 각 행의 **최상위 키만** 보고
값이 객체여도 안으로 들어가지 않았다. spec이 `estimates`의 `estimate`, `jobs`의 `payout`을
키로 허용하는 순간 그 안은 무방비였고, 아래 둘 다 **통과했다**:

```
estimate.memo = '고객 김하늘 010-1234-5678 자택'   ← 28-62-01이 "목록에 없다"고 선언한 자유 서술
payout.holder = '박준서'                          ← 28-61-02가 "자체 검사가 잡아낸 경로"라 적은 필드
```

### 고친 방식

1. **중첩 허용 목록**을 타입으로 만들었다 — `ShapeSpec = readonly string[] | { keys, nested }`.
   `estimates`는 `{ estimate: PSEUDONYMOUS_ESTIMATE_KEYS, breakdown: PSEUDONYMOUS_BREAKDOWN_KEYS }`,
   `jobs`는 `{ payout: PSEUDONYMOUS_PAYOUT_KEYS }`를 선언한다.
2. **선언이 없으면 실패한다.** 값이 객체인데 중첩 목록이 없으면 통과가 아니라 오류다.
   *이 규칙이 곧바로 하나를 찾아냈다* — `estimates[].breakdown`은 객체인데 아무도 검사하지 않고 있었다.
   그래서 `PSEUDONYMOUS_BREAKDOWN_KEYS`를 새로 만들었다.
3. **조용한 건너뜀 제거.** 검사할 수 없는 형태(`continue`)를 없앴다.
   28-64-02가 없앤 "배열이면 건너뛴다"가 형태만 바꿔 남아 있었다.

부수 정리: `pick()`이 메서드 안의 지역 함수였는데 모듈 수준으로 올렸다(아래 02가 함께 쓴다).

## 28-65-02 (중) 열람권 내보내기의 통째 전개 5줄 제거

28-64-03이 "통째 전개를 끊는다"고 적고 실제로는 `requests`·`claims` 둘만 고쳤다.
남아 있던 다섯 줄을 전부 허용 목록 방식으로 바꿨다:

| 위치 | 이전 | 이후 |
|---|---|---|
| 고객 `payments` | `{ ...p }` | `pick(p, EXPORT_PAYMENT_KEYS)` |
| 고객 `refunds` | `{ ...f }` | `pick(f, EXPORT_REFUND_KEYS)` |
| 고객 `reviews` | `{ ...v }` | `pick(v, EXPORT_REVIEW_KEYS)` |
| 파트너 `jobs` | `{ ...j }` | `pick(j, EXPORT_JOB_KEYS)` + `payout`은 `EXPORT_PAYOUT_KEYS` |
| 파트너 `reviews` | `{ ...v }` | `pick(v, EXPORT_REVIEW_KEYS)` |

**테스트를 공허하지 않게 만드는 데 한 번 걸렸다.** 처음에 "결과의 키가 허용 목록 안에 있다"만
확인하는 테스트를 썼는데, 통째 전개의 결과가 마침 현재 타입의 필드 전부라 **수정 전 코드에서도
통과했다.** 28-65가 `isKnownError` 테스트에서 저지른 것과 같은 실수라, 알아채고 다시 썼다 —
저장된 레코드에 목록에 없는 필드를 직접 심고 그것이 결과에 따라오지 않는지 본다.
(수정 전 코드에서 실패하는 것을 확인했다. `검증결과.md`에 출력이 있다.)

## 28-65-03 (중) `isKnownError`를 목록이 아니라 상속으로

도메인 오류 클래스가 9개인데 `isKnownError`의 손으로 쓴 목록에는 8개뿐이었다
(`PlatformReopenError` 누락). 호출부가 `else throw err`라서, 목록에 없으면 ErrorBoundary로 올라가
**화면 전체가 교체된다.**

- `src/domain/errors.ts`에 `abstract class DomainError extends Error`를 두고 9개 클래스를 전부 상속시켰다.
- `isKnownError`는 이제 `err instanceof DomainError` 한 줄이다. 유지할 목록이 없으니 틀릴 목록도 없다.
- `src/domain/errors.test.ts`는 `import.meta.glob`으로 도메인 모듈을 훑어 Error 하위 클래스를
  **발견**한다. 목록을 베끼지 않는다. 새 오류를 추가하면 아무것도 고치지 않아도 검사 대상이 된다.
- `src/ui/format.test.ts`에 있던 "5개를 나열해 참을 확인" 테스트는 지웠다 — 목록을 되풀이하는
  테스트가 남아 있으면 잘못된 안심을 준다.

만들면서 한 번 틀렸다: 처음 `import.meta.glob('./*.ts')`가 `*.test.ts`까지 eager import 해서
다른 파일의 테스트가 이 파일에 함께 등록됐다(한 파일에 299개). 부정 패턴으로 제외했다.
