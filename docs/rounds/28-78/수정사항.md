# 28-78 수정사항 — 첫 화면을 되찾다 (시연 데이터 복구 + 28-77 감사 4건)

사용자 지시: **"감사후 복구"** — 28-77 감사를 먼저 쓰고(`28-77/감사결과.md`), 이 라운드에서 복구한다.

---

## 28-78-00 (복구) 첫 방문의 시연 데이터가 돌아왔다

28-77이 발견해 패치까지 적어 두고 제품 결정이라 미뤘던 것이다. 시드는 `completed` 다음 바로 `settled`로
보냈는데 28-28-01 불변식이 **최종 결제 없이는 정산을 막는다.** 그래서 빈 저장소로 부팅하면
`PlatformError: 고객 결제 완료 후 정산할 수 있습니다`가 던져지고 **스냅샷이 아예 저장되지 않았다** —
첫 방문자에게 일감도 정산 이력도 하나도 보이지 않는 상태로 라이브가 오래 있었다.

```ts
    p.transitionRequest(r.id, 'completed', { completedDate: h.date })
    p.payFinal(r.id, 'card')                     // ← 28-78-00
    p.transitionRequest(r.id, 'settled')
```

**e2e 여정 10곳도 함께 정리했다.** 시연 이력 3건이 처음부터 있으면 "지급 대기 1건" 같은 단언이 깨진다.
느슨하게 바꾸지 않고 **정확히** 맞췄다:

- 이 여정의 요청 id를 스냅샷에서 집어(`myReqId`) **그 행만** 지급 처리한다. 예전에는 "첫 번째 지급 대기
  행"을 눌렀는데, 시연 이력이 같은 파트너의 것이라 엉뚱한 건을 지급 처리하고 그 뒤 여섯 단계가 무너졌다.
- 개수 단언은 구성을 적는다: `지급 대기 4건(시연 이력 3 + 이번 여정 1)`, `정산 완료 4행`,
  `지급 완료 → 이번 건만 지급 완료 목록으로(시연 3건은 대기 그대로)`.

회귀는 **부팅 경로 그대로** 건다(28-77-04가 깔아 둔 자리다): 빈 저장소로 `initPlatform()`을 태우면
요청 6건·정산 완료 3건이 들어가고 스냅샷이 저장된다.

## 28-78-01 (중) 용량이 모자라면 **보관함이 양보한다**

28-75-02는 보관함 정리를 **부팅에만** 두었다. 그런데 예산을 넘기는 사건은 쓰는 중에 일어난다 —
스냅샷이 커지면 `한도 − 스냅샷`이 줄어 어제까지 예산 안이던 보관함이 오늘 밖이 된다. 그 순간부터
새로고침 전까지 저장이 막혔다.

도메인에 포트를 하나 더 연다(저장소는 여전히 모른다 — 숫자와 함수 하나다):

```ts
trimExternal?: (needChars: number) => number      // 확보를 시도하고 **실제로 비운 문자 수**를 돌려준다
```

`assertRoom`은 넘칠 것 같으면 먼저 양보를 청하고, 그래도 모자라면 그때 거절한다. **가드는 살아 있다** —
회귀 두 건이 양쪽을 다 고정한다(줄이면 통과 / 다 비워도 모자라면 여전히 거절).

## 28-78-02 (중) 보관함 정리도 **운영 기록에 남는다**

같은 부팅에서 도는 알림·채팅·사진 정리는 `record('system', 'X 정리', n)`을 남기는데 보관함만 없었다.
넷 중 유일하게 **사용자가 잃은 것**인데, 4초 안내가 지나면 어디에도 흔적이 없었다.

`recordExternalTrim(action, count)`을 열어 `initPlatform`이 부른다(0건이면 남기지 않는다).

## 28-78-03 (중) 가명 키에 **설치별 소금**

28-77-02는 막는 것과 막지 못하는 것을 정직하게 적었지만 잔여물이 하나 있었다: 소금이 없어
`sha256('customer:01012345678')`이 **어느 배포에서나 같은 값**이라, 두 배포의 행을 나란히 놓는 것만으로
"같은 사람이 두 곳에 있다"가 번호를 몰라도 읽혔다. 지목 확인과 달리 **대상을 특정하지 않고도** 얻어지는
정보라 성격이 다르다.

`keySalt`(설치마다 한 번, 스냅샷에 남는다)를 해시에 넣는다. 소금 이전 스냅샷은 옛 키를 버린다 —
새 소금과 맞지 않아 조회되지 않는 죽은 항목이고, 버리는 방향은 안전하다(면제가 사라져 잠금이 걸린다).

## 28-78-04 (하) 구조 테스트의 소비자 범위 = `src/` 전체

`ui/` 조각의 사용처를 `features`·`ui`·`app`·`App.tsx` 넷으로 하드코딩해 두면, `src/` 아래 새 디렉터리에서만
쓰이는 조각이 "한 곳에서만 쓰인다"로 오탐된다. 규칙이 전역이므로 검사도 `src/` 전체를 건다.

## 이 라운드에서 하지 않은 것

- `scripts/api-server.mjs`의 포트 인자가 `--static` 없이 무시되는 것.
- `clientIpOf`의 `trusted`가 "프록시를 검증했다"가 아니라 "헤더가 있다"는 뜻이라는 사실의 문서화.
- `otps` 맵의 키는 아직 평문(5분짜리이고 번호는 `accounts`에 있다).
- 병합(엔티티 단위 인가), 보관함 서버 업로드·자동 복원, SMS OTP, 쿠키 세션·CSP, scrypt, 엣지 레이트리밋.
