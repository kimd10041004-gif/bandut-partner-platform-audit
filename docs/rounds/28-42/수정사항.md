# 28-42 수정사항 (Claude) — 파트너 범위 분리 라운드

기반: `28-41` 복사본(스크래치 wf28-42)에서 작업. 28-41 감사 4건 전부 반영.

## 28-41-01 · 파트너 식별 = 계정, 도메인 범위 분리 [반영]

- `PlatformService.SEED_PARTNER_ID = 'P-001'`(시드 데모 파트너). `partnerOf(requestId)`(견적 파트너), `partnerRequests(partnerId)`. 범위 인자(생략 시 전체 = 관리자·랜딩 하위 호환): `bidStats(partnerId?)` / `statusCounts(partnerId?)` / `settlements(filter, partnerId?)` / `unsettledPayout(partnerId?)` / `monthlyReport(partnerId?)` / `monthSummary(month, partnerId?)` / `completedJobsOf(partnerId)` / `reviewStats(partnerId?)` / `allReviews(partnerId?)` / `upcomingSlots(from, n, partnerId?)` / `partnerHasOpenWork(partnerId?)`. 내부 `jobsOf()`·`reviewsOf()`(리뷰는 요청의 견적 파트너에 귀속).
- **파트너 알림 계정 범위**: `inScope()`가 파트너도 요청의 견적 파트너 = 계정일 때만(요청 없는 알림은 전체). `NotificationBell`은 고객·파트너 모두 `accountId`를 넘긴다.
- `usePartnerId()`(PlatformContext): 파트너 세션의 `accountId`, 없으면 시드 파트너. `PARTNER_ID` 상수는 시드(bootstrap)에서만 사용.
- 도메인 테스트 2건(두 파트너 교차 없음: 견적·상태·낙찰률·슬롯·작업·정산·월 요약·진행 중·리뷰·알림·프로필 / 프로필 다중화 왕복·구 스냅샷 이전·손상 거부) → vitest 189→**191**. 기존 프로필 테스트 1건은 새 저장 키(`profiles`)에 맞게 정정.

## 28-41-02 · 파트너 프로필 다중화 + 고객 업체 카드 연결 [반영]

- `profiles: Map<partnerId, PartnerProfile>` — `getProfile(partnerId = P-001)` / `updateProfile(input, partnerId = P-001)` / `partnerSummary(partnerId = P-001)`(기본값으로 기존 호출 호환). 스냅샷 `profiles` 배열 저장·검증, 구 `profile`은 로드 시 P-001로 이전.
- `PartnerCard requestId` — 그 요청의 견적 파트너 프로필·실적·최근 리뷰. 견적함·거래 상세 호출부 갱신. 파트너 첫 가입 시 프로필 시드도 계정 id로.

## 28-41-03 · 파트너 센터·관리자 UI 범위 적용 [반영]

- 대시보드(오늘·예정 슬롯·상태 수·미정산·월 요약·낙찰률·리뷰·인사 이름) / 일감(입찰 가능 + 내 입찰만, 견적 제출 partnerId = 계정) / 내 작업(내 견적 건만) / 일정(내 낙찰 건 후보·내 슬롯) / 정산(내 정산·작업별 지급 상태) / 마이(내 프로필·성과·리뷰, 파트너 id 칩) 전부 범위 적용.
- 관리자 정산 감독: `job.partnerId`로 파트너 계정을 찾아 이름·계좌 사용(시드 P-001은 계정 없음 → 프로필명/ID 표기, "계좌 미등록"). 회원 탭 파트너 행에 계정 id 표기.
