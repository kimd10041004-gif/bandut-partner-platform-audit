# 28-27 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-27` 전체 + **사용자 지시 반영**("당근처럼 간단 채팅 기능도 구현을 해보자") + 시안 대조(시안 1 "현장 채팅" / 시안 5 고객 거래 상세의 채팅 탭).
사전 확인: `npm run check` exit 0 (vitest 160/160), e2e 27/27 PASS, visual-check 전 항목 PASS, 프로덕션 배포 그린(PR #52 머지). 28-26 감사 5건 전부 수정 확인됨.

CMS 묶음이 완결됐고, 사용자가 다음 목표를 직접 지정했다: **거래 채팅**. 당근의 채팅이 그렇듯 거래(일감)마다 대화방이 붙어야 한다 — 지금은 견적을 받아도, 방문 일정이 잡혀도 고객과 파트너가 대화할 통로가 없다. 질문 빌더(28-27)가 사전 정보를 전달한다면, 채팅은 그 이후의 모든 조율(주차, 출입, 자재 변경)을 담는다. 당근 문법 유지: 플랫 말풍선, 장식 금지, 리스트 행 톤.

---

## 상 (High)

### 28-27-01 · 채팅 도메인 부재
→ 요구: `ChatMessage { id, requestId, sender('customer'|'partner'), text, sentAt(ISO) }`.
- `sendMessage(requestId, sender, text)`: 텍스트 공백 거부(트리밍 저장), 없는 요청 거부, **requested 상태 거부**("견적이 도착한 뒤 채팅 가능" — 대화 상대가 생긴 뒤부터), lost/cancelled 거부.
- `chatFor(requestId)`(시간순) / `unreadCount(requestId, viewer)`(상대가 보낸 메시지 중 안 읽은 수) / `markRead(requestId, viewer)`(읽음 처리).
- 스냅샷 `chats?`+`chatSeq?`+읽음 상태 하위 호환 + 요소 검증 + **도메인 테스트 필수**.

### 28-27-02 · 고객 채팅 UI (시안 5 채팅 탭)
→ 요구: 고객 거래 상세에 "채팅" 카드 — 당근식 말풍선(내 메시지 우측 브랜드 배경, 상대 좌측 카드 배경 + 보더), 시각 표시, 입력창+전송(Enter 지원), 열람 시 읽음 처리. 견적 전에는 안내 문구만.

### 28-27-03 · 파트너 채팅 UI (시안 1 "현장 채팅")
→ 요구: 파트너 내 작업 카드에 채팅 토글 버튼 + **안 읽은 수 뱃지**, 펼치면 동일 말풍선 UI. 파트너가 모르게 흘러가지 않도록 뱃지는 목록에서 바로 보이게.
