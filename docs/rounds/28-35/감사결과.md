# 28-35 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-35` 전체 — 거래 이벤트의 **전달 경로** 점검 + 시안 대조(시안 1·5의 상태 알림).
사전 확인: `npm run check` exit 0 (vitest 176/176), e2e 48/48 PASS, visual-check 전 항목 PASS, 프로덕션 배포 그린(PR #76 머지). 28-34 감사 4건 전부 수정 확인됨.

핵심 지적: 거래는 열 단계를 넘게 오가는데 **상대에게 "무슨 일이 생겼는지" 알려주는 장치가 채팅 뱃지 하나뿐이다.** 견적이 도착해도 고객은 견적함을 열어봐야 알고, 낙찰·결제·추가 작업 결정·완료·리뷰·A/S 접수도 마찬가지다. 당근이 거래 이벤트마다 알림을 쌓듯, 역할별 **인앱 알림 센터**가 필요하다. 서버가 없으므로 도메인 이벤트에서 알림을 생성·영속하고, 헤더 벨에 미읽음 수를 표시한다.

## 상 (High)

### 28-35-01 · 알림 도메인 부재
→ 요구: `Notification { id, role('customer'|'partner'|'admin'), requestId?, text, createdAt, read }`. 도메인 액션에서 생성:
- 견적 제출 → 고객 / 낙찰·미낙찰 → 파트너 / 방문 예약 → 고객 / 추가 작업 요청 → 고객, 결정 → 파트너 / 작업 완료 → 고객("최종 결제") / 예약금·최종 결제 → 파트너(+최종 결제는 관리자) / 리뷰 → 파트너 / A·S·분쟁 접수 → 관리자·파트너, 해결 → 고객.
- `notificationsFor(role)`(최신순) / `unreadCount(role)` / `markAllRead(role)`. 스냅샷 `notifications?`+`notificationSeq?` 하위 호환 + 요소 검증 + **도메인 테스트 필수**.

### 28-35-02 · 헤더 알림 벨
→ 요구: 세 앱 헤더에 벨 버튼 + 미읽음 수 뱃지(0이면 숨김), 클릭 시 패널(최신순, 읽지 않은 항목 강조, 열면 읽음 처리). 28-19 플랫 문법, 모바일 가로 스크롤 금지.

## 중 (Medium)

### 28-35-03 · e2e + 실측
→ 요구: e2e — 파트너 입찰 후 고객 벨 미읽음 ≥1 → 패널 열기 → "견적" 알림 확인 → 읽음 처리로 뱃지 소멸. 패널 스크린샷.
