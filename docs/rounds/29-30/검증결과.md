## 4. 게이트가 잡은 것

**옛 단언 하나가 낡아 있었다.** `tests/marketplace.http.test.ts` 의 "사진 경로는 저장소가 없다고 분명히 말한다 — 503 (29-5)" 가
`process.env` 기본값으로 돌아, 로컬 스위트처럼 `LOCAL_STORAGE_DIR` 이 있는 자리에서는 이제 실제 라우트를 타 **404** (없는 사진)
가 나왔다:

```
FAIL tests/marketplace.http.test.ts > 사진 경로는 저장소가 없다고 분명히 말한다 — 503 (29-5)
AssertionError: expected 404 to be 503
```

이것은 고친 쪽이 맞고 단언이 틀린 경우다 — 저장소가 있으면 503 이 아니어야 한다. 단언을 환경 명시로 바꿨다: 저장소 없음 → 503,
저장소 있음 + 없는 사진 → 404. 둘 다 통과. (첫 스위트에서 `e2e`·`visual-check` 가 한 번 "playwright-core 를 찾을 수 없습니다"
로 멈춘 것은 이 세션의 실행 환경변수를 빠뜨린 것이고, 넣고 다시 돌려 둘 다 OK — 코드와 무관하다.)

**첫 CI 가 잡은 것 — 봇이 7배 느려져 15분 상한에 취소됐다.** PR 을 연 첫 `server` job 에서 거래 봇 걸음이 61초 → **455초**,
그 뒤 `e2e:live` 가 도는 중에 job 이 15분 상한으로 **cancelled** 됐다. 로컬 스위트도 같았다(거래 봇 70초 → 7분 30초,
`e2e:live` 2분 15초 → 3분 40초) — 다만 로컬은 상한이 없어 초록으로 끝났고, 나는 시간을 보지 않았다.

원인: 봇 셋이 화면을 `page.goto(..., { waitUntil: 'networkidle' })` 로 열었다. 29-30 부터 상담이 있는 화면은 SSE 를 **항상**
열어 두므로 네트워크가 조용해지지 않는다 — 스트림이 28초에 닫히고 1초 뒤 다시 잇는 그 틈에야 networkidle 이 온다.
상담 화면을 열 때마다 최대 28초. 코드가 느려진 것이 아니라 **검사의 기다림이 스트림과 맞지 않게 된 것**이다.

고침: `bot-kit.mjs` 에 `openPage`(`load` 까지 기다린 뒤 networkidle 을 **4초 상한**으로 기다린다)·`reloadPage`·`settle` 을 두고
세 봇의 `open`·`reload`·`goBack/goForward`·`waitForLoadState` 를 그리로. 스트림이 없는 화면은 예전처럼 바로 조용해지고,
있는 화면은 4초 안에 자료 fetch 가 끝난다. `server` job 상한은 15 → 20분(봇이 실제로 더 걷는다).

## 5. 아직 확인되지 않은 것

- **운영 Vercel Blob 왕복.** 이 세션과 러너는 Vercel 저장소에 붙을 수 없어 파일 백엔드로 규칙을 쟀다. `server/storage.ts` 의
  Vercel 백엔드는 29-23 부터 서류에 쓰이고 있는 같은 코드다. 그래도 **사진 한 장이 운영에서 실제로 올라가는지**는 병합 뒤
  사장님이 접수 화면에서 한 번 붙여 보셔야 한다. 운영에 `BLOB_STORE_ID` 가 없으면 화면은 예전처럼 "사진 저장소가 아직
  연결되지 않았습니다" 라고 말한다 — 그때는 Vercel 대시보드 Storage 에서 Blob 을 이 프로젝트에 연결하면 된다.
