# 29-30 — 사진과 상담 스트림이 실제로 지나간다 (두 번째 벽)

## 1. 왜 이 라운드인가

29-29 보고에서 솔직하게 적었다: "쿠키로 바꾸자 401 은 사라지고 **503** 이 나왔다. 벽이 둘이었고 첫 벽만 허물었다."
사장님 답: **"해결하자."**

두 번째 벽은 `server/marketplaceApi.ts` 의 `needsBucket()` 이었다. 29-2 에서 v17 의 Cloudflare R2(`env.BUCKET`)를
뜯어낼 때 사진·스트림 경로를 저장소와 **무관하게** 503 으로 막아 두었고, 29-23 이 파일 저장소 포트를 만들었지만
서류에만 썼다. 그래서 사장님 화면에서는:

- 접수 화면의 현장 사진 → "사진 저장소가 아직 연결되지 않았습니다"
- 파트너 증빙 사진 → 같은 말. 완료 확인은 전·후 사진을 요구하므로 **완료 요청 자체를 못 낸다**
- 상담 → 스트림이 안 열려 10초 폴링으로만 돈다 ("다시 연결 중 · 10초마다")
- 작업사례(포트폴리오) 사진 → 못 올린다

## 3. 설계 — `lib/media.ts`

**권한은 새로 만들지 않았다.** 도메인에 이미 있던 판단을 부른다:

| 무엇 | 누가 | 판단하는 곳 |
|---|---|---|
| 접수 사진 올리기 | 주문 고객, 접수·모집 중 | `marketplace.photoPermission(u, id, true)` |
| 증빙 사진 올리기 | 고객 또는 **선택된** 파트너, 거래가 살아 있을 때 | `media.tradeParty` (거래 `context` 와 같은 규칙) |
| 주문 사진 보기 | 주소가 보이는 사람 — 고객·관리자·선택된 파트너 | `marketplace.photoPermission(u, id, false)` |
| 작업사례 사진 올리기 | 승인된 파트너, `X-Publication-Consent: confirmed` 와 함께 | `community.uploadPermission` |
| 작업사례 사진 보기 | 본인·관리자, 또는 **게시된 사례에 쓰였으면 누구나** | `community.assetPermission` + 게시 여부 |

**바이트는 씻어서 넣는다.** v17 의 `cleanImage` 가 JPEG·PNG 만 받고 EXIF(위치·기기)를 벗긴다 — 파트너에게 가는 사진에
고객 집 좌표가 실리지 않는다. SVG 는 받지 않는다. 저장소에 먼저 넣고 표에 적으며, 표가 실패하면 저장소에서 지운다.

**표에는 자리만 남는다.** `photos.object_key` = `orders/<주문>/<사진>`, `portfolio_assets.object_key` = `portfolio/<파트너>/<사진>`.
바이트는 DB 에 오지 않는다(서류와 같은 이유 — 백업에 사진이 섞이지 않는다). 보관 기간 365일이 지난 주문 사진은
관리자가 주문 목록을 열 때 `purgeExpired` 가 저장소와 표에서 둘 다 지운다.

**응답은 우리 서버를 거친다.** 저장소 주소를 브라우저에 주지 않는다. 주문 사진은 `Cache-Control: private` — 공유 캐시가
남의 집 사진을 다음 사람에게 주면 안 된다. 게시된 작업사례 사진만 `public`.

**스트림은 v17 그대로.** `lib/chat-stream.ts` 의 `chatStream` 을 그대로 부른다: 2초마다 다시 읽고 바뀐 것만 보내며 28초에
닫아 브라우저가 다시 잇게 한다. 참여자가 아니면 첫 읽기가 403 을 던져 스트림 대신 보통의 403 JSON 이 나간다 — v17 과 같다.
쿠키 세션(29-29)이 있어서 `EventSource` 와 `<img>` 가 헤더 없이 인증된다. 이 라운드가 29-29 없이는 불가능했던 이유다.

## 4. 봇이 걷는 길 (`e2e:trade`, 저장소가 있을 때)

1. 고객이 접수 2걸음에서 현장 사진 한 장을 붙인다 → 접수 뒤 주문 상세 `.photo-grid` 에 보인다
2. 고객 창의 쿠키만으로 `/api/photos/:id` 가 **200 image/png** — `<img>` 가 가는 길 그대로
3. 낙찰 전 파트너 → **403**. 다른 파트너 → **403**
4. 낙찰 뒤 선택된 파트너 → **200**. 다른 파트너는 여전히 **403**
5. 상담이 열리면 화면이 "자동 연결 중"(SSE 연결)이라고 적는다
6. 파트너가 증빙 사진 두 장을 올리고, 그 바이트가 파트너에게 **200** 으로 내려온다
7. 그 두 장으로 완료 요청 → 고객 확인 → 정산까지 (이전과 같음)

저장소가 없으면 옛 길(503 확인 + 표에 직접 심기)로 간다. CI 는 이제 저장소를 준다.
