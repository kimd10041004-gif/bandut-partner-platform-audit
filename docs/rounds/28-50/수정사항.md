# 28-50 수정사항 (Claude) — 저장 용량·완료 사진 라운드

기반: `28-49` 복사본(스크래치 wf28-50)에서 작업. 28-49 감사 4건 전부 반영.

## 28-49-01 · 저장 실패 가시화 + 용량 관측 [반영]

- `save()` → boolean. 실패 시 `lastSaveError`에 기록(용량 초과·QuotaExceededError는 "저장 공간이 부족해 마지막 변경이 저장되지 않았습니다 …"로 치환)하고 `onSaveError` 콜백(옵션·속성)으로 통지. 성공하면 `lastSaveError = null`.
- `storageUsage()` → `{ chars, photoChars, photoCount, limit, ratio }`(직렬화 스냅샷 문자 수 기준). `STORAGE_SOFT_LIMIT = 4M`(`PlatformOptions.storageLimit` 주입 가능). `assertRoom(extraChars)`: 사진을 늘리는 쓰기(`addRequest`·`addPhoto`·`setCompletionPhotos`)에서 **변경 전에** 예상 용량이 한도를 넘으면 `PlatformError` — 스토어는 그대로.
- `PlatformProvider`가 `onSaveError`를 받아 `saveError`로 노출하고 `refresh()`마다 `lastSaveError`를 동기화. 앱 셸 `SaveErrorBanner`(`[data-save-error]`, `role="alert"`, sticky) — 다음 저장 성공 시 사라진다.
- vitest 2건: 실패 저장소 주입(기록·통지·복구), 한도 5,000자 주입 시 사진 3장 요청 거부 + 스토어 불변, `storageUsage` 수치.

## 28-49-02 · 사진 보관 정책 [반영]

- `PHOTO_RETENTION_DAYS = 90`. `prunePhotos(today, retentionDays?)`: `settled`(완료일)·`cancelled`(환불 생성일, 없으면 요청 생성일) 후 보관 기간 경과 건의 `photos`·`completionPhotos` 제거, 제거한 요청 수 반환(멱등, 날짜 검증).
- 관리자 현황 진입 시 `sweepDeadlines + sweepPaymentReminders + prunePhotos`. **저장 용량 카드**(`[data-storage]`): 사용률 막대(70%↑ 주황, 90%↑ 빨강), 사용/한도·사진 장수·용량, "오래된 사진 정리 (90일)" 버튼(`[data-prune-photos]`).
- vitest 1건: 정산 100일 경과 제거(현장+완료 사진), 13일 전 유지, 취소 건은 생성일 기준(기본 90일 유지·0일이면 제거), 재실행 0, 잘못된 날짜 거부.

## 28-49-03 · 시공 완료 사진 [반영]

- `RepairRequest.completionPhotos?`, `store.setCompletionPhotos`. `setCompletionPhotos(requestId, partnerId, photos)`: 낙찰 파트너(`partnerOf`)만, `in_progress`/`completed` 상태, 최종 결제 전까지. `validatePhotos` + 용량 가드. 스냅샷 복원 시 검증.
- 파트너 내 작업 카드 `CompletionPhotos`: "완료 사진" 파일 입력(`aria-label`, 리사이즈 재사용, 3장 상한 안내) + `PhotoStrip completion`(삭제 가능). 최종 결제 후에는 입력 없이 "시공 완료 사진" 열람만. 고객 거래 상세 "시공 완료 사진 — 최종 결제 전에 확인하세요", 관리자 거래 상세 "시공 완료 사진"(`[data-completion]`).
- `PhotoStrip`에 `title`·`completion` 프롭(alt 문구도 구분). vitest 1건(타 파트너 거부·시공 전 거부·결제 후 거부·스냅샷 왕복·손상 거부).

## 28-49-04 · e2e + 실측 [반영]

- e2e 5단계 추가(107→**112**): 파트너 완료 사진 1장 첨부 / 고객 거래 상세 완료 사진(최종 결제 전) / 관리자 저장 용량 카드 "사진 3장" / localStorage를 가득 채운 뒤 설정 저장 → 저장 실패 배너 / 정리 후 저장 성공 → 배너 해제. (초안은 같은 키를 같은 크기로 덮어써 통과해 버림 → 공지 문구를 8KB 늘려 스냅샷을 키우도록 수정.)
- 실측 `capture-28-50.mjs`: 완료 사진 4장 첨부 → 3장 상한·삭제, 결제 전/후 입력 유무, 고객 상세 완료 2·현장 2, 저장 용량 카드 수치(사진 4장 318KB), 정리 버튼 안내, 배너 표시·해제, 모바일 가로 스크롤 없음.

## 기타

- 저장 실패 배너를 sticky로 두어 긴 화면 어디서든 보인다. 각 화면의 "저장했습니다" 성공 문구는 도메인 반영 기준이라 배너와 함께 보일 수 있다 — 배너가 영속 실패의 단일 출처.
