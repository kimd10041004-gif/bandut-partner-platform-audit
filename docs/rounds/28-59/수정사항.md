# 28-59 수정사항 — 백업 권한·감사 무결성 (28-58 감사 4건 반영)

원본 `28-58`은 건드리지 않고 스크래치 복사본에서 작업한 뒤 `28-59`로 물질화했다 (해시 기준선 v56 검증 통과).

## 28-58-01 (상) 파트너가 플랫폼 전체를 내려받고 덮어쓸 수 있던 문제
- `src/features/Dashboard.tsx`(파트너 앱 첫 탭)의 "데이터 백업" 카드와 `doExport`/`doImport`를 **제거**했다. 함께 쓰이지 않게 된 `useState`·`downloadText`·`isKnownError`·`refresh` 참조도 정리했다.
- 관리자 설정 탭에 `BackupCard`를 신설했다(`src/features/admin/AdminSettings.tsx`): 내보내기 `[data-export-backup]`(`banded-backup-YYYY-MM-DD.json`), 복원은 **확인 문구 "복원"**을 입력해야 파일 선택이 열린다(`[data-import-backup]`, 비활성 시 `.disabled`). 결과 `[data-backup-msg]` / 오류 `[data-backup-error]`.
- 파트너용 내보내기는 이미 있는 "내 정산 내역 CSV"(28-47-03)가 담당한다 — 파트너 화면에는 플랫폼 전체를 읽고 쓰는 진입점이 남아 있지 않다.
- `label.btn-secondary` 스타일을 추가해 파일 선택 라벨이 버튼과 같은 모양을 갖게 했다.

## 28-58-02 (상) 복원이 감사 로그를 지우고, 복원 자체가 기록되지 않던 문제
- `platform.restoreBackup(json): { kept, ignored }` — 현재 감사 로그를 보존한 채 스냅샷을 적용하고, 가져온 로그는 반영하지 않으며, `관리자 · 백업 복원 · rev N · 보존 k건 · 가져온 기록 m건 무시`를 기록한 뒤 저장한다.
- `importSnapshot`/`applySnapshot`(다중 탭 `syncFromStorage`·기동 로드 경로)의 의미는 그대로 두었다. 감사 로그는 "이 브라우저에서 실제로 일어난 일"만 담는다.
- `auditSeq`를 보존 건수 기준으로 유지해 복원 후 새 기록의 id가 보존된 기록과 충돌하지 않는다.

## 28-58-03 (중) 인증 보안 이벤트가 기록되지 않던 문제
- `AuthService.onSecurityEvent`(`platform.onSaveError`·`onConflict`와 같은 할당형 훅) + `SecurityEvent` 타입, `maskPhone()` 헬퍼.
- 발화: 로그인 실패·로그인 잠금(`recordFail`), OTP 시도 초과, 비밀번호 변경(관리자/회원), 회원 탈퇴.
- 대상은 계정 ID 또는 마스킹 번호(`고객 010****5678`)이며 원문 번호·비밀번호·OTP는 남기지 않는다. 훅이 던져도 인증 흐름은 막지 않는다(try/catch).
- `PlatformContext`가 `auth.onSecurityEvent = (e) => platform.audit('system', …)`로 잇고 언마운트 시 해제한다.

## 28-58-04 (중) 감사 로그의 용량·조회 가시성
- `storageUsage()`에 `auditChars`/`auditCount` 추가, `otherChars`에서 차감. 저장 용량 내역 막대에 `기록` 세그먼트(`[data-storage-audit]`, `.seg.audit`).
- 운영 기록 카드: 주체 필터(`[data-audit-filter="all|admin|system"]`) + 검색(`aria-label="기록 검색"`) + 20건 단위 "더 보기"(`[data-audit-more]`), 제목 `운영 기록 (일치/전체건)`, CSV는 필터 결과 기준.
- vitest 3건·e2e 11단계 추가, 실측 스크린샷 5장, `UI_가이드.md` "백업 권한·감사 무결성 (28-59)" 절, 버전 28.59.0, 헤더 칩 28-59.
