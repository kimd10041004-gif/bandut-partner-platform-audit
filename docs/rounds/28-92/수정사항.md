# 28-92 수정사항 — 홈=요청 폼 · 서비스 카탈로그 확장 · 전국 시·도 (참고 v12 대조 3-1)

`../28-90/참고_v12_대조.md` "더할 것" 1번이다. 참고 시안은 홈이 곧 요청 폼이고, 접수 분야가 **5 그룹 / 19 분야 +
"분야를 모르겠어요"**, 지역이 **전국 17 시·도 → 시·군·구**다. 28-16의 카테고리 13개는 부위 이름(도배·장판·욕실…)이라
냉난방·가전·리모델링·철거·청소가 전부 '기타'였고, 지역은 자유 입력이라 "서울강서구화곡동123-45" 같은 값이 그대로
저장됐다(28-64가 가명본 축약에서 그 값을 닫아야 했던 이유).

## A. 카탈로그 (`src/domain/catalog.ts` 신설)

- `CATALOG` 20개: 참고안의 코드(`PLUMBING` … `UNKNOWN`)·라벨·안내 문구. **식별자는 라벨(한국어)** 이다 — 이 저장소의
  요청·패키지·질문·전문 분야·비활성 목록이 28-16부터 라벨을 저장해 왔기 때문에 코드로 바꾸면 스냅샷 전체를 옮겨야 한다.
  코드는 나란히 두어 뒤 라운드(안전 검토 28-93·라우팅)가 코드로 판단할 수 있게 했다.
- `SERVICE_GROUPS` 5개(설비·전기·기기 / 문·창·가구 / 인테리어·마감 / 주거·상업공간 공사 / 복구·유지관리). "분야를
  모르겠어요"는 그룹 밖이고 늘 마지막이다. `catalog.test`가 카탈로그·`ALL_CATEGORIES`·그룹이 **같은 집합**임을 지킨다.
- `LEGACY_CATEGORY_MAP` 13 → 20 (누수·수전·배수 → 급배수·누수·설비, 장판·타일 → 바닥·타일, 욕실 → 주방·욕실 공사,
  기타 → 분야를 모르겠어요 …). `normalizeCategory()`가 현재 라벨은 그대로, 옛 라벨은 옮기고, 모르는 값은 `undefined`.
- `RepairCategory`(types.ts)는 20개 라벨 유니온으로 바뀌었다. 코드에 박힌 옛 라벨(기본 패키지·질문·랜딩 서비스 카드·
  테스트 60여 곳)은 전부 옮겼다.

## B. 옛 스냅샷 이전 (`platform.ts`)

- `parseSnapshot` → **`migrateLegacyCategories`** → 검증. 요청은 옮길 수 없으면 "분야를 모르겠어요"로(요청을 잃지 않는다),
  패키지·질문·비활성 목록·전문 분야는 옮길 수 없는 항목을 **버린다**(운영 설정이라 다시 고르면 된다). 검증이
  `packages[1].category: 로봇 수리`로 스냅샷 전체를 거절하지 않게 하는 것이 요지다.
- `addRequest`가 분야를 **처음으로 검증**한다(옛 라벨은 옮기고 목록 밖은 `알 수 없는 분야`). 그동안 요청의 category는
  어떤 문자열이든 저장됐다. `updateProfile`도 전문 분야 토큰을 옮겨 저장한다(중복 제거).

## C. 지역 — 전국 17 시·도 (`catalog.ts` `DISTRICTS`)

- 참고안의 시·도/시·군·구 목록 그대로(17 시·도, 세종은 세종시 하나). 저장 형식은 종전과 같은 `"서울 강서구"` 한 문자열이라
  `profileMatch`(토큰 포함)와 가명본 축약(시/도 + 시군구)이 그대로 맞는다. `formatRegion`·`parseRegion`.
- `src/ui/RegionSelect.tsx`: 시·도 → 시·군·구 두 select(`aria-label="시·도"`, `"시·군·구"`). 시·도만 고른 상태는
  빈 문자열(아직 지역이 아니다), 세종은 곧바로 채운다. 요청 위저드와 고객의 **요청 수정 폼**(`수정 시·도`/`수정 시·군·구`)이
  같이 쓴다. 자유 입력 칸은 없어졌다 — 옛 값이 들어오면 비어 있는 것으로 보여 주고 다시 고르게 한다.

## D. 홈 = 요청 폼 (`Landing.tsx`)

- 히어로 오른쪽의 사진을 **요청 폼 카드**(`[data-hero-form]`)로 바꿨다: "어떤 작업이 필요하세요?" + 그룹 탭 6개(전체 + 5) +
  분야 카드 20장(이름 + 한 줄 안내). 카드를 누르면 그 분야로 위저드가 열린다(로그인 게이트를 지나도 선택이 남는다 —
  28-16의 `setDraftCategory`). 히어로 문구·CTA·신뢰 배지는 그대로다.
- `src/ui/CategoryPicker.tsx`: 그룹 탭 + 카드 그리드. 홈 히어로(설명 있음)·랜딩 "카테고리" 섹션(칩)·요청 위저드(설명 있음)·
  파트너 프로필 전문 분야(다중 선택 칩)가 같은 부품이다 — 고객이 고르는 분야와 파트너가 내거는 분야가 같은 목록·같은
  이름이어야 매칭이 맞는다. 카드는 `data-category="<라벨>"`을 단다(설명 문구에 다른 분야 이름이 섞이므로 e2e는 이것으로 집는다).
- 관리자 설정의 분야 토글은 20개가 되면서 그룹 이름을 옆에 단다.

## 하지 않은 것

- **한 요청에 여러 분야**(참고안 `workItems[]`)와 **안전 질문**(문 잠김·긴급 증상)·`MANUAL_REVIEW`는 28-93이다. 둘은
  같은 폼 단계에 함께 붙고 판단 규칙이 코드(`scopeReviewCodes`)에 걸리므로 카탈로그가 먼저 있어야 했다.
- 상세 주소·연락처 칸(참고안 3단계)은 연락처 가림(28-94)과 함께.
- 히어로 사진(`/brand/hero-main.jpg`)은 파일을 남겼다 — 28-101(브랜드 필름·배경)에서 다시 정한다.
