핵심 지적: 28-50에서 사진에만 보관 정책을 넣었다. 그런데 **알림은 모든 이벤트마다 쌓이고 한 번도 지워지지 않는다** — 새 일감 알림은 매칭 파트너 수만큼 복제되고(28-47), 견적 수정·답변·답글까지 추가돼(28-53·54) 활성 사용자 기준 하루 수십 건이 영속된다. 벨 패널은 20건만 보여 주면서 저장소에는 전부 남는다. **채팅도 길이·건수 제한이 없고** 정산이 끝난 거래의 대화가 영원히 남는다(개인정보 최소 보관 원칙 위반, 저장 용량 카드에도 잡히지 않음). 저장 용량 카드는 "사진"만 세분화해 나머지가 왜 커지는지 운영자가 알 수 없다.

## 상 (High)

### 28-54-01 · 알림 보관 정책
→ 요구: `NOTIFICATION_READ_RETENTION_DAYS = 30`, `NOTIFICATION_UNREAD_RETENTION_DAYS = 90`, `NOTIFICATION_CAP = 500`. `pruneNotifications(now)`: 읽은 알림 30일·안 읽은 알림 90일 경과 제거, 그래도 상한 초과면 오래된 것부터(읽은 것 우선) 제거, 제거 수 반환(멱등). 앱 기동(`initPlatform`)과 관리자 현황 진입 sweep에서 실행. **도메인 테스트 필수**(경계·상한·멱등·스냅샷).

### 28-54-02 · 채팅 한도·보관
→ 요구: `CHAT_MAX_TEXT = 500`자 초과 거부, 요청당 `CHAT_MAX_PER_REQUEST = 300`건 초과 거부(안내 문구). `pruneChats(today, retentionDays = 180)`: 정산 완료(완료일)·취소(환불/요청 생성일) 후 180일 경과 거래의 채팅과 읽음 기록 제거, 제거 수 반환(멱등). sweep에 포함. 테스트.

## 중 (Medium)

### 28-54-03 · 저장 용량 내역
→ 요구: `storageUsage()`에 `notificationChars/Count`, `chatChars/Count` 추가. 관리자 저장 용량 카드에 사진·알림·채팅·기타 비중 막대(`[data-storage-breakdown]`)와 "오래된 알림 정리"(`[data-prune-notifications]`)·"오래된 채팅 정리"(`[data-prune-chats]`) 버튼. 채팅 입력에 남은 글자 수·`maxLength`.

### 28-54-04 · e2e + 실측
→ 요구: e2e — 저장 용량 카드에 알림·채팅 건수 표시 / 501자 채팅 거부 / 저장소의 알림을 읽음·40일 전으로 조정 후 관리자 현황 진입 → sweep으로 알림 0건. 상한·보관 규칙은 vitest. 실측: 카드 내역·정리 버튼·채팅 한도.
