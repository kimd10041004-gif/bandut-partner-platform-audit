# 29-13 수정사항 — 업체 찾기, 로그인 없이

명세 4절(고객이 보는 업체 페이지)을 구현한다. 기존 `partners`·`portfolio_cases`·`reviews`를 그대로
쓰고 표를 새로 만들지 않았다.

## 1. 로그인 없이 본다

명세 4절: "업체와 공개 시공 사례는 로그인 없이 열람한다. 질문 작성·상담 시작·작업 요청 때
로그인한다."

지금까지 업체 상세(`/companies/[id]`)는 세션이 있어야 열렸다. 둘러보는 사람에게 먼저 로그인을
요구하면 아무도 업체를 볼 수 없다. 업체 페이지는 원래 공개하려고 만드는 것이다.

`server/marketplaceApi.ts`의 공개 읽기 자리(랜딩·서비스 소개가 이미 쓰는 곳)에 둘을 더했다.

```
GET /api/companies              업체 찾기 목록 — 지역·분야·이름으로 좁힌다
GET /api/company/<id>           업체 상세 — 화면이 부르는 주소 그대로
```

상세 경로 이름은 화면이 부르는 그대로 뒀다(`company/<id>`). v17 화면을 고치지 않는 것이 29-1부터의
규칙이다.

## 2. 나오는 것은 승인된 업체와 공개된 사례뿐

목록도 상세와 같은 조건으로 고른다 — `status='APPROVED'`이고 계정이 정지되지 않은 업체. 목록에서
보이는데 눌러 보면 404인 일이 없어야 한다. 미승인 업체는 주소를 직접 쳐도 404다.

이 판단은 `lib/community.ts`가 한다. 라우터는 누구에게 보여 줄지 정하지 않는다.

## 3. 숫자를 만들어 내지 않는다

카드에 붙는 것은 **행에서 나온 것뿐**이다.

| 표시 | 어디서 |
|---|---|
| 공개 사례 N건 | `portfolio_cases`에서 `published=1`인 행의 수 |
| 후기 N건 · 평점 X.X | `reviews`에서 `hidden=0`인 행. **없으면 "후기 없음"** |

후기가 0건인 업체에 0.0점을 붙이지 않는다. 나쁜 업체처럼 보이고, 그건 근거 없는 표시다.

**"시공 건수"라고 쓰지 않았다.** 우리가 세는 것은 업체가 스스로 올린 공개 사례이지 완료한 공사가
아니다. 이름이 정확해야 숫자가 정직해진다. 명세 4절의 "시공 건수·별점·인기 표시를 근거 없이
만들지 않는다"가 그 말이다.

인기순·추천순 정렬도 넣지 않았다. 근거로 삼을 것이 아직 없다 — 업체명 순으로만 낸다.

## 4. 목록은 21개를 받아 20개를 보여 준다

"더 있는가"를 알려고 전체 개수를 세면 목록을 한 번 더 훑는다. 한 개를 더 받아 보고 넘치면 "더
있습니다"라고만 말한다.

`work_items`는 JSON 배열 문자열, `regions`는 문자열이라 LIKE로 고른다. 업체 수가 적은 동안은
이것으로 충분하고, 늘어나면 색인 있는 표로 옮긴다 — 그때 바뀌는 것은 이 함수 하나다.

## 하지 않은 것

- **공개 Q&A** — 다음 순서다.
- **거래 전 상담방** — 그다음이다.
- **업체별 페이지 편집기** — 편집본·공개본 분리가 필요해 따로 잡는다.
- **정렬 선택** — 근거 있는 기준이 생기면 그때.
