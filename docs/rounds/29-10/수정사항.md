# 29-10 수정사항 — 공개 화면에 관리자 문을 내걸지 않는다

사장님이 프리뷰를 직접 보고 네 가지를 짚었다. 둘은 이 라운드에서 고쳤고, 하나는 확인이었고,
하나는 사장님이 정하실 일로 남았다.

| 짚은 것 | 이 라운드 |
|---|---|
| 탭에 지구 모양이 뜬다 | 검사가 아이콘을 **받아 본 적이 없다**는 것을 찾았다. 받아 보게 고치고 PNG 예비를 뒀다 |
| 인테리어 꾸미기 쓸 만하다 | 확인 — 손댄 것 없다 |
| 관리자 비번을 모르겠다 | 저장소·채팅 어디에도 쓰지 않는다. Vercel 환경변수에만 있다 |
| 관리자 접속이 한 번에 열리면 보안 문제다 | 공개 화면에서 내렸다 (아래 1) |

## 1. 관리자 로그인을 공개 화면에서 내렸다

`/login`이 세 역할을 나란히 내걸고 있었다. 손님 누구나 "관리자"를 골라 비밀번호를 넣어 볼 수
있다는 뜻이고, **운영자 문이 어디인지도 대놓고 알려 준다**. 서버가 막아 주더라도 문을 내걸 이유는
없다.

```
전   /login          [ 고객 ] [ 파트너 ] [ 관리자 ]
후   /login          [ 고객 ] [ 파트너 ]
     /login/admin    역할 선택 없음 · "관리자 로그인"
```

`/login/admin`은 화면 어디에서도 링크하지 않는다 — 아는 사람만 직접 친다.

**이건 문을 감춘 것이지 잠근 것이 아니다.** 완전히 다른 주소로 떼거나 Vercel 배포 보호로 막는 것은
사장님이 정하셔야 할 일이라 남겼다.

두 자리에 있던 "세 역할을 고를 수 있다" 단언을 뒤집었다.

| 어디 | 전 | 후 |
|---|---|---|
| `scripts/e2e-next.mjs` | 세 역할이 다 있다 | 공개 화면에 `admin`이 **없다** · `/login/admin`은 직접 치면 열린다 · "관리자 로그인"이라고 말한다 (19 → 22) |
| `deploy-check` 화면 안 검사 | 세 역할을 센다 | `data-login-role="admin"`이 있으면 **실패**시킨다 |

## 2. 탭 아이콘 — 검사가 한 번도 받아 본 적이 없었다

로컬에서 `/favicon.svg`는 200이고 `image/svg+xml`이고 `<link rel="icon">`도 제대로 나간다.
그런데 우리 검사 중 **어느 것도 아이콘을 받아 본 적이 없다**.

```
단위 가드              파일이 저장소에 있는가          ← 여기까지
deploy-check 에셋 검사  src="…" 만 센다                ← 아이콘은 <link rel="icon"> 이다
```

29-7에서 `metadata.icons` 구멍을 막았다고 했는데, 그건 "저장소에 파일이 있는가"까지였다.

배포 확인이 이제 홈·로그인 HTML에서 아이콘 `href`를 뽑아 **실제로 받아 보고**, 200이면서 이미지
MIME인지 확인한다. 아니면 "브라우저가 기본 아이콘을 씁니다"라고 말하고 실패한다.

SVG를 못 읽는 브라우저를 위해 PNG 예비도 뒀다.

```
icons:{icon:[{url:'/favicon.svg',type:'image/svg+xml'},{url:'/brand/favicon.png',type:'image/png'}]}
```

`app/layout.tsx`는 v17 원본 서식(한 줄)을 그대로 지켰다 — 포매터가 이 파일을 늘려 놓은 것을
되돌렸다. 29-1에서 정한 대로 v17 화면 파일은 포맷 대상 밖이다.
