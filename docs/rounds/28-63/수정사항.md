# 28-63 수정사항 — 허용 목록 완성·입찰 이력·토글 접근성 (28-62 감사 4건 반영)

원본 `28-62`는 건드리지 않고 스크래치 복사본에서 작업한 뒤 `28-63`으로 물질화했다 (해시 기준선 v60 검증 통과).

## 28-62-01 (상) 허용 목록을 절반만 적용했고, 안전망이 아는 이름만 보던 문제
- 통째로 통과하던 컬렉션에 각각 허용 목록을 걸었다:
  `PSEUDONYMOUS_ESTIMATE_KEYS`·`STORED_ESTIMATE`·`SLOT`·`PAYMENT`·`REFUND`·`PARTNER_CANCEL`·`PACKAGE`·`QUESTION`·`SETTINGS`.
  자유 서술 3종(`Estimate.memo`, `Refund.reason`, `PartnerCancel.reason`)은 목록에 없다.
  `settings`는 운영 지표(`disabledCategories`·`warrantyDays`)만 남고 공지·약관은 빠진다. `daysOff`는 날짜 배열이라 유지.
- **`assertPseudonymousShape` 추가** — 결과의 각 컬렉션을 허용 목록과 대조해 **목록 밖 키가 하나라도 있으면 실패**시킨다.
  값 대조(`assertNoRealNames`)와 함께 두 겹으로 건다. 새 필드가 생기면 기본이 "제외"이고,
  내보내려면 목록에 이름을 적어야 한다 — 컬렉션을 통째로 넘기는 실수가 구조적으로 성립하지 않는다.

## 28-62-02 (상) 낙찰 전 입찰 철회가 흔적을 남기지 않던 문제
- `BidWithdrawal { id: BW-0001, requestId, partnerId, at, beforeDeadline }` + 스냅샷 `bidWithdrawals`/`bidWithdrawalSeq`(검증 포함).
- `withdrawBid`가 맵에서 지우기 **직전에** 기록한다(기존 알림·재오픈 흐름 불변).
- `bidWithdrawals(partnerId?)` 최신순, `bidWithdrawalCount(partnerId, sinceDays, today)` — 28-51 `partnerCancelCount`와 같은 90일 창.
- 관리자 회원 목록에 "입찰 철회 n회 (90일)"(`[data-member-bid-withdrawals]`).
- 파트너 열람권에 `withdrawnBids` 포함 + **철회한 요청도 열람 범위에 들어온다**(입찰이 지워져도 내 이력이므로).
- 가명본에서도 이 컬렉션이 허용 목록을 거친다.
- 덧붙여 `exportPartnerData`에 **비유출 검사**를 걸었다 — 본인 상호를 제외한 고객·타 파트너 이름이 남으면 실패.
  가명본에만 있던 안전망을 대칭으로 맞췄다.

## 28-62-03 (중) 토글 그룹이 선택 상태를 보조기기에 알리지 않던 문제
- `src/ui/primitives.tsx`에 `ToggleGroup<T>` 추가 — `role="group"` + `aria-label`, 각 버튼 `aria-pressed`.
  옵션이 `data-*`를 실어 나르므로 기존 e2e 선택자가 그대로 산다.
- 8곳 적용: 고객 결제 수단·요청 질문 보기·희망 시간대, 관리자 회원 역할/운영 기록 주체/백업 모드,
  파트너 작업 상태/정산 상태. 질문 보기와 시간대·작업/정산은 구조상 인라인 유지가 나아 같은 속성만 직접 부여했다.
- `.filter-group` 클래스·모양을 그대로 써서 시각 변화가 없다(`visual-check` 통과로 확인).
