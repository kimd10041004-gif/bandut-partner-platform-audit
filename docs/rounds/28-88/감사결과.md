## 01 (상) 저하 응답에 `cache-control: public, max-age=60`이 붙는다

`handlePublicStats`는 응답 셋에 **같은 헤더**를 붙인다 — 정상 집계, "아직 실적 없음"(`stats: null`),
그리고 **대기열이 찼을 때의 `stats: null`**(`acquireDbSlot()`이 `false`):

```ts
const headers = { 'cache-control': `public, max-age=${CACHE_SECONDS}` }   // 세 경우 공통
...
if (!(await acquireDbSlot())) return { rev: -1, stats: null }             // → 200 + 위 헤더
```

`public`은 CDN·중간 캐시에게 "누구에게나 이 응답을 60초 재사용해도 된다"는 뜻이다. 즉 **부하가 몰린
순간의 빈 응답 하나가 60초 동안 모든 방문자에게 "실적 없음"으로 서빙될 수 있다** — 부하가 지나간 뒤에도.
28-87-03이 "랜딩은 null을 감당한다"고 적은 것은 *한 방문자*에 대해 참이고, 캐시를 거치면 *모두*에 대해
거짓이 된다.

게다가 클라이언트는 **"실적이 없다"와 "지금 못 읽었다"를 구별할 수 없다** — 둘 다 `{ stats: null }`이다.
랜딩이 지표 블록을 접는 것은 같지만, 그 뒤의 재시도·로그·운영자의 판단이 다르다.

**고치는 모양**: 저하 응답에는 `cache-control: no-store` + `degraded: true`. 정상 `null`(행 없음)은
지금대로 `public`이어도 된다 — 그것은 사실이다.

## 02 (중) 멈춘 쿼리 하나가 인스턴스의 공개 경로를 얼린다

`acquireDbSlot()`은 자리가 나기를 **무기한** 기다리고, `load()`의 `db.query`에는 **타임아웃이 없다**
(`pg`의 `Pool`은 기본값이 없다). DB가 응답을 멈추면(네트워크 단절·잠금 대기) 슬롯 하나가 영원히 잡히고,
뒤의 32개는 영원히 기다리며, 33번째부터는 `null`을 받는다 — 01의 헤더를 달고.

28-87-03의 동시성 상한은 "DB가 느릴 때 로그인을 굶기지 않기" 위한 것이었는데, **DB가 멈추면**
같은 장치가 공개 경로를 통째로 세운다. 상한은 그대로 두고 **시간의 상한**을 더하면 된다 —
`Pool`에 `query_timeout`·`statement_timeout`, 대기열에 대기 시간 상한. 둘 다 몇 줄이다.

## 03 (중) 가드가 파일 밖의 변형을 못 본다 — #243이 고친 것의 거울상

#243은 `export const cache = new Map()`을 놓치던 것을 고쳤다. 그런데 `moduleStateOfSource`는
변형 여부를 **같은 파일 안에서만** 찾는다:

```ts
if (constMatch !== null && !MUTATORS.some((m) => src.includes(`${name}.${m}`))) continue
```

`export const cache = new Map()`을 `a.ts`에서 선언하고 `b.ts`에서 `cache.set(...)`하면 `a.ts`만 보는
가드는 "읽기 전용 표"로 판단해 **건너뛴다.** #243이 넓힌 것이 `export`인데, `export`의 뜻이 바로
"다른 파일이 쓴다"다 — 넓힌 자리에서 거짓 음성이 생겼다. 거짓 경보를 없애려다(28-88-05) 반대쪽이 열렸다.

그리고 **"28-87의 두 결함은 둘 다 이 자리에서 멈췄을 것이다"는 과장이다.** `getPool` 위 주석에는
28-87 이전부터 "**서버리스**에서 호출 간에 재사용된다"가 있었다 — 그 단어 하나로 `MENTIONS` 검사를
통과한다. 즉 결함 01(풀 공유 오해)은 이 가드로 멈추지 않았을 것이다. 가드가 막는 것은 "적지 않는 것"이지
"틀리게 적는 것"이 아니라고 05가 스스로 적어 두었는데, 같은 문서의 다른 문단이 그것을 잊었다.
**한계를 적어 두고도 그 한계 밖의 값을 주장했다** — 28-86 감사 01, 28-87 감사 02와 같은 모양이다.
