## 상 (High — 틀)

### 28-12-01 · 토큰이 단층 구조 — 팔레트와 시맨틱이 섞여 있음 (seed-design 대조)
현 tokens.css는 `--brand: #15695a`처럼 시맨틱 이름에 원색 값이 직접 박혀 있다. seed-design의 핵심은 **팔레트(원색 스케일) ↔ 시맨틱(용도)** 2계층 분리 — 리브랜딩은 팔레트 교체로, 테마는 시맨틱 오버라이드로 역할이 나뉜다.
→ 요구: tokens.css를 팔레트 계층(`--teal-600`, `--navy-900`, `--gray-*`, 상태 원색)과 시맨틱 계층(기존 변수명 유지, 팔레트 참조)으로 재구성. **컴포넌트 CSS와 다크 블록은 무변경** — 결과 값 동일성을 빌드 CSS로 증명할 것.

### 28-12-02 · 프로젝트 디자인 시스템 정의 문서 부재 (design-to-ui 대조)
UI_가이드.md는 "어디를 고치나"를 답하지만, "우리 디자인이 무엇인가"(아이덴티티·매핑·레시피)를 정의한 문서가 없다. naver design-to-ui의 project-design-system 개념처럼 모든 UI 작업의 단일 참조점이 필요하다.
→ 요구: `DESIGN_SYSTEM.md` — Identity/팔레트→시맨틱 매핑 표/타이포 스케일/컴포넌트 인벤토리·레시피/모션 규칙/시안 상태 가이드 매핑.

### 28-12-03 · 시각 검증이 수작업 — QA 파이프라인 미공식화 (design-qa 대조)
매 라운드 Playwright 검증을 손으로 짜고 있다. 절차를 스크립트로 공식화해야 다음 라운드부터 검증이 재현 가능하다.
→ 요구: `scripts/visual-check.mjs` — 주요 탭 스크린샷 + 라이트/다크 배경 픽셀 검증을 한 번에 수행, 실패 시 비정상 종료. 검증결과.md의 공식 도구로 편입.

## 중 (Medium)

### 28-12-04 · 대시보드 첫인상이 지표로 바로 시작 (시안·bear2u 철학 대조)
파트너 모바일 시안의 홈은 "{이름} 파트너님, 좋은 하루 되세요!" 인사말로 시작한다. 획일적 대시보드 탈피 관점에서도 아이덴티티 있는 히어로가 필요하다.
→ 요구: 대시보드 상단 히어로 — 프로필 업체명 연동 인사말 + 오늘 날짜, 대형 타이포.
