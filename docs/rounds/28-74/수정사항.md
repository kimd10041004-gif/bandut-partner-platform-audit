# 28-74 수정 사항 — 「보관함이 저장을 막지 않게」

**사용자 결정: 감사 4건 + 보관함 전체 목록 UI.**

28-73은 28-72의 수정을 완성했고, 그 과정에서 28-72-03의 보관함(덮이는 스냅샷을 지키는 장치)을 넣었다.
이번 감사(`28-73/감사결과.md`)는 그 장치가 **정작 이 기기의 정상 저장을 실패시킬 수 있다**는 것을 짚었다 —
최대 12MB를 쓰면서 용량 회계 어디에도 없었고, 그중 꺼낼 수 있는 것은 1개뿐이었다. 손실을 막으려던 것이
손실을 만드는 상태라 이번 라운드의 중심이다.

---

## 28-73-01 (상) 보관함을 용량 회계 안으로 + 예산

**회계.** `PlatformOptions.externalChars?: () => number`를 두고, `storageUsage()`가 `externalChars`·`totalChars`를
함께 돌려준다. `ratio`와 `assertCapacity`가 **합계** 기준이 됐다. 도메인은 여전히 저장소를 모른다 — 앱이
알려 준다(`initPlatform()`이 `() => overwrittenChars(storage)`를 넘긴다). 넘기지 않는 호출자의 동작은
`() => 0` 기본값이라 그대로다. 용량이 모자라 던지는 문구에 `보관함 NKB 포함`이 붙어 **원인이 보인다**.

**예산.** 개수 상한만으로는 부족했다 — 스냅샷 상한이 4MB이므로 3개는 12MB이고, 그것만으로 브라우저
오리진 할당량을 넘긴다. `OVERWRITTEN_BUDGET = STORAGE_SOFT_LIMIT / 4`(1MB) 안에서만 유지하고 넘치면
**오래된 것부터** 버린다. 방금 덮인 본문 하나도 예산에 안 들어가면 **보관을 포기한다** — 저장을 막느니 낫다.

**용량 카드**(관리자 현황)에 보관함 세그먼트와 KB 표기를 더했고, 사용량 표기가 `chars`에서 `totalChars`로 바뀌었다.

회귀: `platform.test` 2건("보관함 크기가 카드와 가드에 잡힌다" — 수정 전에는 `externalChars` 자체가 없었고
`ratio`가 실제보다 낮았다 / "`externalChars`가 던져도 용량 계산은 계속된다"), `bootstrap.test` 2건(예산 초과 ·
하나도 안 들어가면 건너뜀).

## 28-73-02 (중) 보관함 계약을 실제 구현으로 테스트

`src/app/bootstrap.test.ts`에 보관함 7건을 더했다(기존 커서 3건 옆): 최근 것이 앞 · 개수 상한 · 예산 초과 시
오래된 것부터 · 하나도 안 들어가면 보관 안 함 · 손상 JSON과 배열 아닌 값 내성 · `setItem`이 던져도 안 샘 ·
저장소 없음. 관리자 목록 UI는 서버 e2e 1단계로 덮었다(28-73-04).

## 28-73-03 (중) 계정 잠금에 최근 성공 IP 면제

28-72-02의 계정 카운터(30회)는 무차별 대입을 막았지만, 아이디가 고정된 관리자에게는 "누구나 30회로 운영을
15분 멈춘다"가 되어 28-71-02가 없앤 DoS를 되살렸다. **최근 30일 안에 그 계정으로 성공한 IP는 계정 잠금에서
면제**한다(`trustedIps`, 계정당 5개까지, `auth_state` 스냅샷에 남아 서버리스의 다른 인스턴스도 안다).

- 공격자의 IP는 성공한 적이 없다 → 무차별 대입은 여전히 30회에 막힌다.
- 운영자는 늘 쓰던 자리에서 계속 들어온다 → 남이 운영을 멈출 수 없다.
- (계정, IP) 5회 잠금은 **면제하지 않는다** — 그 IP 자체가 잠긴 것은 그대로다.

로컬 모드는 `lockScope`가 없어 기억도 면제도 없다(동작 무변화). 회귀 3건 + 서버 경로는 e2e가 덮는다.

## 28-73-04 (중) 보관함 전체 목록 UI

개수를 보여 주면서 첫 항목만 내려받던 버튼을 **목록**으로 바꿨다 — 항목마다 시각·크기·내려받기 버튼, 그리고
`보관함 비우기`. 3개를 보관하면서 1개만 꺼낼 수 있던 상태(나머지는 용량만 차지)가 없어졌다. 새 화면은 만들지
않았다 — 기존 백업 카드 안이고, 내려받은 JSON은 바로 옆 복원 입력이 받는다.

`readOverwritten()`을 컴포넌트 본문에서 `useState` 초기화로 옮겨 **리렌더마다 파싱하지 않는다**.

## 곁들여 고친 것

- 서버 e2e의 "가입 코드 없이는 가입할 수 없다"가 `sleep(300)` 뒤에 화면을 읽고 있었다 — 첫 요청이 느리면
  (풀 생성·첫 쿼리) 아직 오지 않은 응답을 실패로 읽는다. 이번 라운드 중 로컬에서 실제로 한 번 그렇게 났다.
  `waitForText` 헬퍼로 **문구가 나타날 때까지 기다린다**(10초 상한). 고정 sleep을 단언 앞에 두지 않는다.

## PR 리뷰(Copilot) 반영 2건

리뷰가 짚은 두 가지 모두 실제 결함이었다. 감사 항목과 같은 기준으로 **수정 전 코드에서 실패하는 회귀**를
먼저 만들고 고쳤다.

**(a) `trustedIps` 복원 검증이 느슨했다 (`src/domain/auth.ts`).** 원래 필터는 `typeof at === 'number'`뿐이라
`Infinity`가 통과했다. `now - Infinity`는 `-Infinity`라 TTL 비교가 **항상** 참이 되어, 그 IP는 계정 잠금을
**영원히** 면제받는다 — 28-73-03이 세운 규칙(최근 성공 IP만, 30일)을 무력화한다. `NaN`도 문제다: TTL 정리에도
상한 정렬에도 걸리지 않아 5칸을 영구히 차지하다 진짜 IP를 밀어낸다. 이제 `[string, 유한한 number]`만 받는다.
(JSON에 `Infinity` 리터럴은 없지만 `1e999`가 파싱되면 `Infinity`가 된다 — 회귀 테스트가 그 경로를 쓴다.)

**(b) 보관함 목록이 화면을 연 채로는 갱신되지 않았다 (`src/features/admin/AdminSettings.tsx`).**
`useState` 초기화에서 한 번만 읽으니, 설정을 열어 둔 사이 conflict가 나면 **방금 덮인 것이 목록에 없다** —
꺼내야 할 바로 그 순간에 없는 셈이라 28-73-04가 고치려던 문제가 절반 남아 있었다. 그렇다고 렌더마다
최대 1MB를 파싱할 수는 없어, `overwrittenChars()`로 **길이만** 보고(파싱 없음) 달라졌을 때만 다시 읽는다.
계기는 두 가지다 — 이 탭의 복제 상태·동기화 안내가 바뀔 때(보관은 복제기가 원격을 받아들이기 직전에만
일어난다), 그리고 다른 탭이 보관 키를 건드렸을 때(`storage` 이벤트, 28-56과 같은 계기).
