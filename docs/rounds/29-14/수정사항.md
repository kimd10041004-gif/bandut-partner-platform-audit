# 29-14 수정사항 — 공개 Q&A

명세 7절(공개 질문)과 8절(권한 경계)을 구현한다.

## 1. 표 하나를 더한다 — 업체·사례는 복제하지 않는다

기존 구조에 질문을 담을 자리가 없어 `questions`를 새로 만들었다. 업체와 사례는 **ID로만** 참조한다.

```
questions
  id · partner_id → partners(user_id) · customer_id → users(id)
  case_id → portfolio_cases(id)  (선택)
  body · answer · answered_at · hidden · created_at · updated_at
```

v17 원본 파이프라인을 그대로 지났다. `db/sqlite/0008_public_questions.sql`을 더하고
`npm run db:pg-schema`로 `db/marketplace.pg.sql`을 다시 냈다 — 그 파일을 직접 고치지 않는다.

## 2. 누가 무엇을 하는가

| | 읽기 | 쓰기 |
|---|---|---|
| 로그인 안 함 | 공개 질문 | 로그인 안내만 |
| 고객 | 공개 질문 | 질문 작성 |
| 그 업체 | 공개 질문 | 답변 |
| 다른 업체 | 공개 질문 | 아무것도 — 서버가 403 |
| 관리자 | 전부 | 숨김·해제 |

**읽기는 로그인 없이 연다.** 질문을 공개하는 이유가 다음 손님이 같은 것을 묻지 않게 하려는
것인데, 로그인해야 읽힌다면 그 이유가 사라진다.

**답변은 그 업체만.** 질문이 걸린 업체와 답변하는 계정의 업체가 같은지 서버가 본다(명세 8절의
"질문의 대상 업체와 답변 계정의 소유 업체 일치"). 화면에서 버튼을 감추는 것은 편의일 뿐이다.

**사례를 걸 때도 확인한다.** 질문에 시공 사례를 붙일 수 있는데, 그 사례가 **그 업체의 공개된
사례**가 아니면 거부한다. 남의 사례 ID를 붙여 넣지 못한다.

## 3. 실명을 공개 게시판에 남기지 않는다

질문자 이름은 서버가 가려서 보낸다 — "김고객"이 아니라 "김OO". 화면에서 되돌릴 방법이 없다.
공개 게시판에 실명이 남을 이유가 없고, 한 번 나간 이름은 되돌릴 수 없다.

## 4. 알림 벨은 울리지 않는다 — 이유를 적어 둔다

처음에는 질문·답변마다 알림을 넣으려 했는데 통합 검사가 409로 막았다.

```
{"error":"다른 변경 사항이나 일정 충돌이 있습니다. 새로고침 후 확인해 주세요."}
```

`notifications.order_id`가 **NOT NULL**이다. 그 표는 주문에 매인 알림용이다. 질문 하나 때문에
v17 표의 모양을 바꾸지 않기로 했다.

대신 업체의 **받은 질문함**에서 미답변이 맨 위에 온다. 문자·푸시가 붙는 라운드에서 다시 본다.

## 5. 화면 — v17 파일을 고치지 않고 붙인다

업체 상세는 v17 원본이라 손대지 않는다(29-1부터의 규칙). 질문 조각을 따로 만들어 그 아래에
얹었다. 라우터에서 둘을 나란히 그린다.

## 하지 않은 것

- **신고 기능** — 지금은 관리자가 직접 숨긴다. 사용자 신고 접수는 별도로 잡는다.
- **질문 수정·삭제** — 공개된 글이라 정책을 먼저 정해야 한다.
- **거래 전 상담방** — 다음 순서다.
