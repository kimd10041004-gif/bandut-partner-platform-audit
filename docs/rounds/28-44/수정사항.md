# 28-44 수정사항 (Claude) — 입찰 마감 라운드

기반: `28-43` 복사본(스크래치 wf28-44)에서 작업. 28-43 감사 4건 전부 반영.

## 28-43-01 · 입찰 마감 도메인 [반영]

- `PlatformService.defaultBidDeadline(희망일, 오늘)` = min(희망일−1, 오늘+3), 오늘 이상. `addRequest(input, today)`는 미입력 시 기본값 채움, 과거 마감일·희망일 형식 오류 거부. `date.ts`에 `addDays` 추가.
- `submitEstimate(…, today)`: `bidClosed`(마감일 < 오늘)면 "입찰이 마감되었습니다" 거부 — 마감 당일까지 가능.
- `sweepDeadlines(today)` 멱등 정리: 마감 지난 requested/estimated에 고객 알림 1회(0건 → 연장/취소, n건 → 비교 선택), `RepairRequest.deadlineNotifiedFor`로 중복 방지(`store.setDeadlineNotified`). `extendDeadline(requestId, 날짜, today)`: 낙찰 전·오늘 이후·현재 마감 이후만, 플래그 초기화(`store.setBidDeadline`). 스냅샷 검증 추가.
- 시간은 전부 인자 주입(기본 `todayUTC()`). 도메인 테스트 3건 → vitest 194→**197**.

## 28-43-02 · 파트너 일감: 마감 표시·차단 [반영]

- 카드에 "마감 YYYY-MM-DD" + D-day, 마감 지난 건은 "입찰 마감 — 고객 결정 대기" 태그와 버튼 없음(제안 수정 불가), 입찰 폼 후보 제외, 정렬 옵션 "마감 임박순".

## 28-43-03 · 고객: 마감 안내·연장 [반영]

- 홈 목록·거래 상세에 "입찰 마감 D-n"(`Dday`). 마감 지난 요청: 견적 있으면 견적함 유도 배너, 0건이면 **마감 연장** 폼(날짜 `min=오늘`, 기본 희망일 기준 재계산). 위저드 2단계 마감일이 **선택→필수·기본값 자동**(희망일 바꾸면 손대지 않은 경우 재계산, `aria-label="입찰 마감일"`). 부트 + 고객 홈 진입 시 `sweepDeadlines()`.

## 28-43-04 · e2e + 실측 [반영]

- e2e 2단계 추가(85→**87**): 위저드 기본 마감일 자동 채움 / 고객 홈 D-day. 마감 경과 시나리오는 시간 주입 vitest로 검증(브라우저 시계 조작 없이). 실측 3장: 위저드, 고객 상세, 파트너 일감.
