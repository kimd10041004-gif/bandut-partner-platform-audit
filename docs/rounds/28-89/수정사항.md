# 28-89 수정사항 — 관리자 등급·권한 분리 + 첫 화면 배치 편집기 (28-88 감사 3건)

사용자 요청: **"UI를 관리자가 직접 조작해서 배치하고 수정할 수 있도록 하고, 관리자도 등급이 필요해.
접근 권한을 나눈다."** 여기에 28-88 감사 3건을 같이 넣었다.

두 기능은 서로 붙어 있다 — 첫 화면을 관리자가 만질 수 있게 되는 순간 **누가** 만질 수 있는지가
같이 정해져야 한다. 그래서 A(등급)를 먼저 만들고 B(배치)가 그 위에 얹힌다.

## A. 관리자 등급 — 소유자 · 매니저 · 열람

28-88까지 관리자는 계정 **하나**(`admin`)였다. 누가 들어오든 파기·복원·지급을 전부 할 수 있었다.
운영에 사람이 둘 이상 붙는 순간 그것은 "실수로 파기"와 "권한 없이 지급"이 같은 비밀번호 뒤에 있다는 뜻이다.

### 등급표 (`src/domain/adminGrade.ts`)

| 행위 | 열람 | 매니저 | 소유자 |
|---|:-:|:-:|:-:|
| `view` 현황·목록·기록 보기 | ✓ | ✓ | ✓ |
| `operate` 승인·거절·정지·환불·지급·A/S·리뷰 | | ✓ | ✓ |
| `editSettings` 문구·FAQ·패키지·질문·보증·카테고리·**첫 화면 배치** | | ✓ | ✓ |
| `exportBackup` 백업 내려받기 | | ✓ | ✓ |
| `destructive` 복원·되돌리기·파기·시연 삭제 | | | ✓ |
| `manageAdmins` 관리자 추가·등급·제거·비밀번호 초기화 | | | ✓ |

셋으로 끊었다. 더 잘게 쪼개면 사장님이 매번 표를 봐야 한다.

### 어디에 있고 어디서 막는가

- **계정**: `AuthService.admins[]` — `{id, name, grade, passwordHash, createdAt, createdBy}`. 기존 `admin`이
  소유자로 시드된다. 28-88까지의 스냅샷(`adminPasswordHash`)은 불러올 때 소유자 `admin`으로 옮겨진다 —
  비밀번호가 그대로 통한다(회귀 테스트).
- **로그인**: 관리자 로그인 입력의 "아이디" 칸이 이제 진짜 아이디다. 세션에 `grade`가 실린다.
  잠금 키가 `admin:<아이디 가명>`이라 **한 관리자를 잠가도 다른 관리자는 들어온다**.
- **도메인**: `addAdmin`·`setAdminGrade`·`removeAdmin`·`resetAdminPassword`는 `assertOwner`를 지난다.
  마지막 소유자는 내리거나 지울 수 없고, 자기 자신은 지울 수 없다. 전부 보안 이벤트 → 운영 기록.
- **서버 `api/auth.ts`**: op마다 필요한 행위를 `ADMIN_OP_ACTION`에 적고 `canAdmin(session.grade, …)`으로 본다.
  열람 세션의 승인·파기·관리자 추가는 **403**. 등급이 없는 옛 세션은 "다시 로그인하세요"(403).
  등급 변경·제거·비밀번호 초기화는 그 관리자의 서버 세션을 전부 폐기한다 — 옛 등급이 토큰에 남지 않는다.
- **서버 `api/snapshot.ts`**: 열람 세션의 `PUT`은 403. `db/schema.sql`에 `sessions.grade` 열이 생겼고
  `server/session.ts`가 발급·조회 때 싣는다.
- **화면**: `AdminGradeShell`(App.tsx)이 열람·무등급 세션의 관리자 화면 전체를 읽기 전용(`.admin-readonly`,
  `[data-admin-readonly]` 배너)으로 감싼다. 그 위에 파기·복원·되돌리기·시연 삭제·백업 내보내기·배치 저장은
  `useAdminCan()`으로 **버튼마다** 비활성 + `gradeHint`("소유자 이상만 할 수 있습니다").
  헤더의 이름 옆에 등급 태그(`[data-session-grade]`). 회원 탭 첫 카드가 관리자 계정 목록·추가 폼이다.

### 막지 못하는 것 — 정직하게

서버 모드의 스냅샷 쓰기는 **통째 쓰기**(28-72)다. 서버는 본문 안에서 "파기"와 "설정 변경"을 구별하지 못하므로
**매니저와 소유자를 `PUT`에서 구별하지 못한다** — 매니저가 화면을 우회해 직접 PUT하면 파기·복원도 막지 못한다.
서버가 확실히 막는 것은 ① 열람이 쓰기가 되는 것, ② 매니저가 관리자 계정을 만지는 것, ③ 매니저가 `purgeAccount`
op를 부르는 것이다. 그 이상은 엔티티 단위 API가 생겨야 막힌다(계속 이월). `adminGrade.ts` 머리말에 같은 말이 있다.

## B. 첫 화면 배치 편집기

28-17부터 랜딩의 섹션 순서는 코드에 박혀 있었다. 이제 `settings.landing`이 데이터다:

```ts
LandingLayout { sections: [{ id, visible }] × 6, titles: Partial<Record<id, string>> }
// id: categories · steps · services · packages · faq · cta  (히어로·푸터는 고정)
```

- `normalizeLanding`이 불러올 때 지난다 — 구 스냅샷(`landing` 없음)은 기본 배치, 손으로 고친 JSON은
  모르는 섹션을 버리고 빠진 섹션을 기본 순서로 뒤에 붙인다. **새 섹션이 생겨도 구 배치가 그것을 숨기지 않는다.**
- `updateSettings({ landing })`는 검증한다: 여섯 섹션 정확히 한 번, 최소 하나 노출, 제목 60자.
  "조용히 고치기"가 아니라 거부다 — 관리자가 실수한 것은 관리자에게 말해야 한다.
- `Landing.tsx`의 `renderSection(id)`가 `sections.filter(visible)` 순서로 그린다. 각 섹션에
  `data-landing-section`이 붙어 e2e·렌더 테스트가 순서를 읽는다. `landingTitle()`이 덮어쓴 제목 또는 기본 제목.
- 관리자 설정 > **첫 화면 배치** 카드(`LayoutCard`): ↑↓ 이동, 노출 토글, 제목 입력(제목 없는 섹션은 입력 없음),
  "배치 저장"(바꾸기 전엔 비활성)·"기본 배치로". 매니저 이상.

## 28-88 감사 3건

### 01 (상) 저하 응답에 `cache-control: public, max-age=60`이 붙었다

대기열이 찼을 때의 `{stats: null}`이 정상 응답과 **같은 헤더**를 달고 나갔다. CDN이 그것을 60초 동안
모든 방문자에게 "실적 없음"으로 되풀이할 수 있었다 — 부하가 지나간 뒤에도.

**수정** (`api/publicStats.ts`): 자리를 못 얻은 응답은 `cache-control: no-store` + `body.degraded: true`.
행이 정말 없어서 나가는 `null`은 사실이므로 그대로 `public`이다. 단일 비행으로 같은 결과를 나눠 받는
쪽도 같은 규칙이다. 회귀: 40개를 동시에 넣어 33개는 `public`, 나머지는 `no-store`+`degraded`.

### 02 (중) 멈춘 쿼리 하나가 공개 경로를 얼렸다

`pg`의 `Pool`은 쿼리 타임아웃 기본값이 **무한**이고, `acquireDbSlot()`은 자리를 무기한 기다렸다.

**수정**: `server/db.ts`의 `poolOptions()`에 `query_timeout`·`statement_timeout` = 8초(`QUERY_TIMEOUT_MS`).
`acquireDbSlot()`은 `PUBLIC_WAIT_MS`(4초) 안에 자리가 나지 않으면 대기열에서 빠져 `false`(→ 01의 저하 응답).
회귀: DB가 멈춘 채로 둘째 요청을 넣으면 2초 안에 `degraded`로 돌아오고, 시간이 다한 대기자가 자리를 새게
하지 않는다(`peak` 여전히 1).

### 03 (중) 가드가 파일 밖의 변형을 못 봤다 + 05의 과장

`moduleStateOfSource`가 `.set(` 등을 **같은 파일 안에서만** 찾아서, `a.ts`가 선언하고 `b.ts`가 쓰는
`export const cache = new Map()`은 "읽기 전용 표"로 건너뛰었다. `export`의 뜻이 바로 "다른 파일이 쓴다"다.

**수정**: `moduleStateOfSource(src, corpus)` — 변형은 `api/`·`server/` **전체 소스**에서 찾는다.
회귀: 선언 파일 밖의 `cache.set`을 잡고, 아무 데서도 안 쓰면 여전히 상수다.

**정정**: 28-88-05가 "28-87의 두 결함은 둘 다 이 자리에서 멈췄을 것"이라고 적은 것은 과장이었다.
`getPool` 위 주석에는 28-87 이전부터 "서버리스"가 있었으므로 결함 01(풀 공유 오해)은 `MENTIONS` 검사를
통과했을 것이다. 멈췄을 것은 02 하나다. `server/serverlessState.test.ts` 머리말과 `28-88/수정사항.md`에
정정을 적었다 — 한계를 적어 두고 그 밖의 값을 주장한 것이 28-86 감사 01, 28-87 감사 02와 같은 모양이었다.
