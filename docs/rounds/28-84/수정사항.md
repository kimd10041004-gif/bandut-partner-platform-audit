# 28-84 수정사항 — 유도의 양 끝을 근거 위에

28-83 감사 4건(`28-83/감사결과.md`)을 전부 고쳤다. 한 줄로: **28-83은 "목록 대신 유도"를 옳게 시작했지만
유도의 양 끝(어디서 읽는가 · 어디서 출발하는가)이 아직 손으로 적힌 경로였다.**

사용자 눈에 보이는 변화는 없다 — 전부 가드·테스트·문서다. 화면 동작과 도메인 계산은 그대로다.

---

## 01 (상) 유도의 **출처**를 `src/domain` 전체로

**원인.** `src/ui/customerSurfaces.test.ts`가 `const DOMAIN = 'src/domain/platform.ts'` 한 파일만 읽었다.
같은 라운드의 28-83-03은 호출자 쪽 도달 범위를 `src` 전체로 넓히면서 `src/domain`을 통째로 검사에서
잘라냈는데, 정작 **진실은 그 안 파일 하나에서만** 읽었다. `src/domain`에는 30개가 넘는 모듈이 있다.

**수정.** `domainFiles()`가 `src/domain`을 훑고(`.d.ts` 제외), `derivedSeedSensitive()`가 파일마다 돈다.
완전성 검사(`excludeSeeded?: boolean` 개수 대조)도 파일별 합계로 비교한다. 시그니처 정규식은
`private` 하나만 보던 것에서 `private|protected|public|static|async`로 넓혔다(놓치면 개수 대조가 실패한다).

**수정 전 실패 인용.** `src/domain/settlement.ts`에 시드 민감 집계를 하나 심고 두 가드를 나란히 돌렸다:

```
=== 28-83 가드 (platform.ts 한 파일만 읽는다) — 같은 결함 ===
 Test Files  1 passed (1)
      Tests  4 passed (4)

=== 28-84 가드 (도메인 전체를 읽는다) ===
     × 금지 목록이 도메인에서 유도한 집합을 모두 담는다 (28-83-01)
AssertionError: 시드에 민감한 집계가 새로 생겼습니다 … expected [ 'settlementTotals' ] to deeply equal []
      Tests  1 failed | 4 passed (5)
```

출처가 실제로 여러 파일인지 자체를 고정하는 테스트도 더했다(「유도의 출처가 도메인 전체다 — 파일 하나가 아니다」).

## 02 (상) 서버 모드 기본값 경로를 **양방향으로** 고정

**원인.** 28-83-02는 프롭 없이 렌더하는 테스트를 넣었지만 단언이 **부정형 둘뿐**이었다.
테스트 환경의 `AUTH_MODE`는 `local`이라 그것은 "로컬에서는 안 보인다"만 증명한다 —
**기본값이 `AUTH_MODE`에 연결돼 있다는 것 자체는 아무도 증명하지 않았다.**

28-83 문서는 "기본값을 `'server'`로 바꾸거나 import를 지워도 통과했다"를 고친다고 적었는데,
그 두 변이는 실은 테스트가 아니라 `noUnusedLocals`가 잡는다(감사 02에서 `error TS6133`로 확인).

**수정.** `src/features/landing/Landing.serverDefault.test.tsx` 신규. `AUTH_MODE`는 빌드 상수라
런타임에 못 바꾸므로 `vi.mock('../../app/bootstrap', …)`으로 `'server'`를 주입한다. 파일 단위로
적용되므로 별도 파일에 두어 `Landing.test.tsx`의 로컬 쪽 단언과 섞이지 않게 했다.
프롭 없이 렌더해 `data-hero-stats`가 **있음**을 단언한다 — 28-83-02의 부정형과 짝이 된다.

**수정 전 실패 인용.** 감사 02가 인용한 그 변이(`authMode = AUTH_MODE === 'server' ? 'local' : AUTH_MODE`)를
다시 넣고 돌렸다. 감사 시점에는 이것이 **타입 0건 · 테스트 486건 · 빌드 전부 통과**했다:

```
     × 프롭을 넘기지 않아도 서버 빌드에서는 지표를 그린다
AssertionError: 서버 빌드인데 기본값 경로가 지표를 그리지 않습니다 — 기본값이 AUTH_MODE에 연결돼 있습니까?:
  expected '<div class="landing"><section class="…' to contain 'data-hero-stats'
 Test Files  1 failed | 2 passed (3)
      Tests  1 failed | 8 passed (9)
```

나머지 8건은 그대로 통과한다 — 이 변이를 잡는 것은 **정확히 새 테스트 하나**다.

## 03 (중) 가드는 **식별자**를 본다 + 한계를 문서에 적었다

**원인.** `new RegExp(`\\.${api}\\(`)` — `.이름(` 이라는 **호출 형태**만 봤다. 구조 분해 한 줄로 우회됐다.

**수정.** 주석·문자열 리터럴을 걷어낸(`stripNonCode`) 코드에서 `\b이름\b`로 **식별자**를 본다.
문자열을 지우는 이유는 문서 문구·에러 메시지에 이름이 들어가 거짓 경보가 나지 않게 하기 위함이다.
(`publicPartnerSummary`는 대문자 P라 `\bpartnerSummary\b`에 걸리지 않는다.)

**그리고 못 하는 것을 파일 상단과 `UI_가이드.md`에 적었다** — 이름을 하나도 부르지 않고 원자료에서
같은 숫자를 직접 계산하면 이 가드는 원리적으로 아무 말도 못 한다. **그것은 리뷰가 볼 몫이다.**
28-83의 주석은 가드가 완전한 것처럼 읽혔다. 가드를 믿게 만드는 것보다 한계를 아는 것이 먼저다.

**수정 전 실패 인용.** `PartnerCard.tsx`(고객이 업체를 고르는 자리)를 구조 분해 호출로 바꿨다.
28-83 가드는 `Tests 4 passed (4)`로 초록이었고(감사 03), 28-84 가드는:

```
     × 고객 경로는 시드를 포함한 집계 API를 부르지 않는다
+   "src/ui/PartnerCard.tsx → partnerSummary",
      Tests  1 failed | 4 passed (5)
```

## 04 (중) 도달 탐색의 **출발점**을 라우팅에서 유도

**원인.** `const CUSTOMER_DIRS = ['src/features/landing', 'src/features/customer']`.
파일 주석은 "새 고객 화면을 만들어도 디렉터리에서 유도되므로 자동으로 포함된다"고 했지만
**그 두 디렉터리 안에서만** 참이었다. 디렉터리 자체가 손 목록이라, 랜딩을 렌더하는 `src/App.tsx`부터가
검사 밖이었다(감사 04에서 도달 18개 중 없음을 확인).

**수정.** `customerRoots()`가 `App.tsx`의 `APPS` 중 `key: 'customer'` 블록에서 `view:` 컴포넌트를 뽑고
`<Landing`을 더해, import 표로 파일 경로를 푼다 — "고객 화면"이 관례가 아니라 **라우팅이라는 근거**를 갖는다.
`App.tsx` 자신은 **잎으로만** 넣는다: 본문은 검사하되 import는 따라가지 않는다.
따라가면 세 앱을 전부 import하므로 관리자 화면까지 고객 경로로 끌려와 가드가 무의미해진다.
그 경계를 테스트로 고정했다(`expect(files).not.toContain('src/features/admin/AdminOverview.tsx')`).

**수정 전 실패 인용.** `App.tsx`에 `platform.statusCounts().completed` 한 줄을 심었다.
28-83 가드는 App.tsx를 아예 보지 않았고, 28-84 가드는:

```
     × 고객 경로는 시드를 포함한 집계 API를 부르지 않는다
AssertionError: … expected [ 'src/App.tsx → statusCounts' ] to deeply equal []
      Tests  1 failed | 4 passed (5)
```

## 이번 라운드에서 **하지 않은 것** (조용히 빼지 않는다)

- **가드를 타입 기반(TypeScript 컴파일러 API)으로 바꾸는 것.** 03의 근본 해결이지만 새 의존성과
  상당한 구현이 들어가고 CI 시간을 늘린다. 사용자가 이번 범위를 "감사 4건만"으로 정했다.
  대신 **한계를 문서에 명시**하는 쪽을 골랐다 — 완전하지 않은 가드를 완전한 척 두는 것이 더 나쁘다.
- **서버 모드 익명 방문자 문제.** 28-82가 발견하고 28-82·28-83에 이어 **세 라운드째 이월**한다.
  세션 없이 접근하는 공개 집계 엔드포인트가 필요하고, "무엇까지 공개해도 되는가"라는 보안 판단이 따른다.
  이번 02가 서버 모드 쪽 절반을 **테스트로는** 닫았지만, **화면으로는 여전히 열려 있다** —
  로그인하지 않은 랜딩 방문자는 `/api/snapshot`이 세션을 요구해 아직 지표를 받지 못한다.
  이월 횟수를 여기 적어 둔다. 다음 라운드의 첫 후보다.
- **`public*` 대응물의 존재 검사.** 오류 메시지는 "대응물을 만드세요"라고 하지만 실제로 있는지는
  검사하지 않는다. 지금은 셋 다 있고, 없을 때 CI가 아니라 리뷰가 잡는 것이 과하지 않다고 봤다.
