# 28-16 수정사항 — 28-15 감사 5개 항목 전부 처리 (거래 상세 라운드)

작업 방식: 기존 규칙 그대로 — 28-1~28-15는 일절 수정하지 않고 스크래치 복사본(`scratchpad/wf28-16`)에서 수정 후 `28-16` 스냅샷 생성. 사용자 제공 상세 시안 5장("상세야")의 분석·로드맵은 루트 `상세시안_분석.md`.

## 항목별 수정 내용

### 28-15-01 [상] 추가 작업 고객 승인 흐름 → 도메인 재설계
- `requestExtraWork()`: 파트너가 시공 중(in_progress) 추가 작업을 **pending**으로 요청.
- `decideExtraWork()`: 고객이 pending을 승인/거절 — 결정일 기록, 재결정 불가.
- `completeJob()`: **pending이 남아 있으면 거부**("고객이 결정하지 않은 추가 작업 N건"), 합계는 승인분만 포함.
- 하위 호환: `status` 없는 기존 추가 작업(구 `approveExtraWork` 데이터) = 승인으로 취급, 스냅샷 검증에 status 필드 추가. `approveExtraWork`는 하위 호환용으로 유지.
- 파트너 내 작업 탭: "고객에게 승인 요청" 폼으로 전환 + 항목별 승인 대기/승인됨/거절됨 뱃지, 합산은 승인분만.
- 회귀 테스트 5개(pending 생성·완료 차단·승인분만 합산·재결정 불가·구 스냅샷 호환).

### 28-15-02 [상] 고객 거래 상세 → 신규 구현 (시안 5)
- 고객 홈 카드 → "거래 상세 보기": 진행 타임라인, 견적 내역(공급가/부가세/기본 견적/승인된 추가 작업/**최종 결제 예정 금액**), **추가 작업 승인 요청 카드(승인하기/거절하기)**, 결정 내역, 방문 전 안내, 예약 일시 표시, 뒤로 가기.
- 홈 카드에 "추가 작업 승인 대기 N건" 뱃지.

### 28-15-03 [상] 거래 진행 타임라인 → 도메인 파생 + 공용 부품
- 도메인 `requestTimeline()`: 요청 등록(등록일)→견적 도착→견적 수락→방문 예약(슬롯 날짜)→시공 시작→추가 작업(대기/결정)→작업 완료(완료일)→정산 완료. 이탈(미낙찰/취소)은 파생 가능한 단계까지 표시 후 종결 이벤트. 테스트 2개(전 구간 done+날짜 파생, 이탈 종결).
- `Timeline` 공용 부품(`ui/primitives.tsx`) — 세로 도트+연결선, done=브랜드. 고객 상세·관리자 상세 공용.

### 28-15-04 [상] 관리자 거래 상세 → 신규 구현 (시안 4)
- 요청 관리 표 행 클릭 → 거래 상세: 고객·파트너·상태, 타임라인, 금액 정보(총 거래 금액 + 수수료 3% 예상 — `PLATFORM_FEE_RATE` 상수 사용), 추가 작업 내역(상태 뱃지), 뒤로 가기.

### 28-15-05 [중] 파트너 작업 현황 칩 필터 → 신규 구현 (시안 2)
- 내 작업 탭 상단 칩 필터: 전체/낙찰/작업 예정/진행 중/완료·정산/종결 (`.filter-group` 부품 재사용). 필터 결과 0건 전용 빈 상태("다른 필터를 선택해 보세요")를 작업 0건과 구분.
