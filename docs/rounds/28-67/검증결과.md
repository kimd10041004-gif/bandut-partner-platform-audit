### 28-66-01 완전성 검사가 `daysOff`를 잡는다

spec에서 `daysOff` 한 줄을 빼면(= 28-66 상태) **기존 테스트가 곧바로 실패한다**:

```
× daysOff는 통째로 통과하지 않는다 — 형태를 재조립한다
PlatformError: 가명 처리에 실패했습니다 — daysOff가 결과에 실리는데
허용 목록(spec)이 없습니다. 검사받지 않는 컬렉션을 내보내지 않습니다.
```

28-66 코드에서는 이 컬렉션이 **아무 검사도 받지 않고 통과했다.** 완전성 검사를 켜자마자 잡혔다.

새 회귀 테스트 6건(`src/domain/pseudonymous-shape.test.ts`, 총 12 passed):
```
✓ 결과에 실리는데 spec이 없는 컬렉션을 잡는다 — daysOff가 그렇게 빠져 있었다
✓ spec이 선언된 daysOff는 통과하고, 값 배열에 객체가 섞이면 실패한다
✓ spec 경로를 결과에서 찾을 수 없으면 실패한다 — 검사가 조용히 사라지지 않는다
✓ 최상위 [id, 레코드] 행의 나머지 원소도 검사한다 — row[1]만 보던 비대칭 제거
✓ 스칼라·스칼라 배열은 spec 없이도 통과한다 — 실릴 내용이 없다
✓ 컨테이너는 안쪽 spec으로 통과시키되 나머지 키를 마저 본다 (out.store)
```

기존 테스트 한 줄을 새 계약으로 바꿨다 — **그 줄이 곧 결함이었다**:
```diff
- // 없는 경로는 여전히 건너뛴다
- expect(() => assertPseudonymousShape({}, [['store.requests', []]])).not.toThrow()
+ expect(() => assertPseudonymousShape({}, [['store.requests', []]])).toThrow('찾을 수 없습니다')
```

## 포트 계약 — 두 구현이 같은 스위트를 통과한다

```
$ npx vitest run src/domain/ports.contract.test.ts
 Tests  14 passed (14)

SnapshotPort 계약 — LocalSnapshotPort   (5건)
SnapshotPort 계약 — MemoryRemotePort    (5건)
MemoryRemotePort — 주입한 실패·지연      (4건)
```

`describe.each`로 **같은 5건**을 두 구현에 돌린다: 빈 저장소 → null / write·read 왕복 /
연속 쓰기의 rev 기대 / expectedRev 불일치 → conflict + 원격 최신본 동봉 / 동시 writer 하나만 성공.
28-68에서 HTTP 어댑터를 만들면 배열에 한 줄만 더하면 된다.

### 계약 테스트가 내 어댑터의 버그를 잡았다

`LocalSnapshotPort.write()`를 처음엔 `await this.read()`로 현재 값을 읽게 썼다.
계약의 "동시 writer 둘 중 하나만 성공"에서 **둘 다 성공**했다:

```
FAIL  SnapshotPort 계약 — LocalSnapshotPort > 동시 writer 둘 중 하나만 성공한다
AssertionError: expected [ true, true ] to have a length of 1
```

`await`가 비교와 쓰기 사이에 양보를 만들어 다른 writer가 끼어든 것이다.
비교-쓰기 사이에 `await`가 없도록(`readSync`) 고쳐서 통과한다.
**서버를 붙이는 날에야 발견했을 종류의 결함이다.**
