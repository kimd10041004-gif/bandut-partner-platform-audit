# 28-21 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-21` 전체 — **사용자 지시 "UI를 이제 관리자가 조작하고, 설정하고, 유지보수하기 좋게"** + 상세 시안 3(관리자 CMS·운영 설정 UI) 대조.
사전 확인: `npm run check` exit 0 (vitest 145/145), e2e 16/16 PASS, visual-check 전 항목 PASS, 프로덕션 배포 그린(PR #36 머지). 28-20 감사 3건 전부 수정 확인됨.

핵심 지적: 목적자 분리까지 됐지만 **운영은 아직 개발자의 일**이다 — 홈페이지 문구·노출 카테고리·안내 콘텐츠를 바꾸려면 코드를 고쳐야 한다. 시안 3의 CMS(카테고리 관리 토글·메인 카피·FAQ·발행)처럼, 관리자가 화면에서 직접 조작하는 **운영 설정 계층**이 필요하다.

---

## 상 (High)

### 28-21-01 · 운영 설정 도메인(SiteSettings) 부재
→ 요구: 도메인에 `SiteSettings { heroTitle, heroSub, notice, disabledCategories, faqs }` + `getSettings()`(기본값 병합)/`updateSettings()`(부분 갱신)/`enabledCategories()`. 검증: 히어로 문구 공백 불가, 전 카테고리 비활성 불가(최소 1개 유지), 존재하지 않는 카테고리 거부, FAQ 질문 공백 불가. 카테고리 런타임 목록을 도메인(`ALL_CATEGORIES`)으로 이동(UI constants는 재사용). 스냅샷 `settings?` 하위 호환 + 요소 검증 + **도메인 테스트 필수**.

### 28-21-02 · 관리자 설정 탭 부재 (시안 3)
→ 요구: 관리자 콘솔 5번째 탭 "설정" — ①서비스 카테고리 관리(토글 스위치, 비활성 시 고객 웹에서 숨김) ②홈페이지 문구(히어로 타이틀·서브) ③공지 배너(비우면 미표시) ④FAQ 관리(추가/삭제) ⑤기본값 복원. 저장 즉시 반영(시안의 임시저장/발행 이원화는 단일 관리자 데모 범위에서 즉시 발행으로 단순화 — 문서에 명시).

### 28-21-03 · 고객 웹이 설정을 따르지 않음
→ 요구: 랜딩 히어로 문구·공지 배너·FAQ 섹션(설정에 있을 때만)·카테고리 그리드, 그리고 위저드 카테고리가 전부 `getSettings()`를 따를 것. 위저드 사전 선택 카테고리가 비활성이면 첫 활성 카테고리로 폴백.

## 중 (Medium)

### 28-21-04 · e2e에 운영 반영 시나리오 부재
→ 요구: e2e-journey에 "관리자가 문구 수정 + 카테고리 비활성 + FAQ 추가 → 고객 랜딩·위저드에 즉시 반영" 단계 추가.

### 28-21-05 · 유지보수 경계 문서화
→ 요구: UI_가이드에 "코드로 바꾸는 것(토큰·부품) vs 관리자 설정으로 바꾸는 것(문구·카테고리·FAQ)" 경계 표 추가 — 운영자가 개발자를 부를 일과 아닐 일을 문서로 구분.
