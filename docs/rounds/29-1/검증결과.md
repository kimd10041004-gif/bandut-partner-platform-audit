# 29-1 검증결과

## 1. 게이트 (기존 앱 그대로)

| 게이트 | 결과 |
|---|---|
| `npm run check` | `Checking formatting...` 통과 · `Test Files 37 passed | 1 skipped (38)` · `Tests 690 passed | 19 skipped (709)` (28-97: 549 — v17 도메인·통합 141 + Postgres 포트 3) · `✓ built` |
| `npm run e2e` · `visual-check` · `npm audit` | 화면을 건드리지 않아 28-97과 같다 (아래 §4) |

## 2. 이식이 원본과 같은가 — v17 테스트를 그대로 돌린다

v17의 통합 테스트는 **Node 내장 SQLite**(`node:sqlite`)로 자기 스키마를 세우고 도메인을 태운다. 우리 저장소에서
경로 두 줄만 고쳐 그대로 돌렸다:

```
 Test Files  8 passed (8)
      Tests  141 passed (141)
```

한 건도 고치지 않고 통과했다 — 도메인·서비스·정책이 원본과 같은 규칙으로 돈다는 뜻이다.

## 3. 그 도메인이 Postgres에서도 같은가

```
      Tests  3 passed (3)
```

`tests/pg.port.test.ts`가 확인하는 것:

1. **자리표시자** — `?` → `$n`, 문자열 안의 물음표는 건드리지 않는다.
2. **주문 한 바퀴** — 접수 → 거래방식 확정 → 견적 → 낙찰. 서버가 VAT·총액을 다시 계산해 198,000원,
   낙찰 전 파트너에게 주소가 없고 낙찰 뒤에는 보이며, 일정 슬롯 1건이 남는다.
3. **트리거** — SQLite `RAISE(ABORT)`를 plpgsql로 옮긴 것이 실제로 막는다: 감사로그 수정·삭제(`AUDIT_IMMUTABLE`),
   같은 파트너·같은 날 겹치는 일정(`SCHEDULE_CONFLICT`).

스키마는 `node scripts/pg-schema.mjs`가 만든 `db/marketplace.pg.sql`을 그대로 적용했다 — 표 30 · 외래키 29 · 트리거 17.

## 3-1. 첫 CI가 잡은 것 — 테스트가 남의 표를 지웠다

첫 푸시(`52583f8`)에서 `server` job이 빨간불이었다. `npm run test:pg`는 통과했는데, **그 다음 단계**가 깨졌다:

```
ERROR: relation "snapshots" does not exist
STATEMENT: select count(*) as 스냅샷_행수 … from snapshots;
```

`tests/pg.port.test.ts`가 스키마를 세우려고 `drop schema public cascade`를 했고, 같은 DB를 쓰는 스냅샷 API·계약
테스트·서버 e2e의 표까지 함께 지운 것이다. 로컬에서는 내가 그 표를 직접 되살려 두어 드러나지 않았고, **여러 검증이
한 DB를 나눠 쓰는 CI에서만** 보였다.

고친 방법: 이 테스트는 자기 스키마(`marketplace_port_test`) 안에서만 만들고 지운다. 연결마다 `search_path`를 그쪽으로
돌리고, 끝나면 그 스키마만 버린다. `public`은 건드리지 않는다.

## 3-2. 두 번째 CI가 잡은 것 — 라운드 번호에 `28`이 박혀 있었다

`52583f8`의 격리 수정으로 `test:pg`와 저장된 행 확인은 통과했지만, 다음 푸시(`5fcac80`)에서 `server` job의
서버 모드 e2e가 딱 한 단계 실패했다:

```
✗ 서버 모드 빌드 표기 (data-auth-mode=server, 28-1)
[e2e:server] 55 passed, 1 failed
```

기대값이 `29-1`이 아니라 `28-1`이다. 라운드 표기는 `package.json`의 version이 단일 출처인데(README), 그 표기를
만드는 자리 세 곳이 **major를 문자열로 박아 두고 minor만 읽고 있었다**:

| 자리 | 있던 코드 |
|---|---|
| `scripts/e2e-server.mjs` | `` `28-${version.split('.')[1]}` `` |
| `.github/workflows/gates.yml` | `r="28-$(… version.split('.')[1])"` |
| `.github/workflows/deploy-check.yml` | `from_json="28-$(… version.split('.')[1])"` |

28 라운드 안에서만 돌 때는 맞는 값이 나왔다. 29로 올린 이 라운드가 처음으로 그 가정을 깬 것이다. 세 자리 모두
`version.split('.').slice(0, 2).join('-')`로 바꿔 major·minor를 함께 읽게 했다. 라운드를 올릴 때 손댈 자리가
`package.json` 하나로 다시 줄었다.

수정 전 실패 인용은 위 CI 출력 그대로다. 수정 뒤 로컬에서 서버 모드 빌드(`VITE_AUTH_MODE=server npx vite build`)
후 연속 3회 모두 `56 passed, 0 failed`. 게이트 라운드 확인도 `29-1`로 폴더·`src/App.tsx` 양쪽을 찾는다.

## 4. 이번 라운드가 건드리지 않은 것

화면·라우팅·배포는 그대로다. 라이브는 여전히 기존 SPA이고, 배포 확인 게이트는 번들에서 `29-1`을 찾는다.
새 코드는 아직 어떤 화면에서도 불리지 않는다 — 다음 라운드(29-2)에서 Next.js 앱 셸과 함께 연결한다.

## 5. 남는 것

- 29-2 앱 셸·화면·세션 연결 → 29-3 스냅샷·보관함·가명본·용량 가드 삭제와 배포 전환.
- 사진 저장소(29-4), 포트폴리오·게시물·캘린더·대시보드(29-5~29-8), 브랜드 자산(29-9).
- 기존 스냅샷 데이터의 이전: 실사용자가 없어 새 표는 비운 채로 시작하고, 기존 스냅샷은 백업으로만 남긴다(29-3에서 확정).

건드리지 않았으니 예정된 상태다. 서버 모드 전환은 29-2~29-3에서 앱 셸 교체와 함께 한다.

## 7. 리뷰

Copilot 리뷰를 요청했고 **지적 없이 끝났다**(12분 대기, 리뷰 0건). CI는 `gates`·`server` 모두 초록이었다.

이번 라운드에서 사람이 아니라 **CI가 두 번 막았다**는 점은 남겨 둘 만하다.

| | CI가 잡은 것 | 로컬에서 안 보인 이유 |
|---|---|---|
| §3-1 | 테스트가 `public` 스키마를 지워 다른 검증의 표까지 날렸다 | 로컬에서는 내가 그 표를 손으로 되살려 두었다 |
| §3-2 | 라운드 표기에 `28`이 박혀 있었다 | 28 라운드 안에서는 맞는 값이 나왔다 |

둘 다 **여러 검증이 한 자원을 나눠 쓸 때**만 드러나는 종류다. 로컬 게이트를 아무리 돌려도 안 나왔다.
