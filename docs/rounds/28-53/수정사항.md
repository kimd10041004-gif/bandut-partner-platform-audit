# 28-53 수정사항 (Claude) — 낙찰 전 수정 라운드

기반: `28-52` 복사본(스크래치 wf28-53)에서 작업. 28-52 감사 4건 전부 반영.

## 28-52-01 · 고객 요청 수정 [반영]

- `RequestPatch`(`description`·`region`·`desiredDate`·`desiredTime`·`budget`·`budgetRange`·`answers`, 카테고리 제외). `updateRequest(requestId, patch, today)`: 낙찰 전만, 빈 문자열·날짜(오늘 이후)·시간대·예산·답변 검증, 수정 내용 없으면 거부. `store.update`가 병합 + `editedAt`·`editCount` 기록(빈 답변·빈 예산 범위는 키 제거). 희망일이 현재 마감 이하로 앞당겨지면 `defaultBidDeadline`로 마감 재계산. 입찰자 전원 계정 범위 알림. 스냅샷 검증(`editCount ≥ 1`).
- vitest 1건: 검증 4종·마감 재계산·답변 정리·알림 2건·낙찰 후 거부·스냅샷 왕복·손상 거부.

## 28-52-02 · 파트너 견적 수정·입찰 철회 [반영]

- `StoredEstimate.revision`(재제출마다 +1, 원안은 없음)·`submittedAt`. `submitEstimate` 재제출 시 고객 알림 "견적이 수정되었습니다 (n차) — … (이전 X원)". `bidOf/bidsFor` 복사본과 스냅샷 직렬화·복원에서 차수·시각 유지(초안은 `cloneBid`가 `{estimate, breakdown}`만 복사해 차수가 사라짐 → 스프레드로 정정).
- `withdrawBid(requestId, partnerId, today)`: 낙찰 전·마감 전·내 입찰만. 남은 입찰이 없으면 `store.reopen(id, 'requested')`(estimated→requested 허용으로 확장). 고객 알림(남은 견적 n건). `partnerCancels`에는 기록하지 않는다.
- vitest 1건: 1차·2차 수정·알림 문구·타 파트너 철회 거부·마감 후 거부·마지막 철회 → requested·신뢰 지표 0·낙찰 후 거부·스냅샷 왕복.

## 28-52-03 · 화면 [반영]

- 고객 거래 상세(낙찰 전): "요청 수정"(`[data-edit-request]`) → 인라인 카드(요청 내용·지역·희망일·시간대, `aria-label` 수정 …) + "수정 저장"/"취소", 검증 오류는 폼 안에 표시(`[data-edit-error]` — 실측에서 오류가 카드 밖에 있어 보이지 않던 것을 정정). 헤더 메타에 "수정됨 n회"(`[data-edit-count]`).
- 파트너 일감 카드: 기존 "제안 수정" 옆 "입찰 철회"(`[data-withdraw-bid]`, 결과 메시지 `[data-withdraw-msg]`), "내 입찰 완료 (n차 수정)". 고객 견적함 "n차 수정" 태그(`[data-revision]`).

## 28-52-04 · e2e + 실측 [반영]

- e2e 4단계 추가(119→**123** + 시드 상대화로 유지 1): 고객 요청 수정 → 상세 반영·수정됨 1회 / 파트너 견적 수정 → 카드 1차 수정 / 견적함 1차 수정 태그 + 253,000원 / 입찰 철회 → 다시 입찰 가능(입찰 0건). 총 **124** PASS.
- **시드 날짜 상대화**(`seedPlatform(p, today)`): 고정 날짜(2026-09-02 마감 등)가 날짜가 바뀌자 전부 마감돼 기존 e2e "토글 해제 → 전체 일감(전기 건 표시)"가 깨짐 → 시드 요청·이력 날짜를 오늘 기준 상대값(D+1/D+3/D+8, D-8/D-6/D-1)으로. 배포 시연에서도 시드 일감이 며칠 뒤 전부 마감되던 문제를 함께 해결.
- 실측 `capture-28-53.mjs`: 빈 내용 저장 거부, 수정 후 상세, 파트너 알림, 카드 "(1차 수정)", 견적함 태그·253,000원, 고객 알림(이전 275,000원), 철회 메시지·입찰 0건·상태 requested, 모바일 가로 스크롤 없음.
