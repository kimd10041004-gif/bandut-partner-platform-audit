# 29-24 — 들어온 사람의 처음과 마지막

## 1. 사용자가 물은 다섯

사장님이 다섯 가지를 짚으셨다. 코드에서 하나씩 확인한 결과다.

| 물음 | 지금 상태 |
|---|---|
| 소셜 로그인(구글·네이버·카카오) | **없다.** 관련 코드가 한 줄도 없다 |
| 회원 탈퇴 | **절반만 있다.** 서버는 되는데 **화면에 버튼이 없다** |
| 이메일 비밀번호 찾기 | 비밀번호 찾기는 있으나 **휴대폰 인증**이다. 이메일은 받지 않는다 |
| 최초 사용 안내 | **없다.** 가입하면 빈 목록이 나온다 |
| 결제 수단 | 토스 하나이고 `method: 'CARD'` 로 못박혀 있다 |

이번 라운드는 이 중 **둘**을 한다 — 탈퇴와 최초 안내. 둘 다 "가입한 사람이 겪는 처음과 마지막"이고,
서버가 이미 대부분 해 둔 자리라 화면만 붙이면 되는 일이다.

나머지 셋은 §6 에 남긴다.

## 2. 화면을 붙이기 전에 문부터 세웠다

탈퇴 버튼을 그리려고 `withdraw` 를 읽다가 알았다. **진행 중인 거래가 있어도 그냥 된다.**

```ts
// server/domain/auth.ts — 있는 것은 이것뿐이다
if (!verifyPassword(password, account.passwordHash)) throw new AuthError('비밀번호가 일치하지 않습니다')
```

계약금을 낸 고객이 탈퇴하면 이름과 번호가 즉시 지워지고, 주문은 그대로 남는다. **파트너는 방문
일정이 잡힌 일감을 쥔 채 연락할 사람을 잃는다.** 파트너 쪽도 같다 — 정산이 안 끝났는데 탈퇴하면
받을 돈이 있는 사람이 사라진다.

계정 도메인은 주문을 모르고, 알게 만들면 안 된다. 그래서 **판단은 계정 쪽, 사실은 거래 쪽**에서
오도록 `server/accountExit.ts` 를 사이에 뒀다.

| 역할 | 막는 것 |
|---|---|
| 고객 | 끝나지 않은 주문 · 결과가 안 난 결제 · 아직 못 받은 환불 |
| 파트너 | 맡은 채 안 끝난 작업 · 지급이 안 끝난 정산 |

끝난 것은 `CANCELLED` 와 `COMPLETED` 둘뿐이다. 작업이 끝났어도 **돈이 안 끝났으면** 끝난 것이
아니라서 결제·환불·정산을 따로 센다.

**표가 없으면 예외가 그대로 올라간다.** 0 으로 바꾸지 않았다 — 스키마가 덜 선 서버에서 "막을 것이
없다"는 결론이 나오면, 이 문은 정확히 필요한 순간에 열린다.

## 3. 거절 이유가 비밀번호를 알려 주지 않는다

게이트를 **비밀번호 확인보다 먼저** 둔다.

```ts
const blocks = await withdrawBlocks(c, session.role, session.accountId)
if (blocks.length > 0) throw new BadArgs(blocks.map((b) => b.message).join(' '))
out.result = auth.withdraw(session.role, str(args[0], '비밀번호'))
```

순서를 바꾸면, 맞는 비밀번호를 확인한 뒤 거절하게 된다. 그러면 거절당한 사람에게 **비밀번호가
맞았다는 사실만** 알려 주는 셈이다.

## 4. 탈퇴 화면 — 누르기 전에 알려 준다

`components/marketplace/account-exit.tsx`. 셋을 지킨다.

- **되돌릴 수 없다고 먼저 말한다.** 누르고 나서 알게 하지 않는다.
- **왜 안 되는지를 누르기 전에 보여 준다.** `withdrawCheck` 는 읽기만 하는 op 다. 서버가 같은 것을
  다시 보므로 이 화면은 **안내이지 자물쇠가 아니다.**
- **비밀번호를 한 번 더 받는다.** 남이 열어 둔 화면에서 탈퇴시킬 수 없다.

관리자 화면에는 붙이지 않았다. 관리자 계정은 스스로 나가는 것이 아니라 소유자가 제거한다(28-89).

## 5. 최초 안내 — "본 적 있음"을 적지 않는다

흔한 방법은 처음 로그인할 때 안내를 띄우고 `localStorage` 에 봤다고 적는 것이다. 그 방법은 두 번
틀린다. 브라우저를 바꾸면 다 본 사람에게 다시 뜨고, 안내만 닫고 아무것도 안 한 사람에게는 다시
뜨지 않는다.

**서버가 아는 사실로만 판단한다.**

| 누구 | 언제 나오나 | 사라지는 때 |
|---|---|---|
| 고객 | 접수한 요청이 0건 | 첫 접수를 하면 |
| 파트너 | 승인 전 | 승인되면 |

첫 걸음을 실제로 떼면 스스로 사라진다 — **닫는 버튼이 없는 이유다.** 파트너 쪽은 제출 → 서류 →
승인의 세 걸음이고, 끝난 걸음에 표시가 붙는다. 사업자인지 개인인지에 따라 둘째 걸음의 문구가 다르다.

## 6. 이번에 하지 않은 것

- **소셜 로그인.** 세 곳 모두 사장님이 개발자센터에서 앱을 등록하고 키를 받아 환경변수에 넣으셔야
  한다. 그리고 소셜로 들어온 사람도 **휴대폰 인증은 따로 받아야 한다** — 카카오 계정만으로는 그
  사람에게 연락할 방법이 확인되지 않는다.
- **결제 수단 확대.** 토스페이·계좌이체·가상계좌는 결제 완료 시점이 서로 다르다. 가상계좌는 입금까지
  며칠이 걸리고 그동안 주문 상태를 어떻게 둘지 정해야 한다. 토스 계약이 실제로 열린 뒤가 맞다.
- **이메일 비밀번호 찾기.** 권하지 않는다. 이메일을 받지 않는 구조라 칸부터 새로 만들어야 하는데,
  문자 인증이 이미 도는 상태에서 얻는 것이 적다.
- **탈퇴한 계정의 기록 파기.** `purgeAccount` 는 이미 있고 관리자만 부를 수 있다. 법정 보관 기간을
  누가 언제 판단하는지는 아직 사람 몫이다.
