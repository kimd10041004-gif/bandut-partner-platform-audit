# 29-24 검증결과

## 1. 탈퇴 게이트 — 수정 전 실패를 먼저 냈다

`tests/accountExit.http.test.ts` 넷. 게이트를 빼고 돌린 결과다.

```
× 진행 중인 주문이 있으면 이유와 함께 막는다
  AssertionError: {"ok":true,"result":{"id":"AC-0001","role":"customer","name":"탈퇴 회원",
  "phone":"","withdrawnAt":"2026-09-12T07:35:31.673Z"}}: expected 200 to be 400
× 비밀번호가 틀려도 거절 이유는 거래다
× 주문이 끝나면 탈퇴가 열리고, 실제로 탈퇴된다
```

입찰이 돌고 있는 고객이 **`"ok":true` 로 탈퇴됐고 `탈퇴 회원` 이 됐다.** 이것이 이 라운드의 근거다.

게이트를 되돌리자 넷 다 통과한다.

## 2. 그 넷이 각각 재는 것

| 줄 | 왜 있나 |
|---|---|
| 주문이 없으면 탈퇴할 수 있다고 답한다 | 게이트가 **아무나 막는 것**이 아님을 본다. 이 줄이 없으면 "항상 거절"도 통과한다 |
| 진행 중인 주문이 있으면 이유와 함께 막는다 | 미리 보기(`withdrawCheck`)와 실제 누름(`withdraw`)을 **둘 다** 본다. 그리고 계정이 살아 있는지 확인한다 — 거절이 절반만 되지 않았는가 |
| 비밀번호가 틀려도 거절 이유는 거래다 | 순서가 지켜지는지. 메시지에 '비밀번호'가 없어야 한다 |
| 주문이 끝나면 탈퇴가 열리고 실제로 탈퇴된다 | 막기만 하고 열어 주지 않으면 그것도 고장이다. 세션이 함께 끊기는지도 본다 |

## 3. 봇이 화면 다섯 줄을 더 건다

`e2e:roles` 가 23 → **30** 줄이 됐다.

```
✓ 승인 전 파트너에게 남은 걸음이 보인다
✓ 처음 온 고객에게 다음 걸음이 보인다
✓ 안내가 가리키는 곳이 접수 화면이다
✓ 승인된 파트너에게는 안내가 남지 않는다
✓ 고객 계정 화면에 탈퇴 자리가 있다
✓ 거래가 없으면 탈퇴가 열려 있다
✓ 관리자 화면에는 탈퇴 자리가 없다

[e2e:roles] 30 passed, 0 failed
```

"승인된 파트너에게는 안내가 남지 않는다"가 수정사항 §5 의 설계를 재는 줄이다. 안내에 닫는 버튼이 없으므로,
**스스로 걷히지 않으면 영원히 남는다.**

처음 쓴 자리는 틀렸다 — 봇이 이미 승인을 마친 뒤라 "승인 전 파트너"를 재는 줄이 0 개를 셌다.
승인 직전으로 옮기고, 원래 자리는 "승인 뒤에는 사라진다"로 바꿨다. **재려는 것과 실제로 재는 것이
달랐던 경우**라 그대로 두면 통과만 하고 아무것도 확인하지 않았을 것이다.

title={pending ? '승인 검토 중입니다' : submitted ? '승인까지 남은 걸음입니다' : '파트너 활동을 준비해 주세요'}

## 6. 곁가지로 잡은 것 — 순서에 기대던 검사

`tests/marketplace.http.test.ts` 는 `public.sessions` 를 쓰면서 **그것을 남이 만들어 주기를 기다리고
있었다.** 빈 DB 에 그 파일만 돌리면 열두 줄이 죽는다.

```
error: relation "sessions" does not exist
 ❯ tests/marketplace.http.test.ts (13 tests | 12 failed)
```

CI 는 작업 절차에서 `psql -f db/schema.sql` 을 먼저 돌려 이 의존을 가려 왔다. 즉 **CI 는 초록인데
검사 자체는 혼자 설 수 없는** 상태였다.

`tests/support/globalSetup.ts` 로 옮겼다. 파일들이 시작하기 **전에 한 번** 돈다 — 각 파일의
`beforeAll` 에서 부르면 검사가 도는 도중에 DDL 이 실행되므로 그 자리는 피했다.

빈 DB 열두 번 연속 확인했다.

## 7. 아직 확인되지 않은 것

### 7-1. 이미 있던, 가끔 나는 실패 — 이 라운드 것이 아니다

`tests/passwordReset.http.test.ts` 의 한 줄이 **열 번에 두세 번** 빨갛다.

```
× 복구가 끝나면 그 계정의 기존 세션이 살아 있지 않다
  AssertionError: {"ok":false,"error":"휴대폰 번호 또는 비밀번호가 일치하지 않습니다 (남은 시도 4회)"}
  expected 422 to be 200
```

**이 라운드가 만든 것이 아니다.** 같은 29-23 을 같은 기계에서 돌려 12 번 중 2 번 같은 실패가 났다.
처음에 29-23 을 18 번 돌려 전부 초록인 것을 보고 "이번 라운드가 만들었다"고 적을 뻔했는데,
그 18 번은 기계가 한가할 때였다. **부하가 오르자 예전 코드에서도 난다.**

원인은 `auth_state` 한 행을 여러 파일이 같이 쓰는 자리로 좁혀 뒀다. 고치려면 그 쓰기 경로를
건드려야 해서 이 라운드에 넣지 않는다 — 별도 라운드가 맞다.

이번에 한 것은 **실패가 스스로 이름을 말하게** 만든 것뿐이다. 확인하지 않고 지나가던 걸음
(`verifyOtp`)에 단언을 붙이고, 상태 코드만 보던 자리에 응답 본문을 실었다. 그 덕에 위 메시지를
얻었다.
