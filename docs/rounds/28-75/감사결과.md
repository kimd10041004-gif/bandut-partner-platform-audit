감사자 관점: 이 라운드가 **새로 넣은 것**만 본다. 28-74 감사 4건을 고쳤고 PR 리뷰 1건까지 반영했으므로,
그 수정들이 만들어 낸 새 표면이 대상이다. 병합 `efca7ef`(+ §7 후속 `e2a68c2`), 게이트 전부 초록,
배포 확인됨(`/assets/index-k0C_1ZRF.js`).

한 줄 요약: **규칙은 고쳤는데 그 규칙이 지켜지는 순간을 다 세지 않았다.**
28-74-01은 "보관이 저장을 막는 일이 **구조적으로** 사라진다"고 적었다. 그 문장이 성립하려면 두 가지가 더 필요하다 —
예산이 **받아들일 본문**까지 세어야 하고, 이미 쓰여 있는 초과분을 **누군가 줄여야** 한다. 둘 다 없다.

## 28-75-01 (상) 예산이 "이번에 받아들일 원격 본문"을 세지 않는다 — 보장이 성립하지 않는다

`stashBudget()`은 **지금 로컬 스냅샷**을 기준으로 남은 자리를 잰다:

```ts
export function stashBudget(platform: PlatformService): number {
  const u = platform.storageUsage()
  return Math.max(0, Math.min(OVERWRITTEN_BUDGET, u.limit - u.chars))   // u.chars = 지금 로컬
}
```

그런데 이 값이 쓰이는 자리는 복제기가 **원격을 받아들이기 직전**이다(`replicator.ts`):

```ts
stashed = this.stash?.(mine, ...) === true      // ← 여기서 예산을 잰다 (로컬 기준)
...
if (remote.body !== '') this.source.accept(remote.body)   // ← 그리고 로컬이 원격으로 갈린다
```

`accept` 뒤의 스냅샷은 **원격 본문**이다. 원격이 로컬보다 크면 합계가 한도를 넘는다:

| | 보관 전 | 보관 뒤 | accept 뒤 |
|---|---|---|---|
| 스냅샷 | 2.0MB | 2.0MB | **3.5MB** (원격) |
| 보관함 | 0 | 1.0MB (예산 = min(1MB, 4−2)) | 1.0MB |
| 합계 / 한도 4MB | 2.0 | 3.0 | **4.5 — 초과** |

그 뒤 `assertRoom`이 합계로 판정하므로 그 기기의 **모든 저장이 막힌다** — 28-74-01이 없앴다고 적은 바로 그 상태다.
그리고 보관함을 비우는 화면은 여전히 관리자 전용이므로(28-74-01의 이월 사항) 파트너 기기는 풀 방법이 없다.

원격 본문의 크기는 `stash` 호출 시점에 이미 손에 있다(`remote.body`). 예산을 그것으로 재면 된다.

**고칠 방향**: `stash`에 "받아들일 본문의 크기"를 함께 넘겨 `limit - 원격본문크기`로 예산을 잡는다.
(도메인이 저장소를 모르는 경계는 그대로 — 크기는 숫자 하나다.)

## 28-75-02 (상) 이미 쓰인 초과 보관함을 아무도 줄이지 않는다 — 28-74에 당한 기기는 그대로 막혀 있다

28-74는 **프로덕션에 나갔다**(배포 확인됨, `/assets/index-BTR_azXN.js`). 그 사이 conflict를 겪은 기기에는
고정 예산으로 쓰인 보관함이 최대 1MB 남아 있다. 28-75는 **앞으로의 보관**만 고쳤다.

`stashOverwritten`은 예산에 안 들어가면 **아무것도 쓰지 않고** 돌아간다:

```ts
while (next.length > 0 && JSON.stringify(next).length > cap) next.pop()
if (next.length === 0) return false      // ← setItem을 부르지 않는다 = 옛 값이 그대로 남는다
```

즉 초과분이 줄어드는 유일한 길은 **다음 conflict에서 새 본문이 예산에 들어가는 것**이다. 그런데 막힌 기기는
바로 그 조건이 안 맞는 기기다(스냅샷이 커서 `cap`이 작다). conflict가 다시 오지 않으면 영영 그대로다.

**앱이 뜰 때 한 번도 맞춰 보지 않는다**는 것이 핵심이다. `initPlatform()`은 보관함을 용량 회계에 넣기만 하고
(`externalChars`) 크기를 손보지 않는다. 부팅 때 한 번 `stashBudget` 기준으로 잘라 내면 그 기기는 바로 풀린다.

**고칠 방향**: `initPlatform()`(또는 `initReplicator`) 에서 부팅 시 1회 `trimOverwritten(storage, budget)` —
예산을 넘으면 오래된 것부터 버리고, 하나도 안 들어가면 **비운다**(그때는 비우는 것이 사용자에게 이롭다:
꺼낼 수 없는 1MB보다 쓸 수 있는 1MB가 낫다. 다만 그 사실을 알려야 한다 — 04 참고).

## 28-75-03 (중) 실패한 로그인 한 번의 비용이 **계정 수에 비례**하게 됐다

`pruneTrustedIps`를 `login()` 맨 앞에 넣었다 — 성공이든 실패든 매번 돈다:

```ts
this.pruneLoginFails(now)
this.pruneTrustedIps(now)   // 28-74-02
```

`pruneTrustedIps`는 **모든 계정 × 모든 IP**를 훑는다:

```ts
for (const [account, ips] of this.trustedIps) {
  for (const [ip, at] of ips) if (now - at > TRUSTED_IP_TTL_MS) ips.delete(ip)
  ...
}
```

계정 1만 개면 최대 5만 번의 Map 연산이 **로그인 시도마다** 돈다. 무차별 대입 시도는 정확히 그것을 많이 만든다 —
막으려는 공격이 서버 CPU를 계정 수만큼 증폭해서 먹는 구조다.

같은 모양을 이 저장소가 이미 한 번 지적했다: 28-72 PR 리뷰가 "`recordFail`이 `login()`과 중복으로
`pruneLoginFails`를 부른다 — 실패 한 번에 Map 스캔 3회"를 짚었고 28-73이 그것을 없앴다. 그 판단이 옳았다면
이번에 다시 들어온 전체 스캔도 같은 잣대를 받아야 한다.

**고칠 방향**: 시간 게이트(마지막 스윕으로부터 N분 지났을 때만) 또는 저장 시점으로 옮긴다.
만료의 목적은 "영영 남지 않게"이지 "밀리초 단위로 정확하게"가 아니다.

## 28-75-04 (중) 주석이 자리를 잃었고, 문구가 "안 했다"와 "못 했다"를 뭉갠다

**(a) `purgeAccount`의 설명이 다른 함수에 붙었다.** 새 private 메서드를 기존 docstring과 그 함수 **사이**에
끼워 넣었다:

```ts
  /** 기록 파기 (28-39-01) — 관리자, 탈퇴 계정만. 법정 보관 기간 경과 후 실행 */
  /**
   * 28-74-02: 이 계정의 전화번호가 들어간 키를 전부 버린다 ...
   */
  private forgetAccountKeys(role: SignupRole, phone: string): void { ... }

  purgeAccount(accountId: string): void { ... }        // ← 설명이 없다
```

`forgetAccountKeys`는 "기록 파기 — 관리자, 탈퇴 계정만"이라는 **틀린 설명**을 이고 있고, `purgeAccount`는
설명을 잃었다. 이 저장소의 규율이 "주석이 사실을 말한다"이므로 이것은 형식이 아니라 내용 문제다.

**(b) "보관하지 못했습니다"가 두 가지를 같은 말로 덮는다.** 28-75 리뷰(Copilot)가 원인 단정을 지적해
문구에서 원인을 뺐다. 옳은 방향이었지만, 그 결과 **애초에 보관 기능이 없는 경우**(저장소 없음 → `stash`를
넘기지 않는다)와 **시도했으나 실패한 경우**가 같은 문장을 받는다. 앞의 경우 사용자는 잃어버린 무언가를
찾으러 나서게 된다 — 없는 것을.

**(c) `_원바이원_감사대기_상태.json`의 끝 개행이 사라졌다**(`\ No newline at end of file`).
이 파일은 GPT 감사자가 읽는 상태 파일이므로 조용히 형태가 바뀌는 것은 바람직하지 않다.

**고칠 방향**: (a) docstring을 제자리로. (b) `stash`가 없을 때는 "보관하지 못했습니다"를 붙이지 않는다
(덮였다는 사실만 말한다). (c) 개행 복구.

## 이번 라운드가 잘한 것 (되돌리지 말 것)
