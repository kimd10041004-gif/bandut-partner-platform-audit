# 28-46 수정사항 (Claude) — 취소·환불 라운드

기반: `28-45` 복사본(스크래치 wf28-46)에서 작업. 28-45 감사 4건 전부 반영.

## 28-45-01 · 환불 도메인 [반영]

- `Refund { id, requestId, paymentId, amount, deduction, afterVisit, reason, status: pending|done, createdAt, doneAt? }`. `transitionRequest(…, 'cancelled')`가 예약금 결제를 찾으면 환불 대기 자동 생성 — 취소 시점의 슬롯 방문일이 오늘 이하면 `afterVisit`(실비 차감 협의), 아니면 전액. 고객·관리자 알림.
- `settleRefund(refundId, { deduction, reason })`: 중복 처리 거부, 차감 0 이상·예약금 이하, **방문 전 취소는 차감 불가**, 차감 시 사유 필수, 완료 시 고객 알림(+차감분 파트너 알림). `refundFor` / `pendingRefunds`. `opsQueue.pendingRefunds`(+counts). 환불 대기 중인 고객은 탈퇴 차단(`openTransactionCount`).
- 스냅샷 `refunds`/`refundSeq` 저장·검증(금액·차감 범위·상태·doneAt). 도메인 테스트 2건 → vitest 199→**201**(기존 opsQueue 테스트 기대값에 `pendingRefunds: 0` 추가).

## 28-45-02 · 고객: 환불 상태 표시 [반영]

- 거래 상세 **예약금 환불** 카드(`.refund-card`, `data-refund-status`): 대기/완료·환불액·사유·차감·처리일. 취소 확인 문구를 약관 제6조 정책 문구로 교체.

## 28-45-03 · 관리자: 환불 처리 [반영]

- 현황 "조치 필요" **환불 대기** 그룹(`data-ops="refund"`): 요청·고객·예약금·방문 전/후, 방문일 경과 건은 차감액·사유 입력, **환불 완료** 버튼. 정산 감독 결제 현황에 취소 건 포함 + "환불" 열.

## 28-45-04 · e2e + 실측 [반영]

- e2e 5단계 추가(91→**96**): 주방 수전 예약금 결제 → 취소 → 고객 환불 대기 → 관리자 조치 필요 환불 대기 1건 → 환불 완료 → 고객 환불 완료. 첫 실행은 테스트 기대값 불일치로 빌드가 갱신되지 않아 옛 번들로 돌아 2건 실패 → 기대값 정정 후 96/96.
- 실측 3장.
