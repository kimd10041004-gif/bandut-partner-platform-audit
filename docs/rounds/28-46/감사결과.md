# 28-46 감사결과 (GPT 역할 — Claude 세션 대리 수행)

감사 범위: `28-46` 전체 — 취소·환불 반영 후, **파트너가 자기 일감을 찾는 경로** 점검.
사전 확인: `npm run check` exit 0 (vitest 201/201), e2e 96/96 PASS, visual-check 전 항목 PASS, `npm audit` 0건, 프로덕션 배포 그린(PR #114 머지). 28-45 감사 4건 전부 수정 확인됨.

핵심 지적: 파트너 프로필에 "전문 분야"와 "서비스 지역"이 있지만 **어디에도 쓰이지 않는다.** 일감 탭은 전국·전 카테고리 요청을 그대로 나열하고, 새 요청이 올라와도 파트너는 알림을 받지 못한다(고객만 "견적 도착" 알림을 받는 비대칭). 파트너가 늘수록 일감 탭은 소음이 되고, 응답 속도(고객이 첫 견적을 받기까지)는 플랫폼의 핵심 지표다. 프로필의 두 필드는 자유 텍스트라 매칭에 쓸 수도 없다 — 카테고리는 시스템 목록에서 고르고, 지역은 토큰(시·구)으로 비교해야 한다.

## 상 (High)

### 28-46-01 · 매칭 도메인
→ 요구: `PartnerProfile.specialties`(쉼표 구분 카테고리)·`region`(쉼표 구분 지역 토큰)을 파싱하는 `profileMatch(profile, request)` — 카테고리 일치 AND (지역 토큰 중 하나가 요청 지역에 포함, 지역 비어 있으면 통과). `matchedRequests(partnerId, today)` — 낙찰 전·마감 전 요청 중 매칭되는 것. **`addRequest` 시 매칭되는 프로필 보유 파트너 전원에게 알림**("내 지역·분야 새 일감 — …", 계정 범위). `updateProfile`은 specialties의 각 토큰이 카테고리 목록에 있는지 검증. **도메인 테스트 필수**.

### 28-46-02 · 프로필 폼 구조화
→ 요구: 마이 탭 프로필 폼의 전문 분야를 **카테고리 필 다중 선택**(저장은 쉼표 문자열로 하위 호환), 서비스 지역은 쉼표 구분 입력 + 안내("예: 서울, 고양 — 요청 지역에 포함되면 매칭"). 가입 직후 시드 프로필(`DEFAULT_PARTNER_PROFILE`)은 전문 분야 비움 → 매칭 없음(파트너가 설정해야 알림).

### 28-46-03 · 일감 탭 맞춤 필터 + 대시보드
→ 요구: 일감 탭 "내 지역·분야만" 토글(프로필에 분야가 있으면 기본 켜짐), 카드에 "맞춤" 태그. 대시보드 "입찰 가능" 지표를 맞춤 일감 수로(전체 수 병기).

## 중 (Medium)

### 28-46-04 · e2e + 실측
→ 요구: e2e — 파트너 프로필 저장(욕실 + 서울) → 일감 탭 맞춤 토글로 서울·욕실 건만 → 고객이 서울 욕실 요청 등록 → 파트너 알림 "새 일감". 실측: 프로필 폼·맞춤 일감 탭.
