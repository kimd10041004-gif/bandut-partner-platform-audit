### 28-70-01 (상) 인증이 인증이 아니다 — 가입 3요청이 마켓플레이스 전체의 읽기·쓰기 권한이다

`api/auth.ts`의 `register`는 **누구나** 부를 수 있고 OTP를 **응답에 돌려준다**(`out.result = { account, otp }` — "시연"이라 적혀 있다).
`verifyOtp`도 누구나. 그러므로 서버 모드에서 인터넷의 누구든:

```
POST /api/auth {op:'register', args:[{role:'customer', name:'x', phone:'01000000000', password:'12345678', agreeTerms:true, agreePrivacy:true}]}
POST /api/auth {op:'verifyOtp', args:['customer','01000000000', <방금 받은 otp>]}
POST /api/auth {op:'login', args:['customer','01000000000','12345678']}     → 토큰
GET  /api/snapshot?workspace=main   → 모든 고객의 이름·주소·전화·사진, 모든 파트너의 계좌 표기, 채팅
PUT  /api/snapshot?workspace=main {body:'{"version":1,…빈 상태…}', expectedRev:<head>}  → 마켓플레이스 전체 교체
```

`verified`는 휴대폰 소유를 뜻하지 않는다. 28-70 문서는 "인가는 불가능하고 인증까지"라고 정직하게 적었지만, **인증도
성립하지 않는다** — 자기 서명한 계정이다. `updated_by`는 누가 지웠는지 알려 줄 뿐 막지 못한다. 켜는 절차(`서버_연결.md` 1~5)
어디에도 이 사실이 없다.

근본 수정(SMS 전 단계): 서버 모드 가입은 **가입 코드**(`SIGNUP_CODE` 환경변수, 없으면 `register` 503)로 막는다 — 운영자가
아는 사람에게만 준다. 스냅샷 **읽기·쓰기는 관리자가 승인한 계정만**(파트너 `approval === 'approved'`, 고객은 관리자 승인 필드
신설 `customerApproved` 대신 **가입 코드 + 관리자 정지 권한**으로 충분하다고 보되, 문서에 "가입 코드를 아는 사람 = 마켓플레이스
읽기·쓰기 권한"이라고 적는다). 세션 발급은 `verified` 무관하게 이미 도메인이 막는다.

### 28-70-02 (상) 낡은 커서가 빈 로컬을 서버 위에 쓴다 — 손상 복구 한 번이 마켓플레이스를 지운다

`PlatformService.load()`(`platform.ts:796-820`)는 스냅샷이 손상되면 `removeItem(key)`하고 **새 인스턴스**(rev 0)를 돌려준다.
그런데 `<key>:rev`와 커서 `<key>:remote`는 그대로 남는다. 다음 저장(`initPlatform`의 sweep 하나면 된다)에서
`save()`가 `rev = max(0, stored 40) + 1 = 41`. `Replicator.loadCursor()`는 `{remoteRev: 7, localRev: 40}`을 **무조건 채택**하고
(`pushedLocalRev === undefined` 분기), `run()`은 `read → remote.rev 7 === remoteRev 7 → 남이 안 썼다 → pushedLocalRev 40 ≠ 41 → write(빈 본문, expectedRev 7)` → **200**. 서버 스냅샷이 빈 상태로 바뀌고, 다른 기기들은 다음 탭 복귀에서 그것을 받아들인다.

28-69-02의 커서는 "브라우저가 이미 밀어 올린 적 있다"를 기억하는 장치인데, 브라우저의 로컬 진실이 리셋됐다는 사실은
기억하지 않는다. 같은 모양이 `syncFromStorage`의 `applySnapshot` 실패(`return false`)에는 없고, 손상 리셋에만 있다.

근본 수정: (a) `bootstrap.initPlatform()`이 돌려주는 `restored === false`이면 `initReplicator()`가 커서를 **지운다** —
리셋된 브라우저는 새 기기다(규칙 2: 원격을 받아들인다). (b) 복제기 자체 방어: `loadCursor()`에서 `cursor.localRev > source.revision()`
이면 커서를 버린다(커서가 로컬보다 앞설 수는 없다). (c) 이 시나리오의 회귀 — 수정 전 `remote.body === 빈 본문`.

### 28-70-03 (중) 운영 안전장치가 없다 — 스크립트 하나가 프로덕션을 비우고, 세션은 영원히 쌓이고, 전화번호 하나로 남을 잠근다

- **(a)** `scripts/e2e-server.mjs`는 시작하자마자 `truncate snapshots, auth_state, sessions`를 **무조건** 한다. `DATABASE_URL`이
  프로덕션이면 계정·스냅샷 전부가 사라진다. 가드가 없다.
- **(b)** `sessions`는 만료·폐기 뒤에도 삭제되지 않는다. 로그인마다 행이 하나씩 — 정리 경로가 코드 어디에도 없다.
- **(c)** 잠금 규칙(28-51-02: 5회 실패 → 15분)이 인터넷에 노출됐다. 전화번호만 알면 **남의 로그인을 계속 잠글 수 있다**
  (`recordFail`은 IP를 모른다). 도메인 규칙 자체는 유지하되, 서버가 잠금 중 **올바른 비밀번호**를 받았을 때 풀어 주는지 —
  `assertNotLocked`가 먼저라 안 풀린다.
- **(d)** `handleAuth`·`handleSnapshot`의 503이 `err.message`(DB 오류 원문)를 그대로 낸다 — 28-68부터 이월.

### 28-70-04 (중) 검증·문서 어긋남

- **(a)** `e2e-server.mjs` "토큰이 브라우저에 있고 서버에는 해시만": `token_hash = <토큰 원문>` 행이 0개라는 단언 — base64url 43자가
  hex 64자와 같을 수 없으니 **항상 참**이다. 진짜 단언은 "`sha256(토큰)`이 있는 행이 1개"여야 한다.
- **(b)** `/api/auth`는 `?workspace=`를 받지만 `/api/snapshot`은 세션을 **항상 `main`**에서 찾는다(`sessionOf(db, DEFAULT_WORKSPACE, …)`).
  `main`이 아닌 워크스페이스로 로그인한 토큰은 스냅샷에 401 — 계약 테스트가 `main`만 써서 안 드러난다. 둘 중 하나로 통일.
- **(c)** 서버 모드에서 비관리자의 거울은 자기 계정 하나다. `PlatformContext:78-80`이 `auth.listAccounts()`로 채우는
  `platform.extraNames`(28-63-02 가명 처리 자체 검사의 이름 출처)가 **로컬 모드보다 적게 안다**. 검사는 요청의 `customerName`도 보므로
  무력화는 아니지만, "계정 서비스가 아는 이름"이 서버 모드에서 줄어든 것을 어디에도 적지 않았다.
- **(d)** `28-68/서버_연결.md` 5단계는 "켜면 된다"로 읽힌다 — 01·03(a)의 전제 조건이 없다. `README`의 "관리자 초기 계정" 줄은
  서버 모드 문장이 붙었지만 가입 코드·권한 범위는 없다.

### 그 밖에 기록만

- `hashPassword`(SHA-256 2000회, 동기)가 `for update` 잠금 **안에서** 돈다 — 로그인·가입이 워크스페이스 단위로 직렬화된다.
  파일럿 규모에서는 문제없고, scrypt 전환 때 함께 본다.
- 토큰이 `localStorage`(`banded-session-v1`)에 있다 — XSS면 곧 세션. `vercel.json`에 CSP가 없다. 쿠키(HttpOnly)로 옮기는 것은
  같은 origin API에서 가능하지만 e2e 구조가 바뀐다.
- 로그인한 계정은 `workspace` 파라미터로 행을 무한히 만들 수 있다(정규식만). CI 격리용 파라미터를 프로덕션에서 끌 방법이 없다.
- `applyMirror(complete:true)`가 관리자 세션의 응답마다 계정 전체를 저장한다 — 회원이 수천이면 저장 이벤트가 커진다.
- 이월: `@types/node` 누출, `pg.Pool`/`-pooler`, 구 스냅샷 마이그레이션, `markPayout` string 오버로드, `stripComments`, `api/` 훑기
  범위, 타임아웃 커버리지, StrictMode 이중 초기화, 시드·e2e의 실제 시계, 같은 기기 두 탭 수십 ms 창의 거짓 "덮였습니다".
- **반증한 것**: 거울의 변경 메서드 11개는 전부 `assertWritable()`로 막혀 있다(grep 12 = 정의 1 + 호출 11). 화면 13곳 모두
  `authActions`를 거친다(`auth\.(login|register|…)\(` 직접 호출 0건). 세션 토큰 원문은 서버 어디에도 저장되지 않는다.
