# 28-70 수정 사항 — 「서버 계정·세션」 + 28-69 감사 4건

**사용자 결정: 감사 4건 + 인증 전부.** 12개 op 모두 서버 경유, 서버 모드 e2e를 CI에서.

28-69 감사(`28-69/감사결과.md`)의 결론은 "아직 붙이면 안 된다"였다 — 읽기 경로가 첫 동기화 뒤에 죽고(01),
같은 브라우저의 두 탭이 서버를 사이에 두고 서로를 conflict로 만든다(02). 둘 다 토큰을 배선하는 순간 발현한다.
이 라운드는 그 넷을 먼저 고치고(A), 그 위에 서버 계정·세션(B)을 얹어 **실제로 배선했다** — 단, 빌드 시 모드로.
배포된 앱은 여전히 로컬 모드(`VITE_AUTH_MODE` 미설정)라 동작이 바뀌지 않는다. 서버 모드는 CI가 진짜 Postgres
위에서 기기 셋 e2e로 검증한다.

## A. 28-69 감사 4건

### 28-69-01 (상) 탭 복귀는 rev만 확인한다

- `SnapshotPort.head()` 추가 — Local·Memory·Http 세 구현. `api/snapshot.ts`는 `GET …&head=1`이면 `select rev`만.
- `Replicator.sync({ checkRemote: true })`: 로컬 변경이 없어도 `head()`로 원격 rev를 보고, 내가 마지막으로 본
  값과 다르면 read 경로를 태운다. 본문(최대 4MB)은 rev가 다를 때만 받는다. 직렬화는 로컬 변경이 있을 때만(28-68-02a 유지).
- `PlatformContext`의 focus·visibility·storage 경로가 `checkRemote: true`로 부른다.
- 회귀: "보기만 하는 기기도 focus sync에서 남의 변경을 받아들인다"(수정 전 `accepted: []`), "rev만 확인하고 같으면
  본문을 받지 않는다"(`heads 2`, `reads` 그대로, `bodyCalls 1`). 계약 테스트 `head()` 2건.

### 28-69-02 (상) 커서는 브라우저 것이다

- `ReplicatorOptions.cursor`(`CursorStore`) — `{remoteRev, localRev}`를 `banded-platform-v1:remote`에 저장하고 매 실행 앞에
  읽는다(`syncFromStorage`가 `:rev`를 읽는 것과 같은 모양). 다른 탭이 앞서 있으면 그쪽 값을 받는다. 새로고침한 탭도
  "이미 밀어 올린 브라우저"임을 안다 — 오프라인 편집 뒤 새로고침이 새 기기 합류로 오해되지 않는다.
- 안전망: conflict의 원격 본문이 방금 보내려던 본문과 같으면 accept 없이 rev만 채택한다.
- **다른 탭의 storage 이벤트는 받기만 한다** — `sync({ pushLocal: false })`. 보내는 것은 변경을 만든 탭의 디바운스 몫이다.
  진행 중에 쌓인 요청은 **합집합**으로 다시 돈다(storage 이벤트만 쌓였으면 다시 돌 때도 보내지 않는다) — 서버 모드
  e2e에서 탭2가 `again` 재실행(기본 옵션)으로 밀어 올려 탭1과 409를 낸 것을 잡았다.
- 배너 문구: 덮인 로컬 변경이 있었을 때만 "…이 기기에서 반영되지 않은 변경은 덮였습니다", 아니면 "다른 기기의 변경을
  받아들였습니다"만.
- 회귀: 02(같은 브라우저 두 탭 — `writes 2→1`, `conflict→synced`, 진짜 변경 `되돌려짐→유지`), 02-b(안전망),
  02-c(storage 이벤트는 보내지 않는다), 02-c2(again 합집합 — 수정 전 `writes 2`).

### 28-69-03 (중) 수명주기·시계

- `start()`가 stop이 거둔 재시도를 다시 걸고, stopped 중에 도착한 상태(`deferred`)를 흘려보낸다. `markChanged()`는
  offline이면 예약이 없을 때만 건다(`armRetry` 멱등).
- `ReplicatorOptions.now` 주입. (a-2)는 가짜 시계로 `[1500] → [1000] → [0]`을 실제로 진행시킨다(수정 전 `[1500]`).
- `fakeScheduler.fire(n, rep)`는 실제 시간이 아니라 `rep.idle()`(inFlight + again 재실행)을 기다린다.

### 28-69-04 (중) 검증 공백·문서

- (a) 계약 테스트에 **복제기 × HttpSnapshotPort × Postgres 합성** — A push → B 합류 accept → B push → A `checkRemote` accept.
  토큰 없는 포트는 왕복 없이 `rejected 401`, 재시도 예약 없음.
- (b) `rejected` 뒤 `needsRead`는 401·403일 때만 — 413·400·422는 원격이 바뀌었다는 뜻이 아니다(수정 전 `reads +1`).
- (c) `api/snapshot.ts`·`db/schema.sql`의 "28-69에서 사용자별 분리" 문장을 사실대로.

## B. 서버 계정·세션

### 규칙은 한 코드다

`api/auth.ts`가 **클라이언트와 같은 `AuthService`**를 Postgres 행(`auth_state`) 위에서 돌린다: `select … for update` →
Map `StorageLike`에 body → `new AuthService(storage)` → 세션 있으면 `adoptSession` → 권한 검사 → 메서드 → `exportState()`가
바뀌었으면 `update … rev = rev + 1`. 가입 검증·해시·잠금·OTP·승인·탈퇴 규칙 745줄과 테스트 473줄이 그대로 서버 규칙이다.
손상된 body는 클라이언트처럼 초기화하지 않고 503으로 막는다(서버에서 그것은 계정 전부의 조용한 유실이다).

| op | 누가 |
|---|---|
| register · verifyOtp · login | 누구나 |
| logout · me | 세션 |
| changePassword · setMarketingOptIn · setPayoutAccount · withdraw | 세션 본인 |
| listAccounts · approvePartner · rejectPartner · setSuspended · purgeAccount | admin 세션 |

### 세션

- `login`이 32바이트 불투명 토큰을 발급하고 `sessions`에 **sha256만** 저장(`server/session.ts`). 만료 `SESSION_TTL_MS[role]`,
  로그아웃·정지·탈퇴·파기 때 `revoked_at`. `/api/snapshot`도 이 토큰으로만 열린다 — `WORKSPACE_SECRET` **삭제**.
- `snapshots.updated_by`에 쓴 계정 ID — 통째 쓰기의 책임 귀속.
- 관리자 초기 비밀번호 `ADMIN_PASSWORD` — 없거나 8자 미만이거나 시연값이면 503.
- 서버 모드에는 시연 시드가 없다.

### 클라이언트

- `AuthService({ mirror: true })`: 읽기는 그대로, 변경 메서드 11개는 `assertWritable()`로 던진다. `adoptSession`·`applyMirror`
  (같은 값이면 저장하지 않는다 — 탭 사이 storage 핑퐁 방지, e2e에서 실제로 났다)·`exportState`(세션·rev 제외).
- `HttpAuthClient`(던지지 않는다) · `TokenStore`(`banded-session-v1`, 역할별) · `createAuthActions`(12 op async 파사드 —
  로컬 모드는 `AuthService` 직접, 서버 모드는 HTTP 뒤 거울 갱신; 401이면 토큰·세션 정리).
- 화면 13곳(`AuthGate` 5 · `MyAccount` 3 · `Settlement` 1 · `AdminMembers` 4 · `AdminOverview` 1)이 `authActions`를 `await`한다.
- `bootstrap.ts`: `AUTH_MODE`, `initTokens`, `initAuthActions`, 서버 모드면 `HttpSnapshotPort('/api/snapshot', () => tokens.any(), 'main')`
  + 커서 store. `PlatformContext`: 시작·탭 복귀에 `restore()`(계정 키의 storage 이벤트에만), 로그아웃 상태의 401은 배너 아님.
- `App.tsx` 라운드 표기에 `data-auth-mode`.

### 서버 스크립트·CI

- `scripts/api-server.mjs`: `/api/auth` 라우팅(엔트리 하나로 묶어 풀을 공유), `--static dist`(Vercel과 같은 origin 구성).
- `scripts/e2e-server.mjs`: 기기 셋 31단계 — 가입·OTP·로그인·복원, 시연 비밀번호 거부, 보기만 하는 기기의 탭 복귀(28-69-01),
  같은 기기 두 탭(28-69-02), 승인 도달, 로그아웃 토큰 401, 잠금, `sessions`에 원문 없음. `E2E_TRACE=1`이면 API 왕복을 찍는다.
- `gates.yml` server job: `ADMIN_PASSWORD`, 계약(로그인해서 토큰), `VITE_AUTH_MODE=server` 빌드 → `e2e:server`.
