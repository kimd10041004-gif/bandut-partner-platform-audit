## 2. 배포 확인이 **운영에서 실제로 잰 값**

`.github/workflows/deploy-check.yml` 이 `main` 푸시마다·매시간 운영 주소를 찔러 봅니다.
아래는 29-32 병합 직후 run #153 (2026-09-18 06:33 UTC) 의 실제 출력입니다.

```
ROUND:       29-32     ← 서빙 HTML 의 라운드 표식. 29-32 가 실제로 올라가 있다
MODE:        server    ← bandut-auth-mode 표식. 로컬 모드가 아니다
PATHS_BAD:   0         ← 36개 경로 전부 살아 있음
CONTENT_BAD: 0         ← 화면 안 내용도 어긋난 것 없음
ENV_READY:   no        ← ↓ 아래 참조
ENV_DB:      unknown   ← ↓ 아래 참조
```

**`ENV_READY: no` 의 정확한 의미** — 검사가 붙여 준 설명 그대로입니다:

> 두 값(`DATABASE_URL`·`ADMIN_PASSWORD`)은 설정됨 — 인증번호를 전달할 방법이 없어 **가입만** 막혀 있다
> (프리뷰는 `AUTH_DEV_OTP=on`, 운영은 `SMS_*` 셋)

실제 응답:

```
HTTP 503 {"ok":false,"error":"문자 발송이 아직 연결되지 않아 가입과 비밀번호 찾기를
받을 수 없습니다. 잠시 뒤 다시 시도해 주세요."}
```

**`ENV_DB: unknown` 의 이유** — DB 왕복 탐침이 가입 경로로 묻는데, 위의 SMS 벽에서 먼저
멈춥니다. 그래서 **운영 DB 왕복은 실측되지 않았습니다.** 프리뷰에서는 `ok` 였으나 그건 운영이 아닙니다.

**브라우저 단계는 이 실행에서 `skipped`** 입니다 — `deploy-check` 의 브라우저·가입 왕복 단계는
`workflow_dispatch` 입력으로 켤 때만 돕니다. 자동 실행에서는 HTTP 검사까지만 합니다.

## 3. 환경변수 지도 (이름과 역할만 · 값 없음)

값은 Vercel 안에만 있습니다. 저는 읽은 적이 없고 이 저장소에도 없습니다.
"현재 운영 상태" 는 위 §2 의 검사 출력과 화면 동작에서 **역산한 것**입니다.

### 3-1. 운영에 반드시 필요한 것

| 이름 | 무엇을 지키는가 | 현재 운영 상태 |
|---|---|---|
| `DATABASE_URL` | Postgres 연결. 없으면 503 | **설정됨** |
| `ADMIN_PASSWORD` | 관리자 로그인. 없거나 8자 미만이거나 시연값이면 **503** (시연값으로 조용히 열리지 않음) | **설정됨** |
| `SMS_PROVIDER` `SMS_API_KEY` `SMS_SENDER` | 가입·비밀번호 찾기 인증번호 발송. **셋이 모두** 있어야 함 (`server/authSafety.ts` `smsConfigured`) | **미설정 → 신규 가입·비번찾기 503** |

### 3-2. 선택 — 없으면 해당 기능만 닫힘

| 이름 | 역할 |
|---|---|
| `BLOB_STORE_ID` `BLOB_READ_WRITE_TOKEN` `BLOB_TOKEN` | Vercel Blob 사진 저장소. 없으면 `LOCAL_STORAGE_DIR`, 그것도 없으면 저장소 없음(503) |
| `BLOB_WEBHOOK_PUBLIC_KEY` | Blob 웹훅 서명 검증 |
| `MAIL_PROVIDER` `MAIL_API_KEY` `MAIL_SENDER` `MAIL_TIMEOUT_MS` `MAIL_WINDOW_MS` | 이메일 비밀번호 복구. 셋이 모두 있어야 함 (`mailConfigured`) |
| `TOSS_CLIENT_KEY` `TOSS_SECRET_KEY` `TOSS_BASE` `PAYMENTS_LIVE_APPROVED` | 결제 (`lib/payments.ts`) |
| `LOCAL_STORAGE_DIR` | 로컬·CI 파일 저장소 |
| `DATABASE_URL_UNPOOLED` | 있으면 쓰는 자리가 있음. **무조건 대체하도록 바꾸지 말 것** (사장님 지시) |

`lib/payments.ts` 의 모드 판정이 흥미롭습니다 — `test_ck_`/`test_sk_` 접두사면 `test`,
`live_ck_`/`live_sk_` **그리고** `PAYMENTS_LIVE_APPROVED === 'true'` 여야 `live`.
둘 다 아니면 `unconfigured`. **감사 포인트: 이 판정을 우회해 실결제가 열리는 경로가 있는지.**

### 3-3. 위험 스위치 — 운영에 절대 켜지면 안 되는 것

| 이름 | 켜지면 무슨 일이 | 코드 |
|---|---|---|
| `AUTH_DEV_OTP` | **인증번호 검증 우회.** 운영에 들어가면 누구나 남의 번호로 가입 가능 | `server/authSafety.ts` `devOtpAllowed()` — `VERCEL_ENV==='production'` 이면 무조건 `false`, `preview` 에서만 `'on'` 을 본다 |
| `E2E_ALLOW_TRUNCATE` | 봇이 **표를 비웁니다.** 운영에 들어가면 데이터 삭제 | `scripts/bot-kit.mjs` · 봇들 |

> **아스트라에게**: 이 둘이 운영에서 켜질 수 있는 경로가 실제로 없는지 봐 주세요.
> `devOtpAllowed()` 는 `VERCEL_ENV` 를 믿습니다 — 그 값이 신뢰할 수 있는지,
> 그리고 이 함수를 **거치지 않고** OTP 를 통과시키는 다른 길이 없는지가 핵심입니다.

## 4. 알려진 운영 제약

| | |
|---|---|
| 신규 가입 | **불가** (SMS 미설정, 503). 기존 계정 로그인은 됨 |
| 비밀번호 찾기 | 문자 경로 불가. 이메일 경로는 `MAIL_*` 설정 여부에 달림 — 미확인 |
| 운영 도메인 | 미연결. `.vercel.app` 주소로만 접근 |
| 옛 `s256$` 해시 계정 | 로그인해야 scrypt 로 올라감. 현재 몇 개인지 **세지 않았습니다** |

| DB 접속 문자열 (`postgres://user:pass@host`) | 5개 파일에서 걸렸으나 **전부 가짜**: `server/db.test.ts` · `server/dbFingerprint.test.ts` · `server/dbProbe.test.ts` 의 테스트용 가짜 호스트, `.github/workflows/gates.yml` 의 러너 localhost, 문서 1건 |
| `.env` · `.pem` · `.key` · `id_rsa` · `credentials` 류 파일명 | **0건** |

원본 저장소의 **전체 이력 262커밋**에 대해서도 같은 검사를 돌렸고 결과는 같았습니다
(가짜·localhost 만). 그럼에도 이력을 옮기지 않은 것은, 제 검사가 **제가 아는 10가지 형식만**
본 것이기 때문입니다. 스냅샷으로 가면 "과거 어느 커밋의 사고" 라는 위험군 자체가 사라집니다.

> 이 검사의 한계를 감사 대상에 포함해 주셔도 좋습니다 — 제가 못 보는 형식이 있다면 그것이
> 바로 제가 모르는 위험입니다.
